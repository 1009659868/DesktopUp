# Desktop-Up V2 统一候选证据矩阵 V1

状态：`ACTIVE — NO CANDIDATE RESULTS`

日期：2026-08-20

## 1. 矩阵用途

本矩阵是所有技术候选的统一裁判。它同时用于：

- 静态事实审查；
- 海报呈现与桌面宿主最小原型；
- 支撑技术域比较；
- 最终复测、评分和淘汰；
- 向架构阶段交付已验证约束。

矩阵建立不代表任何候选已通过。所有结果初始为 `NOT RUN`。

## 2. 固定比较基线

### 2.1 产品夹具

所有海报候选必须呈现同一组夹具：

1. Night Ops 默认视觉原型；
2. 六张 Item 卡片的 3×2 基线；
3. 零 Item、一 Item、多 Item、失效 Item、缺图标和超长名称；
4. 展开/收起、锁定/解锁、USING/EDITING；
5. 默认透明模板、Neon HUD、Cinema Lightbox、minimal-fallback 的最小等价表达；
6. 相同逻辑尺寸、圆角、标题栏、按钮、卡片和命中区。

候选可以使用各自渲染语法，但不能减少视觉或交互要求来获得通过。

### 2.2 初始系统环境

- Windows 11 x64，记录精确 OS build；
- 单主显示器；100%、125%、150%、200% 缩放分别运行；
- 记录分辨率、工作区、GPU、驱动、远程桌面/虚拟化状态；
- 记录候选、SDK、编译器和运行时精确版本；
- Release/优化构建；调试构建只能用于定位，不能用于性能结论；
- 同一机器、同一壁纸、同一普通程序和同一测试顺序；
- 多显示器、混合 DPI、负坐标和热插拔不作为本轮发布通过项，但记录候选是否存在结构性封锁。

### 2.3 外部交互夹具

- Windows 桌面空白、桌面快捷方式和框选；
- 资源管理器普通窗口；
- 浏览器普通窗口；
- Windows 文件选择器；
- 普通全屏/无边框全屏程序；
- 桌面右键菜单和刷新；
- 键盘 Win+D、任务栏“显示桌面”、触控板显示桌面手势；
- Explorer 重启；
- 控制中心普通窗口和托盘入口。

## 3. 结果状态

| 状态 | 含义 |
| --- | --- |
| `NOT RUN` | 尚未执行 |
| `UNKNOWN` | 执行或观测不足，不能判断 |
| `PASS` | 按规定次数和证据等级完整通过 |
| `FAIL` | 可复现违反通过条件 |
| `CONDITIONAL` | 仅在已登记的有界适配层下可能通过，等待一次复测 |
| `NOT APPLICABLE` | 经章程确认确实不适用，必须写理由 |

P0 硬门中 `UNKNOWN`、`CONDITIONAL` 和 `NOT RUN` 均不等于 PASS。

## 5. 诊断充分性硬门

候选必须能为上述失败提供可观察证据。以下缺一则 `HG-DIAG-01` 不通过：

- native handle/表面身份；
- owner、parent、相邻 z-order；
- visible/minimized/cloak/activation/topmost 状态；
- 逻辑窗口矩形、可见框、客户区和 DPI；
- 当前宿主/桌面适配状态和重连原因；
- 命中区域版本和 USING/EDITING/lock 状态；
- 渲染首帧、重建、崩溃、资源和帧率事件；
- snapshot revision、命令 ID、冲突和错误类别；
- 与录屏对齐的单调时钟时间戳。

无法观测的“偶尔闪一下”不能被写成不可复现，也不能判定通过。

## 7. 评分锚点

每项 0–5 分，必须附证据：

| 分数 | 定义 |
| ---: | --- |
| 0 | 无法满足、证据缺失或需要违反冻结边界 |
| 1 | 只能部分满足，依赖无边界 workaround 或不可接受风险 |
| 2 | 可实现但存在重大适配层、维护或性能风险，尚未闭合 |
| 3 | 完整满足，适配层和维护成本普通且已有复现证据 |
| 4 | 完整满足，边界清晰、工具良好、余量明显 |
| 5 | 完整满足且实现直接、证据充分、长期维护与故障余量优于其他合格候选 |

评分不得使用小数制造虚假精度。每个分数同时标记置信度：`LOW / MEDIUM / HIGH`。

## 8.1 E5 公共诊断夹具

所有海报候选必须输出 `desktopup.desktop-host.event.v1` JSONL，并使用 `prototype/desktop-host-win32/ts-h01-e5/conformance-manifest.json` 映射本矩阵场景。离线 validator 负责拒绝身份漂移、旧 epoch/frame、TopMost、普通顶层 fallback、revision/bounds 不一致和清理泄漏。

夹具 validator 自测通过只证明检测器的正反例可工作，不产生任何矩阵 PASS。顶部白条、灰框、可见闪烁、Explorer 原生输入、普通/全屏窗口层级、视觉保真和性能仍按本矩阵保留人工媒体与原始采样。公共 TS-H01 的 USER-ACCEPTED、PARTIAL、UNKNOWN、DEFERRED 结论不得自动填入候选表。

## 9. 运行顺序

每个海报候选按相同顺序执行，减少状态污染：

1. 干净构建和冷启动；
2. 呈现边界、拖动、缩放、收起；
3. 输入穿透与交互命中；
4. 普通窗口、文件对话框、桌面右键和焦点；
5. 三种显示桌面入口；
6. 控制中心 20 轮；
7. Explorer 重启和 degraded；
8. DPI/分辨率逐档；
9. 主题切换、故障注入和恢复；
10. 性能、长期静置和资源释放；
11. 安装/卸载与净机；
12. 重启设备后关键硬门复测。

任何影响后续结果的失败都要重新建立干净前置条件。

## 11. 敏感性与决策规则

1. 对全部权重执行 ±20% 合理扰动并重新归一化；
2. 若排名在合理扰动下频繁反转，结论视为不稳健，需要补充实验而不是立即选择；
3. 总分接近且证据置信度不同，优先补足低置信度项；
4. 两个候选硬门与评分近似时，比较有界适配层、故障面和可逆性，不凭个人偏好决胜；
5. 最终选择必须经用户评审，记录拒绝项和残余风险；
6. 选择只说明技术组合进入架构阶段，不等于原型代码或进程拓扑自动成为生产方案。

## 12. 不构成证据的材料

- 框架官网营销页的笼统能力描述；
- 搜索摘要、论坛转述或没有版本的代码片段；
- 单张截图、静态窗口成功创建或一次肉眼观察；
- 只在 Debug/开发机成功；
- 不同候选使用不同画面、尺寸、动作或测试次数；
- 把历史项目的成功/失败直接归因到新原型；
- 没有原始日志、录屏、版本和复现步骤的结论；
- “可以以后写 native workaround”但没有适配层边界。
