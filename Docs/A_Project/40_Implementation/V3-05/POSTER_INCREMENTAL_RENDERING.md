## 根因与整改边界

1. `ContentAssetDemand` 将布局/全局来源版本、尺寸和主题都计入资源键；真实图标实际是与布局无关的规范位图，却随移动/观察元数据一起失效。
2. `PosterSpatialRuntime.ContentSourceFor` 随全局 ContentVersion 新建服务，`BindContentSource` 释放整张海报缓存；增删单项也波及未变化项。
3. `DrawContentSnapshot` 每帧清空 Canvas，整图版本变化清空卡片字典；单张图标完成又令整图重绘并通知中心，形成重复提取/重建链。

整改：来源适配器按海报保留、成员按稳定身份对账；真实规范图标显式声明独立资源身份（海报/Item/会话/来源及刷新代次），不将布局版本当像素版本。通用或测试提供方仍保留原严格键；删除、换来源/自定义图、显式刷新、退出均使相关旧结果无效。可见集/并发/内存预算不扩大。

视觉层按 Item/循环副本保留节点，移动只更新坐标；增删只增删相关节点，选择/样式只更新受影响卡片；图标就绪仅换该卡片的图像子节点，不重建布局/命中、不刷新控制中心。布局、装饰覆盖和像素失效分别处理，保留收展预布局安全点。
