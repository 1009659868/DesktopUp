## 3. 默认位置与旧配置

`ManagedStorageLocationPolicy.Resolve`先识别当前配置身份，再处理：

| 状态 | 决策 |
| --- | --- |
| 已有明确活跃根 | 归属、版本、可用性均核实才复用；缺失/离线/只读不偷偷换到别处 |
| 未记活跃根，只有一个旧登记根 | 核实后选旧根，保留原路径和全部内容；不强迁默认目录 |
| 多个旧登记根 | 保持原状，要求明确活跃根；升级不猜测、不自动合并 |
| 没有旧根 | 提出默认位置；本批不创建、不认领、不登记 |
| 未知版本或其他配置身份 | 拒绝写入，保留原内容 |

默认路径提案为 `%LOCALAPPDATA%\DesktopUp\Storage\daily或preview\<配置物理身份SHA256>\`。日常/Preview与不同配置分开；隔离运行必须显式注入自己的存储基目录，生成其下`isolated\<身份摘要>`，缺失时拒绝，绝不回退日常路径。稳定身份后续沿用当前物理配置目录身份，不能仅按可复制的配置文件ID认领另一库的目录。

路径模型拒绝卷根、相对/UNC/设备路径、父目录段、歧义尾点/尾空格、额外冒号及与调用方提供的安装/状态/缓存等保护目录重叠。这只是字符串级早期拒绝；最终适配层还必须持有真实句柄，复查reparse、卷、目录身份、写权限、归属凭证及完整保护路径集合。未做原生检查不能执行创建。

空目录更换无需复制文件，但仍需持久确认、目标核实和一次索引切换；不能绕过归属安全。首次默认创建不要求用户选址；与“用户主动更改并迁移”需要确认整个影响范围是两回事。

## 4. 整体迁移提案与共享关系

`ManagedStorageRelocationPolicy.Prepare`冻结请求、目录清单、目录/集合归属、内容关系和版本读集，形成确认指纹：

- 主动“更改并迁移”覆盖当前配置全部登记受管集合，包括空集合、多旧根；不是自动升级时合并，也不是只改以后新增内容的地址。
- 每个集合恰好有一个登记归属及一份完整库存；缺集合、重复物理目录、漏成员、未知内容ID、负数/溢出计数均拒绝。目标须确认空白、安全、与所有源互不包含且物理身份不同；未知关系、同址或同名内容不能当覆盖操作。
- 受管项及适配层核实的别名/子项共同计算影响；关联A/B时两者都入读集。无关旧Reference原文件不搬动，不创建新卡片。是否真正属于目录后代由原生库存适配层证明，纯模型不凭字符串猜测。
- 保持ContentItem、Collection、Membership、PosterItem及图标资产等身份。纯提案保存原目录快照；D2-02验证新定位重写、关系/布局保真与事务原子性；D2-03真实内容复制与故障的限定验证见§9。
- 读集包括配置物理身份、活跃选择版本、根集合版本、内容版本、运行代次和全部受影响海报版本。无关海报的布局版本不参与；内容总版本仍作为保守冲突保护。
- 确认绑定完整指纹；源目录、所有权、库存、目标或相关版本变化须重新预览，不靠旧确认继续。

## 5. 顺序与普通失败语义

`Decide`的正常提案链为：确认当前提案 → 持久写意图 → 保留源的复制/逐项校验 → 全部目标核实 → 一次提交索引及收据 → 核实后清理旧受管副本。

| 边界 | 纯模型决策 | 后续执行器责任 |
| --- | --- | --- |
| 未确认或确认过期 | 要求本次确认/重新预览 | 不创建移动任务，不使用旧同意 |
| 未持久意图 | 只允许先写意图 | 未保存成功不得复制或清源 |
| 复制途中/部分目标 | 保留源继续核实或等待，不能切索引 | 源完整可用；取消/普通失败自动收尾已证明属于本次的临时目标 |
| 提交前取消 | 保持旧位置 | 不提交新索引；清理不能扩大到不明目标或唯一完整副本 |
| 提交前源/相关版本变化 | 重新预览，保持源 | 不覆盖外部编辑，不回放旧移动意图 |
| 有可信持久提交收据，阶段字段仍旧 | 以已提交事实为准 | 崩溃不得把新位置回切到旧位置，也不得重做整次移动 |
| 提交后取消/清理故障/旧副本改变 | 新位置保持，保留旧副本 | 必要时短提示旧副本位置，不让用户经营恢复任务 |
| 提交后目标不可核实 | 保留新索引和旧副本，不清理 | 报告真实位置和不可用事实，不能称新内容可用 |
| 未知阶段/收据不符/后来换了活跃根 | 保留并核查 | 不推测、更不能清理目录 |

模型里的`CommitOneTransaction`仅为动作提案；D2-02持久层在一个事务中核对完整读集、更新活跃根/集合/别名定位、保存独立提交收据，只发布一个revision。收据不接受UI或导入JSON直接授权。D2-03接真实内容证明与受限清理，原生句柄跨越事务；生产入口和人工验收仍待后继步骤。

重启仅核实和收尾已发生的动作，不自动重新发起整库迁移。普通失败不引入“收纳恢复”待办、继续/停止按钮或用户任务；无法核实的副本宁可保留，并明确文件位置。

## 9. D2-03保留源复制与故障验证

### 9.1 实际文件通道

### 9.2 持久证据与自动收尾

schema仍为19。配置`state/storage-relocations/<operationId>/`保存独立、只写一次且刷盘的源清单、逐项创建收据、准备声明、目标核实及结束结果；绑定物理配置身份、DB意图和确认指纹，沿用库外文件历史保护。它不是可导入配置或新的用户任务列表。

普通取消、复制失败、事务失败会自动收尾已证明属于本次的目标，释放迁移占用，原位置/原内容保留，用户可用新的预览重新操作。提交后取消保持新位置，剩余旧副本不继续清理。清理途中取消只停止后续删除；已提交事实不撤回。一次记录为需保留的路径，后续重放不会突然再清除。

成功清理只移除旧受管负载；旧根、集合空目录和归属声明作为历史保留，未知根文件不扫描清空。当前后端返回`Committed/Cleaned/RetainedPaths/Reason`；D2-04须用短结果/路径呈现，不恢复“继续/停止恢复任务”的流程。

### 9.3 支持矩阵与限制

| 范围 | 本轮结论 |
| --- | --- |
| 固定本地卷上的普通可写文件、嵌套目录、空目录 | 同卷及真实跨卷准备、提交、清理已隔离验证 |
| Windows快捷方式 | 创建真实`.lnk`，字节一致、目标路径不变，未执行目标 |
| 多旧根/空集合、已迁移bundle再次迁移 | 同一真实文件通道通过；不复制旧归属元数据到新负载 |
| 跨卷取消及索引失败 | 实际不同卷验证源保留、目标自动收尾、索引不半提交 |
| 文件被占用、只读、附加数据流 | 拒绝/保留，不解除用户保护或静默丢流 |
| 硬链接、reparse、压缩/稀疏/加密/云占位、网络或可移动卷 | 当前守卫拒绝，不算支持完整Windows文件语义 |
| 大目录/大文件 | 沿用每文件256 MiB、整次1 GiB/4096条目保守预算，含证据所需目录；不是无限量迁移能力 |
| 真满盘、断电、各种ACL/普通权限实机组合 | 未认证；真满盘按用户决定延期，锁定/取消/注入IO失败不替代这些结论 |
| 原生跨卷拖入、生产设置、卸载保护、人工效果 | 未接/未验，隔离后端PASS不能转授 |

当前内部全树库存仍含所有权元数据以绑定安全指纹；复制明确排除经验证的集合声明，D2-04展示数量/大小必须用负载投影，不直接照抄安全库存计数。首次默认空根的创建/选择仍由D2-04接线，不把“没有集合绑定的登记根”当可自动接管目录。
