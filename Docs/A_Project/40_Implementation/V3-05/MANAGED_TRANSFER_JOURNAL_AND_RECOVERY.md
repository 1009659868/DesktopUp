## 1. 持久化与事务

schema16只追加受管根目录、集合注册、批次与逐项账本；schema13～15定义和校验和不改。沿用升级前备份、未来版本拒绝，旧引用/图标不自动迁走。

注册现有持久目录与直接子集合，不按海报标题生成路径，不把Reference绑定改成Managed。目录创建/选择和跨配置的根目录所有权声明仍需后续入口合同。

Begin冻结确认指纹、完整内容/受影响海报读集、文件ID、父目录ID及有界清单；重复操作ID幂等，未解决账本占用重叠路径。Claim事务复核读集与海报资格，先持久化Executing再执行。同配置独占文件锁阻止第二个执行/恢复进程；关联写入受保护，无关海报几何命令不因此全局冻结。

文件结果与索引分阶段提交。索引复用原引用添加/移除、布局及CAS通道，每个成功项一个revision；完成收据与索引同事务。批次逐项结果不冒充文件系统原子事务。只有内部验证通道有权移除存储成员，普通命令不能伪造传输收据。

## 2. 文件支持范围

| 情形 | 当前处理 |
| --- | --- |
| 同卷本机文件、文件夹、快捷方式本体 | 有界清单/身份验证，句柄重命名且不覆盖；快捷方式不搬动其指向应用 |
| 跨卷普通单文件/快捷方式本体 | CopyFile不覆盖；刷新目标、验证主体SHA256/长度/身份；复制收据落库后才清理原源句柄 |
| 跨卷文件夹 | 执行前拒绝，未实现递归复制/逐项安全清源 |
| 跨卷文件含额外数据流 | 执行前拒绝，不把主流校验当完整复制 |
| UNC、非固定本机卷、离线占位、加密/重解析对象及祖先 | 拒绝，不下载、提权、跟随或降级 |
| 同名目标 | 不覆盖，另选空闲目标后重新预演 |
| 同路径同对象 | NoOp，不移除卡片、不复制、不增加revision |
| 已登记存储根/集合及其祖先 | 不作为普通内容移动，需单独存储迁移合同 |
| 系统/安装/本应用数据，或临时收纳根 | 不作为本执行器的移动对象/持久目标 |

预算为每批100个源、每棵树4096项、单文件256MiB/合计1GiB、单批JSON4MiB、历史4096批/10000项。超限明确拒绝，不报告部分收纳成功。

身份采用卷序列与128位文件ID；父目录句柄防替换，源句柄保护执行，索引提交前重新固定并验证目标。不能以盘符/字符串前缀替代身份验证。API语义见[FILE_ID_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_id_info)、[FILE_RENAME_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_rename_info)及[SetFileInformationByHandle](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-setfileinformationbyhandle)。本轮仅验证Windows x64边界，不宣称防住断电、管理员恶意篡改或所有过滤驱动行为。

## 3. 恢复与最小保护

阶段：Intent → Executing → FileVerified → IndexCommitted；跨卷在清源前有CopyVerified，另有NoOp、Cancelled、Review。

| 持久记录与现场 | 恢复 |
| --- | --- |
| 未执行Intent | 转Review，重新预演后才能重试，不自动重放 |
| 源不存在、目标身份/完整性可证 | 原读集仍有效才补索引，重复恢复幂等 |
| 源仍存在，包括后来新建的同名源 | 保留两处，转Review，不自动清理 |
| 目标被替换/损坏/消失/无法确认 | 保留现场与账本，转Review |
| 原海报已删或读集冲突 | 保留实际去向，不搬回旧路径、不静默重建海报 |
| 索引已提交 | 不再次搬移 |

取消不改写已发生的事实。跨卷复制后取消、清源失败均保留两份；文件已经移动但索引失败时，不以数据库回滚声称文件已复原。

存储集合与传输记录无海报外键。删除最后一张海报不删内容/账本。移动更新全部已知同源/目录后代引用的locator并保持ContentItem身份；拖出只移除成功项的当前卡片，其他海报的卡片、图标和布局保留。

新增库外managed-file-history.guard，在首个意图入库前刷新落盘，不随取消/删海报/库损坏移除。配置恢复看到此标记，或待恢复备份含传输历史，就拒绝用旧库回退文件去向。可创建/保存备份不等于可回滚物理文件。即使意图后来没有移动，也不自动清标记；不得指导用户删除标记绕过保护。

未启用传输历史的既有备份流程保持；不为探测账本打开损坏原库或触碰待归档WAL/SHM。完整恢复/归档流程仍需补门。

Read API已可独立于海报返回源/目标/阶段/错误，但**尚无普通用户可用的找回、确认重试、释放占用入口**，因此生产拖放仍关闭。

### 7.1 明确区分恢复动作

| 动作 | 可执行范围 | 不会做什么 |
| --- | --- | --- |
| 查看路径 | 所有记录，包括已完成和海报已删除 | 不执行文件内容、不删除任何副本 |
| 重新核对／仅补索引 | 选中单项；目标身份/内容可证且原读集有效 | 不重试Move、不静默刷新CAS、不重建海报 |

重试重新生成来源、目标、共享影响与完整读集；二次确认后，释放旧占用和登记新意图在同一SQLite事务完成。文件执行仍在意图持久化之后。新意图登记失败会回滚旧占用的释放，不留下“旧任务已取消、新任务不存在”的窗口。旧批次不改写为新历史，单项成功后原共享关系、图标及布局通道保持。

两处都有文件、来源被替换、已移动但读集冲突或原海报消失时，只提供记录和路径，继续保留Review。**尚未实现为这些复杂情形重新关联到选定海报、明确清理/放弃的完整处置**；不能因此宣布整个恢复闭环完成，也不能建议删除账本/guard来解除占用。

### 7.2 持久目录选择和恢复

用户选择已有持久目录，确认后在其中建立由GUID标识的专用子目录及所有权元数据。不会自动收纳选中根目录里的已有文件，不会转换Reference集合或切换现存海报的来源；后续拖入需显式绑定其存储目标。

先在配置内预写创建意图，再独占写入根声明、建立子目录和子声明，最后登记数据库。声明绑定配置目录的真实文件身份、根目录身份和集合身份；另一份配置、复制到新目录的配置、目录替换、缺失/未知声明均不能自动接管。Register、Begin与Claim均校验所有权。旧2A自建schema16无声明目录仍保留，但须另外评审认领流程，不静默补写声明。

创建意图、根声明、子声明或数据库登记之后中断，可在“收纳存储目录”选择原目录记录，重新确认并恢复登记。**子目录刚建立、子声明尚未写成的窄窗口无法证明所有权**：保留目录/记录，拒绝自动认领，当前提示另选目录；不猜测空目录必然属于本应用。未知/半写元数据不覆盖。预算256条创建记录；目录登记前也写库外guard，因此登记存储后同样不能以旧数据库恢复抹去归属。

## 8. 异常入口简化与已移动文件关联恢复

DEC-040确定恢复只作异常兜底。本批是2B-2的第一段，不是整个安全门收口，不开放原生拖入/拖出。

### 8.1 用户操作

全局入口改名“收纳恢复”。无待办时不展示任务管理表；有待办时只显示未完成文件及清楚的结果说明，路径/技术状态折叠。常用动作只有查看位置、继续完成、取消尚未开始项；已完成记录只作为历史位置备用入口。成功后仅汇报本项结果，不把其他未完成项和技术指纹铺到主界面。

“继续完成收纳”内部区分两条路径：原文件未移动时重新预览和确认移动；原文件已不在原处且实际目标的身份、完整性可证时，只恢复海报记录，不再次Move。后者允许原海报删除后明确选择另一张现有、显示且未锁定的海报；不重建已删除海报。取出过程中原卡片/海报已删除时，只修复剩余共享来源及存储成员，不重建卡片。

## 9. 保留文件停止重试与目录创建中断出口

本段落实DEC-040的异常兜底，不扩展日常收纳流程。双份、来源变化、目标不可证等记录可以显式停止重试；目录创建缺少完成凭证时可以保留现场并停止创建。两者均不是成功、还原、清理副本或认领目录，原生拖放仍关闭。

### 9.1 三类结束结果

| 用户操作 | 所需证明 | 结果及保留内容 |
| --- | --- | --- |
| 继续完成收纳 | 未移动项重新预演；已移动项必须证明目标和当前关联 | 原正常执行／IndexRecovery通道，不重放已完成Move |
| 取消尚未开始的收纳 | 原对象身份及内容未变、目标不存在 | Cancelled，确证文件未移动 |
| 仅停止重试，不处理文件 | 明确确认该项、当前配置版本及不确定结果说明 | 独立Closure；原阶段、收据、错误、路径和批次读集不变，不显示“已完成” |

停止动作不读取文件内容，也不声称两个路径当前存在或完整；文件锁定、来源被外部修改、移到其他位置均不构成自动删除/关联权限。确认页展示原位置和目标，说明现存引用不改、失效引用需另行修复。确认后旧操作不再重试、不再占用路径，未来移动需重新预览；同名目标仍受不覆盖规则约束。其他待办保持，已结束位置在混合待办和无待办场景都可查。

### 9.2 确认和持久化

schema17只追加content_transfer_closures和storage_provision_closures，不改schema1～16的SQL与校验和，不重写既有文件操作结果。沿用升级前备份、事务DDL和未来版本拒绝。

## 10. 旧目录显式认领与剩余故障边界

### 10.1 认领范围和确认

入口仍在“更多 → 配置与恢复 → 收纳存储目录”，选择“认领已登记的旧目录”。预览绑定当前配置的物理身份、原登记的根/子目录文件身份、当前revision和有界目录清单指纹，显示目录及文件数。确认前后重核对；未知版本、其他配置声明、重置目录、陈旧确认、未结束文件操作均拒绝。

只支持一根一集合、已登记的直接子目录。子目录不要求现代collection-GUID名称，但必须等于旧登记路径且文件身份一致。未登记的任意目录、已停止的未完成创建、一根多集合及实际搬迁不在本批范围；可以保留现场并另选目录，不能删除旧声明/guard绕过。现有内容和引用保持原样，额外文件不自动产生卡片。

schema18追加managed_storage_adoptions，不改schema1～17 SQL或校验和。执行顺序：只读预览 → 明确确认 → 库外guard → 持久准备记录 → 排他写入根/子认领凭证 → 再核对 → 单事务激活。未激活记录即使已有两份凭证，也不能授权传输；启动只读发现，不自动激活。中断后须重新确认，同一确认幂等；配置/内容已变必须新预览，旧准备记录和凭证保留。认领不推进内容revision，不修复引用，不移除原文件。

归属凭证与创建凭证不混写；正常创建不能覆盖已认领根。进入已有传输通道时仍校验当前归属、根与子目录身份。文件清单只服务这次确认，之后正常收纳变化不要求重复认领。

### 10.2 复制中途取消和支持矩阵

跨卷单文件改用CopyFileExW进度回调，在复制中途响应取消；回调异常不能跨原生栈抛出。仍先完整校验目标、落复制收据，再处理源；不覆盖已存在目标，不自行清理不确定副本。

使用PROGRESS_STOP而非会删除目标的PROGRESS_CANCEL。微软[CopyFileExW说明](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-copyfileexw)描述STOP保留部分目标；本机NTFS C→G实测中，非最终进度回调后STOP未留下目标，启用RESTARTABLE的诊断也相同。因此不承诺必有半份目标，不据文档推定现场结果，更不静默补造副本。生产保留FAIL_IF_EXISTS，无自动断点续拷。

恢复按实际现场区分：源完整/目标不存在，只允许重新预览后的新操作；源仍在/目标存在，保留两处、不自动重试；源已不在，仅已有完整目标证明才能关联恢复。复制取消、注入中断与原生进程崩溃是不同证据。

| 场景 | 本段处理及证据范围 | 原生准入 |
| --- | --- | --- |
| 已登记旧无声明目录 | 显式元数据认领；陈旧/未知/身份变化/未结束操作拒绝 | 新界面待人工 |
| 创建缺凭证、未登记/已停止目录、一根多集合 | 保留现场，不猜归属；另选目录或后续单独迁移 | 不开放任意接管 |
| 同卷普通文件/目录树 | 身份与清单核对；实际rename后并发变化保留现场，不提交成功 | 仍须普通权限/新增人工审查 |
| 跨卷单文件正常复制 | 有界本机文件、复制收据先于源处理、故障恢复 | 后端限定测试；原生尚未准入 |
| 实际复制进度中取消/回调中断 | 自建32MiB源保持完整；无收据/成功索引；按真实目标有无恢复 | 不宣称进程硬崩溃或必留半份 |
| 复制后写失败/截断注入 | 保留原始失败证据；与真实满盘分列 | 不替代满盘 |
| 真实满盘 | 用户明确本轮不挂载测试虚拟磁盘，延期未验 | 未消项，原生安全门不转PASS |
| 跨卷目录树、额外流、reparse、云占位/网络/设备路径 | 执行前明确拒绝，不静默改为引用或复制 | 暂不支持 |
