## 2. 字段分区与提交原子边界

| 分区 / 动作 | 内容 | 提交与权限 |
| --- | --- | --- |
| 几何草稿 | 保存显示器内的Fallback X/Y DIP、宽度、保存展开高度；显示器身份取原目标，本增量不提供跨屏选择 | 四字段作为一份空间请求；只由原空间运行器准备、验证并提交，不能直接组装裸Move/Resize写库 |

| 立即动作 | 锁定、收展、显隐；删除需原后果确认；目录新增/复制/重命名后续原端口 | 使用动作时所见的原目标/版本；不隐式保存其他草稿；同目标变化令未提交草稿过期 |

初版分区应用，不提供跨分区“全部应用”。新编辑器同一时刻只持有一个脏分区，修改另一分区会拒绝并提示先应用或取消；不是先成功一部分再报另一部分失败。M08分区仍单独应用，实体CAS兜底同目标并发；后续控件需明确每个应用按钮的范围。

锁定时禁止几何变化，仍可改允许的内容/样式。沿用现有权限，收起时允许位置请求，不允许改变尺寸；需要先展开再缩放。本步不放宽隐藏/降级目标的空间可执行资格，是否可执行由03的原运行器判断，不伪造可用宿主。

几何文本允许符号和小数点“.”，不接受空值、空白、指数、千位分组、NaN/Infinity及过长输入；保留无效原文供更正。复用现有最小宽/高240 DIP，不在文本解析时钳位。有限坐标不等于当前屏幕可放置：合法工作区/像素范围/碰撞在空间提案阶段验证；不能默认悄悄移动到其他位置并当作原请求成功。

## 3. 选择、草稿和投影规则

1. 使用PosterId，不使用列表索引/标题。选择只改变编辑目标，不写库、不移窗。
2. 目标首次载入时冻结basis（原值、目标ID、entity version）；latest只保存最新已提交投影。脏草稿收到投影不自动rebase。
3. 全局revision较旧的投影整份忽略；相同revision的运行有效几何更新可读，但不得覆盖草稿。
4. 无关海报/设置更新不使内容草稿CAS冲突；同一目标任何实体更新标记过期。允许发出旧basis以得到明确Conflict，不自动合并/重试。
5. 切目标、目标消失或关闭窗口丢弃未提交本地草稿，并释放编辑保护；不会自动保存或重定向到另一张。界面接线时须明确显示此规则。
6. 取消载入最新已提交值，不写库；编辑回原值也释放保护并跟随latest。
7. 零目录或不存在目标禁用编辑，不选择其他目标来承接旧操作。已关闭编辑器不再接受晚到投影，重开建立新实例。

新模型输出ProtectsInteraction，供后续接入原交互保护；仅创建/浏览清洁会话不保护。当前尚未接生产保护，不改变已存在M08行为。

## 4. 发送与迟到结果

- BeginApply先冻结pending，再交给外部执行；防同步ProjectionChanged重入。pending期间禁止编辑、重复应用、取消及同编辑器立即动作。
- 每次请求生成唯一ID，并绑定观察revision及原目标。关闭/切换只能丢弃本地等待，不等于撤销已发出的事务；事务仍只能作用原目标，执行时照常验证CAS。
- 迟到请求ID/观察revision不匹配时不能结束新请求或覆盖新目标草稿。A→B→A也不能复用A旧请求。
- 成功须有匹配目标和版本的权威投影；缺少结果不能显示“已保存”。比当前latest旧的合法成功结果不使界面倒退。
- 失败保留可解释错误与草稿；Conflict/空间不足/存储失败不自动重试。NotFound的最新权威空目录应清除已删除目标，即使未单独收到投影事件。
- 用户取消草稿、没有变化、失败和重放分别遵循原命令合同；不制造额外业务revision或假成功。

## 5. 几何请求与有效高度

ControlCenterGeometryRequest不是IStateCommandService可执行命令，也不提供ToCommand。它冻结原目标basis、编辑值、当前全目录/全部实体读集；目标本身始终使用原basis版本，不能以读到新版本掩盖过期草稿。

03接线必须：取得真实环境/会话代次与当前有效几何 → 用同一空间服务求解并核对依赖 → 原R4组呈现/读回 → 单revision完整CAS → 失败走原恢复。环境变化、障碍更新、目录增删、锁定或宿主不可用均不得绕过。纯请求的ReadsCurrent只检查数据读集，不认证原生环境、可放置性或像素呈现。

EffectiveLayout是单独只读显示：仅接受目标/提交revision/layout generation一致的有效值；不写回Width或ExpandedHeight。几何草稿是持久意图字段，不拿临时高度或动画中间帧初始化保存高度。实际位置概览用有效投影，字段必须标注保存配置与当前运行的区别；具体屏幕映射由02/03细化，不能混用绝对像素和工作区局部DIP。

## 6. 连续场景与证据边界

| 场景 | 必须保持 |
| --- | --- |
| A编辑→B更新/设置更新→A应用 | 不串写，无无关CAS冲突 |
| A编辑→A锁定/隐藏/重命名→应用 | Conflict、不覆盖新状态，取消后载入最新 |
| 应用→同步投影回调→结果 | 只提交一次，pending不提前丢失 |
| A pending→切B→改B→A迟到；再回A发新请求 | 不覆盖B或结束新A请求 |
| 草稿/pending→删除→零目录→旧结果/旧投影 | 不复活目标，不误选他张，零目录保持 |
| pending→关闭→事务完成→重开 | 原目标合法提交可保留；重开读权威状态，不恢复旧草稿 |
| 几何/样式交叉编辑 | 明确拒绝跨分区混合提交，无静默部分成功 |
| 临时高度变化→编辑X→应用 | 保存高度不漂移 |
| 空间请求→障碍版本改变→提交 | 完整CAS冲突，源不移动/写入 |
| 多参数更新→SQL故障 | 字段、head、回执全部回滚，草稿保留 |

纯几何桥接测试只使用原SpatialGestureSession/SpatialGestureCommitPolicy及隔离SQLite，不是生产数值编辑适配器或原生动画验证。旧测试复用但重新执行；结果在下一节追加，不能沿用旧总数作新PASS。
