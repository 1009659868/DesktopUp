- `ContentLayoutFlow.ProjectTiles`增加不超过一个网格节距的overscan准入区域，**不放大viewport**，避免改变循环成立条件或归一化偏移。绘制/命中继续只用真实clip；资源集合在同一tile投影上先可见、后预取，按ItemId去重、最多64项。循环副本只保留一个资源身份，预算用尽不删内容/不改变作者布局。
- `ContentAssetDemand`携带Poster/Item/session/document/member/placement/source version、DPI、完整tile像素尺寸和主题版本。仍为每表面4并发、64缓存条目、16MiB缓存和单载荷4MiB；结果通过当前可见key及运行代次再校验。来源key不解释为路径，未接真实文件、Shell、网络或位图解码。
- 修复原资源队列满后依赖下一次滚动才能补位的问题：真实provider完成释放槽位后，合并回UI队列继续调度；同一可见key失败不逐帧重试。metadata版本风暴保留原cache，忽略取消的旧任务仍占原槽位，不能每次通知新增4路。 另以真实flight存在性和wrapper清理后补位，覆盖离开可见区后快速返回同key的顺序竞态。
- `ContentSourcePorts`复用现view/resource/open意图端口，新增可信host打开处理器；普通运行仍DEMO/no-op。来源元数据不得改成员集合/顺位/图钉/构图；缺失、重复身份、异常或过期版本显示不可用fallback并拒绝打开。只有显式成员命令通过完整CAS一次revision修改作者集合。
- 来源版本改变立即使旧手势/打开配对/中心见证失效；隐藏/销毁后旧结果不得更新表面。adapter绑定跟随海报目录而非暂存HWND，显示恢复使用新session；同源多海报不串写作者布局。该内部host注入端口不是模板脚本/用户插件入口，也不是已冻结的V3-05持久schema。
- 补充R4安全点：来源通知遇到收展/命令期间只撤销旧资源准入，不重建预布局树；原结束/恢复入口刷新latest版本，不新增计时器或第二布局owner。
- 循环接缝的选中跨度handle复用现生产press/flush/end：两轴×两模式覆盖快速反向、取消、有效松手、一次保存、Undo/Redo；无“先整理才能拖Item”的新增限制。作者大小调整使用现尺寸入口，不改变默认手势合同。
