# M07：嵌套收展导致上游归位失效

日期：2026-09-09。本文保留修订前诊断历史；后续用户授权的连续合同、纯模型和生产接入已完成自动门，详见[实施与最终验证](M07_SPATIAL_CONTINUITY.md)。人工观感待确认，M07仍OPEN。下文“拟定/未实现”仅描述原诊断时点。

用户已确认“…”菜单交互正常，菜单 R1 的原故障记为人工通过；本问题单独登记，不撤销菜单结论，也不将剩余 M07 安全门自动记为通过。

## 1. 现象与期望

三张海报自上而下 C、B、A，初始均收起。仅展开 C 再收起 C 时，B/A 正常推让并归位；增加一次 B 展开后，收起 C 留下明显空位，B 仍停在被 C 推动后的位置。

本次期望应区分两种状态：B 的“展开状态”是新的用户意图，应保留；B 因 C 扩大而产生的“临时位移”不应仅因 B 展开而永久化。A 还受到 B 展开的推动，不能独立恢复成最早的绝对坐标。

## 3. 根因：条件归位合同过于粗粒度

1. [现有矩阵 C06](../../20_Architecture/POSTER_SPATIAL_STRATEGY_MATRIX_V1.md)将“移动/缩放、改锁定或收起等导致布局证明失效”统一归为不归位。保护后续用户意图的目的成立，但没有区分位置意图和收展姿态。
2. [PosterLayoutGenerationPolicy](../../../../src/DesktopUp.Domain/PosterLayoutGenerationPolicy.cs)将 `IsCollapsed` 变化视为布局变化。B 展开会改变 B 的姿态/高度、布局代次和最后操作标识；A 再次被推也改变其布局代次/操作标识。
3. [SpatialReturnPolicy.CheckEligibility](../../../../src/DesktopUp.Domain/PosterSpatialSolver.cs)要求当前目标与 `TargetAfter` 整个记录相等。B/A 不再等于 C 展开后的快照，归位资格返回 `TargetChanged`。
4. [SpatialPushSolver.FindReturnTargets](../../../../src/DesktopUp.Domain/SpatialPushSolver.cs)只接受仍合格的目标，所以 C 收起的参与者只剩自己。随后仍消费 C 的展开证明，不会在下一次 B 收起时自动恢复这一层上游位移。
5. [仓储](../../../../src/DesktopUp.Infrastructure/SqliteStateRepositories.cs)对布局变化调用 [Invalidate](../../../../src/DesktopUp.Infrastructure/SqliteSpatialProofRepository.cs)，将对应源操作置为 invalidated、参与者标记为 `layout-generation-changed`。当前读路径仍读回参与者证明，最终资格由上述记录相等检查保证；不能把原因简单描述成“数据库删掉了 B”。

因此，这不是菜单 R1 改坏收展，也不是单纯缺少动画；是现有实现忠实执行了一个没有支持“嵌套收展仍保留上游位移关系”的保守合同。现有未调整链归位/移动后不归位测试不能证明这一新序列符合期望。

## 4. 建议修订边界（待后续确认与实施）

- 仅切换展开/收起，不自动清除上游推让带来的位移关系；归位只撤销仍有效的上游位移，保留当前收展姿态、宽度和有效高度，不恢复整份历史矩形。
- 对本例：C 收起释放的空间允许 B 保持展开并向上回移；A 保留 B 展开仍需的让位量，与 B 协同移动，不穿过 B、不直接跳回初始 A 坐标。
- 同时更新 B 自己那次展开的收起锚点及其对 A 的推让/归位关系。否则即使这次 B 移动正确，下次收起 B 仍会因旧坐标或 `SourceChanged` 失效。
- 用户显式拖动/缩放、锁定固定障碍、隐藏/删除、环境/session 变化等安全边界保留；不能为支持嵌套而直接放宽所有 generation/CAS 检查。
- 路径和最终占位必须同时合法；新障碍阻挡时继续遵循安全归位子集，不强行穿透、覆盖锁定海报或把无关海报吸入归位链。
- 沿用现有同步归位批次，不追加“等 C 完全收好才移动 B/A”的尾段。动画曲线打磨仍延期。
- 完整实体读集 CAS、权威状态单次提交和物理失败恢复不取消。不能只在视觉上移动 B，而不更新状态与后续归位关系。

本轮仅诊断及记录，没有修改空间生产代码或将以上建议标为已实现。既有矩阵 C06 的旧行为保留作现状证据，后续实施需同步修订矩阵、因果合同和夹具。

## 5. 后续最小回归范围

1. 基线：展开 C → 收起 C，B/A 同步回原位。
2. 新场景：展开 C → 展开 B → 收起 C；B 保持展开，B/A 协同撤回 C 的位移，无额外空挡。
3. 接续场景：再收起 B，A 按更新后的 B 关系归位；不回跳到旧 y，不丢失合法归位资格。
4. 反向顺序：展开 C → 展开 B → 收起 B → 收起 C；不因中间姿态变化永久丢失 C 的位移关系。
5. B/A 有用户拖缩、锁定或回程新障碍时，仍保护用户意图并保持全程不重叠；多层嵌套、向上/先下后上及临时高度分别补参数化夹具。

下一步应先落定“位置意图与姿态分离、嵌套位移关系如何更新”的最小合同，再做纯求解及仓储集成回归；不重新实现 DesktopHost 或菜单控件。
