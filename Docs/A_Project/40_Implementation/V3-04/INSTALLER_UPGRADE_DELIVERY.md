### 产品边界

1. 当前用户、同 Preview 通道识别既有安装，默认选择最新版本的安装位置；在该位置执行覆盖升级。已有多个并行安装时只升级选定位置，其他目录/入口不擅自删除；手动选择空目录仍可独立安装。阻止同版重装及降级，登记与标记不一致时停止。
2. 升级不调用旧卸载器、不执行归还、不打开/迁移数据库、不扫描收纳目录。配置与真实内容完全不进入替换清单；复用既有运行期维护锁，要求应用正常退出，不强杀、不绕过UIPI。
3. 先完整准备并校验新包，再备份旧程序清单和入口，替换程序，最后切换版本登记/快捷方式。只清理有确切归属和摘要的文件，未知文件保留；旧声明文件被修改、重解析点、占用、目录冲突等均保守停止。
4. 原目录升级使自启动命令路径保持不变；Run值和Windows禁用状态不改、不默认开启。桌面入口继承已存在的自有入口选择，也允许在安装页更改；改指其他目标的快捷方式不删除。
5. 普通失败恢复本次替换，保留原版和诊断；异常中断保留持久日志及备份，恢复需核对归属与文件摘要，不用未知文件换取“零残留”。成功后清除旧登记、自有旧入口和旧程序备份，仅保留当前可用卸载入口。

### 实施批次与退出标准

- U1 身份/计划：明确目录、版本、载荷清单、入口和自启动快照；路径/登记不一致、同版/降级、在运行均不得改写旧安装。实现独立安装辅助进程，避免向海报/内容Worker堆入安装业务。
- U2 替换事务：新载荷先准备、逐项校验，原程序备份与日志持久化；异常按已声明动作回退；注册/入口切换放最后。现有新装与卸载保护不削弱，旧临时入口被替代后清理。
- U3 安装器接线/发布验证：默认识别原目录，显示“原位升级/数据保留”，正常新装仍可自选路径；独立候选实际走安装包升级、运行和卸载。不得把开发辅助测试开关打入正式包。
- U4 集中人工：仅两组——①旧版→新版：程序/版本/快捷方式/配置与收纳/自启状态；②占用或中途取消保护、正常退出后重试及新版卸载入口。自动定向覆盖失败恢复，不叠加历史拖放/架构矩阵。

自动验证采用独立目录/配置、自建最小载荷与版本登记；实际成品升级限定在测试旧安装路径，不操作日常安装。测试前后核对真实配置、Run、快捷方式和已有安装登记。测试结束清理自建安装/入口/重复产物，证据保留归档；人工候选只保留所需包与入口，验收后提供收尾。

历史自然卸载首因、P1/R6锁冲突与剩余读取/观察成本继续保留，不因升级测试成功销项。普通权限/跨机/真实登录未验不得补PASS。

## 实现与退出标准核对

U1～U3 已实现，U4 待用户集中验收。没有移动已有业务文件，也没有修改海报、拖放、数据迁移或内容归还逻辑。

- `DesktopUp.Setup` 独立小型辅助进程：安装清单/身份校验、精确文件事务、注册/快捷方式适配及运行期维护租约；不依赖 App、ContentWorker、Application、SQLite。与安装包共享运行库，只有四个辅助入口文件进入载荷。

- 默认目录识别选择当前用户最高 Preview 版本；多个并行安装不全量清扫。启用/禁用自启动的 Run/StartupApproved 不写入；路径不变使原自启命令继续指向同一启动器。这里只保证状态保留，不宣称新实现了登录验证或联网更新。
