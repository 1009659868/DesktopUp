## 1. 范围与优先级

悬停负责预览，点击负责快速展开，拖动负责移动；按下后自动辅助让出控制权。
硬性空间/生命周期安全 → 显式手动意图与跟手 → 自动收展。锁定、工作区、碰撞、完整读集CAS仍有效。

- 本次针对启用自动收展的海报标题空白/拖动区；“…”、收展按钮、Item、底栏及外部窗口不套用标题空白点击规则。
- 自动关闭时保留既有手动入口；编辑态沿用自动暂停及拖缩合同。锁定不禁止自身收展，但禁止产生拖动和被邻居推动。
- 不新增悬停等待或长按计时阈值；沿用当前5px移动阈值及其坐标口径。之后若需DPI调整，必须独立修改命中合同，不能本轮偷换。
- “快速展开”是跳过剩余动画，在完整合法组帧准备好后统一呈现，不承诺零耗时，不是缩短离开延迟。
- 不扩张为手动连点最后意图队列、全局减少动效或新动画引擎；外部连点计时错误仍走独立R2-A。

## 2. 五种意图与固定分流

| 意图 | 识别依据 | 冻结行为 |
| --- | --- | --- |
| TI-I1 悬停查看 | 收起态，真实进入有效展开热区，自动资格成立 | 按既有自动路径正常展开 |
| TI-I2 习惯点击 | 标题按下后未确认拖动，在有效释放位置松手 | 快速展开；只展开不切换收起，已展开则无额外姿态提交 |
| TI-I3 想拖动收起海报 | 按下时仍收起，或展开尚未完成；随后达到拖动阈值 | 收起态拖动：位置立即跟手，已露出的内容与移动并行快速收拢 |
| TI-I4 收起途中拖动 | 按下时收起动画尚未完成；随后达到阈值 | 同样转收起态拖动；不先等收起结束，不返回旧坐标 |
| TI-I5 展开完成后拖动 | 按下时已经接受合法展开终态；随后达到阈值 | 保持展开态拖动，不自动变小 |

“完全展开”包括已接受的合法临时有效高度，不要求等于偏好高度；必须读取当前呈现阶段，不能只读数据库IsCollapsed判断中间帧。

## 3. 按下—移动—释放仲裁

1. 标题按下立即建立捕获/手势身份，记录当前实际呈现标题抓取点与阶段；暂停同源正在进行的整组收展（含被推/归位邻居），不取消后恢复到旧committed坐标。
2. Pending期间保持当前画面；无计时长按动作。一直按住不移动就一直保持，直到释放、真实失效或接管拖动。
3. 移动未达阈值仍Pending；达到阈值即确认拖动。分类以按下时阶段固定，不能因时间流逝改成另一种拖动，也不能等动画完成才移动。
4. CompactDrag：标题按鼠标增量移动；源内容从当前高度向当前标题下的收起高度快速收拢，邻居按合法因果归位同步更新。即使原展开曾抬高标题，也不能把标题拉回旧收起锚点。
5. ExpandedDrag：保持按下时已接受的展开有效高度。普通拖动不推动其他海报；两类拖动均按实际呈现占位/扫掠碰撞约束跟手，不能提前把仍可见的内容当透明区穿过障碍。
6. Pending释放且仍符合标题点击命中规则：申请一次快速展开。PointerDown不能立即展开终态，以免先抢走本来用于拖动的意图；释放到标题外/被取消的手势不能补成点击。
7. 已确认拖动的释放不能再生成Click。CompactDrag结束后保留新位置和收起态；若剩余收拢还未结束，只完成该收拢，不再恢复辅助增长。鼠标停留不重新展开，真正离开再进入才重新获得自动资格；显式标题点击可主动快展。
8. ExpandedDrag结束保持展开；离开后重新按普通自动资格计完整延迟，不执行旧deadline。
9. 锁定时不建立拖动；超阈值被拒绝的拖动不能在松手时误生成快展点击。无位移的有效标题点击仍可展开。
10. 一个手势的接收目标在按下时确定。动画使标题/Item移动不能把同一次按下/释放或残余点击序列转投到新露出的Item；不在原生/XAML路径各执行一次。

最后展开帧与按下同一轮到达时按事件序列和已接受呈现标记判定；一经记录不再变更。按钮、菜单及外部普通点击继续保留各自语义，不能为实现TI-I2恢复“任意点击都会反转动画”的旧错误。

## 4. 空间与呈现只有一套

自动进入/离开决定“何时”；标题仲裁决定“用户要什么”；共享空间求解决定“能怎样展开/收起”。不得新增自动版/点击版方向求解器。

- 同一快照、源、偏好高度、内容指标、锁定状态和因果关系下，悬停与手动展开必须产生相同合法空间结果（操作ID等身份字段除外）。
- 顶部有余量通常向下；中部先下后上；贴底下方容量为零时向上。下方推让容量及已有障碍一起计算，不仅检查屏幕空白。
- 全高优先；完整候选不可行再求合法临时高度；不足主题最小高度则保持收起与邻居原位。偏好高度不被临时高度覆盖。
- 快展复用同一求解/事务，只跳过剩余表现帧。源与全部受影响邻居一起准备/提交，保留R4容量、内容预布局、逻辑裁切、输入岛同步及结束恢复；不单独把源SetHeight到终点。
- 收拢与搬动使用同一运行器和当前已呈现组几何。拖动本身不授权推邻居；撤回原收展的合法因果推让与用户移动分清，保留链/分支/合流和用户介入记录。
- 条件归位仍为“不能完整安全归位就原地不动”，不部分回收、不推动无关海报。主动调整源只重建源锚点，不能重置所有邻居Home。
- 固定抓取点只约束用户拖动，不改变普通悬停/按钮的先下后上策略。工作区/碰撞导致位移受限是安全边界，不代表自动增长可抢夺位置。

## 5. 生命周期、提交与终止

- 单一空间所有者原子移交：自动请求结束/移交回执、标题capture和组帧由同一会话协调，旧自动回调不能把新手势回滚。不得简单屏蔽全部BeforeManualIntent或删除起点校验。
- 绑定PosterId、session/capture token、操作/呈现代次、实体/目录读集和Shell/显示/工作区代次。只接受实际成功呈现的帧作为下一步起点。
- 目标删除/隐藏/锁定、策略关闭、恢复、CAS冲突、路由失效、坐标不可读、系统取消模式、程序主动取消及呈现失败仍进入显式取消/恢复流程。单纯鼠标捕获转移不再与这些情况合并，按下方§8安全中止；一次释放资源、不补发点击、不无限busy。
- 一次组合操作的源位置/姿态、合法邻居变化、因果关系在原权威事务通道统一提交；不逐帧落库、不用System口任意写位置、不产生平行状态权威。
- 完整终点/中间扫掠均须安全。语义轨迹和工作预算有界、重复/旧事件幂等；预算耗尽仍保留释放/安全结束能力。
- 用户按住时Pending/Dragging可以持续；释放/取消后则必须有限结束。不得把“持续按住”当资源泄漏，也不得把旧BlockedAfterRelease作为新正常终态。
