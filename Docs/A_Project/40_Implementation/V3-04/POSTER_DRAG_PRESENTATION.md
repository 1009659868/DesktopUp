## 实施顺序与退出标准

1. 共用按需Rendering调度：同帧输入合并为最新位置，移除普通16ms等待及标题拖动的间隔门；释放处理最终位置，取消／关闭撤销待执行回调。标题姿态动画规则不因调度统一而删除。
2. 纯平移复用：不重画未变内容；复用相对命中几何，发布新的绝对位置和版本。原生视觉／输入一起提交，保留读回、失败停止与恢复；尺寸／内容／模式变化仍走完整路径。
3. 定向验证：最新输入、取消／释放、旧回调隔离、同代区域及碰撞／标题直接风险；独立构建与隔离原生呈现检查。对比实际调用次数／耗时，不把程序内探针当真人视觉帧率。
4. 集中人工仅两组：普通／自动收起／编辑移动的慢速连续性；贴边碰撞、取消及移动后的点击／拖放一致。用户确认后才收口，不自动合并。

## 实现与清理

- App/Runtime/Posters/PosterDragFrameScheduler：普通／编辑海报拖动与自动收起标题共用单次Rendering订阅；保留最新请求，取消使已捕获的旧回调失效，闲置不订阅。删普通DispatcherTimer、旧调度标志／待处理记录及标题LastFrameMs门。
- 普通Move与标题共同经过PrepareSpatialFrame／CommitSpatialFrames；碰撞安全路径仍逐段处理，释放使用最终指针，旧版本／环境、锁定、捕获、失败停止与CAS未撤。缩放也使用同一帧调度，但尺寸变化保留完整内容更新。
- ContentInputGeometryCache只缓存相对几何，所有上下文／尺寸变化失效；缓存生成成功才替换旧项，每次发布仍增加Revision。输入路由不允许旧版本带着新绝对坐标发布。
- 同尺寸、同ContentPresentationFrame平移不重新Present／Measure内容；姿态租约同一视口不重复重建裁剪。窗口原生读回、同代命中、OLE目标位置更新保留。
- 输入HWND在成功group batch后只读回，不重复SetWindowPos；读取实际GetWindowRgnBox，形状一致时不重建，原生区域丢失／重置仍重建后发布，不能只依赖缓存。
- 标题按需调度须覆盖“停止移动但尚未收拢”续帧；新增HasPendingWork保留该行为。100ms捕获／失效看门狗不是帧时钟，仍保留；自动姿态动画的时长／步长配置未删除。未合并两套手势语义为一套状态机。
- 没有文件移动或存储／迁移修改，没有为此重开基础架构层。全海报新鲜核对与路由区域复制仍有成本，不以跳过安全检查换取数字。
