## 历史实施边界

- Domain/Canvas：受限声明、真实能力目录、实例状态、校验与布局；J0设计JSON不作为现有v1导入格式。旧配方保持原路径兼容。
- Application/Features/Canvas：固定目标的设计草稿、修订和预览令牌、提交与回执、设计撤销；复用现有状态事务和CAS，不另建文件归属或统计。
- App/Presentation/Canvas：稳定节点增量呈现、布局结果和内容槽适配。现有内容视图、暖图标、原生输入及平移调度继续复用。
- App/Views/ControlCenter：仅增加画板编辑入口；独立编辑视图按能力生成参数、装配与预览，不继续向窗口partial堆用例逻辑。
- 首批无外部资源／脚本／网络／AI调用；雨效复用可信模块或受控适配，按需调度并服从暂停／减少动画。仍用矩形原生输入及宿主操作入口。

1. 独立记录上轮验收和清理，再实现运行声明及基础／雨夜样例；新增源码按功能目录归位，无第二轮文件移动。

4. 编辑器先预览，再显式应用并保存；关闭／取消不写库，撤销仅提交设计差异，不回写旧成员或热度。发布失败使用现有恢复入口，重开从已提交设计重建。

## 实施结果与协议映射

| 职责 | 实际落点／语义 |
| --- | --- |
| 声明与能力 | Domain/Canvas；7种白名单能力，最多128节点／64参数，父级先声明、深度16，单一members槽；不接路径、资源、脚本或网络 |
| 布局 | 归一化矩形、文字后接内容槽的纵向流；文字按保守行高分配，装配移除回收空间；呈现和输入使用同一布局结果 |
| 草稿与提交 | Application/Features/Canvas；固定PosterId及实体／设计版本，修改即作废预览令牌；实际宿主准备后以已有事务／CAS提交；重复请求沿现有持久化回执回放 |
| 保存／撤销 | LayoutParametersJson的v9仅用于含Canvas状态的实例；旧实例保持原版本，迁移001～027原字节不改。保留当前／上次设计，撤销是新设计提交，不替换成员、文件、统计或其他外观设置 |
| 视图与接线 | Views/Canvas独立编辑器；Views/ControlCenter只加入口与生命周期。Runtime/Posters承接原生预览，Presentation/Canvas负责稳定ID装饰节点及内容槽适配 |
| 生命周期 | 静态布局只缓存本实例一份；雨线48个固定对象，服从既有共享时钟／暂停，不另建timer。收展保留展开构图，仅裁剪可见区域；新尺寸仍执行内容保护 |

生产声明是`desktopup.canvas-recipe`、`protocolVersion:1`；不是J0 `0.1-draft` JSON的完整解析器。J0能力目录／草稿的核心语义在类型和会话中实现，设计样例里的资源、任意自由布局、可编辑操作锚点及非矩形原生空洞还没有开放。当前两内置声明可复用于不同海报，覆盖独立保存；未实现通用模板库导入／导出、历史多级撤销或AI工具发布。旧v1入口继续原合同，切回旧模板显式退出画板并可撤销，不复制一套文件所有权。查询当前设计RequestId可核对最近提交；任意历史请求的完整查询UI不在本批，事务回放测试覆盖重开后幂等。

准备与持久化仍不是跨GPU／数据库原子事务：实际渲染失败不能取得可提交预览；原生失败按既有边界恢复／隔离，已提交设计在重开后重建。未知声明或未知持久化版本只读保留，不回退覆写原字节。
