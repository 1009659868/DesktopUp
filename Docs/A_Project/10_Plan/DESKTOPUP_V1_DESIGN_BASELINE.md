## 2. 一句话产品定义

DesktopUP 是一款面向 Windows 11 的低资源桌面海报启动器：把散乱的游戏快捷方式安全收纳到可折叠、可换肤、可自动排版的大幅面桌面海报中，并保留完整恢复、撤销和卸载能力。

它不替换 Explorer，不接管 Windows 原生桌面图标坐标，也不把普通控制中心窗口作为产品主体。

## 3. V1 目标体验

正常启动或开机自启后：

1. 桌面海报是唯一持续可见的产品表面；
2. 控制中心、设置和 AI 助手只在用户主动呼出时显示；
3. 托盘保持轻量可用，负责显隐、编辑、锁定、暂停、主题和退出；
4. 海报没有 Windows 原生标题栏、任务栏按钮或默认 Alt+Tab 项；
5. 海报透明区域不拦截原生桌面选择、右键和图标点击；
6. 全屏、锁屏或显示器关闭时停止主题动画和无效渲染；
7. Explorer、显示器或 DPI 变化后恢复到合理可见位置。

## 5. 运行表面与宿主

### 5.1 单全局宿主

V1 采用一个全局透明桌面宿主，而不是每显示器宿主或每海报一个 WebView2。

- 当前阶段只要求主显示器上的单海报闭环；
- 后续多海报仍共享同一宿主和渲染环境；
- 跨显示器坐标、命中区域和 DPI 映射属于实现验证项，不重新打开宿主拓扑决策；
- WorkerW 不可用时保留明确可观察的 `ToolWindow` 回退；
- 任意非公开 Windows 行为必须隔离在适配层并可关闭。

### 5.2 海报默认几何

- 默认宽度：`max(工作区宽 × 0.22, 280px)`；
- 最大宽度：工作区宽度的 45%；
- 默认高度：工作区高度减去上下安全边距；
- 默认位置：主显示器右侧；
- 默认锚点：右上角；
- 用户拖动或调整宽度后持久保存；
- 显示器变化后使用归一化锚点恢复，绝对坐标只作为回退。

## 6. 海报结构与状态

### 6.1 自制标题栏

海报顶部必须包含模板内的自制 DOM 标题栏，不得与 Windows 原生窗口标题栏混淆。

标题栏同一行至少包含：

```text
海报标题 / 模板标识 / 项目数量  |  收起或展开  |  锁定或解锁
```

- 未锁定时，`USING` 和 `EDITING` 均允许从标题栏空白区域拖动海报；
- 按钮、链接和游戏图标不是拖动命中区；
- 锁定后禁止移动、缩放和改变锚点；
- 锁定不影响展开、收起、启动游戏或海报内部自动排版。

### 6.2 正交状态模型

```text
海报状态 = 呈现模式 × 交互模式 × 运行时模式 + 锁定属性
```

- 呈现：`EXPANDED` / `COLLAPSED`；
- 交互：`USING` / `EDITING`；
- 运行时：`ACTIVE_STATIC` / `ACTIVE_ANIMATED` / `PAUSED` / `STOPPED`；
- 锁定：每海报布尔属性，默认 `false`。

新海报默认：

```text
EXPANDED + USING + ACTIVE_STATIC + unlocked
```

`auto_collapse_enabled` 默认 `false`。

## 7. 首发模板体系

V1 首发共三套内置模板：一套默认模板和两套可替换主题模板。

| 模板 | 角色 | 目标 |
| --- | --- | --- |
| `transparent-default` | 默认模板，暂名 | 高透明、低装饰、低视觉焦点，优先与壁纸融合 |
| `neon-hud` | 可替换主题 | 赛博 HUD、霓虹线条、扫描线与数据化排版 |
| `cinema-lightbox` | 可替换主题 | 电影灯箱、暖白轮廓、胶片结构与衬线标题 |

默认模板不是错误回退模板。系统仍需保留独立的最小安全回退渲染，以便模板缺失或损坏时保证启动和恢复入口可用。

`transparent-default` 的正式名称与完整视觉规格仍待单独形成设计稿，但其低焦点、透明和默认启用角色已经冻结。

## 8. Shadow DOM 模板引擎

每张海报模板挂载到独立 Shadow Root：

```text
Poster host element
└─ shadowRoot
   ├─ template style
   ├─ template DOM
   ├─ custom title bar
   ├─ icon slot
   └─ status/decor slots
```

约束：

- 模板 CSS 不得污染控制中心、宿主页面或其他海报；
- 全局状态通过显式属性、CSS custom properties 或渲染输入传入 Shadow Root；
- 模板内部仍使用 `--tpl-*` 变量命名，便于 schema 与参数面板映射；
- 用户 CSS 只能进入对应模板的 Shadow Root；
- 热切换时替换 Shadow Root 内的模板 DOM 和样式，不重建 WebView；
- 宿主拥有命中区域、暂停、拖动命令和错误边界，模板不能越权控制原生窗口。

## 9. 完整模板安装能力

主题导入导出不仅保存参数覆盖，还必须支持安装缺失的完整模板。

完整模板包至少包含：

```text
manifest.json
params-schema.json
template.html
template.css
presets/
assets/
可选的受限扩展声明
```

安装流程：

1. 解压到隔离临时目录；
2. 校验路径穿越、符号链接、压缩炸弹、文件类型和大小；
3. 校验 manifest、schema、插槽和模板版本；
4. 净化 HTML、CSS、SVG、图片和字体；
5. 展示模板来源、权限与变更预览；
6. 用户确认后原子安装到应用数据目录；
7. 注册模板索引并允许创建 ThemeInstance；
8. 安装失败不得留下半注册模板；
9. 卸载模板不得破坏正在使用的海报，必须先迁移到默认模板或安全回退。

包含脚本或未来受限代码能力的模板必须走独立信任流程；首发内置三模板不依赖脚本。

## 10. 收纳、恢复与默认行为

“海报默认展开”与“是否收纳快捷方式”是两个独立维度。

导入时用户必须明确选择：

- **仅添加**：只登记并显示入口，不移动桌面快捷方式；
- **安全收纳**：经过预览、确认、保险库和恢复账本后移动 `.lnk/.url`；
- `.exe`、游戏本体、文件夹和普通用户文件永不被移动。

应用不得以任何默认值替代用户对“移出桌面”的确认。

## 11. 智能排版与主题定制

保留既有设计：

- 排名由最近使用、有效启动次数和新鲜度综合决定；
- 图标使用对数缩放，目标范围 50%–300%；
- 支持全自动、锚定+自动、全手动三层控制；
- 四级主题定制为预设、结构化参数、素材替换和受限代码覆盖；
- 所有自动或 AI 修改必须服从锁定边界和统一撤销链。

## 12. AI 边界

AI 为可选 BYOK 控制面能力：

- 无 Key 时不初始化 Provider、不联网；
- Key 进入 Windows Credential Manager，不进入前端、数据库或日志；
- AI 只调用与手动 UI 共用的受控命令；
- AI 不得执行任意 Shell、原生程序或绕过模板/海报安全边界；
- AI 不得静默解锁并移动已锁定海报；
- AI 不得绕过预览和用户确认执行真实快捷方式收纳。

低风险操作是否允许免确认暂不冻结。后续应按“只读、仅预览、可逆写入、文件系统写入、安全边界变更”分级后单独形成决策。

## 13. 性能与恢复硬门

- 静态桌面无持续 `requestAnimationFrame`；
- 全屏、锁屏或显示器关闭时无主题渲染活动；
- 模板热切换目标低于 200ms，不含布局重算；
- 海报透明区域不吞桌面输入；
- 使用态不抢前台焦点；
- Win+D、Explorer 重启、主屏变化、热插拔和 100%–200% DPI 后可恢复；
- 数据或模板损坏时进入可诊断安全回退；
- 导入、收纳和恢复故障不得覆盖或丢失用户快捷方式。

## 14. V1 非目标

- 不替换或注入 Explorer；
- 不控制 Windows 原生桌面图标坐标；
- 不静默扫描或移动桌面文件；
- 不提供官方 AI Key、云代理或计费；
- 不执行来源不明的 DLL、EXE 或无限权限脚本；
- 不在首版建设在线主题市场或账户云同步；
- 不把每海报一个永久 WebView2 作为生产方案。

## 15. V1 实施顺序

1. 冻结状态源、Shadow DOM 边界、标题栏拖动和单全局宿主契约；
2. 建立默认透明模板及安全回退；
3. 完成大幅面右侧海报、位置持久化和展开/收起；
4. 完成 Neon HUD 与 Cinema Lightbox；
5. 完成模板热切换、完整模板安装和错误降级；
6. 完成真实 Windows、性能和 Release 验收；
7. M1 通过后才进入真实快捷方式收纳 MVP。
