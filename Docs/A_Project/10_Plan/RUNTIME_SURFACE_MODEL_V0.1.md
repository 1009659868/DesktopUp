# Desktop-Up 运行表面模型 V0.1

状态：`ACTIVE DESIGN BASELINE`

日期：2026-08-02

## 1. 已接受的产品模型

V1 跨文档决策统一见 [`DESKTOPUP_V1_DESIGN_BASELINE.md`](DESKTOPUP_V1_DESIGN_BASELINE.md)。V1 已冻结为**单全局透明宿主**；多屏坐标、命中区域与 DPI 映射仍是实现验证项，但不重新打开宿主拓扑决策。

Desktop-Up 是一个后台常驻的 Windows 桌面收纳工具，不是以普通主页窗口作为主体的传统桌面应用。

正常运行时，用户持续看到的 Desktop-Up 界面只能是融入真实桌面的海报收纳层。主页、设置和 AI 助手属于按需打开的控制界面，不得随普通启动或开机自启自动占据桌面。

内部可以由同一个 `DesktopUp.exe` 进程管理多个原生窗口和 WebView，但用户可见角色必须严格分离：

```text
DesktopUp.exe 常驻运行时
├─ Desktop Surface / 桌面收纳层      正常运行时唯一持续可见的产品表面
├─ Control Center / 控制中心         用户主动呼出时才显示
├─ Settings and Agent / 设置与助手   控制中心或托盘按需打开
└─ Tray / 通知区域入口               始终轻量可用，负责显隐和呼出
```

## 2. 表面职责

### 2.1 桌面收纳层

- 承载一张或多张海报模块、游戏图标、展开/收起、锁定和启动交互；
- 与真实壁纸融合，不显示 Windows 原生应用标题栏、任务栏按钮或默认 Alt+Tab 项；这里的“不显示应用标题栏”只指 Windows 原生标题栏，模板内自制 DOM 标题栏仍必须存在；
- 不主动抢占前台焦点；海报之外的透明区域不阻塞桌面选择、右键和原生图标；
- 主页关闭、设置关闭或 Agent 未启动时仍独立存在；
- 用户拖动的是单全局透明宿主内的海报模块锚点，不是控制中心窗口或宿主窗体；
- V1 固定使用一个全局透明宿主承载当前及后续海报，共享同一渲染环境；
- 不为每张海报永久创建独立 WebView2，避免海报数量线性放大内存和进程成本；
- WorkerW/桌面层挂载失败时可降级为明确标记的 bottom-most `ToolWindow`，但仍不得伪装成控制中心。

### 2.2 控制中心

- 使用当前 A0 主页的视觉方向，负责海报、项目、主题、性能、备份和系统集成管理；
- 主页中的桌面画布是编辑预览，不是实际桌面收纳宿主；
- 预览修改通过统一命令和状态模型同步到桌面收纳层；
- 只在托盘、开始菜单、快捷方式或第二实例的显式用户动作下打开；
- 关闭后释放预览动画和非必要资源，不隐藏或销毁桌面海报；
- 可以是普通可聚焦窗口，并在打开期间出现在任务栏和 Alt+Tab。

### 2.3 设置与 Agent

- 设置可以作为控制中心路由或独立按需窗口实现，但不能成为桌面收纳层的一部分；
- AI 助手属于控制面能力，没有 API Key 时不初始化 Provider、不联网；
- 设置和 Agent 的关闭不改变桌面海报可见性；
- 所有修改都通过与手动 UI 相同的本地命令、预览、确认和撤销链执行。

### 2.4 通知区域入口

- 托盘由 Rust 原生运行时拥有，不依赖控制中心 WebView 常驻；
- 单击默认显示/隐藏桌面海报，双击打开控制中心，右键提供主页、设置、锁定、主题、暂停、自启和退出；
- 显式“退出 Desktop-Up”才结束运行时；关闭控制中心只隐藏控制中心；
- Explorer 重启后恢复托盘和桌面宿主，不能通过启动控制中心掩盖恢复失败。

## 3. 生命周期契约

| 事件 | 桌面收纳层 | 控制中心 | 托盘/进程 |
| --- | --- | --- | --- |
| 普通启动 | 显示已启用海报 | 隐藏 | 运行 |
| 开机自启 | 显示静态海报 | 不创建或隐藏 | 运行 |
| 托盘单击 | 显示/隐藏 | 不变 | 运行 |
| 托盘双击或“打开主页” | 不变 | 创建、显示并聚焦 | 运行 |
| 打开设置/AI | 不变 | 显示对应路由或按需表面 | 运行 |
| 关闭控制中心 | 不变 | 隐藏或释放 | 运行 |
| 隐藏全部海报 | 隐藏 | 不变 | 运行 |
| 第二实例启动 | 不重复创建 | 呼回已有控制中心 | 第二实例退出 |
| 显式退出 | 销毁 | 销毁 | 移除托盘并退出 |

安装后的首次引导可以由用户主动选择打开，但不得把“每次启动自动弹出控制中心”作为默认行为。

## 4. 不可破坏的用户体验规则

1. 正常启动完成后，如果用户没有主动打开主页，屏幕上只能看到桌面海报模块。
2. 桌面收纳层和控制中心是同一产品的不同表面，不共享窗口装饰、焦点或显隐生命周期。
3. 控制中心的海报画布只是预览；真实桌面上的海报不得嵌进控制中心窗口中运行。
4. 关闭主页不能导致海报消失，隐藏海报不能强制打开主页。
5. 海报宿主的透明空白不得形成不可见的鼠标遮挡层。
6. 运行时可以没有任何普通窗口，但托盘、恢复协调器和桌面宿主仍可工作。

## 5. 当前 A0 与目标模型的关系

已对齐：

- 已存在主页和独立海报两个原生表面；
- 已验证 `ToolWindow` 回退、无任务栏入口、海报锁定/拖动/收起、托盘和单实例；
- 当前主页视觉可以继续作为控制中心设计基础。

尚未对齐：

- A0 目前启动时默认显示控制中心，不符合“只显示桌面收纳层”的正常启动契约；
- A0 独立海报仅证明单海报窗体可行，尚未实现 V1 冻结的单全局透明宿主；
- WorkerW、Win+D、空白区域穿透、Explorer 恢复和多屏坐标/DPI 映射尚未全部通过硬门；
- 控制中心预览和真实桌面宿主仍使用演示级 `localStorage` 同步，不是统一生产状态通道。

## 6. 同类产品参考边界

公开资料中的“小智桌面”体现了可借鉴的产品分层：桌面分区持续承载文件/快捷方式，主面板和设置由任务栏入口按需调用，并提供分区样式、透明度和收起方式。Desktop-Up 只参考这种“桌面分区与管理面板分离”的交互原则，不推断或复制其未公开的内部实现。

## 7. 后续实现门

在继续 C-DHF-02 前，先完成一个窄范围“表面角色对齐”切片：

1. 普通启动和开机自启不显示控制中心；
