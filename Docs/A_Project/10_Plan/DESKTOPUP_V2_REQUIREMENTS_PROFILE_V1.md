## 2. 重构前提：V1 的结论

### 2.1 为什么重构而不是继续修补

V1 的 P0 缺陷 DU-BUG-001（透明海报顶部白条）经过 2026-08-17/18 两轮系统排查后，结论如下：

- 白条不属于 WebView2 自绘帧（CDP 实时帧无白条），而是**宿主窗口的 DWM 呈现层**对表面顶部约 24 行的不透明白色坏合成；
- 屏幕合成状态呈多级劣化（白条 / 分段穿透 / 完全缺席），`PrintWindow` 自绘恒为过期帧，无法作为真相；
- 已否定的候选：屏幕贴边、壁纸、原生 caption、子窗口偏移、copy-bits、同尺寸 bounds 重同步、HRGN、整屏固定宿主、owner/坐标混淆、revision-only 幂等同步、**常驻 WS_EX_LAYERED**、**tao 遗留 blur-behind + WM_ERASEBKGND 整幅填充（Accent Policy 替换实验）**、**禁用 GPU（--disable-gpu）**、强制重绘；
- 已确认的诱因类别：**“Tauri 透明窗口（tao）+ 窗口模式 WebView2（wry）+ DirectComposition 视觉树 + 动态样式切换”在 Windows 11 上的组合本身不稳定**，问题可被触发但无法在该架构内根治。

用户决定：桌面海报宿主架构推倒重做，**V2 代码全重写，V1 代码与测试仅作为参考文档；渲染候选优先原生 Direct2D/DirectComposition**。V2 的首要任务是**渲染宿主选定**，而不是继续叠加窗口补丁。

## 7. 架构级需求（V2 核心增补）

### RP-ARC-01 渲染宿主实验先行（`P0/FROZEN`）

- V2 的第一个工作流就是渲染宿主选定实验；任何上层功能不得先于选定启动；
- 实验只实现一个透明圆角海报、标题栏、六张占位卡片的最小表面；
- 不先迁移控制中心、SQLite、托盘或 Item。

### RP-ARC-02 候选与最小验证矩阵（`P0/FROZEN`）

候选（**优先实施顺序已定：先做原生 Direct2D/DirectComposition**；其余为回退候选）：

1. Rust/C++ Direct2D/DirectComposition 原生渲染（**优先**）；
2. 原生 layered window + 离屏位图渲染；
3. Qt Quick/QML 透明原生海报；
4. WebView2 Composition Controller + DirectComposition。

每个候选必须同时通过（否则淘汰）：

1. 冷启动与 20+ 轮连续拖动/松开，零顶部条带、灰框、裁切；
2. 空白框选、桌面右键、原生图标单击/双击通过；
3. Item 卡片、标题栏按钮、锁定、收起/展开命中通过；
4. 海报不覆盖控制中心、资源管理器、浏览器、文件选择器；
5. Win+D、Explorer 重启、暂停、显隐、退出通过；
6. 状态恢复与 CAS 不回退；
7. 静态 10s CPU 增量 ≤0.10s、工作集 ≤50 MiB（或用户接受的新预算）；
8. 呈现状态可自检（配合 RP-INV-12）；
9. 安装器可稳定携带新增运行时依赖。

### RP-ARC-03 呈现健康自检（`P0/FROZEN`）

- 运行时提供内容呈现自检（例如周期性或事件驱动的最小呈现探针）；
- 自检失败 → 结构化诊断 + 一次静默重建 + 逐级通知 + 手动重连，不得伪装成功；
- 自检本身不得破坏层级、输入或性能预算。

### RP-ARC-04 静态渲染与呈现恢复耦合（`P0/FROZEN`）

- 0 FPS 静态策略（V1 性能要求保留）必须绑定“触发类操作后强制一次重绘/呈现恢复”；
- 触发类操作至少包括：拖动结束、控制中心开/关、显示/DPI 变化、暂停恢复、Win+D 后、Shell 恢复后。

### RP-ARC-05 渲染真相权威（`P1/FROZEN`）

- 渲染正确性证据以屏幕像素对比为准；`PrintWindow`/GDI 后备缓冲区仅作辅助，不得单独作为 PASS 依据（V1 中其为过期帧）。

### RP-ARC-06 控制中心与海报渲染器解耦（`P1/FROZEN`）

- 控制中心是普通窗口，可以继续用 WebView2；
- 海报宿主渲染技术与控制中心互不绑定，替换海报渲染器不得波及控制中心、托盘或状态权威；
- 若海报宿主选 WebView2 系方案，必须用与窗口模式不同的承载方式（如 Composition Controller），且同一进程内多 WebView 不得造成表面重建耦合。

### RP-ARC-07 透明机制单一化（`P1/FROZEN`）

- 每个渲染方案只保留一种透明/呈现机制；禁止 blur-behind、accent policy、WS_EX_LAYERED、颜色键等多机制叠加；
- 运行期窗口样式切换收敛为最小集合，每次切换必须可回退且经过 §7.2 矩阵回归。

### RP-ARC-08 失败回退是产品能力（`P1/FROZEN`）

- 每个渲染方案必须提供明确、可诊断的回退形态（例如 bottom-most ToolWindow 或明确失败状态）；
- 回退不伪装成功，不常驻 TopMost，不影响桌面输入。

## 24. V2 分期

```text
V2-P0  渲染宿主选定实验（唯一先行）
       → 候选矩阵 → 选定决策 → 冻结渲染架构
V2-P1  以选定渲染器重建桌面海报宿主
       → 接入 V1 的 Rust 核心 / SQLite / 托盘 / 生命周期
       → 主屏单海报 Release 交互门（含 §7.2 全矩阵）
V2-P2  控制中心重建（或复用）+ 预览投影 + 状态权威联通
V2-P3+ Item 契约/仓库 → 只读发现 → 仅添加 → 真实启动 → 整合门
       → 安全收纳 MVP → 模板平台 → 排序布局 → 主题作者/AI → 发布
```

V2-P0 的完成定义 = 至少一个候选通过 §7.2 全矩阵 + 选定决策记录 + 其余候选淘汰证据。

## 25. V2 完成定义

1. 选定渲染器在支持环境稳定运行，白条/分段/缺席状态不可复现，且有自检与回退；
2. V1 画像 §30 的全部十条完成定义在 V2 上满足；
3. V1 已交付能力（托盘/单实例/生命周期/SQLite/自启）在 V2 宿主上无回退；
4. 呈现层证据以屏幕像素对比为准，A/B/C 文档与验证证据一致。
