# Desktop-Up 产品设计稿 V0.1

状态：`DRAFT`

日期：2026-08-02

## 1. 一句话体验

把散乱的游戏快捷方式拖进一张有风格的桌面海报；海报自动排好图标，平时可收起，需要时展开并直接启动游戏。

## 2. 目标用户与核心场景

### 2.1 目标用户

- 桌面上有较多 Steam、Epic、Xbox 或独立游戏快捷方式的玩家；
- 喜欢桌面美化，但不愿学习复杂配置语言的用户；
- 愿意用 CSS/SVG/脚本制作或分享主题的高级用户。

### 2.2 核心任务

1. 三分钟内完成首次安装、创建海报和导入快捷方式。
2. 不打开复杂设置即可完成收纳、展开、启动和恢复。
3. 改变分辨率或重启 Explorer 后，海报仍能回到合理位置。
4. 全屏游戏运行时，用户无需手动暂停工具。
5. 卸载时能够恢复收纳过的快捷方式并清理应用痕迹。

## 3. 产品信息结构

运行表面的权威角色和生命周期见 [`RUNTIME_SURFACE_MODEL_V0.1.md`](RUNTIME_SURFACE_MODEL_V0.1.md)。正常启动时只有桌面海报持续可见；控制中心、设置和 Agent 均由用户按需呼出。

```text
系统托盘
├─ 单击：显示/隐藏全部海报
├─ 双击：打开主页
└─ 右键菜单
   ├─ 主页 / 设置
   ├─ 显示、编辑和暂停
   ├─ 快速主题切换
   ├─ AI 助手 / 配置 AI
   ├─ 开机自启 / 重新连接桌面
   └─ 退出

控制中心
├─ 海报与项目
├─ 主题与参数
├─ 自动整理规则
├─ AI 助手
├─ 性能与暂停
├─ 启动与系统集成
└─ 数据备份与恢复

桌面海报
├─ 展开态
├─ 收起态
├─ 自动隐藏态
├─ 编辑态
└─ 单海报锁定态
```

不可混淆的界面角色：

- 桌面海报是产品的默认可见主体，融入真实桌面；
- 控制中心是普通按需窗口，当前 A0 主页视觉继续用于该角色；
- 控制中心内的桌面画布仅用于预览和编辑，不替代真实桌面宿主；
- 普通启动或开机自启不得默认弹出控制中心。

## 4. 桌面海报设计

### 4.1 组成

- 背景层：图片、渐变、噪点、遮罩或轻量动画；
- 信息层：海报标题、副标题、项目数量和可选状态；
- 项目层：游戏图标、名称和可选平台角标；
- 控制层：折叠、锁/钉、更多菜单和编辑态拖拽手柄；
- 安全区：保持图标与视觉主体不互相遮挡。

### 4.2 状态

| 状态 | 行为 |
| --- | --- |
| 展开 | 显示海报和全部可见项目，可滚动或分页 |
| 收起 | 只显示封面条、标题或收藏夹图标 |
| 自动隐藏 | 鼠标离开后收起，进入热区后展开 |
| 编辑 | 显示锚点、边界、吸附线和尺寸手柄 |
| 锁定 | 固定当前海报的位置、尺寸和锚点，仍允许展开、收起和启动游戏 |
| 暂停 | 保留最后静态画面，停止动画和定时任务 |

### 4.3 锚点与拖动

- 海报以“显示器 + 归一化坐标 + 边缘锚点”保存位置；
- 支持左上、右上、左下、右下和自由锚点；
- 拖动时吸附屏幕边缘、其他海报和安全间距；
- 显示器消失时迁移到主显示器可见区域；
- 透明桌面宿主窗体固定覆盖对应显示器，用户拖动的是宿主内的海报模块，不直接移动宿主窗体；
- 每张海报标题栏提供“锁/钉”按钮；锁定后禁止拖动、缩放、改变锚点和被自动外部重排；
- 锁定不影响海报内部图标自动排版、展开/收起或启动游戏；
- AI 和普通自动化命令不得移动锁定海报，必须先由用户明确解锁；
- 显示器断开或 DPI 变化导致海报不可见时，安全恢复可以把锁定海报迁回可见区域，并记录原因；
- 默认锁定布局，使用单海报锁按钮或托盘“锁定/解锁全部海报”进入编辑状态；锁定状态持久保存。

## 5. 自动排版

第一版提供三种确定性布局：

1. **网格**：最易读，适合较多游戏；
2. **书架**：横向分组，突出封面和平台；
3. **错位卡片**：视觉更强，适合少量精选游戏。

排版规则：

- 新项目只触发局部重排；
- 手动固定的项目不参与自动换位；
- 同名快捷方式通过目标地址和来源去重；
- 海报空间不足时优先分页或滚动，不无限缩小图标；
- 所有自动调整均可撤销。

## 6. 首次使用流程

```text
安装完成
  → 选择是否开机自启（默认关闭）
  → 选择一个预设海报
  → 拖入快捷方式或扫描桌面
  → 选择“仅添加”或“收纳并移出桌面”
  → 自动排版
  → 完成并锁定布局
```

“收纳并移出桌面”必须显示明确说明：应用只移动快捷方式，不移动或卸载游戏。操作完成后提供撤销入口。

## 7. 快捷方式收纳与恢复

真实对象的支持范围、导入预览、“仅添加/收纳并移出桌面”分流和恢复事务以 [`快捷方式导入与安全收纳模型 V0.1`](SHORTCUT_IMPORT_AND_COLLECTION_MODEL_V0.1.md) 为准。

每个导入项目保存：

- 稳定项目 ID；
- 来源类型和原始路径；
- 快捷方式目标、参数、工作目录和图标来源；
- 是否由 Desktop-Up 移动；
- 移动前路径与恢复状态；
- 内容哈希或可用于冲突识别的指纹。

恢复时：

- 原位置空闲：恢复原文件名；
- 原位置已有同名文件：不得覆盖，恢复为带编号名称并报告；
- 原显示器或路径消失：恢复到用户桌面的 `Desktop-Up Restored` 文件夹；
- 恢复失败：保留托管副本并输出可操作错误，不继续清理该记录。

## 8. 主题与风格

内置首批方向：

- **Cinematic**：游戏封面、电影标题和柔和暗角；
- **Neon HUD**：赛博霓虹、扫描线和克制粒子；
- **Windows Glass**：Mica/亚克力感、圆角和低饱和；
- **Retro Pixel**：像素边框、有限色板和无插值图标；
- **Minimal Shelf**：低干扰纯色书架，性能最低。

主题参数至少覆盖颜色、背景、透明度、模糊、圆角、阴影、字体、图标大小、间距、动画速度和帧率上限。

### 8.1 延后视觉改版方向

状态：`DEFERRED UNTIL FUNCTIONAL HARD GATES PASS`

- 当前 A0 的深色主页和深色海报只作为功能原型，不作为最终视觉验收基线；
- 后续主页、设置与桌面收纳窗统一调整为米白色、清新、轻盈、低压迫感的视觉方向；
- 主页与海报需要形成同一套颜色、圆角、阴影、留白、字体和状态反馈语言，同时保持桌面海报与管理界面的角色区分；
- 本轮不改配色与样式，避免视觉返工干扰 WorkerW、命中测试、恢复、暂停和真实收纳闭环；
- 在核心功能和性能硬门完成后、正式主题与发布视觉冻结前，单独建立视觉重设计切片并提交效果稿确认。

## 9. 主题导入层级

| 层级 | 内容 | 默认权限 |
| --- | --- | --- |
| 参数主题 | 清单、参数、内置组件组合 | 默认允许 |
| 素材主题 | CSS、SVG、图片、字体 | 校验后允许 |
| 代码主题 | 受限脚本或 WASM | 默认禁用，用户单独信任 |

代码主题不得直接访问文件系统、网络、注册表、进程或原生 IPC。失去响应时必须能单独终止，不拖死主程序。

## 10. 性能与暂停体验

- 静态主题仅在数据、尺寸或可见性变化时重绘；
- 全屏/最大化应用覆盖海报所在显示器时自动暂停；
- 锁屏、显示器关闭、远程会话断开或电池节能时暂停；
- 允许按应用覆盖默认规则；
- 用户可选择“暂停动画”或“停止主题并释放资源”；
- 恢复桌面时不播放补帧动画。

性能指标是测试预算，不是未经测量的承诺：

| 场景 | V0.1 预算 |
| --- | --- |
| 静态桌面 | 不存在持续 `requestAnimationFrame`；CPU 长期接近空闲 |
| 自动暂停 | CPU/GPU 渲染活动趋近于零 |
| 动态可见 | 默认 30 FPS，可选 15/60 FPS |
| 压力数据 | 4 张海报、200 个项目、双显示器可用 |
| 启动影响 | 延迟加载扫描器和编辑器，不阻塞登录桌面 |

## 11. 控制中心

- 控制中心默认不随普通启动和开机自启显示，只在用户显式打开主页、设置或 Agent 时创建/显示；
- 左侧为功能导航，右侧为实时预览和参数；
- 实时预览通过统一状态命令同步到独立桌面收纳层，关闭控制中心不影响海报；
- 修改参数即时预览，点击保存后才写入正式主题实例；
- 危险操作如清空集合、删除托管快捷方式必须说明影响并提供恢复；
- 开机自启只有一个明确开关，默认关闭；
- 提供“导出诊断包”，默认去除用户名和绝对路径。

## 12. 托盘与快捷入口

- Desktop-Up 运行时创建标准 Windows 通知区域图标；图标位于主区域还是“∧”折叠栏由 Windows 和用户决定；
- 单击图标显示/隐藏全部海报，双击打开主页，右键打开原生快捷菜单；
- 右键菜单必须提供主页、设置、编辑模式、暂停、开机自启和显式退出；
- 右键菜单提供“锁定/解锁全部海报”，单张海报仍保留独立锁按钮；
- “快速主题”子菜单可直接切换当前海报主题，不需要打开控制中心；
- 关闭主页只隐藏到托盘，首次发生时提示一次；只有“退出 Desktop-Up”结束运行时；
- 未配置 API Key 时菜单显示“配置 AI…”，但不初始化 Provider；
- Explorer 重启后重新创建托盘图标；连续失败时提供“重新连接桌面”。

详细契约见 [`TRAY_AND_QUICK_ACCESS_DESIGN_V0.1.md`](TRAY_AND_QUICK_ACCESS_DESIGN_V0.1.md)。

## 13. 本地 AI 助手

- AI 是可选功能，用户自行填写 OpenAI、DeepSeek 或兼容接口的 API Key；
- 没有 Key 时 Agent 不启动、不联网，手动功能保持完整；
- 用户可以描述主题、图标尺寸、间距、排序和收起方式等需求；
- 模型只生成结构化变更计划，由本地命令系统校验和执行；
- 所有变更必须先预览、后确认、可撤销；
- AI 可生成参数 JSON、主题 DSL、CSS 和 SVG 草稿；受限脚本后置；
- Key 保存在 Windows Credential Manager，不能进入 WebView、数据库或普通日志；
- Desktop-Up 不提供 API Key、额度、计费或云代理，费用由用户所用 Key 对应的平台决定。

详细设计见 [`AI_ASSISTANT_DESIGN_V0.1.md`](AI_ASSISTANT_DESIGN_V0.1.md)。

## 14. 安装与卸载体验

最终安装文件暂定为 `DesktopUpSetup.exe`。默认按当前用户安装，无需管理员权限。

安装目录必须提供 `uninstall.exe`。一键清理卸载顺序：

1. 请求 Desktop-Up 安全退出；
2. 恢复由 Desktop-Up 收纳的快捷方式；
3. 删除开机自启和应用集成项；
4. 删除程序、缓存、主题副本、日志和数据库；
5. 不删除游戏、游戏平台、外部主题源文件或普通桌面文件；
6. 输出成功、部分成功或需人工处理的清晰结果。

若有快捷方式无法恢复，卸载程序必须停止删除相关托管副本，并给出“打开保留目录”操作。

## 15. MVP 范围

必须包含：

- 手动拖入/扫描桌面快捷方式；
- 新建、删除、拖动、缩放、锁定和折叠海报；
- 网格自动排版；
- 启动项目和打开目标位置；
- 安全收纳、撤销与恢复；
- 3 个内置静态主题和参数编辑；
- 托盘、开机自启开关和自动暂停；
- 导入/导出备份；
- 安装、升级和完整卸载。

MVP 不包含：

- 在线主题市场；
- 云同步和账户系统；
- AI 自动生成海报；
- 任意原生插件；
- 深度改写 Explorer 原生图标坐标。

AI 助手属于主题系统完成后的可选增强，不阻塞无 AI 的本地 MVP。托盘主页/设置/快速主题菜单属于 MVP 必须能力。

## 16. 海报视觉方向（V0.1 修订 - 2026-08-03）

本产品设计稿的 §4（桌面海报设计）已被 [`POSTER_REDESIGN_V0.1`](POSTER_REDESIGN_V0.1.md) 及其配套设计文档大幅更新。主要变更方向：

- 海报从 490×392 小型悬浮窗升级为桌面级大幅面展示面板
- 图标从等大网格改为基于启动频率的对数动态缩放
- 从单一深色视觉改为可切换模板系统（Neon HUD + Cinema Lightbox）
- 海报状态模型从六种平铺状态重构为三维正交模型

§8.1 中记录的米白清新风延后方向与 Cinema Lightbox 暖白方向一致——Lightbox 模板即是该方向的具象化。

## 17. 待用户确认的设计项

- 正式产品名与图标；
- 默认海报风格优先级；
- 海报收起的默认触发方式；
- 安装时是否展示“立即开机自启”选项；
- 首版是否必须包含受限 JavaScript 主题，还是在参数/DSL/CSS/SVG 稳定后进入后续版本。
