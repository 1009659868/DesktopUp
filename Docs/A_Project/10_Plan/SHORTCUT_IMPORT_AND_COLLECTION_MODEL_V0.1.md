# Desktop-Up 快捷方式导入与安全收纳模型 V0.1

状态：`PLANNED FOR A1`

建立：2026-08-02

最近修订：2026-08-14

## 1. 目的与排期位置

本模型定义正式 Item 从“应用自有仓库与数据驱动海报投影”，到真实桌面项目“发现并进入海报”，再到“可撤销收纳和卸载恢复”的完整闭环。它属于 A1 `Collection and Launch` 模块；A0 宿主硬门通过后，先完成海报表面/交互收敛，再立即进入 C-CIM，排在完整主题系统和 AI 助手之前。

当前 A0 Demo 中的 `GAME_CATALOG` 仍是假数据；C-CIM 的首要退出条件是让它退出正式运行路径，以隔离夹具和 SQLite Item 快照驱动海报。建立本计划不代表已经扫描或移动用户桌面文件。

## 2. 用户入口

首版提供两个主动入口，不在冷启动时静默扫描：

1. 将 `.lnk`、`.url` 或 `.exe` 拖入海报或控制中心；
2. 用户点击“扫描桌面”，明确选择当前用户桌面和/或公共桌面。

扫描必须在后台执行、可取消、有数量和耗时上限。首版不扫描 Steam、Epic、Xbox 等游戏平台数据库；平台发现属于 A3/M4。

## 3. 支持对象与边界

| 对象 | 导入处理 | “收纳并移出桌面”处理 |
| --- | --- | --- |
| `.lnk` | 用 Windows Shell COM 解析并保留目标、参数、工作目录和图标位置 | 只移动 `.lnk` 文件到应用保险库 |
| `.url` | 解析并校验协议白名单 | 只移动 `.url` 文件到应用保险库 |
| `.exe` | 只登记启动目标和元数据 | 禁止移动、复制或修改程序文件 |

应用永不移动或删除游戏本体、游戏平台目录、普通文件或文件夹，也不把 Explorer 图标坐标作为权威布局数据。

图标解析顺序为：快捷方式 `IconLocation` → 目标程序图标 → 安全占位图。缓存只保存应用拥有的图标副本，不改写源文件。

## 4. 导入预览

任何写入前必须显示预览，至少包含：

- 显示名称、对象类型、来源位置与解析后的启动目标；
- 图标预览，以及无效目标、受限协议和解析失败提示；
- 已存在项目、同路径、同目标和同指纹冲突；
- 每一项将执行的动作，以及可从批次中取消选择的入口。

用户确认时选择：

- **仅添加**：保存项目与启动元数据，源文件保持原位；
- **收纳并移出桌面**：仅对可托管的 `.lnk`/`.url` 建立恢复账本并移入保险库。

导入批次不得以静默默认值代替用户对“移出桌面”的确认。

## 5. 数据和恢复账本

`CollectionItem` 保存显示与启动语义；`ManagedShortcut` 保存文件托管与恢复状态。两者必须使用稳定 ID 关联，不能把可变化的绝对路径当作唯一身份。

账本至少记录：

- 原始路径、保险库路径、来源范围和内容指纹；
- 目标、参数、工作目录、图标来源和解析状态；
- 操作批次、当前事务状态、恢复状态、最后错误和时间戳；
- 操作是“仅添加”还是由 Desktop-Up 实际托管。

数据库与保险库都位于应用数据边界内。诊断日志默认隐藏用户名、API Key 和不必要的完整路径。

## 6. 安全收纳事务

单项收纳采用可恢复的两阶段事务：

```text
Discover
  → Parse
  → Preview
  → Confirm
  → 写入 PENDING 账本
  → 复制到保险库临时位置
  → 校验大小与指纹
  → 原子提交保险库副本
  → 移走原快捷方式
  → 写入 MANAGED
```

约束：

- 任一步失败都不得覆盖现有文件；
- 原文件移走前必须存在已校验的保险库副本和 `PENDING` 账本；
- 启动时检查未完成事务，优先回滚或恢复，不能直接清理；
- 重解析点、不可读路径、跨卷异常和权限错误必须停止该项并报告；
- 批量操作按项提交，单项失败不隐瞒其他项结果。

## 7. 撤销、恢复与卸载

撤销和卸载共用同一恢复服务：

- 原位置空闲：恢复原文件名；
- 原位置存在同名文件：不覆盖，使用带编号名称并报告；
- 原路径不可用：恢复到用户桌面的 `Desktop-Up Restored` 文件夹；
- 恢复失败：保留保险库副本和账本，卸载程序不得删除它们；
- 仅添加项目：只移除 Desktop-Up 记录，不触碰源文件。

`uninstall.exe` 必须先展示托管项目恢复结果，再决定哪些应用数据可以清理；部分失败时提供“打开保留目录”和可重试入口。

## 8. A1 实施切片

| 切片 | 对应 C | 交付 | 写入用户桌面 |
| --- | --- | --- | --- |
| A1.0 | C-CIM | `CollectionItem`/`PosterItem` 契约、SQLite schema/CAS、仓库 CRUD、空/失效状态、隔离夹具与数据驱动海报投影 | 否 |
| A1.1 | C-ROD | `.lnk/.url/.exe` 解析器、图标提取、去重、可取消只读发现和假目录夹具；只产出候选项 | 否 |
| A1.2 | C-PAA | 拖入/扫描入口、逐项预览、冲突处理与“仅添加”，经正式 Item 仓库进入海报 | 否 |
| A1.3 | C-LCH | 海报真实启动、失效入口、错误反馈、打开目标位置和启动结果记录 | 否 |
| A1.4 | C-SVT | 保险库、两阶段账本、“收纳并移出桌面”、撤销和故障注入 | 经用户逐批确认 |
| A1.5 | C-RCV | 异常事务恢复、卸载恢复接口和失败保留保险库 | 仅恢复操作 |

A1.0 只允许应用自有 SQLite 与隔离夹具；A1.1 只读发现不直接写库；A1.2 必须经预览确认后才能仅添加。在 A1.0..A1.3 自动化和整合 Release 门通过前，不启用 C-SVT 的真实桌面移动能力。开发和故障注入优先使用隔离测试目录，不使用用户桌面作为测试夹具。

## 9. 阶段门

### 9.1 A1 / V1-P3 可用 MVP 门

- `GAME_CATALOG` 不在正式运行路径，零/一/多/失效 Item 均来自 C-CIM 仓库快照；
- `.lnk` 参数、工作目录和图标语义在只读发现、仅添加和启动后保持一致；
- `.url` 非白名单协议不能进入可启动状态，`.exe` 从未被移动或复制；
- C-CIM、C-ROD、C-PAA、C-LCH 和 C-PCRG 均有自动化或 Release 证据；
- 200 项扫描可取消，后台扫描不阻塞桌面海报交互；
- 无用户主动操作时不扫描桌面，也不改变桌面内容。

### 9.2 A1 / V1-P4 安全收纳门

- 仅添加、收纳、撤销、重启恢复和卸载恢复均有自动化覆盖；
- 连续 100 次故障注入覆盖复制中断、校验失败、同名冲突、权限失败和进程异常退出；
- 任何测试都没有覆盖或丢失用户快捷方式；
- 真实文件移动只发生在用户逐批确认后，失败时保留保险库与账本。

## 10. 明确不在本模型内

- 游戏平台安装发现与联网元数据抓取；
- 自动判断并移走所有桌面图标；
- Explorer 注入、原生桌面图标坐标接管；
- 移动游戏本体、文件夹或普通用户文件；
- 由 AI 绕过预览和确认直接执行收纳。
