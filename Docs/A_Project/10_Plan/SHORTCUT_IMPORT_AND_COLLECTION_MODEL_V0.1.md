# Desktop-Up 快捷方式导入与安全收纳模型 V0.1

状态：`PLANNED FOR A1`

日期：2026-08-02

## 1. 目的与排期位置

本模型定义真实桌面项目从“发现”到“进入海报”，再到“可撤销收纳和卸载恢复”的完整闭环。它属于 A1 `Collection and Launch` 模块，只有 A0 桌面宿主硬门通过后才进入实现，排在主题系统和 AI 助手之前。

当前 A0 Demo 中的 `GAME_CATALOG` 仍是假数据；建立本计划不代表已经扫描或移动用户桌面文件。

## 2. 用户入口

首版提供两个主动入口，不在冷启动时静默扫描：

1. 将 `.lnk`、`.url` 或 `.exe` 拖入海报或控制中心；
2. 用户点击“扫描桌面”，明确选择当前用户桌面和/或公共桌面。

扫描必须在后台执行、可取消、有数量和耗时上限。首版不扫描 Steam、Epic、Xbox 等游戏平台数据库；平台发现属于 A3/M4。

## 3. 支持对象与边界

| 对象 | 导入处理 | “收纳并移出桌面”处理 |
| --- | --- | --- |
| `.lnk` | 用 Windows Shell COM 解析并保留目标、参数、工作目录和图标位置 | 只移动 `.lnk` 文件到应用保险库 |
| `.url` | 解析并校验协议白名单 | 只移动 `.url` 文件到应用保险库 |
| `.exe` | 只登记启动目标和元数据 | 禁止移动、复制或修改程序文件 |

应用永不移动或删除游戏本体、游戏平台目录、普通文件或文件夹，也不把 Explorer 图标坐标作为权威布局数据。

图标解析顺序为：快捷方式 `IconLocation` → 目标程序图标 → 安全占位图。缓存只保存应用拥有的图标副本，不改写源文件。

## 4. 导入预览

任何写入前必须显示预览，至少包含：

- 显示名称、对象类型、来源位置与解析后的启动目标；
- 图标预览，以及无效目标、受限协议和解析失败提示；
- 已存在项目、同路径、同目标和同指纹冲突；
- 每一项将执行的动作，以及可从批次中取消选择的入口。

用户确认时选择：

- **仅添加**：保存项目与启动元数据，源文件保持原位；
- **收纳并移出桌面**：仅对可托管的 `.lnk`/`.url` 建立恢复账本并移入保险库。

导入批次不得以静默默认值代替用户对“移出桌面”的确认。

## 5. 数据和恢复账本

`CollectionItem` 保存显示与启动语义；`ManagedShortcut` 保存文件托管与恢复状态。两者必须使用稳定 ID 关联，不能把可变化的绝对路径当作唯一身份。

账本至少记录：

- 原始路径、保险库路径、来源范围和内容指纹；
- 目标、参数、工作目录、图标来源和解析状态；
- 操作批次、当前事务状态、恢复状态、最后错误和时间戳；
- 操作是“仅添加”还是由 Desktop-Up 实际托管。

数据库与保险库都位于应用数据边界内。诊断日志默认隐藏用户名、API Key 和不必要的完整路径。

## 6. 安全收纳事务

单项收纳采用可恢复的两阶段事务：

```text
Discover
  → Parse
  → Preview
  → Confirm
  → 写入 PENDING 账本
  → 复制到保险库临时位置
  → 校验大小与指纹
  → 原子提交保险库副本
  → 移走原快捷方式
  → 写入 MANAGED
```

约束：

- 任一步失败都不得覆盖现有文件；
- 原文件移走前必须存在已校验的保险库副本和 `PENDING` 账本；
- 启动时检查未完成事务，优先回滚或恢复，不能直接清理；
- 重解析点、不可读路径、跨卷异常和权限错误必须停止该项并报告；
- 批量操作按项提交，单项失败不隐瞒其他项结果。

## 7. 撤销、恢复与卸载

撤销和卸载共用同一恢复服务：

- 原位置空闲：恢复原文件名；
- 原位置存在同名文件：不覆盖，使用带编号名称并报告；
- 原路径不可用：恢复到用户桌面的 `Desktop-Up Restored` 文件夹；
- 恢复失败：保留保险库副本和账本，卸载程序不得删除它们；
- 仅添加项目：只移除 Desktop-Up 记录，不触碰源文件。

`uninstall.exe` 必须先展示托管项目恢复结果，再决定哪些应用数据可以清理；部分失败时提供“打开保留目录”和可重试入口。

## 8. A1 实施切片

| 切片 | 交付 | 写入用户桌面 |
| --- | --- | --- |
| A1.0 | SQLite schema、解析器接口、只读扫描、假目录测试夹具 | 否 |
| A1.1 | 拖入/扫描、图标提取、去重、导入预览、“仅添加” | 否 |
| A1.2 | 保险库、两阶段账本、“收纳并移出桌面”、撤销与恢复 | 经用户逐批确认 |
| A1.3 | 海报启动、打开目标位置、异常事务恢复与卸载恢复接口 | 仅恢复操作 |

在 A1.0/A1.1 的自动化测试全部通过前，不启用真实桌面的移动能力。开发和故障注入优先使用隔离测试目录，不使用用户桌面作为测试夹具。

## 9. 阶段门

A1 退出前必须满足：

- `.lnk` 启动参数、工作目录和图标语义在导入后保持一致；
- `.url` 非白名单协议无法启动，`.exe` 从未被移动或复制；
- 仅添加、收纳、撤销、重启恢复和卸载恢复均有自动化覆盖；
- 连续 100 次故障注入覆盖复制中断、校验失败、同名冲突、权限失败和进程异常退出；
- 任何测试都没有覆盖或丢失用户快捷方式；
- 200 项扫描可取消，后台扫描不阻塞桌面海报交互；
- 无用户主动操作时不扫描桌面，也不改变桌面内容。

## 10. 明确不在本模型内

- 游戏平台安装发现与联网元数据抓取；
- 自动判断并移走所有桌面图标；
- Explorer 注入、原生桌面图标坐标接管；
- 移动游戏本体、文件夹或普通用户文件；
- 由 AI 绕过预览和确认直接执行收纳。
