# Desktop-Up V2 需求风险、反例与待定项

状态：`REQUIREMENTS BASELINE — GENERAL CONTENT / MULTI-POSTER USER REVISION 2026-09-07`

最后修订：2026-09-11（对齐已明确决定，不新增产品裁决）

## 1. 文档职责

本文保留旧项目和上一轮 V2 尝试暴露出的失败表现，把它们转换为后续技术选型、架构和验收必须证伪的风险。它不保留任何旧技术路线结论，也不把历史故障写成新实现的当前 Bug。

状态使用：`OPEN / DEFERRED / ACCEPTED RISK / CLOSED / SUPERSEDED`。

## 2. 历史防回归风险

### V2-RISK-001：透明海报出现顶部条带、异常边框或非客户区残影

| 字段 | 内容 |
| --- | --- |
| 类型 | `ARCHITECTURE / RENDERING RISK` |
| 状态 | `OPEN — FUTURE SOLUTION MUST DISPROVE` |
| 历史表现 | 海报位于屏幕中部时，打开控制中心后拖动真实海报，顶部出现固定高度白条；后续尝试曾演化为灰色透明边框、整屏顶部白条或常驻条带。 |
| 已知教训 | 不能把屏幕边缘、壁纸、CSS 贴边、单纯坐标误差或一次截图当作根因；必须区分应用内容、宿主窗口非客户区、透明合成层和最终屏幕合成。 |
| 需求 | 候选方案必须具备可观察的呈现边界；拖动、缩放、显隐、控制中心开关、DPI/分辨率变化均不得产生条带或异常边框。 |
| 关闭条件 | 选定方案在统一实机矩阵中持续通过“零条带、零异常边框”，并提供可重复诊断证据。 |

### V2-RISK-002：海报短暂或持续覆盖普通程序，或被桌面层遮挡

| 字段 | 内容 |
| --- | --- |
| 类型 | `WINDOW OWNERSHIP / Z-ORDER RISK` |
| 状态 | `OPEN — FUTURE SOLUTION MUST DISPROVE` |
| 历史表现 | 控制中心、编辑拖动、桌面右键、文件选择、刷新、Win+D 或焦点变化后，海报可能短暂置顶、持续覆盖普通程序、隐藏后恢复或发生单帧闪烁。 |
| 需求 | 层级必须恒满足：普通窗口、控制中心、系统对话框与全屏程序 > DesktopUP 海报 > Windows 桌面图标 > 壁纸；键盘 Win+D、任务栏“显示桌面”和触控板手势不得先隐藏、最小化、cloak、掉层或脱锚再补救。 |
| 关闭条件 | 键盘 Win+D、任务栏显示桌面、触控板手势、Explorer 重建、普通窗口和全屏矩阵通过，并能记录 owner、parent、z-order、可见性、最小化与 cloak 实际值。 |

### V2-RISK-003：控制中心编辑后真实海报拖动、缩放或命中失效

| 字段 | 内容 |
| --- | --- |
| 类型 | `INTERACTION / STATE AUTHORITY RISK` |
| 状态 | `OPEN` |
| 历史表现 | 预览拖动一次后无法继续拖动；进入编辑模式也无法调整长宽；预览与真实海报可能重叠、分离或互相覆盖。 |
| 需求 | 预览是状态投影，真实海报是运行表面；两者经同一权威状态和带版本命令同步，操作不得静默更换输入所有权或留下悬空编辑会话。 |
| 关闭条件 | 连续拖动、缩放、取消、提交、关闭重开矩阵通过，且无重复实例、失效命中区或状态分叉。 |

### V2-RISK-004：参数和状态回弹

| 字段 | 内容 |
| --- | --- |
| 类型 | `STATE CONSISTENCY RISK` |
| 状态 | `OPEN` |
| 历史表现 | 风格预设或视觉滑杆修改后立即回到旧值；控制中心、托盘和海报可能状态不同步。 |
| 需求 | 单一权威状态、修订号/CAS、草稿与提交边界、失败保留和冲突反馈必须明确；UI 不得用旧快照覆盖刚提交的新状态。 |
| 关闭条件 | 并发、重开、失败、退出恢复和版本冲突测试全部通过。 |
