# DesktopUP V2 运行表面、控制中心与托盘关系 V1

状态：`REQUIREMENTS BASELINE — GENERAL CONTENT / MULTI-POSTER USER REVISION 2026-09-07`

最后修订：2026-09-07（原始需求建立于 2026-08-18）

## 1. 文档职责

本文冻结主页/控制中心、桌面海报、设置/AI、托盘、后台核心与状态仓库之间的用户可见关系和生命周期。它不规定这些表面由几个进程、何种 UI 框架或哪种窗口 API 实现。

## 2. 核心产品模型

DesktopUP 是后台常驻的桌面启动与收纳工具，不是以主页窗口为主体的传统应用。

```text
DesktopUP Runtime
├─ Desktop Poster Surfaces     0..N 张独立配置的桌面收纳海报
├─ Control Center / Home       唯一管理窗口，用户主动呼出时显示
├─ Settings / AI               控制中心路由或按需表面
├─ Native Tray                 唯一常驻轻量入口
├─ Command and State Core      命令、状态、生命周期、Windows 适配
└─ Persistence / Recovery      业务状态、迁移、账本、备份和诊断
```

用户可见角色必须分离，即使未来实现选择把多个角色放进同一进程：

- 海报不使用控制中心的窗口装饰；
- 控制中心内预览不是真实海报；
- 托盘不依赖控制中心存活；
- 关闭设置或 AI 不改变海报；
- 运行时允许没有任何普通窗口，但海报、托盘和恢复协调仍工作。

## 3. 桌面海报表面

### 3.1 职责

- 承载海报标题、Item、展开/收起、锁定、启动和有限上下文菜单；
- 与真实壁纸融合；
- 默认无原生标题栏、任务栏按钮和 Alt+Tab 项；
- 不主动激活前台；
- 非交互区域允许桌面输入；
- 独立于控制中心生命周期；
- 从单一状态快照投影，不保存第二份业务真相；
- 桌面挂载失败时报告降级，不以打开控制中心掩盖。

### 3.2 不承担的职责

- 不承担完整设置、主题编辑、备份恢复和 AI 会话；
- 不直接扫描、移动或删除用户桌面文件；
- 不拥有 API Key；
- 不直接决定安装、自启和卸载策略；
- 不把窗口句柄、物理像素或 Shell 细节写入业务状态。

## 4. 控制中心/主页

### 4.1 角色

控制中心是普通管理窗口，负责组织复杂功能而不是常驻桌面。

建议信息架构：

```text
控制中心
├─ 概览 / 当前海报
├─ 海报与 Item
├─ 主题、预设与参数
├─ 活跃度、自动排序与布局
├─ 启动、导入与安全收纳
├─ 性能、暂停与诊断
├─ 系统集成与开机自启
├─ 备份、恢复与数据管理
└─ AI 助手与 Provider 设置
```

### 4.2 窗口行为

- 可聚焦，可在任务栏和 Alt+Tab 出现；
- 普通启动和自启默认不创建；
- 托盘双击、菜单、开始菜单、快捷方式或普通第二实例可呼出；
- 同一时间最多一个控制中心；
- 关闭窗口不等于退出应用；
- 首次关闭可提示一次“仍在托盘运行”；
- 再次打开时若保存位置位于已断开显示器，迁回主屏可见区域；
- 创建失败必须结构化记录并提供可重试入口，不能静默无响应。

### 4.3 资源生命周期

- 优先按需创建；
- 关闭后优先释放预览 renderer、动画、编辑缓存和页面资源；
- 如果平台限制只能隐藏，应明确记录，且停止所有非必要循环；
- 托盘和真实海报不得依赖控制中心资源；
- 重复打开关闭不积累窗口、renderer、事件监听或消息订阅。

## 5. 控制中心预览

### 5.1 定位

预览画布是桌面状态的缩放投影：

- 真实桌面工作区映射到画布可用区域；
- 海报使用归一化位置和尺寸投影；
- 画布大小变化后重新计算比例；
- 真实桌面绝对坐标不能直接当作控制中心像素；
- 预览内容始终完整可见，可用留白承载不同宽高比。

### 5.2 命令

- 预览只发出移动、缩放、锁定、收起、模板和参数命令；
- 每个命令携带 expected revision；
- 核心校验权限、边界和状态后提交；
- 成功返回新快照；冲突返回当前 revision 和冲突原因；
- UI 不维护会覆盖核心状态的长期乐观副本；
- 拖动过程可本地临时预览，释放时提交；失败恢复已接受快照；
- 高频参数可以节流，但保存前必须使用最新 revision。

### 5.3 连续交互验收

- 连续移动至少三次；
- 编辑态连续改变宽高至少两次；
- 窗口大小变化后继续可编辑；
- 关闭重开后预览存在；
- 真实海报随后仍可移动、锁定和收起；
- 真实海报始终位于控制中心之后，不遮挡控制中心。

## 6. 托盘

### 6.1 基础行为

| 操作 | 行为 |
| --- | --- |
| 单击图标 | 无动作，不改变海报或主页 |
| 双击图标 | 打开/激活唯一控制中心；重复双击不关闭、不重复创建 |
| 右键 | 打开原生快捷菜单 |
| 关闭主页 | 返回托盘，运行时继续 |
| “退出 DesktopUP” | 保存必要状态并显式退出 |

单击无动作是刻意选择：海报是桌面常驻表面，不应因误触托盘突然隐藏。

### 6.2 右键菜单结构

```text
DesktopUP
├─ 打开主页
├─ 新增海报
├─ 设置…
├─ 显示全部海报                 [✓]
├─ 编辑布局                     [ ]
├─ 锁定全部海报                 [ ]
├─ 暂停动态效果                 [ ]
├─ 快速主题                     >
│  ├─ Transparent Default       [✓]
│  ├─ Neon HUD
│  ├─ Cinema Lightbox
│  └─ 管理主题…
├─ AI 助手… / 配置 AI…
├─ 开机自启                     [ ]
├─ 重新评估活跃度
├─ 重新连接桌面
└─ 退出 DesktopUP
```

### 6.3 菜单规则

- 快速主题必须有明确目标；无目标时先选择，不隐式退回或重建默认海报；零海报时提示先新增；
- 未配置 Key 显示“配置 AI…”，不得初始化 Provider；
- 编辑、暂停、显隐、自启和全局锁定使用可读勾选状态；
- 全局锁定批量写入每张海报，单张海报仍可独立锁定；
- 锁定不妨碍启动和收起/展开；
- 主页/设置复用唯一控制中心；
- 重新连接桌面在降级或失败时突出；
- 菜单失败显示短通知并保留原状态；
- 键盘导航可用；100/125/150/200% 缩放分别在单主显示器环境验证，不据此宣称混合 DPI 或跨屏通过。

### 6.4 图标状态

- 正常：品牌图标；
- 已暂停：tooltip 标明动态效果已暂停；
- 需要处理：桌面挂载、恢复或状态损坏有简短原因；
- 不使用高频闪烁；
- tooltip 简短，例如 `DesktopUP · 1 张海报 · 已暂停`。

## 7. 启动意图与单实例

| ID | 输入 | 结果 |
| --- | --- | --- |
| LIFE-01 | 首实例，无参数 | 创建唯一托盘，显示已启用海报，不打开控制中心 |
| LIFE-02 | 首实例，精确 `--autostart` | 静态海报与托盘，不打开/聚焦控制中心，不修改自启注册 |
| LIFE-03 | 普通第二实例 | 通知现有实例打开控制中心，第二实例退出 |
| LIFE-04 | 第二实例 `--autostart` | 保持现有 UI，不改变焦点，静默退出 |
| LIFE-05 | 未知、重复或组合参数 | 不改变现有 UI，结构化拒绝，调用进程非零退出 |
| LIFE-06 | 内部诊断参数 | 只允许首实例进入受控诊断，不成为公开产品参数 |

ready 前的控制命令必须排队并只投递一次。重复或乱序请求最终仍只能有一套海报、一枚托盘和零/一个控制中心。

## 8. 可见性、暂停与锁定的所有权

### 8.1 可见性

- 海报显隐是运行时状态，不改变用户的 Poster 定义；
- 隐藏海报不打开控制中心；
- 控制中心关闭不隐藏海报；
- 锁屏、显示器关闭等系统不可见与用户手动隐藏要区分原因；
- 恢复时按原因优先级计算最终可见性。

### 8.2 暂停

- 手动暂停动态效果只影响动态绘制；
- 系统暂停可以停止输入和呈现更新；
- 托盘勾选与核心真实状态一致；
- 暂停/恢复连续三轮结果一致；
- 默认静态主题没有明显动画时，验证状态、按钮和资源活动，而非强求肉眼动画差异。

### 8.3 锁定

- 单张锁定是持久状态；
- 全局锁定命令批量提交；
- 控制中心、托盘和海报按钮必须读取同一权威；
- 锁定后任何表面都不能移动/缩放；
- 解锁动作不能被 AI 隐式包含在另一命令中。

## 9. 状态同步

### 9.1 Snapshot

所有表面订阅版本化 snapshot，至少包含：

- revision；
- Poster 可持久字段；
- Item 列表/摘要；
- 可见性、暂停、ready、degraded 等运行时派生状态；
- 当前权限；
- 当前选中海报；
- 可操作诊断。

### 9.2 Command

命令至少包含：命令类型、目标、expected revision、参数、来源表面和请求 ID。

结果至少区分：成功、无变化、权限拒绝、revision 冲突、校验失败、宿主未就绪、I/O 失败和退出中拒绝。

### 9.3 防回弹

- UI 不能同时从 localStorage 和正式仓库加载同一字段；
- 保存成功后新 revision 原子广播；
- 旧 snapshot 不得覆盖新 snapshot；
- 窗口重新创建先取得正式 snapshot，再渲染；
- revision-only 变化不应无条件触发窗口移动、缩放或重建；
- 主题滑块的预览值、已保存值和服务器拒绝值有明确区分。

## 10. 焦点、任务栏和层级

### 海报

- 默认不激活，不在任务栏和 Alt+Tab；
- 精确层级契约为：普通窗口、控制中心、系统对话框与全屏程序在海报之上；海报在 Windows 桌面图标与壁纸之上；
- 键盘 `Win+D`、任务栏“显示桌面”和触控板显示桌面手势期间必须连续可见，不得出现先隐藏/最小化/cloak/掉层/脱锚再恢复的帧；
- 鼠标按下、拖动、右键关闭、文件对话框和 Shell 恢复都不得短暂 TopMost；
- 不得用激活、临时 TopMost 或覆盖普通应用补救层级；
- Explorer 不可用时的回退形态必须明确、可诊断且不常驻 TopMost；
- 任一时刻无法满足目标层级时必须报告 degraded，而不是伪装正常。

### 控制中心

- 是正常可激活窗口；
- 从托盘打开时显示并聚焦；
- 关闭后焦点自然返回系统，不强行激活海报；
- 海报不因控制中心开关改变 z-order 角色。

## 11. Explorer、任务栏和桌面恢复

- 收到任务栏重建事件后恢复唯一托盘；
- 重新发现桌面挂载环境并验证海报角色；
- 重复事件去抖、单飞、限制重试；
- 连续失败进入 degraded 状态，托盘提供“重新连接桌面”；
- 恢复过程不打开控制中心掩盖失败；
- 退出中忽略迟到的 Shell、显示和托盘事件；
- 禁止通过通用 TopMost 脉冲恢复层级。

## 12. 显示器与 DPI

- 保存显示器稳定身份、归一化锚点和绝对回退；
- 工作区、DPI、分辨率变化后重算几何和命中；
- 海报若完全不可见，迁回主屏合理区域并记录原因；
- 控制中心也需要已断开屏幕恢复；
- 主屏多海报正式认证，保留单海报回归；多屏、混合 DPI、负坐标、主屏切换和热插拔独立验证；
- 未验证不得标记支持。

## 13. 显式退出顺序

1. 生命周期粘滞进入 `exiting`；
2. 拒绝新命令和迟到恢复；
3. 取消 AI、扫描、导入和主题安装任务；
4. 刷新必要状态与账本；
5. 销毁控制中心和海报；
6. 移除托盘；
7. 释放资源并结束进程。

关闭控制中心、隐藏海报、暂停动态效果都不是退出。

## 14. 诊断

控制中心提供导出诊断包，至少包含：

- 版本、平台、显示器/DPI 摘要；
- 海报和控制中心生命周期状态；
- snapshot revision 与最近命令结果；
- 桌面挂载、层级、命中、呈现健康；
- 托盘恢复次数和最近错误；
- 资源采样；
- 脱敏后的错误事件。

不得包含 API Key、Authorization、用户名、不必要绝对路径和用户请求正文。

## 15. 验收标准

1. 普通启动/自启不显示控制中心；
2. 海报和托盘存在，任务栏无海报按钮；
3. 单击、双击、右键托盘符合契约；
4. 双击打开控制中心，关闭后海报不受影响，再打开正常；
5. 第二实例只唤回控制中心，不重复海报/托盘；
6. 连续打开关闭控制中心 20 轮无资源、层级和状态回退；
7. 控制中心窗口缩放时预览始终可见；
8. 预览连续拖动/缩放和真实海报操作一致；
9. 锁定、暂停、显隐和快速主题在三表面一致；
10. 文件选择器、浏览器、资源管理器始终盖在海报之上；
11. 键盘 Win+D、任务栏“显示桌面”和触控板手势各执行 10 轮，海报全程连续可见，零隐藏、零掉层、零重挂可见帧；
12. Explorer 重启 10 轮后恢复目标层级；无法恢复时进入明确 degraded 并提供重连，不得覆盖普通程序；
13. 显式退出后海报、控制中心、托盘和进程全部结束；
14. 在单主显示器环境分别以 100/125/150/200% 缩放验证托盘菜单、控制中心和命中清晰；
15. 未配置 Key 时托盘 AI 入口只引导配置且没有网络请求。

## 16. 技术选型边界

本文不决定：进程数量、窗口框架、海报渲染 API、控制中心 UI 技术和消息总线。选型只要不能同时满足角色隔离、层级、输入、状态、资源和恢复矩阵，就必须淘汰。

## 17. 多海报协调与生命周期

- 控制中心具有海报列表、当前选择、创建/重命名/复制配置/隐藏/显示/移除入口；预览画布显示全部已启用海报并标识当前目标，不能把多个海报叠成同一状态。
- 每张海报有稳定 PosterId、独立内容/主题实例与运行会话。选择海报只改变编辑目标，不隐式移动、激活或改变其他海报。
- 允许零海报：删掉最后一张后托盘和控制中心仍可用，重启不再次创建演示海报。首次初始化标识与“当前无海报”必须区分。
- 复制海报默认复制配置并建立新身份/主题实例，可显式复用来源集合；不默认复制、搬动真实文件。来源只读/失效时保留诊断。
- 海报级显隐与全局临时隐藏分开：全局恢复还原原本应显示的海报，不把单独隐藏的海报全部显示。收起是高度状态，不等于隐藏。
- 托盘保留一份，显示海报总数/可见数、全局暂停、锁定汇总（全锁/部分/全未锁）。单张命令必须有目标；批量命令明确作用对象与结果。
- 托盘“快速主题”“编辑布局”“重新评估活跃度”不得隐含选中某张；有明确目标选择，或标注全部并预览范围。
- 关闭控制中心释放预览/草稿/订阅，不关闭任何海报；退出应用统一停止接收命令、终止手势、完成/记录文件任务、持久化并释放所有实例。
- Explorer/显示变化由共享环境协调器广播 generation；每个实例独立重挂和报告结果，失效实例不得影响其他实例恢复。
- 不存在的目标返回 NotFound；关闭/删除后到达的旧手势和回调不得复活海报。预览草稿按 PosterId 隔离，切换目标或关闭时明确保存/取消。
- 数据库故障属于共享故障，不能承诺只影响单张；主题/内容源局部故障应优先单张降级。单进程中的未捕获原生崩溃也不宣称已被实例隔离解决。
- 运行日志带 PosterId、command/request ID、全局/实体 revision、generation；禁止仅记录“海报恢复成功”而不知道哪一张。

最小人工门为三张不同用途海报：独立拖缩/锁定/收起/显隐、控制中心切换、托盘批量、重复开窗、重启恢复、删至零、Explorer 恢复和退出零残留。仍须沿用既有层级、白框与输入回归。

### 17.0 空间协同与选择目标补充（2026-09-07）

- 多海报“独立状态”不等于绝不相互移动：无碰撞时操作A不改B/C；明确的收展推让可以改变受影响、未锁定海报的位置，但不能串改其主题、内容参数或锁定/收起状态。
- 空间事务涉及源海报、被推动海报、所有参与判断的障碍和当前显示环境；中途删除/隐藏/改锁定、版本冲突或显示变化必须取消或重新求解，不能把旧位置写到新实体。
- 收起过程中的条件归位须有来源和版本依据；符合条件者随收起同步移动，不能等待收起结束才开始归位；被再次调整的海报不再自动归位。不能只在窗口内保存无主旧坐标，重启后再盲目应用。
- 展开优先完整尺寸，并始终先利用下方合法余量，再向上补足；下方无容量才纯向上，不能因上方独立够用而跳过下方。完整方案不可行再按同一路径临时展开；最小高度为完整标题、一行完整Item和必要页脚。保存的展开尺寸与运行时有效高度分开，三端一致反映“完整/临时受限/无法展开”，不独立重算或将临时高度写入便携配置。空间不足零布局提交，仅按钮反馈；重启/恢复按当前环境重算，不重放旧临时像素或自动覆盖尺寸意图。
- 全部海报列表与当前选中ID是控制中心最低管理能力；不能将“后台已有集合投影”当作“用户已能切换全部海报”。隐藏、锁定、收起和降级海报仍要可选；目标不存在时显示空态/明确重新选择，不能隐式写入另一张。

### 17.1 首启与管理入口（2026-09-07 用户明确）

- 普通首次无配置时只建一张默认海报；已有有效配置按其集合恢复。主动删至零不再补默认，导入方案不额外叠加默认。
- 控制中心、托盘菜单均有“新增海报”。托盘新增不要求控制中心常驻；两者复用同一创建命令和幂等身份规则。
- 控制中心的目标海报操作、每张海报的“...”均有“删除海报”；锁定不应变相禁止用户从管理入口删除，但始终需要确认。
- 提示框写明目标名称、独立布局/设置被移除、真实内容保留及受管内容找回入口；最后一张另提示程序继续在托盘运行。
- 取消/关闭提示框不提交；目标版本在确认后重新校验。确认框可以正常获取交互焦点，但不能把真实海报抬到普通程序之上；不能把删除菜单事件当作拖动或启动 Item。

### 17.2 配置迁移入口

控制中心“备份、恢复与数据管理”提供“导出习惯配置”“导入习惯配置”。用户携带一份文件在另一主机应用，导入展示海报列表、位置映射、主题/来源缺失及对当前布局的影响，再确认提交。它不同于完整数据库备份，不携带凭据或实际桌面文件。

恢复后逐张按持久状态创建会话；一个配置中的坏主题仅使对应海报 fallback。零海报配置仍可从中心或托盘新增。完整字段与失败边界见 [需求画像 §32](DESKTOPUP_V2_REQUIREMENTS_PROFILE_V1.md#32-首次启动管理入口与跨主机配置)。
