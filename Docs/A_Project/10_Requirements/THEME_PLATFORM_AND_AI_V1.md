# DesktopUP V2 自定义主题平台与 AI 接入设计 V1

状态：`REQUIREMENTS BASELINE — CANVAS / TEMPLATE BEHAVIOR USER REVISION 2026-10-29`

最后修订：2026-10-29（原始需求建立于 2026-08-18）

## 1. 文档职责

本文完整迁移主题模板、参数 schema、素材槽、受限结构/样式覆盖、导入导出、版本迁移、原子安装、错误回退，以及 BYOK AI Provider、凭据、上下文、工具权限、ChangePlan、确认分级和错误隔离。

旧设计使用 Shadow DOM、CSS custom properties 和 Rust+JS 混合作为当时实现方案。V2 只保留其产品能力和安全性质：最终技术无论是 Web、Qt 还是原生绘制，都必须提供等价隔离、参数化、资源权限、原子切换和 fallback。

## 2. 目标

- 普通用户一键换风格；
- 进阶用户用结构化参数精细调整；
- 高级用户替换素材和受限结构；
- 主题作者可以导入/导出完整模板；
- AI 与手动 UI 共用同一命令，不出现第二条越权路径；
- 任何主题或 AI 失败都不影响 Item 启动、海报基本操作和用户数据；
- 无 AI、无网络、无第三方主题时产品仍完整可用。

## 3. 概念模型

```text
TemplatePackage
├─ Manifest
├─ ParameterSchema
├─ ProtectedStructureContract
├─ VisualDefinition
├─ BehaviorPrefabs / EventBindings
├─ MenuDefinitions / StateStyles
├─ Presets
├─ AssetSlots / Assets
├─ Optional User Overrides
└─ Required Capabilities

TemplatePackage ── 1:N ── ThemeInstance ── 1:1 ── Poster
```

### 3.1 TemplatePackage

至少包含：稳定 template key、显示名、语义版本、作者、描述、信任级别、参数 schema、预设、素材槽、结构/视觉定义、行为快照与事件绑定、菜单声明和状态样式、缩略图、能力声明、迁移信息和完整性校验。信任标签不授予任意代码或系统权限。

### 3.2 ThemeInstance

每张海报一个主题实例：模板版本、当前预设、只保存用户改过的参数覆盖、素材覆盖、受限样式覆盖、结构插槽覆盖、创建/更新时间和 revision。

模板默认值属于包；实例只保存覆盖。渲染时合并默认值、预设和实例覆盖，优先级固定且可诊断。

2026-10-29用户明确：新增海报实例化完整默认模板；打开“当前海报”必须同步同一实例的画面与行为，包括默认v收展和…更多菜单。默认不等于强制，显式空绑定／移除控件必须覆盖默认值，不在渲染或重开时补回。作者可自由组合／替换UI和受限行为；模板版本更新不静默改旧实例。协议和落地顺序见[联合协议顶部](../20_Architecture/CanvasContracts/CONTRACT.md)及[同源整改计划](../30_Plans/POSTER_CANVAS_ENGINE_DESIGN_PLAN.md)，目前是设计要求，review07尚未满足。

海报是产品名称，底层抽象为可收纳对象的可视化容器实例。统一身份、内容绑定、能力和版本、提交及操作语义，不统一矩形外框、标题栏或组件排列。圆形、异形、多个离散区域仍是一份实例；模板不能成为第二个文件所有者。联合协议与样例见[画板合同](../20_Architecture/CanvasContracts/CONTRACT.md)，J0设计已获用户认可，非现有运行时能力。

2026-10-27 J1重审明确：创作核心是从空白自由组合、导入素材、保存／实例化可复用场景，不是点选预制组件。结构编辑在独立创作工作台完成，控制中心只显示作者开放的常用参数；基础收纳与雨夜书桌是普通场景作品，不是编辑器特殊分支。本轮只交视觉设计，确认后才实施，原受限候选人工未通过。

### 3.3 `minimal-fallback`

- 内置安全回退，不是正常默认模板；
- 不出现在常规模板选择器；
- 模板缺失、损坏或被安全阻断时临时使用；
- 不写回用户选择；
- 保留用户数据、必要内容承载和应用级诊断；不改写用户作品。不因合法设计省略标题、菜单或收展就启用fallback，也不借错误回退增加隐藏收展行为。

## 4. 模板样例与视觉角色

2026-10-27首个联合设计闭环以基础收纳和雨夜书桌验证同一协议下的不同装配、区域和参数面板；minimal-fallback仍独立。下表保留其他视觉探索角色，不再要求先做齐三种风格才交付最小引擎。

| 模板 | 角色 | 能力 |
| --- | --- | --- |
| `transparent-default`（暂名） | 正常默认模板角色 | 低装饰、低焦点；通用 Box 与 NIGHT OPS 游戏海报为不同预设，不强制所有用途使用大标题 |
| `neon-hud` | 可替换 | 霓虹色板、扫描线、HUD 标记、数据化排版 |
| `cinema-lightbox` | 可替换 | 暖白灯箱、胶片齿孔、衬线标题、柔光 |
| `minimal-fallback` | 错误回退 | 最小安全结构，不参与正常选择 |

精确视觉见 [海报视觉与交互规格](POSTER_VISUAL_AND_INTERACTION_V1.md)。

## 5. 四级定制

### 5.1 深度 0：预设与开关

面向大多数用户：

```text
模板           [Transparent Default ▾]
动态缩放       [开]
背景柔化       [关 / 低 / 中 / 高]
圆角           [无 / 小 / 中 / 大]
Item 间距      [紧凑 / 标准 / 宽松]
配色方案       [模板预设 ▾]
```

每个枚举映射到明确的深度 1 参数集合。切换即时预览、可撤销、失败恢复旧值。

### 5.2 深度 1：结构化参数

参数面板由能力目录与模板参数描述共同生成，不要求每个模板改控制中心代码。按已装配组件显示可折叠参数组，区分配方默认值和实例覆盖；进阶编辑提供组件树、布局／区域及素材引用，另存模板与修改当前实例分开。首个运行切片先做参数及基础装配，复杂路径／完整拖拽编辑器后续，不据此把协议锁成矩形。

参数类型至少支持：

- color；
- percent；
- pixel/length；
- number；
- boolean；
- enum；
- font/asset reference（受权限约束）；
- grouped/conditional parameters。

每个参数至少声明：key、label、description、type、default、min/max/step、enum values、group、是否动态、迁移别名和作用目标。

示例概念 schema：

```json
{
  "groups": [
    {
      "id": "colors",
      "label": "颜色",
      "params": [
        {
          "key": "accent",
          "type": "color",
          "default": "#72e4ff"
        }
      ]
    },
    {
      "id": "layout",
      "label": "排版",
      "params": [
        {
          "key": "itemGap",
          "type": "pixel",
          "min": 8,
          "max": 32,
          "default": 12
        }
      ]
    }
  ]
}
```

参数契约不得携带或触发任意可执行表达式。需要转换时只能使用受控声明式变换或宿主内置转换 ID；具体表达和执行技术由后续架构决定。

### 5.3 深度 2：素材替换

模板通过 manifest 声明具名槽位：背景、装饰、字体、Logo/角标等。

| 类型 | 格式 | 默认上限 | 处理 |
| --- | --- | --- | --- |
| 背景图片 | PNG/JPG/WebP | 2MB | 解码重编码、去元数据 |
| SVG | SVG | 200KB | XML 解析，移除脚本、foreignObject、事件、外链 |
| 字体 | TTF/OTF/WOFF2 | 5MB | 格式校验、授权提示、应用自有副本 |
| Logo/角标 | PNG/SVG | 500KB | 同图片/SVG 安全链 |

素材导入不修改源文件。实例引用应用数据目录内经过校验的副本。

### 5.4 深度 3：受限样式和结构覆盖

- 只允许作用于所属模板实例；
- 不能污染控制中心、宿主或其他海报；
- 标题栏、介绍文字、收展按钮和菜单入口均可省略；保护真实文件与事务权限，不强制保留作品内UI或默认动作；
- 禁止外部网络、任意代码、iframe/object/embed、事件属性和系统接口；
- 解析失败跳过错误覆盖并保留模板默认结构；
- 编辑器提供语法错误、差异、隔离预览和恢复默认；
- 先提供参数编辑、组件装配与候选预览，复杂可视化编辑分批推进；不得预设 DOM、固定矩形或固定层级。

## 6. 受保护结构契约

必须保留最小语义，而不是固定视觉插槽：

- 一个稳定容器身份及与现有内容集合的绑定；首个运行切片使用单内容槽；
- 可被宿主解释的区域、布局及同代命中；矩形排版盒不是外形限制；
- 作者声明的控件与行为必须满足有效引用、命中及受限执行规则；菜单、拖动、收展等作品内交互可省略，不由宿主补足。没有收展就是没有收展，不在…菜单增加救援收展；应用管理与作品创作分开；
- 标题、计数、装饰、空状态均是可选组件，不强制占位；
- 视觉透明度不决定输入透明。非矩形空洞和分离区域原生输入先裁决后实施，不恢复已取消的普通点击穿透。

模板可自由组合，但：

- 真实内容交互与已声明控件按同代命中规则分派，不让整面拖动区吞掉Item操作；控件可删除，底层文件／空间／版本检查不可通过改行为绕过；
- Item 容器由现有数据与布局引擎填充，不复制真实对象和统计；
- 模板不能自行启动程序或写数据库；
- 模板不能决定窗口层级和桌面挂载；
- 模板只能通过受控事件提出操作意图。

## 7. 隔离要求

技术选型后必须证明以下等价性质：

1. 模板样式/绘制状态不泄漏到控制中心和其他海报；
2. 用户覆盖只作用于目标 ThemeInstance；
3. 模板不能直接访问文件、网络、进程、注册表、系统凭据设施或通用 IPC；
4. 失控动画、绘制或脚本可以暂停/终止；
5. 宿主执行同代命中、锁定、暂停及错误边界；拖动等交互按作品声明接线，不额外注入作者未声明的默认动作；
6. 模板切换不重建整个应用核心或状态仓库；
7. fallback 与默认模板物理/逻辑独立。

## 8. 参数权威与防回弹

- schema default、preset、saved overrides、preview overrides 分层；
- 控制中心拖动参数只更新临时 preview；
- 保存通过 expected revision 提交 ThemeInstance；
- 成功后广播新 snapshot；
- 失败/冲突保留预览并显示原因，允许刷新/合并/放弃；
- 旧 snapshot 不覆盖新保存值；
- 不同时从 legacy localStorage 和正式仓库读取同一参数；
- 预设切换与滑块修改必须共享同一权威路径；
- 重启后恢复模板、预设和参数；
- legacy `accent/opacity/density` 不扩张 Poster schema，迁入 ThemeInstance 参数模型。

## 9. 热切换

```text
用户选择模板
→ 取得并校验包/缓存
→ 保存旧 ThemeInstance 与资源快照
→ 在隔离临时实例构建新模板
→ 注入 defaults + preset + overrides
→ 验证受保护插槽和资源
→ 原子替换呈现
→ 布局按新容器重算
→ 保存或撤销
```

要求：

- 快速连续选择 300ms 去抖，最后意图获胜；
- 不出现半模板、旧样式残留或空白帧；
- 失败恢复旧模板、旧参数和旧资源；
- 切换目标 <200ms，不含完整 Item 布局重算；
- 切换不移动海报、不改变锁定/收起/层级；
- 不因 revision-only 变化重建窗口。

## 10. 逻辑包类型与能力

### 10.1 参数快照包

- ≤64KB；
- 包含格式版本、来源模板 key/version、导出时间、可选 label/preset；
- 包含参数契约声明的全部有效参数，便于独立恢复；
- 使用结构化、不可执行载荷，不携带二进制素材；具体序列化技术待定。

### 10.2 参数与素材包

逻辑内容至少包含模板依赖身份与版本、结构化参数、素材映射、素材载荷和完整性信息。

- 依赖已安装模板；
- asset mapping 必须匹配槽位；
- 每个文件有校验和；
- 总大小 ≤20MB；
- 不允许空文件、未声明文件或越界路径。

### 10.3 完整模板包

必须携带等价的：

```text
manifest
parameter schema
protected structure definition
visual/style definition
presets/
assets/
optional parameter snapshot
optional restricted overrides
required capability declarations
```

三类包的序列化格式、容器、内部路径布局和文件扩展名由后续架构阶段决定；上述逻辑组成、上限、安全校验和原子性不变。

### 10.4 整体习惯配置中的主题（2026-09-07）

整体多海报配置不是单张主题参数包。它应逐海报保留模板 key/version、实例参数/覆盖及素材依赖，用于另一主机恢复独立风格；不能只保留本机 ThemeInstanceId。

基础配置迁移先支持内置主题与参数。自定义主题进一步复用本节的参数/素材/模板包能力，提供一份用户可携带的文件，不要求用户手动收集多个内部目录；不另造第二套主题导入器。只导出引用时必须标明未携带的依赖。

缺失/不兼容主题保留原身份与参数并提示，按既有最近可用主题 → minimal-fallback 的顺序降级；修复依赖后可重新应用。导入不直接执行主题代码，不包含 AI Key。配置文件总容量和容器格式单独冻结，不能把单主题 ≤64KB 的上限误套给多海报整体配置。

## 11. 版本与迁移

- 包 format 使用语义版本；未知 major 拒绝并提示升级；
- 模板 key 稳定，模板 version 独立；
- 新版模板新增参数使用默认值；
- 删除参数丢弃前生成迁移报告；
- 重命名通过 declarative migration map；
- 未知字段／能力／版本默认拒绝应用并保留原包；只有明确定义且可预览的迁移才转换，不静默丢失作者数据；
- 纯参数/素材包在模板缺失时拒绝并说明依赖；
- 完整模板包可原子安装缺失模板；
- 迁移失败保留旧包、旧实例和原始导入文件。

## 12. 导入安全链

### 12.1 解压前

- 只接受允许扩展；
- 参数文件 ≤64KB；zip ≤20MB；
- 拒绝明显不匹配的 magic/type。

### 12.2 目录安全

- 隔离临时目录；
- 所有规范化路径必须位于目录内；
- 拒绝 symlink/junction/reparse 越界；
- 总文件数 ≤100；
- 解压后总大小 ≤20MB；
- 单文件 ≤5MB；
- 限制压缩比以防压缩炸弹。

### 12.3 内容安全

- JSON/schema 严格解析；
- 图片解码重编码、限制尺寸/像素和输出大小；
- SVG 移除脚本、外部引用、foreignObject 和事件；
- 字体限制类型、大小并拒绝异常表；
- 样式拦截外链和导入；
- 结构拦截脚本节点、嵌入对象和事件属性；
- 本轮不接收可执行代码；声明包不能通过标记“可信”获得代码执行能力。

## 13. 原子安装与卸载

### 13.1 安装

```text
校验全部通过
→ 暂存完整模板和实例
→ 生成 ChangePlan 与权限预览
→ 用户确认
→ 记录旧索引、目录和引用快照
→ 原子发布包文件、索引和实例引用
→ 清理暂存和旧快照
```

任一步失败，回滚目录、索引、实例和海报引用，不留下半安装。

### 13.2 卸载

- 枚举所有 ThemeInstance、Poster 和 preset 引用；
- 预览迁移到默认模板；默认不可用时进入 fallback；
- 同一事务迁移引用并移除包；
- 任一迁移/删除/提交失败，恢复原引用并拒绝卸载；
- 禁止先删文件后修引用。

## 14. 主题错误处理

| 错误 | 处理 |
| --- | --- |
| 包缺失/校验失败 | 拒绝加载，保留旧模板 |
| 参数 schema 错误 | 海报用默认值，控制中心标明参数不可用 |
| 视觉定义部分错误 | 跳过错误部分；超过阈值时回滚上一份有效模板，无有效旧模板时进入 fallback |
| 受保护结构缺失 | 拒绝替换并保留上一份有效模板；无有效旧模板时进入 fallback |
| 素材缺失 | 使用默认/占位并报告 |
| 热切换失败 | 原子恢复旧模板和参数 |
| 磁盘满 | 拒绝安装，不改索引 |
| 连续主题崩溃 | 禁用该主题，提供手动恢复和诊断 |

## 15. AI 产品定位

AI 是软件内置、独立于控制中心的海报创作面板，不是外部AI客户端接入方案，也不是通用AI平台。用户配置API地址、模型和密钥后主动使用；内置会话、创作Skill与受限工具共同辅助设计。模型只参与设计决策，不参与逐帧绘制、拖动或日常热度；无AI时手动创作与海报运行完整可用。

手动编辑与AI草稿共用画板声明、能力目录和应用用例。规则不能仅靠提示词，程序强制执行授权目标、类型／预算、版本、新鲜检查、取消与安全保护。deepseek-harness作为可裁剪组织参考，不整体装载其通用Shell、文件系统或后台任务能力；具体进程／语言选型先测成本。

```text
无 API Key
→ 不初始化 Provider
→ 不启动 Agent 会话
→ 不发送网络请求
→ 手动功能完整

有 API Key
→ 用户主动打开 Agent
→ 请求发往用户选择的服务
→ 模型返回 ChangePlan/Tool Calls
→ 本地校验、预览、确认、执行、撤销
```

## 16. Provider 与设置

提供方可替换，接入用户选定协议和模型，不默认支持所有兼容端点。工具调用、流式和图像能力需逐适配器确认；先交付必要提供方，不初始化未选提供方。

设置字段：

- AI 总开关；
- Provider；
- Base URL；
- Model；
- API Key；
- 测试连接；
- 删除凭据；
- 是否保存本地对话历史；
- 最大输出长度；
- 超时；
- 可选重试上限。

模型名不硬编码长期常量。兼容端点默认 HTTPS；未来本地模型可显式允许 loopback HTTP。

## 17. 凭据安全

- Key 只存 Windows 当前用户范围的安全凭据设施；具体系统 API 或后端由安全架构决定；
- UI 只能读取“已配置/未配置”和脱敏尾部，不能读完整 Key；
- Provider 请求由受信任核心发出；
- Key、Authorization、用户目录和请求正文不进入普通日志、数据库、崩溃报告；
- 删除凭据和卸载清理对应条目；
- 鉴权失败停用当前会话并提示重新配置；
- Agent 不在后台自动联网。

## 18. AI 上下文与隐私

默认只发送：

- 当前选中海报的必要结构与主题参数；
- 匿名Item ID及布局所需摘要；文件显示名仅在任务确需且用户授权后发送；
- 可用工具 schema；
- 完成任务所需的受限模板片段。

默认不发送：

- 快捷方式绝对路径；
- Windows 用户名；
- 游戏安装目录；
- 桌面截图；
- 其他海报内容；
- 恢复账本和保险库路径。

发送图片或更大上下文必须单独说明并确认。

## 19. ChangePlan

用户描述 → 模型生成结构化操作 → 本地验证 → 预览 → 确认策略 → 提交 → 撤销记录。

ChangePlan 至少包含：

- 显式目标海报、基准设计revision、草稿revision和能力目录revision；
- 操作列表及参数；
- 风险等级；
- 影响状态/文件/网络/信任边界；
- 可逆性和撤销方式；
- 预览摘要；
- 需要的用户确认；
- 失败回滚策略。

模型只提议，不能直接执行；风险、可逆性和应用授权由宿主计算，不能接受模型自报。预览绑定候选摘要和版本，修订后失效；提交前再次校验，迟到结果不能覆盖新草稿。

- 预览、应用、撤销。

## 21. 风险分级

| 等级 | 类型 | 示例 | 当前策略 |
| --- | --- | --- | --- |
| R0 | 只读 | 已授权目标、schema、预设 | 请求范围内不逐工具弹确认，不扩大发送范围 |
| R1 | 仅预览 | 草稿、差异、候选预览 | 不逐工具弹确认，不写正式状态 |
| R2 | 可逆设计写入 | 参数、组件、内容槽布局 | 用户预览后一次点击应用；宿主复核并登记撤销；模型不代替确认 |
| R3 | 文件写入 | 导出、替换素材 | 始终显式确认 |
| R4 | 模板/信任边界 | 导入／导出模板或新增信任 | 另行显式授权，不让模型安装代码 |
| R5 | 用户文件/锁定边界 | 收纳、归还、删除真实文件 | 不提供给创作AI；用户原生操作保持既有规则，不增加拖放确认 |

高风险操作不能混入低风险计划后静默执行。可撤销不等于可以免确认。

## 22. AI 主题草稿

开放顺序：参数及组件声明 → 经验证的素材／受控动效 → 自由外形。任意生成代码、通用执行器不属于联合创作闭环。

```text
生成草稿
→ 临时主题区
→ 路径/大小/类型/权限检查
→ 无网络与系统接口
→ 隔离预览
→ 代码差异和视觉对比
→ 用户确认
→ 安装为新版本
```

AI 不得生成后直接执行任意本机代码。真正的图片线稿重绘需要单独图像服务并上传用户选择的图片，不属于首版文本 Agent。

## 23. AI 错误隔离

- 无效参数：拒绝，可要求模型修正一次；
- 未知工具：忽略并提示边界；
- 超时/限流：停止操作，保留输入；
- 截断输出：不安装不完整主题；
- 预览崩溃：终止预览并恢复原主题；
- 网络/Key 不可用：AI 不可用，手动功能继续；
- 关闭 Agent、切换 Provider、退出或卸载取消活动请求；
- AI 错误不能改变海报层级、启动或用户文件。

## 24. 验收标准

### 主题

1. 基础收纳、雨夜书桌体现不同结构；fallback角色独立，不强制标题栏；
2. schema 可自动生成参数面板，越界值被拒绝；
3. 预设、参数、素材、结构覆盖互不污染；
4. 快速切换取最后意图，失败恢复旧模板；
5. 参数保存重启恢复，无回弹；
6. 导入防路径穿越、链接、压缩炸弹和类型攻击；
7. 完整模板包缺任一必需组成即拒绝；
8. 原子安装失败不留半包；
9. 卸载引用迁移失败时模板保留；
10. 模板崩溃进入有限恢复且不影响 Item 启动。

### AI

1. 无 Key 无 Provider 初始化和网络；
2. Key 提交后不得出现在常规 UI 状态快照、数据库、日志和诊断；输入过程的瞬时内存驻留必须最小化并及时清除；
3. Provider 测试连接和结构化参数修改可验证；
4. 所有修改生成 ChangePlan、预览和摘要；
5. 应用由用户动作驱动；素材／模板等额外范围明确授权，创作AI不获得用户文件操作权限；
6. 100 组无效/越界 Tool Calls 无法越权；
7. 主题草稿不能访问文件、网络、进程和通用 IPC；
8. AI 失败不影响海报、启动和手动主题编辑。

## 26. 多实例独立风格与 AI 目标边界

- TemplatePackage 可共享；每张海报拥有独立 ThemeInstance 和参数覆盖。修改共享包时先验证新版本，再按实例应用；一个实例失败不覆盖其余实例的最近可用版本。
- 参数面板按被选海报模板的 schema 生成；同名参数不得串实例。预览只绑定目标草稿，取消不得写回正式状态；批量主题应用显示每张差异和结果。
- 主题既能表现简约文件格，也能表现海报封面、紧凑应用入口；不能仅用换色冒充风格化主题。保留素材槽、结构插槽、Item 模板和热更新要求。
- 内容排序/热度模型与主题解耦：主题不能伪造打开历史、改变文件归属，换皮不自动清除锚定/手动顺序。
- AIChangePlan 必须声明目标 PosterId/ThemeInstanceId、基准版本、参数/布局差异、影响范围和撤销方式；批量操作枚举目标，不把“当前海报”作为执行时可变隐式变量。
- 无关海报在 AI 请求期间发生修改不应被旧全局快照覆盖；被选目标冲突必须重新预览/确认。AI 不新增真实文件移动或删除权限。
- 用户代码主题不在联合创作范围；WinUI样式字典、异常捕获或子进程都不自动构成完整执行沙箱，不能承诺任意C#/DLL代码热加载。
- 桌面宿主、输入边界、菜单命令的权限校验和应用退出由应用拥有；菜单入口与事件绑定属于作品。局部主题真实加载失败可按已定义路径恢复，合法的空绑定不是失败。主进程或系统图形故障属于共享故障，不作虚假完全隔离承诺。
