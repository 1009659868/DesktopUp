# DesktopUP V2 海报视觉与交互规格 V1

状态：`REQUIREMENTS BASELINE — GENERAL CONTENT / MULTI-POSTER USER REVISION 2026-09-07`

最后修订：2026-09-15（DEC-005宏观参数与真实海报定位补充；原标题/空间规则不变）

## 1. 文档职责

本文完整迁移 DesktopUP 海报的画面效果、构图、几何、状态、命中、拖动、缩放、锁定、收起、空状态、错误回退及首发视觉方向。它描述用户必须看到和体验到什么，不规定使用 Web、Qt、Direct2D 或其他渲染技术。

## 2. 设计目标

海报不是普通应用小窗，而是融入 Windows 桌面的通用收纳与展示表面；纵向游戏海报是其中一种模板，不是所有用途的固定比例：

1. 像壁纸的一部分，而不是盖在壁纸上的浏览器或工具框；
2. 信息层级清晰，最常用 Item 能被迅速发现；
3. 视觉覆盖区域可以大，但真正接收输入的区域必须精确；
4. 标题栏位置在收起/展开中保持不动；
5. 透明、圆角、阴影和壁纸混合在所有生命周期阶段保持一致；
6. 主题可以改变风格，不能改变核心命中、权限和状态语义；
7. 正式内容来自 Item 数据，不把 `NIGHT OPS` 六卡片硬编码为产品内容。

## 3. NIGHT OPS 参考构图

`NIGHT OPS` 保留为游戏海报的视觉原型，不是通用文件格的强制标题、装饰、纵向比例或默认内容。通用基础风格参考 DeskBox 常规 Box 的简约密度；具体模板仍由 DesktopUP 自身规格与验收决定。

### 3.1 纵向结构

```text
┌────────────────────────────────┐
│ DESKTOP COLLECTION ───── 01    │  自制标题栏/集合元信息
│                         收起 …  │
│                                │
│ TACTICAL ARCHIVE / 01          │  eyebrow / 分类
│ NIGHT OPS                      │  主标题
│ 06 TITLES · READY              │  数量与状态
│                                │
│ ┌────────┐ ┌────────┐ ┌──────┐ │
│ │   AL   │ │   GS   │ │  IV  │ │  Item 第一行
│ └────────┘ └────────┘ └──────┘ │
│ AFTERLIGHT  GHOST SIGNAL ...   │
│ ┌────────┐ ┌────────┐ ┌──────┐ │
│ │   LO   │ │   SR   │ │  HC  │ │  Item 第二行
│ └────────┘ └────────┘ └──────┘ │
│ LAST ORBIT  SABLE RUN ...      │
│                                │
│                                │  内容扩展/空白区域
│                                │
├────────────────────────────────┤
│ LOCAL LIBRARY       DRAG TO MOVE│  底部状态/装饰
└────────────────────────────────┘
```

### 3.2 构图语义

- 顶部第一行属于受保护标题栏；
- `DESKTOP COLLECTION`、短线和序号形成轻量集合标识；
- 右上采用收起与“…”菜单入口，锁定进入菜单；每个入口命中独立，图形位置与实际命中一致；
- eyebrow、主标题、数量状态形成三层信息层级；
- Item 卡片与文字标签分层，卡片本身是点击目标；
- 下方大面积空白既可作为视觉呼吸区，也必须遵守桌面穿透规则；
- 底部状态栏低对比，不与核心标题争夺焦点；
- 任何主题均可更换文案、装饰和排版，但受保护操作不能消失。

## 4. 视觉层级

海报由五类逻辑层构成：

| 层 | 内容 | 约束 |
| --- | --- | --- |
| 背景层 | 壁纸透出、色罩、渐变、噪点、轻模糊 | 不出现未绘制白/灰背景 |
| 装饰层 | 线条、扫描线、齿孔、铆钉、辉光 | 默认不命中；暂停时可静止 |
| 信息层 | 集合、标题、副标题、数量、状态 | 必须可读；标题栏拖动规则明确 |
| Item 层 | 图标、名称、平台/状态角标 | 卡片命中，间隙按状态穿透 |
| 控制层 | 锁定、收起、菜单、编辑手柄 | 永远位于内容之上；命中不与拖动冲突 |

实现可以把这些层合并绘制，但逻辑职责和命中所有权不能合并。

## 5. 默认几何

### 5.1 初始位置

- 主显示器工作区右侧；
- `top-right` 锚点；
- 与工作区顶部、右侧和底部保留安全边距；
- 不覆盖任务栏；
- 初次显示为展开、解锁、静态。

### 5.2 尺寸

| 参数 | 默认/范围 |
| --- | --- |
| 默认宽度 | `max(work_area_width × 0.22, 280px)` |
| 最小宽度 | 240px |
| 最大宽度 | 工作区宽度 45% |
| 默认高度 | 工作区高度减去上下安全边距 |
| 最小展开高度 | 240px，且必须容纳受保护标题/菜单及可操作内容视口；允许部分行连续裁剪，所有 Item 通过滚动可达 |
| 最大展开高度 | 工作区高度减去安全边距 |
| 收起高度 | 固定约 60 DIP；只随系统 DPI 投影，不随海报宽度或展开高度改变 |

### 5.3 响应式级别

| 宽度 | 行为 |
| --- | --- |
| ≥360px | 完整标题、装饰、Item 标签和状态栏；布局按固定内容参数换列/换行 |
| 280–359px | 保持标题、按钮和 Item 参数；隐藏次要装饰，布局可减少列数或分页 |
| 240–279px | 最小安全构图；装饰基本关闭；内容可单列并分页/滚动 |
| <240px | 不允许提交 |

### 5.4 外框、内容参数与排版分权

用户于 2026-08-28 正式采用以下模型：

1. `FrameGeometry` 只决定海报位置、外框宽高、锚点、锁定和收起状态；
2. 标题字号、Item 基准尺寸、图标尺寸、间距和密度属于独立 `ContentMetrics`，由主题、控制中心或后续 Item 布局设置修改；
3. 拖动外框边缘只改变内容视口和可用布局约束，不得隐式改写 `ContentMetrics`，不得因为海报变宽就整体放大标题、卡片或页脚；
4. 系统 DPI 是设备投影比例，不属于用户内容参数；DPI 改变可以等比投影内容，但同一 DPI 下的外框 resize 不改变内容尺寸；
5. `ResponsiveLayout` 只负责固定内容参数下的换列、换行、分页/滚动和视口容量；
6. 空间不足时，Item 可以在内容 viewport 的上/下边缘连续裁切；这种裁切只代表滚动位置，不得让 Item 越界压住标题栏/按钮/页脚，也不得让 viewport 外像素接收输入。所有 Item 必须保留在布局结果中，并通过连续滚动或分页提供可达路径；
7. 背景、材质和边缘装饰可以随外框伸展；标题栏按钮继续锚定外框右上角，页脚继续锚定外框底边；
8. 活跃度造成的 Item 动态缩放是独立业务参数，不能复用外框宽高作为缩放输入。

2026-09-15 V2-DEC-005补充：当前海报的宏观内容尺度与疏密通过控制中心滑块调整；基准度量、用户偏好、每Item热度层级和视口约束分开，不能因UI简化退回永久等尺寸模型。详见[Item§10.3](CONTENT_ITEM_ACTIVITY_LAYOUT_V1.md#103-宏观偏好与热度分层2026-09-15)。控制中心选择/定位仅触发短时轻量描边，不抬层、不抢焦点、不展开/移位、不改命中与持久状态；交互/资源边界见[运行表面§5](RUNTIME_SURFACES_AND_TRAY_V1.md)。本补充是设计目标，非现有描边实现证据。

## 6. 几何行为

- USING + unlocked：只允许从标题栏有效拖动区移动；
- EDITING + EXPANDED + unlocked：允许标题栏和非 Item 编辑区域移动海报；
- 编辑态四边及四角允许改变尺寸（同步已接受的V3四边拖缩行为）；
- 右下角缩放固定左上角；
- 收起态不显示缩放手柄；
- 锁定后所有移动与缩放入口禁用；
- 指针移动未达 5px 视为点击，达到或超过 5px 才进入拖动；
- 拖动中视觉位置可实时跟随，提交应合并高频事件；
- 提交失败回到最近接受的几何，并显示可行动提示；
- 工作区改变时重新约束到可见区域，不因为锁定留在屏幕外。

## 7. 收起与展开

### 7.1 不变量

收起不是将海报向中间折叠，也不是重新居中：

- 下方空间足够时标题栏顶部坐标保持不变；不足时标题栏可向上移动，规则见下方“边界展开”；
- 水平坐标和宽度保持不变；
- 常规收起减少底部高度；边界展开后的收起需恢复有效收起锚点，不强制只沿底边收缩；
- 展开优先恢复保存的完整高度；全部完整尺寸候选不可行后才允许本次临时缩减可见高度，规则见§7.5，保存的高度不变；
- 按钮相对标题栏的位置保持不变；标题栏因边界展开移动时按钮及命中区域必须同步移动；
- 收起后 Item 不可见、不命中；
- 收起态仍可拖动标题栏（未锁定时）、切换锁定和展开。

### 7.2 过渡

2026-09-10用户优先级修订：下列两项由[统一索引§4](REQUIREMENTS_RISKS_AND_OPEN_QUESTIONS.md#4-明确暂缓范围)的V2-DEFER-005/006按需保留，不作为近期自动收展/内容主线前置；其余已明确安全与交互规则不取消。

- 高度建议 250ms `ease-out`；
- Item 区展开延迟约 100ms 淡入；收起立即淡出；
- 标题栏不缩放、不闪烁；正常向下展开时不位移，边界展开时连续向上移动，不能以瞬间跳位替代过渡；
- 快速点击 300ms 内合并，最后意图获胜；
- 系统减少动态或手动暂停时可直接切换，无动画。

### 7.3 自动收起

2026-09-10用户明确：以下指针与计时驱动行为属于必要能力（统一索引V2-DEC-001），不能由配置开关存在或System来源不抖替代。2026-09-11用户确认V2-TBD-017：手动收起且鼠标仍停留时保持收起，必须真正离开后再进入才自动展开；静止鼠标下的程序边界变化不能解除抑制。

边界展开与推动规则同样适用于已启用的自动收展；活动拖动/菜单期间不得插入另一轮推让。

2026-09-14用户确认V2-DEC-003（替代旧“拖动中继续增长”默认行为）：悬停正常展开；标题空白按下立即暂停整组动画并固定抓取点，移动达到既有5px阈值才确认拖动，不加长按计时；未拖动的有效释放快速展开，只展开不切换收起。按下时仍收起、尚未完全展开或正在收起，均采用收起态拖动：位置立即跟手、内容并行快速收拢，不恢复旧坐标；按下时已完全展开则保持展开拖动。分类按按下帧固定，不随等待时间改变。收起态拖动结束后保持收起，真正离开再进入才重新自动展开，显式标题点击仍可快展。按钮/菜单/Item不混用此手势。

优先级仍为安全约束→手动跟手→自动辅助（V2-TBD-018）；源与邻居复用同一空间求解、R4组提交/恢复及权威事务。快展只跳过剩余动画，不跳过空间校验或单独提交源。细化合同及待验矩阵见[标题交互合同](../40_Implementation/V3-04/M08_TITLE_INTERACTION_CONTRACT.md)；这是冻结目标，不代表生产已接入。

- 默认关闭；
- 可配置 1–300 秒，默认 3 秒；
- 离开热区后开始计时，进入热区展开；
- 编辑态暂停计时；
- 控制中心打开不应强制收起或展开；
- 系统暂停恢复后按当前指针与上次呈现状态重新判定，不补播动画。

### 7.4 边界展开补充（2026-09-07）

- 保留收起前配置的完整展开高度与宽度；不能仅因靠近底部就缩小海报，应先换方向或组合上下空间。临时缩减仅在§7.5完整方案都不可行后允许，内容参数始终不缩小。
- 下方空间足够：保持标题栏位置，向下展开。
- 收起态已贴工作区底部：保持底边，标题栏直接向上，直到恢复原展开高度；标题栏始终位于展开海报顶部，不翻转内容。
- 下方仍有合法空间但不足（包含邻居阻挡场景）：先保持顶部向下利用可用空间及合法推让余量；再固定求得的底边，让标题栏向上补足。两个阶段必须连续。下方容量为零才纯向上；不得因为上方单独足够而跳过下方空间。失败候选只预计算，不实际挤压后回滚。
- 边界按可用桌面工作区解释，不能侵入任务栏/AppBar 来凑高度。原高度大于工作区或全部完整尺寸方向均被阻挡时，转入§7.5临时可用高度判断，不能改写原高度或靠重叠伪装成功。
- “完整内容”指内容保留、参数不缩小且所有Item可滚动访问；完整尺寸模式还要求恢复保存的高度，临时受限模式不冒称完整尺寸成功。不保证无限Item一次可见。

### 7.5 邻居阻挡、临时展开与无空间提示（2026-09-08 用户确认）

1. 完整尺寸优先，路径始终先下后上：先求下方合法容量（空隙及必要推让余量），再在同一场景中向上补足；下方容量为零才纯向上。B贴底不可推时仍先利用A与B间空隙，不能直接拒绝，也不能跳过空隙直接纯上扩。所有候选先完整求解，失败候选不移动任何海报。
2. 所有完整方案失败后，采用剩余合法空间中的最大可用高度，前提是能容纳“完整标题区域＋一行完整Item＋必要页脚”。保留宽度、字号、Item/图标尺寸和间距；仅减小可见视口，内容仍连续滚动。
3. 最小高度包含标题区域/固定说明等非滚动占位、一行Item的卡片或图标与标签、必要页脚及实际间距。不使用与内容无关的固定数值；没有Item时仍用当前模板的一行占位要求，不能因计数为零把最小值算成零。
4. 临时高度不写回保存的展开高度、归一化尺寸意图或便携配置；下次展开按当时环境重新优先尝试完整高度，不自动放大标题或Item。用户显式尺寸编辑与本次自适应不同，需走原编辑命令。
5. 连最小可用高度也放不下时保持收起，邻居保持原位，无部分推让/布局写入；展开按钮轻微短促抖动，不能整张海报抖动、抬层、改变窗口/输入岛几何或弹阻断对话框。重复点击合并提示，减少动效时用短暂静态强调替代。
6. 点击中心中的展开入口同样获得明确“空间不足”反馈，不以无响应伪装命令成功；无空间与状态过期/宿主失效等错误区分。自动收展沿用可行性判断，但不因轮询反复播放抖动。
7. 自适应后收起仍复用有效收起锚点和同步条件归位；不能剥夺锁定、二次调整与安全回程保护。

## 8. 标题栏

标题栏是海报自制视觉，不使用 Windows 原生 caption。

### 8.1 必需信息

- 海报/集合标题或模板标识；
- Item 数量；
- 收起/展开；
- 更多菜单中的锁定/解锁；
- 必需更多菜单入口；可选状态提示。

### 8.2 命中

- 空白区域可拖动；
- 标题文字是否可拖动由模板声明，但必须保持一致；
- 收起态标题文字可作为展开入口；
- 按钮、链接、输入框、菜单和 Item 不能启动拖动；
- 锁定后空白也不能拖动；
- 按钮至少有正常、悬浮、按下、禁用和键盘焦点状态；
- 可见图标与实际命中范围一致，不允许小图标大面积截获空白。

### 8.3 删除海报确认

每张海报右上角“...”包含“删除海报”，与控制中心目标删除使用同一确认语义。提示具体名称、布局/独立设置移除、真实内容不删除和受管内容保留入口；最后一张提示托盘仍运行。默认取消，关闭或取消不改变海报。确认控件有清晰焦点/键盘路径，点击不触发拖动、收起或 Item 启动。模板不能隐藏该受保护管理入口，锁定也不省略确认。

## 9. Item 卡片

### 9.1 内容

- 图标或首字母占位；
- 显示名；
- 可选平台、序号、启动次数、固定标记、临时活跃提升标记和失效警告；
- 文本超长时单行省略，完整名称通过 tooltip/辅助信息提供。

### 9.2 使用态

- 游戏/启动器预设单击产生一次启动意图；通用文件格的选择/打开手势在 V3-05-06 冻结，见 V2-TBD-013；
- 双击不得重复启动；
- 右键显示 Item 菜单；
- 悬浮可显示边框、统计或状态；
- Item 之外的视觉空白不应因卡片容器过大而截获桌面输入。

### 9.3 编辑态

- 单击选择，不立即启动；
- 拖动按全自动/锚定+自动/全手动模式解释；
- 拖动时原位保留半透明占位，目标位置显示插入线；
- 锚定标记使用低干扰浅金图钉；
- 失效 Item 仍可选择、移除或查看诊断。

## 10. 桌面穿透与命中区域

### 10.1 USING

- 标题栏受保护区域和 Item 卡片命中；
- 卡片之间、卡片下方、装饰层、视觉透明背景穿透；
- 空白左键拖动产生桌面框选；
- 空白右键显示 Windows 桌面菜单；
- 覆盖范围内原生快捷方式可单击/双击；
- 海报右键菜单只能从明确的非穿透海报区域打开。

### 10.2 EDITING

- 海报编辑区域可临时接收移动/缩放输入；
- Item 仍有独立命中；
- 控制中心应明确显示编辑态，避免用户误以为桌面失效；
- 退出编辑后立即恢复 USING 穿透矩阵；
- 锁定海报即使处于全局编辑态，也保持不可移动/缩放。

### 10.3 区域表达要求

宿主应能表达零、一、多和重叠输入矩形：

- 零区域 = 全穿透；
- 一区域 = 只有一个有效控件/标题栏；
- 多区域 = 标题栏、按钮和多 Item；
- 重叠区域 = 合并后不能形成额外不可见遮挡；
- 这里的“多”是输入区域数量，不代表多海报能力。

## 11. 正交状态的视觉反馈

### 11.1 USING → EDITING

- 手柄 150ms 淡入；
- 四角锚点 200ms 淡入；

- 可拖 Item 增加轻阴影；

### 11.2 锁定

- 全局编辑态下可用低干扰虚线提示此海报已锁；
- 视觉提示不能暗示 Item 不可启动。

### 11.3 PAUSED

- 保留最后静态画面；
- 可以略降不透明度并显示暂停原因；
- 不循环闪烁；
- 手动暂停动态效果不禁用按钮；系统级暂停才禁用输入。

- 视觉范围默认 50%–300%，但布局必须限制极端尺寸占用；
- 新 Item 无数据时约 150%；
- 大 Item 不能覆盖标题栏、控制按钮或越出海报；
- 大小变化使用 400ms 轻弹性曲线；
- 排名改变不一定立即改变位置，避免刚点击就跳动；
- 暂停、系统减少动态和低性能模式使用无动画切换；
- 缩放卡片的文字、图标和命中区必须保持一致，不出现视觉与点击范围错位。

## 17. 错误与 fallback

- 当前模板视觉或结构失败：优先保留/回滚上一份已验证可用模板；
- 不存在有效旧模板时才显示 `minimal-fallback` 受保护最小结构，并保留标题、Item、锁定、收起和启动；
- 图标失败：首字母占位；
- 数据失败：显示“海报数据异常”和恢复入口，不静默重置；
- fallback 不作为正常模板、不写回用户选择；
- 错误标记低干扰但可发现，详细诊断在控制中心/托盘；
- 重复渲染失败停止无限重试，提供手动重连。

## 18. 验收矩阵

1. 冷启动首次画面无白条、灰框、裁切和未绘制背景；
2. 主屏中部拖动/松开至少 20 次画面一致；
3. 收起/展开至少 20 次：空间足够时顶部不动；贴底时向上，部分空间时先下后上；恢复原展开高度，按钮与标题栏同步；
4. 控制中心打开关闭 20 轮，海报视觉与层级不变；
5. USING 空白框选、右键和桌面图标通过；
6. Item 卡片、标题按钮和菜单命中通过；
7. 编辑态连续拖动三次、连续缩放两次，退出后恢复穿透；
8. 锁定后移动/缩放无效，启动和收起/展开仍有效；
9. 键盘 Win+D、任务栏“显示桌面”和触控板手势各 10 轮，海报全程连续可见，无隐藏、掉层、重挂或置顶闪烁；
10. Explorer 恢复、暂停、显隐和退出无闪烁/置顶；
11. 零/一/多/失效/超长名称/缺图标 Item 视觉通过；
12. 240px、280px、360px、默认宽度、宽扁和窄高尺寸通过；外框 resize 不改变内容参数，只重排 Item；连续跨越列数边界不得丢失鼠标捕获，Item 在 viewport 边缘连续裁切且不会整排跳失，所有 Item 可经分页/滚动访问，并具备不依赖可见 Item 的滚动入口，且无 Item/页脚重叠或 viewport 外命中；
13. 默认、Neon、Cinema 和 fallback 的受保护交互语义一致。

## 20. 多海报风格、非重叠布局与输入

- 同屏允许简约文件格、游戏海报、紧凑应用入口等不同模板；默认几何表保留为游戏参考预设，不强制每张占据主屏右侧或使用全高外框。新海报需有可见初始位置，不能全部重叠到同一点。
- 宿主只固定受保护 chrome 与操作能力；主题决定信息层级、标题是否突出、素材、卡片/图标样式、背景和动画，不能删除收起、菜单、错误恢复与必要命中入口。
- 通用基础样式需交付可对照的规格：标题与菜单对齐、常规/紧凑密度、图标与标签尺寸、长名截断及完整名提示、选择/悬停/拖放目标态、滚动条、空状态和失效状态。不得把“像 DeskBox”作为唯一验收描述。
- 多选、Ctrl/Shift 扩选、拖出及上下文菜单与海报整体拖动区分；具体打开手势在内容交互门冻结，禁止同时触发选择、打开和搬运。
- 每张先沿用外框/内容参数/响应式排版分离合同；热度改变单个 Item 的呈现尺寸，不把整张海报连带缩放。
- 多海报正常布局不允许外框相交，不能以“前移/后移”或将展开海报盖到其他海报上解决空间冲突。内部层序仅用于受保护临时表面及异常重叠防御；鼠标交互不把海报提升到普通程序之前。旧库/异常注入重叠仍需安全命中，不代表允许用户创建重叠布局。
- 编辑态输入保护只作用目标海报；跨窗口 capture 取消、删除目标、切换主题和系统恢复均需取消/提交手势，不留下覆盖全桌面的输入层。
- 三种用途并排、碰撞接触、连锁推动时验证无白条/灰底、标题命中正确、所有内容可达、透明空白桌面操作正常；重叠仅作为历史/故障注入输入案例。主题样式验收与原生层级验收分开记录。

### 20.1 碰撞、推让与条件归位（用户确认）

2026-09-09动画补充：收展、推动和归位的中间过程应避免明显跳变与新增空隙；像素跳变上限、帧节奏等动画参数应可由配置文件在启动时调整。当前阶段不要求控制中心编辑或热更新；动画参数不得改变碰撞、锁定和完整归位资格。

- 海报之间不能重叠；拖动时存在碰撞，不得通过高速指针移动穿过另一张海报。编辑缩放、收展、中心几何编辑、新建和恢复同样必须遵守空间约束。
- 收起/展开可以推动其他海报；涉及多张时整体结果必须有效，不能一半海报已移动而另一半提交失败。
- 已锁定海报不允许被其他海报推动，是固定障碍；锁定仍不取消该海报自身已有的收起/展开功能。自身收展导致的必要边界位移不能被误认为其他海报对它的被动推动。
- 被推动的海报在未被用户重新摆放/缩放或改变锁定、显隐等归位资格、且归位仍安全时，随源海报收起条件归位。2026-09-09补充：自身收展或再次被系统推动不等于人工重定位；保留其当前姿态，协调链、分支、合流与反向影响，而非恢复历史完整外框。删除、环境变化与后续障碍不能被旧位置覆盖；无法完整归位则原地不动，不部分回收、不推动无关海报，可安全归位的其他分支独立判定。
- 2026-09-08明确：条件归位在源收起过程中同步跟随释放的空间，不能等源完全收起后再补一段归位动画。两张均收起时B展开推动A，再收起B，应看到A随B的回退边界连续归位，不形成额外拉大的空挡，也不提前重叠；连锁参与者采用同一规则，锁定/二次调整/路径安全限制不变。
- 视觉透明空白仍参与海报外框碰撞，不因透明而允许另一张海报穿入；这不改变空白对 Windows 原生图标/桌面输入的穿透。装饰阴影不作为独立实体障碍。
- 缩放只约束用户正在改变的外框，不通过偷偷缩小相邻海报解决冲突；不能为了排布去移动 Windows 原生桌面图标、壁纸或普通程序。
