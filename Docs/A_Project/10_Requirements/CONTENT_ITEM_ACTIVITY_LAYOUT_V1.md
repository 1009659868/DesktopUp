# DesktopUP V2 内容 Item、活跃度与动态排版模型 V1

状态：`REQUIREMENTS BASELINE — GENERAL CONTENT / MULTI-POSTER USER REVISION 2026-09-07`

最后对齐：2026-10-23。单一归属、连续尺寸及已验入口按后续用户决定更新；真实热度仍未实施。公式矛盾和默认值待决，不把需求基线当已上线功能；实施状态见[当前状态](../../00_Catalog/CURRENT_STATUS.md)。

## 1. 文档职责

本文完整定义正式 Item 如何进入海报、如何保存启动语义、如何记录活跃度、如何计算排序和视觉大小、如何进行弹性排布、锚定、人工排序、跳变、空状态和错误处理。

本文是产品与算法需求，不规定数据库库、UI 框架或渲染 API。所有公式都必须在实现前形成可重复性质测试；本文件明确标记旧公式中尚需校正的矛盾。

## 2. 当前原型与正式能力边界

早期`NIGHT OPS`的AL、GS、IV、LO、SR、HC六卡是历史夹具，不进入正式首启。当前已接真实内容，新配置零海报；以下模型字段同时包含尚未接入的热度需求，不代表统计已运行。

正式 Item 能力必须满足：

- 数据来自应用自有仓库快照；
- 零、一、多、重复、失效、缺图标和超长名称均可表达；
- 卡片显示与启动语义来自数据，不写死在模板；
- 海报重启、控制中心重开和主题切换不丢 Item；
- 演示目录不在正式运行路径；
- 初期使用隔离夹具验证，不扫描或移动用户桌面。

## 3. 领域模型

```text
PosterTemplate ─→ ThemeInstance ─→ Poster ─→ PosterItem ←─ CollectionItem
                                            │                    │
                                       PinnedRelation        LaunchHistory
                                                                 │
                                                         ManagedShortcut（后续）
```

### 3.1 CollectionItem

| 类别 | 字段/语义 |
| --- | --- |
| 身份 | 稳定 `id`；路径不能作为唯一身份 |
| 类型 | `file`、`folder`、`shortcut`、`application`、`shell-item`；`game` 是用途标签/应用特例，不再限制集合类型 |
| 显示 | `display_name`、标签、图标来源、可选平台信息 |
| 来源 | `lnk`、`url`、`exe`、`manual` 和稳定 source identity |
| 启动 | target、arguments、working directory、Shell/协议语义 |
| 有效性 | valid、missing、parse_failed、restricted_protocol 等结构化状态 |
| 托管 | 可选 managed shortcut 关系；仅安全收纳后存在 |
| 统计 | total launches、last launched、有限 launch history、added at |
| 跳变 | 可选 burst score、激活时间、参照项、之后真实启动次数 |
| 审计 | created/updated、最近错误、数据来源版本 |

### 3.2 PosterItem

表达 Item 在某张海报中的关系：

- `poster_id`；
- `item_id`；
- `order_key`；
- `pinned`/锚定关系；
- 可选 `page` 与 `local_position`；
- created/updated；
- 当前布局模式不应复制到每个 Item。

DEC-047替代旧共享规则：同一有效对象只允许一个可见海报引用。多海报仍独立管理，跨海报是转移归属而不是新增共享卡片；物理受管集合共用不等于同一对象重复展示。

DEC-037补充：用户替换图标属于当前PosterItem的独立外观，不修改真实内容路径/打开语义，也不改原文件或快捷方式。未指定时使用来源默认图标；“构造卡片”按用户决定延期，不作为已完成的更换图标入口。实现阶段见[工作流§6.4](../30_Plans/V3_GENERAL_CONTENT_MULTI_POSTER_WORKFLOW_V1.md#64-卡片独立图标与构造入口下一步)。

### 3.3 PinnedRelation

至少包含：稳定 ID、poster/item、1-based `pinned_index`、时间和来源 `user|agent`。

- 两项争同一序号时，后固定项稳定偏移到下一空位；
- Item 暂时失效时锚定记录可保留并由自动项填空；
- 默认不自动清理失效 Item 的锚定记录；清理只能由用户显式确认，必须可审计、可撤销，并保留原 Item 诊断信息；
- AI 锚定必须经过与手动操作相同的命令和撤销链。

### 3.4 LaunchHistory

不是必须独立成表，但语义必须存在：

- 累计有效启动次数；
- 最近一次有效启动时间；
- 最近 N 次时间戳，建议默认最多 50 条；
- 启动失败是否计入由 Item 启动产品/架构契约冻结，不能由 UI 猜测；
- 原始真实统计不能被排序刷新或 AI 修改伪造。

## 4. Item 身份、去重与失效

### 4.1 身份

稳定身份可组合来源类型、Shell 解析结果、目标、参数、工作目录和内容指纹。路径变化后仍应有机会识别同一 Item。

### 4.2 去重提示

写入前至少检查：

- 同源路径；
- 同解析目标与参数；
- 同来源身份；
- 同内容指纹；
- 已存在但失效的 Item。

冲突不静默覆盖。用户可以复用现有 Item、创建独立条目、跳过或修复。

### 4.3 失效

- 加载时不静默删除；
- 海报显示警告状态；
- 提供查看属性、重新定位、刷新、从海报移除和从库删除的不同操作；
- 从海报移除只删除关系，不默认删除 CollectionItem；
- 删除仅添加 Item 不触碰源文件；
- 删除托管 Item 必须先处理恢复账本。

## 5. 主动发现与添加

### 5.1 入口

1. 拖入常规桌面内容：应用/游戏入口、快捷方式、普通文件、文件夹、可解析的 Shell 项目；
2. 用户点击扫描桌面，并选择当前用户桌面、公共桌面或两者。

应用冷启动不静默扫描。扫描后台执行、可取消、有数量和耗时上限。

### 5.2 类型边界

| 类型 | 仅添加 | 安全收纳 |
| --- | --- | --- |
| `.lnk` | 保留 Shell target、arguments、working directory、IconLocation | 只可移动 `.lnk` 本身 |
| `.url` | 校验协议白名单并保留 URL 语义 | 只可移动 `.url` 本身 |
| `.exe` | 登记启动目标和元数据 | 禁止移动、复制或修改 |

旧表中的 `.exe` 表示应用启动入口：默认只引用，不搬动已安装应用、游戏本体或平台目录。普通用户文件和文件夹的显式复制/移动已进入范围，按下方通用矩阵和事务安全门处理。

### 5.3 预览

每项显示：名称、类型、来源、解析目标、参数、工作目录、图标、有效性、协议限制、冲突和实际动作。用户可以逐项取消，并明确选择仅添加或安全收纳。

## 6. 启动与统计

### 6.1 启动语义

- 使用 Windows/Shell 等价语义保留快捷方式行为；
- 不能只对 target 路径做不完整启动；
- `.url` 只允许白名单协议；
- DEC-023当前基线：单击选择、双击或有效Enter打开、按住移动即拖；不要求先进入整理态；
- DEC-037澄清：Ctrl/Shift形成的选择集合无论一项/多项均描边，日常普通点击与双击启动不描边；缩放锚点只在编辑模式出现。真实Item无底板，图标按比例占满可用图片区，不占名称区；不改变跨度或命中；
- 一次打开手势最多产生一次有效打开和一次统计，拖动释放不追加打开；
- 旧游戏单击启动预设及EDITING/USING仅保留兼容评审，不覆盖当前基线或静默迁移旧配置；
- 单击和双击检测不得重复启动；
- 错误结构化返回，不让海报崩溃。

### 6.2 统计时点

DEC-034已确认：可信提供方明确证明打开请求成功交接才计一次，不要求外部程序加载完成。排队、修复/选择窗口、Handled、失败/取消不计；原生调用开始后的取消请求不等于终止，后续实际成功交接仍可产生事实。ActivationId幂等，事实与统计将同事务消费；[V3-05-01](../40_Implementation/V3-05/CONTENT_ENTITY_AND_OPEN_CONTRACT.md#4-打开请求与成功事实)已做纯合同验证，生产Shell及真实热度仍待接入。

更新至少包括：

- `total_launches += 1`；
- `last_launched_at = now`；
- 追加有限历史；
- 标记对应海报需要在下次展开重评；
- 不在用户刚点击后立即重排画面。

## 7. 排名模型

### 7.1 目标

- 近期使用优先；
- 长期真实高频具有稳定性；
- 新 Item 有曝光机会；
- 长期未使用逐步下降但不消失；
- 结果可解释、确定、可测试；
- 用户人工意图高于自动算法。

### 7.2 基础公式

```text
rank_score = 0.40 × recency_norm
           + 0.35 × frequency_norm
           + 0.25 × newness_norm
```

| 因子 | 权重 | 意图 |
| --- | --- | --- |
| recency | 0.40 | 最近玩过最可能再次启动 |
| frequency | 0.35 | 长期真实使用形成稳定热度 |
| newness | 0.25 | 新内容不会刚加入就沉底 |

### 7.3 归一化

```text
recency_norm = 1 - min(hours_since_last_launch / 168, 1)

frequency_norm = log(1 + effective_launches)
               / log(1 + max_effective_launches_in_poster)

newness_norm = 1 - min(days_since_added
               / max(1, max_days_since_added_in_poster), 1)
```

边界：

- 从未启动：recency = 0；
- 全部 Item 有效次数为 0：frequency 全部为 0，禁止除零；
- 海报只有一个 Item：max age 与 max launches 使用安全分母；
- 时间倒退/时钟异常：钳制到合法范围并记录诊断；
- 同分排序依次使用 pinned、旧 order key、added_at、稳定 ID，保证结果不抖动。

## 8. 有效启动次数与衰减

### 8.1 产品语义

- 新加入 30 天内具有衰减保护；
- 启动次数越多，越能抵抗时间衰减；
- 最近 14 天不惩罚；之后每 7 天逐步下降；
- 有效次数不低于真实累计次数的一定比例，旧设计为 10%；
- 刷新活跃度不能伪造真实启动次数。

### 8.2 旧提案公式

```text
effective_launches = total_launches × decay_multiplier

decay_multiplier = clamp(
  existence_bonus × frequency_resistance × inactivity_penalty,
  0.1,
  1.0
)

frequency_resistance = min(1,
  log(1 + total_launches) / log(1 + 50))

inactivity_penalty = 0.85 ^
  (max(0, days_since_last_launch - 14) / 7)
```

### 8.3 必须校正的矛盾

旧文档同时声明“30 天内完全免疫衰减”，又把 existence、frequency 和 inactivity 直接相乘。对于新加入且启动次数少的 Item，frequency resistance 小于 1，会破坏“完全免疫”。V2 不得照抄这个矛盾。

实现前必须在以下候选中形成决策并用性质测试证明：

1. 30 天内强制 multiplier = 1，30 天后才进入复合衰减；
2. existence protection 作为对复合衰减结果的下限，而不是乘数；
3. 使用可解释的加权/分段模型替代三个乘数。

无论选哪种，必须满足：30 天内不因低次数被额外惩罚、长期高频下降慢、长期低频下降快、结果连续、单调、有 10% 下限。

### 8.4 旧样例性质

- 新加入 3 天、2 次、昨天启动：不衰减；
- 存在 90 天、80 次、昨天启动：高抵抗，接近不衰减；
- 存在 90 天、80 次、50 天未启动：明显下降但不触底；
- 存在 90 天、3 次、50 天未启动：接近 10% 下限。

这些是产品性质，不强制绑定旧公式。

## 9. 刷新节奏

| 触发 | 行为 |
| --- | --- |
| 冷启动 | 首屏后延迟计算，建议 3 秒内完成，不阻塞海报 |
| 启动后 | 更新统计并标记待重排，不立即移动卡片 |
| 海报展开 | 有待重排标记时重新计算 |
| 手动刷新单项 | 重评时间因子，不修改真实次数 |
| 手动刷新全部 | 批量重评，显示摘要 |
| 后台定时 | 默认无高频计时器；如未来增加必须事件稀疏且可关闭 |

## 10. 动态缩放

### 10.1 基础对数映射

```text
ratio = log(1 + launches) / log(1 + max_launches_in_poster)
scale = min_scale + (max_scale - min_scale) × ratio
```

- 默认最小 50%、最大 300%、无数据默认 150%；
- 全部次数为 0 时所有 Item 使用 default scale；
- 排名使用 effective launches，视觉尺寸应使用更温和的输入；
- 旧提案使用 `sqrt(effective × max)` 后再对数压缩，可作为候选；
- 旧稿要求3–5个肉眼可辨层级；2026-10-21依据用户已验连续尺寸决定，真实热度改为可常驻的小数尺寸，不按固定档位跳变。避免统计更新导致画面跳动由发布时机和稳定映射处理，不靠整数化；
- 卡片视觉、布局占位和命中尺寸一致。

2026-10-21准备核对：宏观0.4～3与单项小数尺寸底座已验，旧注入热度代码仍为五档，不等于真实热度完成。上述50%～300%/150%基线、连续曲线及宏观尺度合成须在生产接入前对齐，旧衰减矛盾仍OPEN；[主计划第7.1节](../30_Plans/V3_GENERAL_CONTENT_MULTI_POSTER_WORKFLOW_V1.md#71-2026-10-21-真实热度准备未实施)区分现状、待实现与待决规则。本次未修改代码或擅自冻结公式。

### 10.2 用户参数

- min scale；
- max scale；
- default scale；
- curve：log/linear/rank；
- decay preset：支持命名预设与关闭选项；具体档位、天数和语义在权威衰减公式冻结后定义，不预先绑定 7/14/30；
- 动态缩放开关。

所有修改即时预览、保存后持久化、可撤销。

### 10.3 宏观偏好与热度分层（2026-09-15）

[V2-DEC-005](REQUIREMENTS_RISKS_AND_OPEN_QUESTIONS.md)补充：控制中心的“整体内容大小/疏密”作用于当前选中海报，不是全局批量，也不是逐Item手填尺寸。

- 整体内容尺度调整共同基准，热度仍决定Item之间的相对尺寸层级和排序；扩大基准不抹平冷热差异。不能把宏观滑块直接写成热度分数或同时改min/max/default的旧业务语义。
- 疏密主要调整间距、内边距和留白，不隐式改图标基准、热度排序或自动/锚定/手动模式；空间不足依赖换行与滚动，不偷偷缩小到刚好装满。
- 卡片、图标、标签可读性、布局占位和命中几何统一协调；不能只缩放图片而保留不匹配的占位或点击框。外框resize仍只改视口。
- UI采用带命名预设节点的滑块，节点可点、节点间可细调；数值/曲线在实现前验证。常用设置即时反馈，结束编辑自动持久化，不要求再点应用；失败与取消临时预览遵循运行表面§5。
- 保存语义值、作用域及映射/schema版本，不只保存节点序号；每海报独立并可纳入后续便携配置。
- 初版等尺寸网格可以继续使用，但布局输入须支持异尺寸结果、稳定ID和模式；先以纯夹具验证接口，不提前实现完整热度模型。§8公式待决和§9交互期间延后重排要求均保留。

设计与兼容边界见[控制中心可用性设计§3](../20_Architecture/CONTROL_CENTER_USABILITY_DESIGN_V1.md#3-宏观偏好与热度排版的接口)。

## 11. 基础布局

### 11.1 首个可用布局

确定性网格是最早可交付布局：稳定顺序、响应式列数、Item 不重叠、空间不足分页/滚动。它不依赖活跃度算法即可使用。

外框 resize 只改变 `container width/height`，不得改写 Item 基准尺寸、标题参数、图标尺寸或主题密度。布局引擎可以在相同内容参数下换列、换行、分页或滚动；只有控制中心/主题参数、活动度缩放或显式布局命令可以改变内容尺寸。

当前视口绘制每个 Item 与 viewport 的可见交集，并只为该交集启用命中；Item 在 viewport 上/下边缘必须连续进入或退出，不得按完整行突然消失。全部 Item 的布局结果和排序身份始终保留，并且必须存在连续滚动、分页或独立滚动控件的可达路径，不能因 frame resize 被静默删除。

### 11.1.1 单轴响应挤压（V2-DEC-011，2026-09-23用户补充）

纵向浏览缩窄外框，只触发内部换行，不缩小Item、不横向裁切或隐藏；内容区最小宽度由最大Item实际占位宽决定。到该边界时，一行一个Item单列竖排。横向对称：缩高换列，内容区最小高度由最大Item实际占位高决定，一列一个Item单行横排。外框再计入对应轴必要padding、边框/chrome和滚动条占位。Item大小指完整必要占位，不仅是图标位图。

2026-09-23用户进一步说明：“由大到小”是在默认热度自动排序下自然产生的排列，不是按当前像素面积重排。有图钉时遵循其约束，可出现小Item在大Item前；关闭自动排序则保留所选模式的顺序。顺序先由排名/人工/图钉确定，尺寸与布局再分别求解；resize只换行/列，不改变有效顺序、pinned_index或作者order key，进入/离开最小边界都不得临时按面积排序。图钉沿§3.3/§13.2既有顺序位基线；具体跨格整理入口仍TBD-022。

最小边界不因旧固定坐标终点或模板禁入区而扩大；图钉不代表不能响应换行的绝对坐标。主轴依然允许连续滚动及部分可见，不要求全部内容同时展示。TBD-026的误解已澄清；DEC-022补充被动极端例外：显示器/DPI等环境使交叉轴真实空间小于最大Item时，临时二维浏览、保尺寸/原构图且布局只读，空间恢复后退出。正常主动缩框仍受上述下限约束，不借例外静默缩图或更换保存模式；TBD-023保留特殊约束与工程证明。旧数据不删、不静默迁移。

本次先按[UI与行为映射草案](../20_Architecture/CONTENT_LAYOUT_UI_REVIEW_V2.md)评审入口和控件，再归并行为合同；原型并非生产实现。

### 11.2 增强布局风格

- 网格：易读，适合数量多；
- 书架：横向分组，适合封面和平台；
- 错位卡片：视觉更强，适合精选内容；
- 行式弹性流：承载大小不同 Item；
- 子列填充：利用大 Item 旁的剩余空间放置小 Item。

主题决定外观，布局引擎决定几何；模板不能自行改变 Item 业务顺序。

### 11.3 可编辑跨格布局前置（V2-DEC-007）

网格是定位基线，不是一格只能放一张图标。Item卡片可跨多个行列，支持大主卡、中卡、小卡以及横版区域混排；图标contain、封面cover及标签属于卡片内部展示，不把小图标简单放大当成封面。默认/新增/导入/复制应遵循同一受支持布局合同。

布局编辑保存每海报独立的逻辑位置、跨度/比例意图、顺序和覆盖来源；手动大小/位置与热度层级分开。热度、宏观尺度/疏密、固定与全手动规则保留，交互期间不自动重排；绘制/命中/滚动必须基于同一几何快照。容器resize不得改写手动跨度或热度参数；受限宽度的响应投影须显式说明并保留意图。

按[设计V1](../20_Architecture/CONTENT_LAYOUT_FOUNDATION_V1.md)与[04-L01～07](../30_Plans/V3_04_L_CONTENT_LAYOUT_PLAN.md)，该地基在真实Item前用DEMO数据实现/验证。完整素材主题、实际热度与AI仍分别推进，不以无限自由画布扩大当前范围。

## 12. 行式弹性流

2026-09-16定位补充：§12.2/12.3是历史具体算法候选，按V2-DEC-007由同一跨格布局求解器吸收，不要求另造第二套行流引擎；排序、连续可达、不重叠等不变式保留。跨格及区域方案见[布局地基设计](../20_Architecture/CONTENT_LAYOUT_FOUNDATION_V1.md)。

### 12.1 输入

- 排序后的 Item；
- scale；
- pinned index；
- frame viewport width/height；
- 独立 ContentMetrics（标题、base item size、图标尺寸、gap、density）；
- horizontal/vertical gap；
-分页或滚动策略。

### 12.2 主流

按顺序从左到右放置。当前行加入下一个 Item 会超过宽度时，先尝试子列，失败再换行。每行记录 used width 和 max height。

### 12.3 子列填充

- 当前行右侧剩余宽度至少能容纳最小 Item 才启用；
- 从剩余 Item 中按稳定顺序选择 scale ≤100% 的小项；
- 从上到下填充，保持主题 gap；
- 总高度可允许轻微超过主 Item 行高，旧提案为 20%；
- 超出限制的 Item 留给后续主流；
- 不能为了塞入而低于 min scale；
- 所有 Item 等大时退化为普通网格。

### 12.4 几何性质

- 不重叠；
- 不越出内容区，不压住标题栏、控制按钮或页脚；
- 同一输入、容器和配置产生相同位置；
- resize 后重新计算行列/分页，但 ContentMetrics、Item scale 与 pinned index 不变；
- 同一 DPI 下改变 frame width/height，不得改变标题、卡片、图标或字体的实际尺寸；
- DPI 变化只做设备投影，不写回用户内容参数；
- Item 与 viewport 的可见交集产生裁切绘制和同范围命中；viewport 外不绘制、不命中，连续滚动不得按整行跳变，且滚动入口不能依赖当前存在完整可见 Item；
- 装饰层不改变布局可用边界；
- 收起态不计算可见 Item 布局，数据标记保留。

## 13. 两种布局模式与直接操作

### 13.1 热度自动布局

未固定Item按rank score和稳定tie-break排列；默认大小由独立热度尺寸资格/覆盖裁决。图钉项占指定顺序位，其他自动项填空。保持既有默认意图，不因本次两模式UI划分静默改用户配置。

DEC-018/019：在桌面海报直接按住Item并移动，预览“松手固定到第N位”，成功移动后只对该项建立/更新顺序锚，其余仍自动。不要求先点击整理、不增加长按等待、不切整张为手动。无效/取消或回原位的无变化拖动不新增图钉；显式图钉可固定当前位。图钉不锁像素坐标/大小，响应换行不变。见[两模式组合稿](../20_Architecture/CONTENT_LAYOUT_PIN_DRAG_REVIEW_V1.md)。

### 13.2 图钉：自动模式内的局部人工控制

锚定项占指定1-based序号，其他Item按自动排名填充空位。有图钉仍是热度自动模式，不让用户另选第三种“锚定＋自动”；旧Anchored数据枚举保留兼容，不直接删除或重写原文。

操作：固定当前位置、移动到精确序号、拖动锚定项更新序号、解除固定、重置全部。

此处“当前位置”指自动模式的当前顺序位，不是网格/屏幕坐标。解除图钉不清除尺寸覆盖；恢复自动尺寸不解除图钉。直接拖动沿DEC-018/019，冲突仍按§3.3向后找空位并先预览。手动位置/留白不映射成此图钉。

### 13.3 纯手动布局

DEC-019明确：用户控制Item位置/顺位、跨度和留白，支持指定内容逻辑网格位置，不仅是修改order key。热度不自动改排或改大小；两模式共用内容身份、输入、事务与呈现基础，不由控制中心另建一套排版状态。

在桌面直接按住并移动即可拖至网格位置，无须每次先打开中心或进入整理。热度自动的顺序图钉不作为手动拖动许可，也不把所有手动项自动加图钉。DEC-020确认落点冲突采用预览局部让位、只动受影响项；有效释放一次保存、一次撤销，不全局补洞。

作者构图与临时投影分开。DEC-020确认：只缩框不编辑时保留原图，空间恢复可还原；适配期间继续编辑则以当前完整逻辑画面建立新构图，开始实际编辑提示，合法释放才保存，可一次撤销。按下不动、无变化或取消不承接投影。几何候选、普通/显式留白区别及反例见[手动构图评审](../20_Architecture/CONTENT_LAYOUT_MANUAL_COMPOSITION_REVIEW_V1.md)；DEC-022受限二维浏览则布局只读，不承接新图。显式保留区/旧约束兼容及被动恢复工程仍按TBD-023/025评审。

DEC-020确认每次从自动切到手动都以当前完整画面重新开始，不自动恢复上次手动图；旧图仅进入撤销/恢复链。DEC-023确定退出A：保留原自动图钉及自动模式尺寸设置，不带入手动阶段改过的尺寸；退出不等于清空覆盖，旧手动构图只沿撤销/恢复链而非下次切换召回。旧全手动未选择退出策略时保持原状、不能无提示丢失人工布局的保护继续有效；旧“保留顺序/转换锚定/恢复自动”不等于新坐标/留白已经保真，不据本决定直接清字段或迁移日常库。

### 13.4 撤销

锚定、解除、拖动、切换模式、批量重排都进入统一撤销栈。自动重评也应提供“恢复上次布局”。

### 13.5 桌面直接操作与中心精细调整

DEC-023确认后续基础手势为单击选中、双击或Enter一次打开、按住移动即拖；不把拖动释放追加为打开。新基线不直接迁移旧单击启动预设或EDITING/USING配置，兼容仍按TBD-007/013；真实打开仍须V3-05执行安全链。

桌面直接操作是两种模式的常规入口，控制中心提供更细的当前Item位置/顺位、跨度、图钉及相关布局参数调整。中心不是拖动前置，“整理/精细调整”只可作为可选工具界面，不是第三种布局模式。

按住后移动越过抖动阈值即拖，不设原地长按定时条件；未拖动的释放与真实打开手势独立仲裁，拖动结束不追加打开。锁定、只读、失效及已有输入所有权保护不因取消整理门槛而取消。

两个入口必须共用目标身份、意图、完整版本校验和撤销链；中心草稿与桌面手势的冲突不能靠最后写入覆盖。模式选择持续保存，关闭中心/结束手势不会恢复自动或禁止下一次桌面拖动。

## 14. 拖拽触发的临时活跃提升

### 14.1 触发条件

同时满足：

1. 自动排名在底部 50%；
2. 用户拖到顶部 50% 并锚定；
3. 5 分钟内真实启动。

纯拖动或纯启动都不触发。

### 14.2 提升目标

临时排序分提升到与新位置相邻自动项相近。只影响 effective rank，不修改 total launches，也不直接改变到最大 scale。

### 14.3 衰减

旧提案：额外 bonus 每天衰减 50%，每次后续真实启动再衰减 30%，约 3 天基本消退，5 天接近零；真实 rank 追上目标时立即结束。

实现要求：

- bonus 可解释、可诊断；
- 时间和启动衰减不重复扣出负值；
- 再次拖动取消旧评估并创建新候选；
- 多个 Item 独立；
- pinned 冲突优先保证明确人工锚定；
- 悬浮只显示“临时提升”而非焦虑型倒计时。

## 20. 通用内容、归属与跨海报操作

### 20.1 内容能力矩阵

| 来源 | 引用/打开 | 复制、移动或落地规则 | 必须验证 |
| --- | --- | --- | --- |

通用是产品范围，不是“所有 Shell 扩展和提供方天然兼容”的宣称。每种能力需独立实现/认证；未通过能力须在支持矩阵和相应UI反馈明确；增量发布说明遵守发布规则，不冒称全支持，不能用文件路径用例替代虚拟项目证据。纯应用入口不能因 Ctrl/Shift 变成安装目录搬运。

### 20.2 三种集合语义

- **Reference Collection（历史引用集合）**：旧数据仍可读取／修复；不再以普通拖入新增共享引用，也不提供普通“仅移除引用”菜单。有效旧引用拖出沿Windows原生移动。
- **Mapped Collection（映射目录）**：显示用户选定真实目录，添加目标与文件操作可影响该目录；解除映射不删除目录；外部变化同步。
- **Managed Collection（受管目录）**：显式设定由应用管理的内容目录，收纳时可以复制/移动；实际用户内容与程序安装/缓存隔离。删除普通海报先按已验生命周期归还；原路径不可用／未知回系统桌面。卸载可保留原位或归还；失败／取消保留剩余文件及入口。

每张海报绑定一个主集合；物理受管集合可共用，但有效对象只有一个可见海报归属。外部文件变化更新对应关系与视图，不能恢复旧共享引用模型。一个海报聚合多个目录/查询源不自动纳入首轮交付。

### 20.3 拖放与文件安全

- 同一海报内部拖动优先解释为选择/排序，不执行磁盘移动；跨海报须先看目标集合模式。
- 跨海报按已验目标能力转移单一归属；映射目录可按已支持的Ctrl复制语义形成新实体，不给同一对象增加共享卡片。普通拖入／出无应用额外确认，Windows必要冲突提示保持。无权限不能静默换语义。
- 原生拖放反馈与实际完成结果分开。若应用异步负责移动，不能又通知源自行删除造成双重清理；执行方和源清理责任必须唯一。
- 批次计划记录 source identity、目标、冲突选项、操作 ID 和每项结果。移动前落盘 journal，之后执行、校验、提交状态；未完成账本可恢复。
- 撤销不等于盲目反向移动：发现源/目标已被外部修改或同名冲突时保留文件并询问，不覆盖新内容。
- 新建文件/文件夹/快捷方式、重命名、复制、回收真实文件只对具有相应能力的集合和 Item 提供；引用集合中新建实体先明确实际存储位置。
- 删除海报、移除关联、解除映射、从库移除、回收源文件的文案、权限、确认和结果必须区分。

### 20.4 活跃度作用范围

成功打开事实必须保留来源PosterId／ItemId、ActivationId与结果，扫描／缩略图／排序／定位不增加次数。单一归属下跨海报转移后的统计身份、是否沿用全局或局部历史，须在热度开工前明确，不假设已有切换开关。模板自动／手动及动态缩放默认值也待裁决；原始事实与算法版本分离，换模型不重置真实历史。

文件大小、名称和磁盘位置不随热度改变；动态尺寸只改变 Item 呈现。50%–300% 的映射、30 天保护、锚定及撤销要求保留；最终衰减公式仍为 OPEN，不以通用化为理由删除特色模型。
