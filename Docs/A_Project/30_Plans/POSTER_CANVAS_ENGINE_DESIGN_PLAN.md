# 海报画板／模板与组件通用引擎：设计准备

2026-10-26，DESIGN NEXT，尚未实施。用户要求先集成已验模型／性能成果，再准备以海报为画板基础的模板与组件通用引擎。T1三种介绍组件仅在`impl/06-pluggable-activity-model`保留原型，未人工验收，不随本轮发布。

## 设计目标与不变量

- 海报是一个拥有身份、生命周期及安全操作区的画板；圆形、异形或多个离散区域仍可属于同一海报。
- 模板声明布局／资源／组件树，海报实例承载用户覆盖；真实文件归属、打开统计与模型建议独立，模板不得获得任意文件执行权限。
- 在既有运行时支持的声明能力内，导入新外形不重新构建、不重启。新增宿主能力与运行时数据换装分开，不承诺任意原生代码热加载。
- 画面与命中用同一代几何；拖入、标题／框选等必要操作可达。透明外观不自动恢复普通点击穿透；非矩形空洞的输入规则需要明确裁决。
- 增量更新、资源预算和性能测量随设计进入，不以引擎之名恢复每次全量重建或增加每组件常驻timer。保留既有会话保护、新鲜校验和失败保留。

## 设计交付顺序

1. **场景与概念模型。** 用基础收纳、雨夜书桌、圆形、双离散区四个样例验证画板／节点／组件实例／内容槽／操作区划分；明确哪些是模板数据、哪些是用户数据，暂不写实现。
2. **统一声明与能力边界。** 组件身份／多实例、容器布局、参数描述和受限数据绑定；基础绘制原语与可信复杂模块如何组合，未知能力／版本的保留和降级。避免继续在大窗口散落枚举分支，也不为架构对称增加无用接口。
3. **运行与成本协议。** 解析→校验→资源准备→测量布局→呈现／同代命中→提交／撤销；区分结构、布局、绘制、数据失效范围。与模型的排序／尺度／位置／动画建议由宿主协调，人工操作优先。
4. **资源包与安全换装。** 路径、类型、尺寸、配额、资源作用域；候选预览／取消、准备成功后原子替换、失败保留最近可用版本。先设计信任边界，再谈AI生成配方。
5. **迁移与最小切片。** 明确v1模板、T1原型、内置Lamp/Rain的适配方式；选一个能展示通用能力且可集中验收的小切片，再从最新develop派生实施分支。新设计不自动覆盖或删除原型。

## 设计退出标准

给出当前／目标差距、模块职责及依赖、关键更新／失败流程、至少两个端到端配方样例、兼容与安全规则、可量化预算和增量实施顺序。用户确认设计方向后再进入开发；设计认可不记为运行验收。剩余观察成本、锁冲突与历史卸载首因继续独立跟踪，不被本引擎工作隐式销项。
