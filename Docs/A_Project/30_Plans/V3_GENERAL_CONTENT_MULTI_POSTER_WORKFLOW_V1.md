### 7.1 2026-10-21 真实热度准备（未实施）

权威设计来自[活跃度/布局第6～10、13～14、19节](../10_Requirements/CONTENT_ITEM_ACTIVITY_LAYOUT_V1.md)，结合单一归属和2026-10-21已验连续尺寸。现状是“成功打开事实、布局/会话/呈现基础已有”，不是“真实热度已经运行”；下一功能须从届时最新impl/develop派生，本轮不创建分支。

**职责与数据链：** 可信打开完成 → 持久成功事实 → 增量幂等统计 → 纯评分/连续尺寸提案 → 海报安全时点应用。复用ContentActionService/SqliteContentOpenJournal已有事实，不新增第二套打开路径；Application负责消费协调和提案生产，Infrastructure负责事务/读写，Domain负责纯数学/确定排序，PosterContentSession/ContentHeatSession保护会话与人工意图，Presenter/原生命中复用同代几何。不向大窗口或SQLite类塞评分政策，不为接口拆出只有转发的层。

1. **真实统计。** 仅可信提供方证明请求已成功交给Windows才计数，不等外部软件完全加载，也不监视外部软件使用时长。选择、拖动、扫描、图标刷新、排序、Reveal、未成功交接的失败/取消或没有成功证明的Handled不增加次数；取消请求发出后若原生调用实际成功交接，仍按原合同记一次事实。以ActivationId幂等，累计次数/最近打开/来源海报与必要的有限历史用于计算；聚合更新与消费标记同一事务，失败重放不能重复计数，更不能重放文件打开。现表未提供正式聚合游标，须设计稳定消费位置/标记，不能直接假设隐式rowid可作长期游标。独立事实与算法版本，换策略不重置真实使用记录。
2. **排名规则。** 现设计基线为最近使用40%＋有效频次35%＋新项曝光25%，频次对数压缩；同分沿已有顺序/加入时间/稳定ID，防抖动。30天新项保护、近期不罚、高频慢衰减和10%下限是产品意图；旧复合公式会破坏30天免疫，仍是ACT-TBD-01/TBD-002，必须先用新/旧、高/低频和时钟边界样例裁决连续性，再实现，不照抄旧乘数。
3. **连续尺寸。** 旧设计的相对尺寸默认50%～300%、无数据150%只是待对齐基线，不等于已验宏观滑块0.4～3。依据用户“能常驻小数尺寸”的要求，真实热度不得复用旧Quantize五档＋整数Round；需明确映射版本、作者基准×宏观尺度×热度相对尺度及合法极值，替换被替代路径而不双轨累积。每次从作者意图派生，不能在上轮有效尺寸上再次乘。尺寸与排名分开，布局/绘制/命中同一几何；不只做缩放动画，不重新加载所有图标。
4. **人工意图与发布时机。** 自动模式仅排序/缩放符合资格的项；顺位图钉保序，手工尺寸优先，纯手动模式完全不由热度改排/改大小。成功打开只更新统计并标记脏，避免刚点完卡片跳走；冷启动首屏后、下一次展开（及后续明确提供的主动刷新入口）时才计算/应用。拖动、框选、命名、菜单、中心草稿与过渡期间延期，仅保留最新合法提案；交互结束只是安全条件，不是任意重排的新产品触发。成员/配置/策略版本过时则丢弃，失败保留最近有效画面。自动热度不主动扩海报外框；空间约束失败保留有效状态、内容可达，与用户主动调尺度的扩框逻辑区分。
5. **可替换与成本。** 先做可注入、带版本的纯策略，输入统计快照/时间/海报参数，输出分数、排序、相对尺寸及解释；不承诺任意DLL/脚本热加载。事件触发、脏海报合并和有界增量消费；不为每海报新增高频timer，不为一次打开整库重算。接入前后测量事实/聚合写入次数、锁等待、计算耗时及发布次数；基础保护不因性能目标删除，未显示瓶颈不另开架构大改。

**开工前要收齐而不是默认为定稿：** 衰减最终式（含30天退出边界）、连续映射和宏观尺度合成、跨海报转移后统计身份/作用域及历史兼容、各模板自动/手动与动态缩放默认值。旧“共享Item多引用”已取消，不能从旧文档恢复该模型；来源PosterId仍用于解释。第14节“拖到前部后5分钟内真实打开”的临时排名奖励仍为后续候选，不虚增次数、是否首发待决。本轮不恢复已撤的刷新菜单。
