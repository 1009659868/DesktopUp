## 3. 每项任务统一执行卡

每项开始前补齐下面信息，缺产品裁决时先解决对应 TBD，不直接用实现默认值掩盖：

1. 目标需求 ID、明确排除范围、前置项及其证据链接。
2. 现有可复用代码与 DeskBox 精确来源/commit；没有阅读不能写“已吸收”。
3. 输入/输出合同、状态权威、版本与失败语义；持久化变更列出迁移/回滚路径。
4. 代码落点和最小改动边界；UI 不直接操作库/文件，原生层不解释主题/热度。
5. 正常、零/边界、取消、冲突、失效、重复调用与退出用例。
6. 自动测试、真实进程/实际发行产物 smoke，以及受影响人工门。源码字符串检查仅作为结构约束。
7. 结果记录路径、构建命令、commit＋dirty 状态、产物路径/hash、环境/权限、预期/实际/证据。
8. 更新 CODE_ANCHORS、VERIFICATION 和 ACTIVE_PATH；失败留在当前门，不以增加任务号规避。

状态只用 PLANNED / IN PROGRESS / AUTO PASS / MANUAL PENDING / PASS / BLOCKED / SUPERSEDED；AUTO PASS 不能自动变 PASS。已有用户 PASS 的矩阵作为回归，不重复要求全量 DPI/安装测试，除非改动触及对应风险。窗口/输入修改始终跑启动、点击、刷新、普通窗口覆盖、Win+D、退出的核心回归。
