## 1. 本次已明确与仍待评审

用户已明确：外框挤压只换行/换列，不缩小 Item、不遮挡交叉轴内容；主动最小交叉尺寸由最大 Item 决定，边界处单列/单行；水平与垂直对称；先设计 UI 和按钮逻辑，再归并行为和实现。同日补充：“由大到小”仅描述默认热度自动排序的表现，存在图钉时可以不是大→小。

已纠正：撤回上一版“仅在最小边界按面积临时排序”的假设。**热度不是由面积反推的；缩框不是一次排序操作。**顺序层先按当前排序模式和图钉产生有效顺序，尺寸层按热度映射/显式覆盖产生尺寸，排布层再保序换行/换列。图钉已有需求基线是占指定1-based顺序位，其余自动项填空；跨格编辑的拖动/固定入口与旧坐标数据迁移仍在TBD-022/025评审，不从“图钉可例外”推定图钉同时锁尺寸。

例如热度顺序为A大、B中、C小：无图钉时单列A→B→C；若C已钉在第1位，有效顺序C→A→B，缩宽到最小也保持C→A→B。把C手动放大不增加真实热度，也不单独触发排名变化。关闭自动排序时按用户保留的顺序排，不因缩到边界又启用热度/面积排序。

## 2. 控件按职责分三处

| 位置 | 常驻内容 | 只在需要时出现 | 不放在这里 |
| --- | --- | --- | --- |
| 控制中心 · 外观 | 模板；内容尺度、疏密两条短滑块（预设节点）；浏览方向二选一；循环开关；一个“整理内容”入口 | 不可用原因、待保存/失败反馈 | 三模式枚举、Item 坐标/跨度输入、图钉、Undo/Redo、网格/跨度一排按钮 |
| 真实海报 · 整理工具条 | “完成整理”；“辅助显示”折叠入口，内含基线网格与左上跨度两个独立开关 | 有撤销历史时显示撤销；正在提交时反馈 | 布局算法、热度公式、整张重置的常驻危险按钮 |
| 选中 Item · 就近工具条/上下文菜单 | 选中后才出现尺寸入口；生产候选支持跨度把手 | “更多”里恢复自动尺寸；图钉等语义确认后才接入 | 未选中时显示空表单、全海报手动模式切换 |

不增加独立“布局”顶层页签。本稿优先把“排布与浏览”并入外观，沿用外观/行为/高级的信息架构；原型只画与本次有关的外观片段，不为展示完整窗口添加无效导航和按钮。高频动作常驻，低频动作折叠，精细动作跟随对象出现；不是把原有全部按钮换成一堆图标。

控制中心关闭不结束海报整理；切目标不把草稿带到另一张。中心与海报的“整理”是同一会话入口，不另起编辑器。锁定海报可浏览，整理入口禁用并说明先解锁；隐藏海报的整理入口需先明确显示/定位，不暗中抬到普通窗口之上。

## 3. 控件 → 意图 → 行为 → 反馈

| 控件/手势 | 用户意图与归并行为 | 保存和反馈 |
| --- | --- | --- |
| 纵向 / 横向分段选择 | ChangeBrowseAxis；按同一模型交换主/交叉轴，不旋转图片 | 普通兼容情况即时预览并一次提交；旧约束冲突先解释/预览，不清字段 |
| 首尾循环开关 | SetLoopPreference；只改变浏览方式 | 即时保存偏好；短内容显示“内容不足一屏，暂不循环”；整理时显示“整理期间暂停”，开关仍代表偏好 |
| 整体尺度短滑块＋节点 | SetContentMetrics，改变全部卡片共同基准 | 滑动预览，释放/键盘确认一次保存；不是外框缩放，不抹平相对层级 |
| 疏密短滑块＋节点 | SetSpacing，改网格间距，不改作者跨度/排序 | 与尺度同保存手感；跨格总占位包含内部格间距，不把这项主动度量变更与外框缩放混淆 |
| 整理内容 | BeginArrange，建立临时许可；定位真实海报 | 不转换 Automatic/Manual，不修改作者坐标，不要求先勾“手动” |
| 选中 Item / 尺寸 | Select / SetItemSpan，改变一个对象的跨格意图 | 选中不写库；尺寸预览后一次保存，可撤销；不改热度原始分数 |
| 基线网格 / 左上跨度 | SetGuidePreference，两个独立辅助偏好 | 不改变几何，不要求两个一起开；原型每次重载默认开 |
| 完成整理 | EndArrange，结束临时许可 | 已提交编辑保留，不触发“恢复自动”或额外重排 |
| 取消 / 撤销 | CancelDraft / UndoCommittedEdit | Esc 取消当前未提交手势；撤销一个已提交语义动作，仍需 CAS；不能混作全量重置 |
| 外框边缘拖缩 | ResizePoster，先保证交叉轴可容纳最大项，再换行/换列 | 不改 Item 跨度与尺寸；碰撞仍由原空间所有者处理；到下限有边界反馈 |

开关即生效、滑块结束自动保存，不增加常驻“应用”。原型的“已更新”仅指演示内存状态，不模拟数据库成功。生产失败要明确“未保存”，还原最新权威投影/保留可重试草稿；不得让控件停在成功状态但真实海报没变。

## 4. 缩框演算与边界

设 Item 的实际占位包含图像、标签、内部装饰，不只图标位图。宏观尺度、跨度和 DPI 度量确定占位；外框拖缩不改变它。

- 纵向：内容最小宽度 `max(Item.width)`；横向：内容最小高度 `max(Item.height)`。外围另加主题明确的 padding、边框、对应轴 chrome 及非覆盖式滚动条占位。标题按钮应折叠/重排，不再用一长排工具按钮撑大内容下限。
- 最大项按对应轴分别计算，可能不是同一张；这是几何下限，不是排序依据。横版/竖版 Item 在横向模式不旋转。
- 宽/高逐步缩小：能放下则保持单项尺寸，放不下则沿主轴换行/列；有效排列从原意图计算，不从上次被挤压结果继续算。
- 到精确最小边界：显式单列/单行，每行/列一个 Item，即使两个小项并排能放下，也不继续拼排；严格保留含图钉约束的有效顺序。无覆盖且默认热度自动排序时自然呈现大→小，这不是排布层额外保证。空海报使用宿主自身最小可操作边界，不取空集合最大值。
- 主轴内容超过视口时允许部分可见、连续滚动进入；禁止的是**没有浏览途径的交叉轴裁切**，不是要求所有 Item 同时完整露出。
- 退出单列/单行的判定和物理像素取整需统一；原型以演示尺寸精确比较，生产需补 `min−1/min/min+1` 与混合 DPI，不擅自引入尺寸迟滞。

重要约束：固定坐标、硬留白/区域若坚持原位，将无法同时满足上述承诺。候选新语义必须允许有效位置响应换行，保留作者安排的意图/来源，而不能通过固定坐标把最小宽度推到很大。旧资料的原文保真与迁移解释独立处理；不因此删除留白或顺序锚。绝对坐标自由画布如仍有价值，应另行评审，不和本次流式浏览偷偷混用。

被动环境比最大项还小属于另一个问题：无剩余空间时“不缩不裁、不增轴、全部可操作”无法全部成立。用户这次主动缩框例子不等于批准被动简化视图；保留 TBD-023，不借原型偷偷采用降级。

## 5. 原型范围与操作

1. 在左侧选纵向，拖右侧演示区的“内容宽度”或海报右边缘到最小；观察固定尺寸卡片按相同有效顺序换行，最后单列，向下滚动可达末项。默认演示顺序模拟热度序，不计算真实热度。
2. 切横向，拖“内容高度”或海报底边到最小；保持 Item 原方向，逐列排布，最后单行，向右浏览末项。右侧缩框滑条是**评审操作器**，不会加入产品控制中心。
3. 来回放大缩小，卡片尺寸不随外框改变；选尺度才改共同基准。点滑条上的节点或拖动都可；疏密改网格间距，跨度不变，跨格占位包含内部间距。原型基线节距为单格尺寸＋间距，卡片占位为跨度×节距−一个间距，使换行后的落点仍对齐网格。
4. 点击“整理内容”，海报出现工具条；点击卡片才出现该项尺寸入口；完成后工具条退出，单项改动保留。两辅助开关独立。Undo 只演示单项尺寸恢复。
5. 循环用开关与资格反馈表达按钮语义，原型**不实现循环滚动、拖动换位、图钉、CAS、R4、被动降级或真实热度**；主轴使用浏览器有限滚动。不能据此把这些功能标 PASS。

原型采用简单、确定的保序逐行/列流式排布，不等于最终装箱算法；主要用来检查职责、控件数量、固定尺寸、最小边界和两轴对称。原型 JS 不应直接复制成生产 solver。真实编辑的鼠标 capture、吸附、推让、撤销冲突必须按后续连续场景和纯模型审查。

## 6. 评审出口与实施映射

评审顺序：先看入口/控件可发现性 → 演算缩框和两轴 → 对照排名/图钉求序与保序布局的接口 → 评审跨格拖动/图钉入口 → 补取消、失败、生命周期反馈 → 合同和连续矩阵 → 原生产实现。已澄清的排序来源不重新列为待决定项。

TBD-026已因用户补充关闭：默认热度序不是尺寸序、图钉可打破大→小、resize不重排排名。TBD-022只继续评审跨格整理中图钉/拖动的具体入口与语义协调，既有顺序位基线不改为硬坐标；TBD-023被动不足仍未决。这些不是增加常驻开关的理由，结果应收敛进同一语义命令/solver/投影。

通过本原型评审也只允许进入合同归并，不自动意味着可以迁移现有配置或开启生产修复。当前下一步仍 LR-R1；LR-R2 以后需用户授权。
