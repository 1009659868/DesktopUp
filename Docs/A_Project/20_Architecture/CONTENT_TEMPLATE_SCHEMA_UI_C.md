## 1. 用户意图与本轮边界

DEC-016：模板可以自带不同的可编辑参数，不应为每个模板修改控制中心代码；用户或 AI 新增模板后，无需重启即可装入、选择和使用。深夜书桌需要光色、柔和度、背景透明度等，雨云需要雨量、雨色、云色等。原型升为 C，保留旧稿比较。

这并不意味着“允许模板随意执行代码”。需要分清：

| 层次 | 由谁定义 | C 原型现状 |
| --- | --- | --- |
| 模板参数 | 模板作者：参数 key、标签、控件类型、范围、默认值、分组、提示 | JSON 声明；通用表单生成 |
| 参数作用 | 模板作者选择宿主已提供的受控能力绑定 | 白名单 bind；不按模板 ID 分支造 UI |
| 场景效果 | 宿主渲染能力或经过评审的扩展 | minimal@1 / lamp@1 / rain@1 三种演示适配器 |
| 内容与空间 | 宿主的 Item、有效顺序、布局、输入、外框空间与事务 | 复用旧原型；本次参数只影响绘制，不接生产 |
| 全局主题 | 控制中心外壳配色 | 保持顶栏“主题”，与海报参数隔离 |

当前渲染能力是有限的，不宣称一份 JSON 能自动实现任何未知效果。新增模板无需给 UI 添分支，但新增一种宿主完全不认识的效果仍需要扩展能力。

## 2. 可以直接试什么

1. 初始“深夜书桌”：调灯光颜色、柔和度、强度、背景不透明度。移动鼠标观察局部照明；透明度只作用于背景，不让 Item/文字整体变透明。
2. 展开样片夹或模板册，选择“雨夜窗边”：表单变为雨量、雨色、云色、速度、闪电和卡片颜色。雨云仍无整块底板；雨量 0 不隐藏云朵。
3. 切左侧海报；同一个模板在不同海报拥有各自参数。切走再切回仍保留本页内存中的设置。
4. “留一份自己的”：同一套表单工厂生成草稿控件，参数作为新模板的默认值保存。取消不改当前海报，保存不自动改原模板；从模板册点选后才使用副本。
5. “装入模板”→“填入薄荷细雨示例”→“检查配方”→“装入并使用”。不用刷新，即出现新模板与其“雨的节奏”下拉框。
6. 也可主动选择本地 JSON。修改样例的 id/name/参数标签和合法默认值，再装入，UI 无需修改。
7. “查看配方”显示模板定义，不把当前海报的参数覆盖偷偷写回模板。复位只作用于当前海报、当前模板。

本页不写文件或数据库，刷新后自定义模板与参数复位。文件选择只读取用户主动选中的 JSON；没有自动扫描目录、后台网络下载或 AI 调用。示例 ID 只可装入一次，再装入需换新 ID。

UI 将模板选择、环境动效和专属参数统一收进样片夹。外层默认收起，只留当前模板摘要；夹内“动效与参数”独立折叠，默认也收起。收起仅隐藏控件，不关动效、不重置参数；两组宏观滑块、浏览方向、行为页仍在夹外。宽屏右侧仍是评审环境，不是产品桌面预览。

### 2.1 C 同日视觉修订：模板域收纳与风动雨云

按用户新注释，专属参数不再占用独立的大面板；模板动效开关按“当前海报＋当前模板”保存本页偏好，切到另一模板不会继承上一模板的关闭状态。该偏好暂不包含在另存配方中，生产持久化未接。

雨云移除大号英文招牌，海报名移到场景上方；云体用分层矢量雾边和缓慢漂移，Item 改为轻透明底与图形标记，保留原身份、跨度、命中区域与布局顺序。装饰图形是静态 DEMO 标记，不是替换真实 Item 图标的生产规则。

间距通过雨天专用 chrome 留白实现：caption 的下边距由共享样式的 12px 改为48px（因块外边距合并，不能把差值直接当实际间距）。内容视口大小及 Item solver 不改。最大风感下云体边界与视口上边缘的五个关键帧实测间距约24.5～27.3px，不再紧贴。切模板会改变该装饰留白，不宣称所有模板外框高度仍相同。

新增专属参数“风感”绑定 cloud.wind，0～100%，本稿默认35%。只影响云/雾层位移与雨丝倾斜；Item 不漂移。云主周期19秒、雾层23/27秒是本轮候选，不是产品冻结值。风感0无云动画；环境关闭、整理、pagehide等暂停；减少动效禁用云/雾/雨动画。只用受控CSS动画，无持续JS帧循环。折叠参数区不会暂停桌面效果。

最新检查与截图归 VERIFICATION；本稿视觉方向已获DEC-017确认，原生资源和光敏安全未认证，动画具体数值不冻结为生产合同。

## 3. 实现逻辑：模板是“配方”，实例是“这次怎么调”

链路为：

**模板声明 → 校验能力与边界 → 注册模板 → 通用控件 → 当前海报参数 → 受控绘制。**

例如一个参数片段：

~~~json
{
  "key": "softness",
  "label": "柔和度",
  "group": "光影",
  "type": "range",
  "min": 0,
  "max": 100,
  "step": 1,
  "default": 60,
  "unit": "%",
  "bind": "lamp.softness"
}
~~~

- UI 看到 range 就生成滑块；color 生成颜色控件；boolean 生成开关；select 生成选项。标签、范围和说明都来自声明，不用知道它是“灯”还是“雨”。
- key 是这份模板自己的参数身份；bind 是宿主懂得的效果接口。换个 key/中文标签仍能工作，但任意不存在的 bind 不会执行。
- 渲染器读取经过校验的最终参数：例如柔和度映射为光照影响半径与渐变范围，雨量映射为固定粒子池中的可见数量。
- 模板定义的默认值不可被日常调参修改；实例值按“海报 ID＋模板 ID”独立保存。未覆盖时采用模板默认值。
- 所有微调直接刷新绘制，不调用内容 solver，不重建 Item 列表。只有选择另一模板等原型既有动作走共享 render。
- 另存副本才复制定义并将草稿参数转为默认值。原模板、其他海报、有效顺序与热度都不变。

### 声明格式（演示版，不是已冻结的产品载荷）

根包含 format、schemaVersion、id、version、name、family、renderer、base、properties。base 提供材质/标题基线；properties 是可选的专属参数声明列表。雨云始终透明，不暴露无效的背景不透明度参数。

C 原型校验：64 KiB 载荷、最多 20 参数、最多 64 模板；雨池 64、合法范围与步长、有限数字、颜色格式、选项数量与值、唯一 key/绑定、已知格式/能力。未知字段也拒绝。参数名称/提示用纯文本，不接受 HTML、URL、CSS 表达式、脚本、native 插件或任意函数。

雨量与速度不会启动新的无限计时器；固定池复用，灯光仍只合并输入帧。环境动效关闭、整理、减少动效与可见性暂停沿用旧场景生命周期。光敏安全、原生性能和 1/3/6 海报资源认证尚未进行。

### 本次无刷新装入如何成立

1. 用户选择/粘贴 JSON；读取未完成或取消时不改现有模板。
2. 检查完成后保留候选，不立即写注册表。
3. 用户确认时再次校验源文、目标、当前模板及注册表数量；过期候选要求重检。
4. 注册新 ID 并选择它；共享模板册和动态参数面板立即刷新。
5. 失败的格式、重复 ID 或非法能力保留原海报；关闭对话框或编辑源文会废弃旧候选。异步文件结果带代次检查，不能在关闭后迟到回填。

这验证的是**同一页面内新增模板并立即使用**。现阶段拒绝同 ID 替换，不将其伪称为完整版本热替换。注册后渲染发生异常的原子回滚、目录监听和持久化是下节设计工作，不以原型成功代替生产证明。

## 4. 未来如何支持更自由的 AI 模板

生产方向不是永远只有灯/雨两种枚举。可将受控能力扩成有限的声明式场景节点，例如遮罩、材质、文字装饰、径向光、粒子发射器，以及被动指针信号。AI 编写的是“组合与参数”，不是主进程可执行脚本。

建议分阶段：

- 首先定义结构/度量、绘制、被动效果三层能力与 schema；结构变化必须产出宿主可验证的度量提案，不自行改变 Item 身份、顺序、抓取点或空间策略。
- 其次用可组合能力覆盖更多风格。自定义资源只允许包内受控路径，禁止路径穿越、外部执行和越权访问；数量/尺寸/帧成本有限额。
- 真正全新算法需受信任、版本化的渲染扩展及安全/性能审核，不能把 AI 输出直接 eval。是否另设隔离扩展进程尚待专门设计。
- 界面也设合理复杂度预算：分组、折叠高级项、提示、复位；不允许作者无限堆满控制中心。参数太多应被设计/校验限制，而不是自动生成就算好用。

这样保留“风格化不只是换色”的目标，同时不让模板接管稳定工具的核心职责。

### 真正生产热更新的待制作合同

**文件稳定写入/显式导入 → 候选解析与资源校验 → 离屏准备 → 等待安全边界 → 一次切换 → 保留 last-good。**

- 目录监听要防半写、重复通知、过大文件与更新风暴；使用稳定写入确认、去抖和 latest-only 代次。
- 模板版本与 schema 版本分开；同 key、类型、单位与能力语义兼容时才保留用户覆盖。不能静默把越界值改成新默认值；不兼容需预览/明确迁移或保留旧版本。
- 更新期间不打断拖动、收展/R4、整理草稿、输入捕获或已有事务；新内容待安全边界整体切换。
- UI 参数定义、实例值、度量/素材与绘制状态同代次提交。离屏失败、提交失败或资源超预算保留旧实例，不能先卸旧模板再试新模板。
- 复用生产状态仓库、CAS/revision、输入与R4恢复通道；不另建永久平行状态权威。本原型 Map 只是演示，不是建议取代这些模块。
- 用户覆盖、当前模板版本和回退资源需可持久化、可恢复；删除正在使用的模板、降级、缺失依赖、恢复备份等另外覆盖连续测试。
- 本任务没有制作目录 watcher、迁移、原生加载器、沙箱、离屏交换或数据库接口。
