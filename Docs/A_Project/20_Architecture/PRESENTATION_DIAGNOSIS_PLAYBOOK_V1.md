# Windows / WinUI 呈现缺陷排查方法

日期：2026-09-10。来源：V3-04-M07 动画白条 R1～R4；用户确认 R4 看起来已解决。
适用：缩放/裁切动画出现白条、旧帧、背景泄漏、终态残留；不是所有渲染问题的通用药方。

## 1. 本次结论与边界

- 原生窗口/客户区已高 220px，XAML root/surface 仍为 210px，内层 structure 却已是 360px。旧检查只证明内层稳定，漏了外层 10px 覆盖缺口。
- R3 两张用户图的纯白带均高 10px，与日志缺口吻合；截图/日志不是硬件逐帧同步采样，不能称为同一 GPU 帧的完整追踪。
- 用户原位重绘后画面无变化：该操作未修复故障，但不能推导“一定不是任何表面残留”。另查明收起态只隐藏列表、未隐藏 meta/footer 行，造成布局尾部残留，须单独修正。
- R4 在原裁切区后预备最大有效表面；就绪后只移动/裁切、不逐帧扩大视觉 HWND；结束/取消统一恢复。覆盖门与用户画面确认共同支持本次修复有效。
- 哪个底层组件填出纯白色未直接捕获，不猜成“必然 GDI/DWM/WinUI 的 bug”。已确认的是可见区域超出已准备根表面的机制。

## 2. 先把现象变成可证伪的问题

记录操作序列、瞬态/终态、方向/尺寸、频率、配置、主题、PID、产物指纹、显示器/DPI和时间。至少留异常帧、完全停止帧和正常对照；先确认实际运行版本。
将“实现完成、自动通过、人工通过”分别登记。用户视觉 FAIL 不能被 API true 或几何 PASS 抵消；不要边改多个变量边归因。

## 3. 同步测量整个覆盖链

统一为物理像素比较；DIP × 实际 rasterization scale，明确屏幕/客户区/局部坐标。不能仅凭字段名相信坐标系。

| 层 | 观测 | 防止误判 |
| --- | --- | --- |
| 原生视觉窗口 | HWND、窗口/客户区矩形、DPI、实际 HRGN | 目标尺寸不是实际读回 |
| WinUI 承载层 | 内容子 HWND、root、background surface 实际尺寸 | 内层稳定不等于根表面就绪 |
| 内容树 | structure、scroll viewport/extent、clip | 重排、隐藏行占位、滚动区越界 |
| 底栏 | 实际位置、高度、裁切、终态行高 | 设计底栏不是原生白条 |
| 输入岛 | HWND、区域、层级、点击实际接收者 | 视觉缺口不一定来自输入岛 |

按 requestId + PosterId + phase + 单调时钟关联准备、原生提交、区域提交、Rendering、结束恢复和稳定后采样。观测默认关闭、隔离数据、有界缓存、成对解除；大量日志也会改变时序。

## 4. 固定变量做对照

1. 保持几何、区域、revision 不变，仅请求重绘并观察前后；返回 true 只表示请求成功。
2. 区分动画中和终态；结束后查 Width/Height/Clip/行高/父子树恢复，不只查 HWND。
3. 条带宽度随步长变化只能提供线索，还需实测覆盖缺口。
4. 每个假设写“预期观测 / 实际观测 / 结论 / 未知”；证据不支持就撤销，不连续叠颜色补丁。

## 5. 方案原则：先准备完整表面，再暴露可见区域

吸收 DeskBox 的内容预布局、整段布局租约、集中提交、明确结束恢复；核对本项目透明背景、独立输入岛、事务恢复差异，不能只复制窗口标志。

- 逻辑可见几何 V 与临时容量 S 分离。S 用本次求解的有效尺寸，不将自适应高度回写首选高度。
- 准备时保留当前 HRGN 遮蔽额外区域，准备固定内容与足够的根表面，再读取实际容量。
- 原生容量、根布局和裁切均满足合同才前进。多个 Rendering 回调是就绪协调，不是 GPU present fence。
- 同一时钟/批次驱动源和邻居；视觉只移动/裁切，输入岛仍按 V 更新。
- 完成、取消、失败都解除临时布局和订阅，恢复 committed/effective 几何、原生大小、HRGN、输入和最终绘制。失败整体恢复，不允许部分窗口假成功。
- 临时容量不进入碰撞、持久化、便携配置或实体 CAS；这些仍使用 V。

## 6. 四类验证缺一不可

- 纯合同：容量覆盖、视口连续、收起行、方向/受限高度、非法尺寸。
- 原生隔离：默认/自定义节奏、两种嵌套关闭顺序、上扩/自适应、动画中取消、主题更新、退出资源归零。
- 生命周期：每帧根表面覆盖可见区、内容尺寸稳定；结束租约释放，原生与逻辑尺寸相等。API 成功不是屏幕呈现 FPS。
- 画面：用户或可信捕获同时验过程和静止终态；无法捕获要明示，不能以几百项测试代替视觉结论。

## 7. 失败尝试为什么不够

| 尝试 | 实际覆盖范围 | 欠缺 |
| --- | --- | --- |
| 提交前 Measure/Arrange/UpdateLayout | CPU 布局 | 不是 GPU 已呈现承诺 |
| 窗口级背景/擦底协调 | 背景连接与生命周期 | 不能弥补尚未扩大的根表面 |
| 内层预布局 + NOREDRAW | 内层尺寸稳定、减少复制 | 外层 HWND 仍逐帧增大，根布局滞后 |
| 末帧重绘/只验最终尺寸 | 重绘请求、终点几何 | 看不到中间缺口，也不证明临时树已恢复 |

背景、内容租约和最终恢复仍是有效实现的组成部分。“单独没解决问题”不等于全部无用。

## 8. 收口与复用

保留纯回归、生产安全断言和必要生命周期日志；移除临时菜单、额外渲染订阅、重绘实验和失效启动入口。当前入口只指向经验证包，历史失败不改写成成功；原始日志/数据库不提交 Git。
以后按本清单先取证再修复，不把固定延时、加深颜色或强制重绘当通用解法。

证据：[R4](../40_Implementation/V3-04/M07_ANIMATION_R4.md)；参考：[DeskBox 呈现研究](../40_Implementation/V3-04/M07_DESKBOX_PRESENTATION_RESEARCH.md)。

### 2026-09-27补充：透明背景需要区分终态与新露出区域

候选23补末帧ERASE后终态正常，用户仍复现动画中灰底。A25%与B100%只交换不透明度，故障随25%转移；ARGB始终未变，opaque背景仅遮住了未清底面。候选24在原生容量/HRGN就绪后清`新圆角区域－旧圆角区域`，保留失败恢复及终态ERASE。不要加深模板颜色掩盖窗口层问题，也不要据普通重绘返回true推断背景像素正常。

原生采样必须记录是否人为保持动画阶段。三个中间HRGN的像素对照补足终态盲区，但不能等同原速每个GPU帧无闪烁。配置、红绿像素和未覆盖范围见[输入报告§8](../40_Implementation/V3-04/LR_R5_POINTER_AND_MODULE_REVIEW.md#8-候选24展开过程灰底与ab不透明度对照)。
