## 1. 本轮如何判断“闭环”

产品目标是稳定、好用的桌面内容收纳工具，不是要求用户学习求解器的排版工具。UI C视觉保留；本页只保留验证意图必要的控件，完整主题/模板域不重做。

每项体验需要走完：**我想做什么 → 找到入口 → 预判影响 → 连续操作 → 识别结果 → 不满意能恢复 → 继续日常使用**。单次落点合法或撤销函数存在不等于闭环。

宏观评审采用以下准则，而不是宣称某操作系统规定了唯一答案：

- 同一物体、同一手势优先同义；差异必须能从当前模式看懂。
- 直接操作不要求先进入“整理”；打开、选择、拖动必须互不误触。
- 自动行为辅助用户，不在操作途中抢位置或改变对象身份。
- 影响范围与操作意图相称；隐藏的全局后果必须被检验，不能只补一句提示。
- 取消保留原状，提交有反馈；撤销能回到有意义的上一步。
- 数据安全、内容可达优先于装饰、紧凑排版与持续动画。

## 3. 基础动作—意图试验表

E1当时提供下表两套试验候选。用户现已按DEC-023明确选择单击选中、双击/Enter打开为后续设计基线；下表B保留历史对照，不再要求比选。旧预设兼容、原生阈值和真实打开执行仍须验证。

| 动作 | 候选A（建议优先试） | 候选B（比较） | 不变边界 |
| --- | --- | --- | --- |
| 左键单击 | 选中 | 直接打开，右键用于选择/管理 | 打开只模拟，无真实文件执行 |
| 双击 / Enter | 打开一次 | Enter打开一次；单击已经打开 | 不能因拖动释放追加打开 |

| 右键 / Shift+F10 | 管理选中Item | 选择并管理 | 不改变布局模式 |
| 手动拖动 | 指定网格位置/留白，局部让位预览 | 相同 | 有效松手一起保存；不热度排序 |
| 热度自动拖动 | 固定落点对应的顺序位 | 相同 | 不是锁坐标/锁大小；不改变其他已有图钉 |
| Esc / 失去捕获 | 取消未提交拖动 | 相同 | 本页不模拟原生进程失效或提交中断 |
| 撤销 / 重做 | 回退/重放整次人工操作 | 相同 | 不倒退容器宽度或最新热度源；本页仅内存历史 |
| 容器缩框 | 保持跨度，换行形成临时显示 | 相同 | 不编辑则恢复原构图；不借缩框改作者布局 |

系统边界需要单独讲清，不能用“拖动”一个词覆盖四类动作：

1. **海报内拖动**：改变布局意图，不改文件路径；本轮可操作。
2. **海报之间拖动**：改变收纳归属还是复制引用，仍须成员合同；本轮移出海报取消。
3. **外部文件拖入/拖出**：引用、复制、移动及系统修饰键不能在本轮自行决定；移文件必须经过恢复账本，不用原型实现。
4. **移除Item/删除海报/删除磁盘文件**：必须不同命令和后果说明；本轮不新增Delete快捷键。
5. **打开**：身份/版本稳定、一次激活最多一次执行；此次只有模拟弹窗，不是Shell集成证明。

## 4. 固定的六个体验任务

先只给参与者看“意图”，不要先教按钮步骤或说正确答案。先记录预期，再操作；允许反馈“找不到入口”“结果意外”“能理解但不舒服”，不强迫选通过。

| 任务 | 给参与者的意图 | 主观察点 |
| --- | --- | --- |
| 01 找到与打开 | 找到项目计划并打开，返回后选中参考资料而不打开 | 选择/打开的区分、偶发移动/双击不误触 |
| 02 移动与恢复 | 把参考资料放到空位，再放到已占位置；不满意时恢复 | 直接拖动、碰撞反馈、局部作用范围、找回/撤销 |
| 03 自动与固定 | 让归档保持靠前，模拟热度变化，再让它重新跟随排序 | 图钉是否可见，固定的是什么，解除是否易找 |
| 04 缩框后再编辑 | 窄→宽，再窄；只调整工具箱，然后放宽 | ER-02，必须先预测其他Item的恢复行为 |
| 05 模式来回切换 | 观察工具箱的图钉和参考资料大小；切手动改位置/大小，再自动→手动 | ER-03，先预测哪些安排保留；A/B使用同一起点 |
| 06 中断与受限 | 拖动后取消；关闭中心继续拖；模拟空间不足 | 不依赖中心、取消后首次动作、是否存在安全继续路径 |

每个任务可重置。E1结果表记录任务/基础手势/退出策略/预期/实际判断/描述，只存本页内存，刷新清空，可展开复制反馈。不自动计为人工PASS。

### 4.1 主持者核对：适配后整图承接

此段不作为用户操作前的“标准答案提示”。

- 宽→窄→宽且未编辑：作者构图未变，恢复原位。
- 窄处单击、拖回原位、取消、非法落点：不承接整图。
- 窄处有效移动：按DEC-020候选承接完整逻辑投影，含屏外项，不仅保存可见切片；本次移动/局部让位与整图承接一个操作。
- 松手前说明整图影响；放宽保留新构图；一次撤销恢复旧构图，但不回退容器宽度。
- 不能只数当前帧移动几项：**改变未来放宽时的恢复位置也是影响**。E1任务04中参考资料与屏外备用都能揭示这个差别。
- 如果用户明白规则后仍认为影响不相称，记录为设计失败，回到DEC-020定向修订；不能以已同意某次选项拒绝重新评估，也不能不断加提示让用户迁就。

### 4.2 主持者核对：退出手动的覆盖处置

共同既有决定：每次进入手动都以当前完整逻辑画面重新建立构图，不恢复上次手动图。手动位置在退出后不继续控制自动排布；整次模式切换可撤销。

E1当时的两个试验候选如下；用户现已按DEC-023明确采用A，B仅为历史对照，不增加双策略产品控件：

- **A：沿用原自动覆盖。** 恢复进入手动前的自动顺序图钉和尺寸覆盖，手动大小更改不带入自动。
- **B：带入明确改过的尺寸。** 保留原自动图钉，仅将本次手动会话中用户明确调整过的Item尺寸带入；其他自动尺寸覆盖不变。不把热度产生的显示尺寸全复制为人工覆盖。

E1有预置图钉和尺寸覆盖，避免“无覆盖的空白样例”掩盖冲突。候选A已获得本轮反馈及明确确认。今后若出现真实反例仍可回评审，不因历史候选存在强迫用户重做B。

需重点回答：原图钉恢复是否预料到？手动改尺寸是否应继续生效？切回手动是否认识到是新构图？误切能否恢复？不要求用户理解内部字段名称才完成日常任务。

## 5. 可运行范围与不可冒充的证据

E1为普通单区域、纵向有限浏览、8个虚构Item；只实现两种模式、直接拖动、局部推让、缩框投影、模式往返和内存撤销。控制中心/海报共享一份内存状态，节点保持稳定，不是另一个生产状态仓库。使用UI C风格的精简试验壳，UI C原稿不覆盖。

- 新文件：experience.html / .css / .model.js / .js / .check.cjs（完整文件名见下方链接）。
- 几何只为证伪体验，不能替换生产solver；简单架子式自动排布、Y向推让和行预算不构成最终算法。
- 热度只改变固定样例顺序，不采集使用统计；手势中禁用试验注入，不声称已验证真实异步调度。
- 空间不足占位不是批准隐藏Item的产品策略；按钮只是还原模拟条件。真实兜底按DEC-022/新方案已定产品边界，但本页未实现它，工程验证仍OPEN。
- 未覆盖横向、循环接缝、自动收展、主题动效叠加、多海报、旧数据/显式保留区、长链极限、原生捕获/系统双击设置、R4、CAS/SQLite、重启恢复、完整键盘/无障碍。
- 原型不读写真实Item、配置或数据库，无网络/持久化；不接文件drop、不启动DesktopUp、不Git同步。浏览器原型通过不能扩大为产品已闭环。
