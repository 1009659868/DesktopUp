## 2. 后续操作基线（DEC-023）

| 意图 | 操作/结果 | 防误解边界 |
| --- | --- | --- |
| 选中 | 单击Item | 不打开、不切布局模式 |
| 打开 | 双击或Enter，一次激活最多打开一次 | 拖动松手不追加打开；键盘长按不重复启动 |
| 直接移动 | 左键按住并移动越过防抖距离即拖 | 无定时长按、无整理前置；原型5px不是生产阈值 |
| 手动构图 | 网格位置与留白；碰撞预览局部让位 | 有效松手一起保存/撤销，不热度补洞 |
| 自动模式中的移动 | 固定目标顺序位，其他项继续自动 | 图钉不锁像素或尺寸；无变化/取消不新建图钉 |
| 缩框但不编辑 | 保跨度换行/列，临时适配 | 放宽按原作者意图还原；不改变排名或固定顺序 |
| 适配后有效编辑 | 整张有效构图与此次移动一起保存 | 含屏外成员；预告影响，可一次撤销；取消/无变化不承接 |
| 进入手动 | 以当前完整逻辑画面开始 | 每次如此，不调回旧手动图 |
| 退出手动（A） | 恢复原自动图钉及自动模式尺寸设置 | 不把手动坐标/留白转换为图钉，不带入手动期间改过的尺寸 |
| 取消与恢复 | Esc取消未提交编辑；撤销回退已提交整次操作 | 重放/撤销也须校验当前成员和版本；不是写回旧版本号 |
| 关闭控制中心 | 不影响桌面Item的下一次直接操作 | 不切模式、不回滚已提交内容、不要求中心常开 |

手动期间的人工图与尺寸由当次构图/撤销链承载；退出A不“清空全部覆盖”。例：自动B已有3×2尺寸覆盖→手动改4×3→回自动仍3×2→再进手动从当前3×2开始。想回手动4×3走撤销，不靠切模式召回旧图。未来如果需要显式带入尺寸，另设明确产品请求，不保留A/B双策略控件作为当前交付负担。

兼容边界：新基线不授权把既有游戏单击启动、旧EDITING/USING或ManualExit配置直接改义。TBD-007/013的新基线部分已定，旧预设/配置映射保留评审；未知数据只读保全。打开真实文件仍归V3-05；内部布局拖动不等于文件搬移，跨海报/外部拖放/移除与磁盘删除不能自行推定。

## 3. 空间不足分三类，不混为一个异常

令交叉轴真实可用内容长度为C；同一度量代次下，最大Item完整占位为M。纵向看宽、横向看高；M含必要标签占位，外框最小值另加对应padding/chrome。空海报使用现有宿主最小操作尺寸，不虚构最大Item。

| 原因 | 判断与处置 | 不能做什么 |
| --- | --- | --- |
| 用户主动缩框 | 正常状态C不得低于M；到下限停止。主轴仍可正常滚动 | 自动缩Item、绕过下限进入紧急模式 |
| 显示器/DPI/真实工作区变化，被动导致C<M | DEC-022允许进入临时受限二维浏览 | 改作者构图/跨度、偷偷切手动或换保存的浏览方向 |
| 海报间碰撞、锁定障碍、展开高度不足 | 沿用已有外框空间策略、推让资格和条件归位；内容只消费其合法结果 | 内容模块自行扩框/推邻居，或借二维浏览绕过锁定/碰撞 |

主轴高度变小但交叉轴仍合法，属于普通滚动/既有受限展开，不需要二维兜底。模板非法度量、坏schema、solver预算耗尽、旧硬约束冲突也不等于物理空间不足，必须分开报告，不用此方案掩盖错误或清数据。

**可满足性边界**：若C=180 DIP、M=240 DIP，不可能同时“保持Item尺寸、每帧完整展示、没有交叉轴移动”。用户批准的取舍是保尺寸/保意图/保可达，允许临时视口裁切与双轴移动。全部区域可访问不等于同一帧全部完整可见。正常空间的DEC-011仍生效。

## 4. 受限二维浏览（DEC-022产品边界与工程候选）

已批准：只在上述被动极端不足时例外；Item不缩小，原构图不覆盖，可滚动访问全部内容，暂不编辑布局，空间恢复后退出。

以下为遵守该边界的工程方案，尚待正式纯模型/原生验证，不视为全部实现细节已验收：

1. **区分逻辑布局与真实视口。** 仍用同一个布局模型，在合法逻辑交叉轴长度max(C,M)上取得完整布局；真实视口仍是C，不谎报窗口已经变大。手动构图只做普通响应投影，绝不承接保存。
2. **有限双轴浏览。** 两轴offset均夹在0～max(0,extent−viewport)。保留Item身份和跨度，viewport裁切不删成员；绘制、命中、焦点导航读同一快照。上例若extent=240，横向可浏览范围为0～60。
3. **布局暂时只读。** 可选择、浏览、按既有能力打开；暂停Item拖位/改跨度、图钉及模式切换等布局写入，不把临时坐标存为作者意图。不是第三种持久布局模式，也不是要求平时先点整理。
4. **不靠隐蔽手势自救。** 必须让用户知道空间受限、原布局保留、两个方向都可浏览；鼠标/键盘须有可发现且与Item拖动不冲突的访问路径。这里冻结能力与可发现性要求，不设计控件位置/视觉。
5. **稳定自动行为。** 建议暂缓改变当前呈现的热度重排/尺寸提案，最新候选有界保留；统计事实与呈现资格分离。临时采用有限浏览，暂停循环投影而不改保存的Loop偏好；接缝锚映射仍须TBD-024证明。
6. **空间恢复后自动退出。** 根据最新作者状态、成员、度量和工作区重算；保留当前Item及其内部锚点，去掉不再需要的交叉轴offset，恢复原浏览策略的资格。不恢复进入受限时过期的数据库快照，不把浏览offset转为布局命令。

实现应显式携带受限原因、环境/度量代次和有效浏览策略，不能通过把FlowAxis写成另一种轴来实现。先验证逻辑快照，再由原R4通道发布/恢复；不创建第二个空间所有者或持久库。

## 5. 进入、恢复与更极端情况

| 状态/事件 | 要做的事 | 保留什么 |
| --- | --- | --- |
| 正常→合法缩窄适配 | 保序/保跨度投影，编辑仍按DEC-020 | 作者构图与普通单轴策略 |
| 被动C<M | 中止未提交内容手势，按最新代次进入受限浏览 | 已提交作者布局、图钉、尺寸和保存偏好 |
| 受限期间继续缩窄/换DPI | 合并最新环境，重新校验真实视口及度量，不重复保存 | 浏览锚/唯一身份；不积累错误尺寸 |
| 空间恢复C≥M | 在安全点重算，自动退出受限；正常单轴不跨轴隐藏 | 当前选择/浏览锚和最新作者状态 |
| 受限期间用户关闭/隐藏/删除海报 | 走原生命周期、废弃迟到结果 | 不因环境恢复复活已删除/隐藏的海报 |
| 冷启动已经空间不足 | 从可解析意图和有效度量建立受限布局，不依赖上次内存快照 | 配置原文；不是新作者布局 |
| 连最小安全交互表面也容不下 | 不建立虚假的可用窗口，沿既有管理入口说明暂不可展示/待安置 | 显隐意图和内容身份，不静默清空 |

用户可用现有外框操作增加合法空间、移动到合适显示器，或恢复系统显示条件；这些仍经原空间所有者。若长期处于极小屏幕，本方案承诺保尺寸浏览，不承诺仍可直接编辑构图；需主动调整尺寸偏好时必须另行通过合法预检，不用受限拖动暗中改大小。

内容的捕获终止取消未提交布局，不沿用海报标题拖动“最新可信外框位置”去保存未知Item落点。真正环境失效要撤销旧手势代次；仅pointerleave不是失效。已经成功提交的事务不能因空间变化回滚。

环境恢复的自动切换须等当前可安全结束的浏览/打开动作，不在双击两次之间更换目标；环境使旧命中不再安全时取消激活，不把第二次点击发给新目标。恢复资格以统一度量和物理像素包含关系判断，避免±1px来回震荡；具体稳定条件/调度预算留纯模型验证，不写死毫秒值。

## 6. 哪些事情仍不能算解决

- DEC-022不是04-06跨机导入“等待安置”的替代。整张海报放不下和Item交叉轴不足是两个层次；不改已确认的TBD-021。
- 手动适配后整图承接仅在可编辑的正常/适配状态适用；受限二维浏览布局只读，不能误触承接。
- 自动热度希望变大不属于显示器被动变小。候选尺寸不合法时延后/保留最后合法呈现，不能靠自动扩框或切二维浏览追随热度。
- 用户主动改模板、宏观尺度、单项跨度要预检；不满足正常约束就拒绝该候选/保留原设置，不能假扮环境变化。
- 显式保留区、旧FixedPosition/多区域约束不合法时，保真兼容仍是TBD-023/025剩余范围。不得增大正常最小值来规避，也不得直接删掉约束。
- 控制中心与海报双入口、循环副本接管的反例已见[组合核对](CONTENT_LAYOUT_COMBINATION_AUDIT_V1.md)；Q1/Q2及正式模型/原生证据仍未收口，不把工程候选写成已实现。
