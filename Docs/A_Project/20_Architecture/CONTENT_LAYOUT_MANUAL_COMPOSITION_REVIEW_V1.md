## 2. 一个权威意图，三类状态

| 状态 | 保存什么 | 何时改变 |
| --- | --- | --- |
| AuthorIntent 作者构图 | 手动位置/跨度、稳定人工读序、普通间隔所体现的留白、显式保留区及其来源、轴/度量基准 | 有效人工编辑或显式模式命令一次提交；普通resize不写 |
| EffectiveLayout 有效布局 | 当前空间下的矩形、顺序、extent、意图映射及适配原因 | 从AuthorIntent重算；不以上一帧投影为新源 |
| EditProposal 编辑提案 | 手势起点、抓取点、完整候选、局部让位集合、是否承接当前投影、读集/代次 | 临时预览；取消/失效即丢弃，合法释放才请求提交 |

两种模式不是两个Item目录；成员、身份、主题、宏观参数仍各有唯一权威。也不建立“自动布局仓库”和“手动布局仓库”互相同步。退出手动前的构图只可进入既有撤销/恢复记录，不成为下次切回手动的隐式来源。

热度自动的已有图钉/尺寸覆盖如何跨手动阶段保留，见§6的候选范围；本轮不冻结数据库字段或直接改旧三模式枚举。

## 3. 手动拖动与局部让位

### 3.1 从按下到保存

1. 按下捕获已呈现的Item身份/矩形、抓取偏移、布局及浏览代次；移动过抖动阈值即取得拖动租约。中心无须预先打开。
2. 影子跟手，落点吸附逻辑网格。影子与最终落点标记分离，不让背景灯光、雨滴或间隔夺走捕获。
3. 每次候选都从**同一手势起点**计算：先移除源项旧占位，再放置源项新占位；不能累计上一预览的推让结果。
4. 对受影响项做有限局部让位，显示全部变更及最终落点。若跨出视口主轴，给出方向/数量提示并可浏览查看，不能声称仅改可见项。
5. 松手先消费最后输入，验证当前落点、全部影响和完整版本；源项＋受影响邻居作为一个命令、一个revision、一个撤销项保存。
6. 无效处释放取消本次操作，不偷偷保存“上一个合法落点”；Esc/no-op不写库。提交失败恢复最新权威投影，不用旧快照覆盖别人新状态。

### 3.2 局部让位的确定性候选

- 在主轴/交叉轴归一化坐标计算：纵向向下让位；横向向右让位，Item本身不旋转。
- 源项优先落在用户指定的合法位置；其他项按手势起点的稳定人工读序处理。与新占位/已让位项发生碰撞的项向主轴后方移动，跨轴坐标与跨度尽量原样保持；碰撞传递形成影响集合。
- 不为了塞满源项留下的洞而把远处Item拉来，也不主动移动与这条依赖链无关的Item。普通空白可以被真实受影响项使用，不等于禁入区。
- 拖回起点或反向经过相同落点时，从相同起点重新推演，邻居回到对应预览位置；**已成功保存后**，下次把源项移走不会让邻居凭旧证明突然弹回，恢复依赖明确撤销。
- 显式保留区及尚未迁移的旧硬约束不能被覆盖或删除。源项命中它们则拒绝；邻居可在既定容量内向后越过障碍。不能把所有新手动Item都当不可推让墙。
- 主轴行/列上限、总成员/计算预算沿既有容量边界；预算耗尽不冒充几何无解。不得扩大海报、推动别张海报或开启第二滚动轴。
- 到DEC-011最小交叉边界时，合法投影为一行/列一项；拖动落点同样预览这一限制，可以保留主轴空行，但不能先允许小项并排、松手后再突然拆开。

这是待R3/4证明的轴对称候选，不是把旧Y方向推让函数直接视为已达标。跨度微调拟复用同一可见让位通道，但源项尺寸合法区间、把手/中心交接还需下一步具体设计。

### 3.3 可复核算例：移动并不等于全局重新排版

以下为已包含必要占位的整数网格，纵向浏览、宽8；坐标用零基(x,y)，并非拟定UI显示格式。

| Item / 跨度 | 起点 | 将A拖到(4,0)后 |
| --- | --- | --- |
| A / 4×2 | (0,0) | (4,0)，明确目标 |
| B / 2×2 | (4,0) | (4,2)，被A推动 |
| C / 2×2 | (4,2) | (4,4)，被B连带推动 |
| D / 2×2 | (0,6) | (0,6)，与影响链无关 |

A的原位置留下空白；D不会被拉去补洞。释放后撤销一次，四项都回到操作前。释放前把A拖回起点，无需撤销命令，预览即可恢复。

## 4. 留白与缩框投影

### 4.1 三种“空白”必须区分

- **普通构图空白**：用户把Item放开形成的间隔，由作者坐标表达；不热度补洞，不自动变成不可见障碍。局部让位可以使用路径上的空白。
- **显式保留区**：已有数据中的有意禁入区域，保留来源、可解释占位及删除/撤销语义；不能为了缩框静默删除。支持主动留白不等于现在扩大为完整区域设计器。
- **模板装饰/视觉留白**：云、灯光等绘制不创建隐形碰撞墙；真正占内容边界的模板chrome要纳入受控度量。热更新不能在抓取中改变度量代次。

以下投影候选先覆盖普通手动构图。显式保留区与旧FixedPosition跨轴越界的迁移/适配仍在TBD-023/025；不能用其末端抬高DEC-011最小宽度，也不能用本轮普通空白算例宣称兼容已解。

### 4.2 普通构图的投影候选

1. 不缩Item跨度。所有占位、绘制与命中共用同一度量，不能只把图片画小来满足界限。
2. 沿上次明确手动提交形成的人工读序处理；候选以作者构图的主轴起点、交叉轴起点和稳定ID形成确定读序。投影期间冻结该序，不从正在挤压的坐标反推热度或新排名。
3. 原交叉位置合法则尽量保留；越界时向交叉轴内侧调整。主轴从作者位置开始，按稳定读序和碰撞要求向后让位，不把后项填到前项之前。
4. 到最大Item决定的最小交叉尺寸，全部交叉起点为0、每带一个Item；主轴原有间隔能保留则保留。不按尺寸重新排序。
5. 放宽空间时始终从原AuthorIntent重算：无编辑、同轴/度量/成员恢复至原环境，则精确恢复原构图；不存在压一次、存一次、越压越散的累计漂移。
6. 低于最大Item占位的被动空间不足不适用此算法，仍需明确兜底。轴切换、成员增删、模板结构变化也不是普通“宽度来回”证明的范围。

布局若只做“越界夹入＋消除重叠”，仍会乱序。例如宽4时：B(1,0)、C(2,0)、A(0,1)，三项均1×1，读序B,C,A。缩到宽2，C被挤到(1,1)，若A继续留(0,1)，视觉读序变成B,A,C。候选必须同时维护稳定读序，把A下移至(0,2)；不能只检查无重叠。精确读序/阅读带算法仍需在混合跨度和两轴完整证明。

### 4.3 缩框与还原算例

原内容宽8：A=4×2@(0,0)，B=2×2@(6,0)，C=2×1@(0,4)，人工读序A,B,C。

| 操作 | A | B | C | 保存作者坐标 |
| --- | --- | --- | --- | --- |
| 宽8→6 | (0,0) | (4,0) | (0,4) | 不写 |
| 宽6→4（最小） | (0,0) | (0,2) | (0,4) | 不写 |
| 宽4→8，无编辑 | (0,0) | (6,0) | (0,4) | 仍原构图 |

这里原本左右留白临时变少，但Item不缩小，C不是因为“更小”而被挪到前面。横向应以主/交叉轴对换得到同类结果，不旋转内容视觉。

## 5. 在适配画面继续编辑：承接当前构图

已确认规则：普通resize只改显示；**有效编辑成功**才把当前适配构图变成新的作者构图。由于显示坐标不是旧作者坐标的一一映射，不采用“鼠标位移加回旧坐标”这种隐含逆推。

- 开始实际编辑时用短提示说明“当前为适配布局，本次调整将保存为新构图，可撤销”，不设弹窗/第二次按下门槛。
- 一个候选内部先取完整逻辑投影为新基准，再执行源项移动与局部让位；只在合法释放后**一起**提交。所有屏幕外Item、成员身份及适用约束也必须包含，不能只重建visible集合。
- 按下不动、拖回无变化、Esc、无效落点、CAS/持久化失败都不承接。阈值触发或显示提示本身不是一次编辑提交。
- 成功后放宽视口遵循**新构图**，不会自动召回旧构图；撤销一次恢复旧作者意图及整个变更集，再在当下空间重新投影。撤销不把窗口宽度也改回去。
- 例：在§4.3宽4时把C从(0,4)移到(0,7)，提交的新图保留A(0,0)、B(0,2)、C(0,7)。再放宽8仍保持该新安排。撤销后在宽8恢复B(6,0)、C(0,4)。
- 简单图钉/辅助显示开关不承接手动构图；位置/跨度这类几何编辑拟沿同一承接机制，具体中心控件提交边界待下一步细化。显式保留区未能合法投影时不能绕过待决边界保存新图。

承接不是截图持久化、额外模式或一套副本库；仍是现有作者意图的一次带完整CAS的替换命令。

## 6. 两模式切换：当前画面优先，不自动恢复旧手动图

### 6.1 已确认的进入手动链

热度自动当前完整布局 → 取得同代次快照/成员见证 → 停止新的自动排版提案参与此次切换 → 把当前呈现的逻辑位置/跨度转为手动构图 → 模式与构图一次提交 → 继续原来的浏览锚。

无论第一次还是再次切到手动都如此，不取上次手动图；重复选择已经激活的手动模式是no-op，不借此承接缩框投影。手动模式内只改变视口仍按§4保留构图，不等于每次resize都“重新开始”。

保留屏幕外成员；不把循环重复tile或视觉过渡的插值矩形当作者位置。未完成的结构呈现先到明确安全点再切换；不能先切Mode标志、随后才发现构图构建失败。

### 6.2 退出手动与自动覆盖：DEC-023采用A

- DEC-023确认切到热度自动时沿原自动策略及仍合法的已有图钉/自动模式尺寸设置重新排版；手动位置/留白不伪装成图钉，不带入手动期间改过的尺寸，不反写热度。
- 模式切换不是“恢复全部自动/清空所有覆盖”。不因切模式暗中取消已有图钉；若将来需要清覆盖，用独立明确命令。
- 手动期间的坐标/跨度构图退出后进入可撤销记录，不成为下一次进入手动的缓存。退出A的保留范围现已明确：原自动覆盖保留、手动尺寸不带入；不新增未采用的B策略控件，旧数据兼容仍单独评审。
- 提示只解释会发生的重排及撤销，不引入每次滑动/拖动都“应用”的旧流程；大影响或旧数据不兼容时先预览，可取消/拒绝。
- 若有正在拖动/未完成的中心草稿，先按单编辑所有者规则完成或取消再切模式；具体无打断交接见下一步。提交失败保持原模式和构图，不能半切换。

可检验轨迹：自动S0→手动M0（来自S0）→手动编辑M1→自动S1→再手动M2（来自S1，**不是M1**）。想回M1走撤销/恢复，不用切模式代替撤销。撤销是新CAS命令，遇到成员/版本变化不能盲目回写旧快照；跨进程历史保留能力未因本文新增。
