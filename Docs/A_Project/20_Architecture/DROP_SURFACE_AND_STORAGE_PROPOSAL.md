## 2. 用户看到的操作

### 拖入

1. 从桌面或支持的文件来源拖到海报，标题、内容留白、Item之间、已有卡片上方都可接收。显示轻描边、动作“移动到此海报”和落点预览。
2. 松手才执行。普通本机文件、目录、快捷方式无需打开控制中心，也无需第一次选择保存目录；成功后原位置移除、真实卡片出现。
3. 不支持、取消或尚未执行的失败撤销预览，保留源文件，短提示后可重新拖动。已经实际移动的部分先核实结果，不以视觉回滚冒充文件回滚。

“任意落点”是海报可见外框内的任意区域，不是整个屏幕。前台程序遮住海报时尊重前台目标，不隔着程序抢收纳。收起态只接当前标题／云标题区域；悬停可预展开，离开／取消恢复原收展意图，不扩大到不可见的展开区域。

### 拖出

从真实Item按住并移动，海报内仍是原排布手势；越界后显示取出反馈，拖回海报继续排布，Esc取消，不要求松手再拖一次。先完成桌面任意有效区域取出，再扩大至Explorer文件夹窗口；不把“任意位置”解释为任意应用都能接收文件。

桌面文件落在系统实际Desktop目录；图标最终排列尊重Explorer及其自动排列设置，不注入Explorer、不把其图标坐标当文件位置。通用Shell接线应保留原生落点信息，但不能承诺像素精确摆放。文件夹目标对应实际文件夹路径，不是“凡在桌面窗体上都回Desktop根目录”。

已受管内容正常取出不逐次确认；旧“仅引用”卡片仍按DEC-039确认原文件路径。确认在靠近本次操作的位置呈现，不强行打开控制中心。共享来源移动继续更新全部依赖，不因简化UI而悄悄破坏其他海报。

### 拖动图标始终跟手

2026-10-12用户补充：未松手进入海报时图标消失或像被海报遮住；要求拖入和拖出始终有对象图标跟随鼠标。此项是基础拖放验收条件，不列作低优先级动画优化。以下规则纳入D1探针、D3／D4接线和D5人工：

- 拖动越过手势阈值后，鼠标抓住的是对象图标，不因进入海报而变成空框、插入线或仅剩“移动到此处”。多选显示图标叠影及数量；有独立图标的卡片使用其当前外观。
- 图标显示在海报内容、云／灯等装饰和落点预览之上，不受海报内容视口裁切。抓取偏移保持连续；跨海报边界、DPI变化、自动展开、滚动和内→外→内不跳位、不重复出现两份跟手图像，也不强制缩放成目标格尺寸。
- 接收描边、插入位置和允许／禁止标记是独立的目标反馈。不允许落下时仍保留跟手图标，附加禁止标记；不能用隐藏图标表示拒绝。
- 原位置可保留淡化占位以便理解，未松手不移动文件、不删除原成员。松手结束拖动图像，文件动作进入原执行／核实流程；处理中占位不冒充成功卡片。Esc、源取消、退出与捕获失效清理临时图像，保留尚未提交的原状态。

技术路线先验证Shell拖动图像管理器：拖入在DragEnter／DragOver／DragLeave／Drop成对转发给IDropTargetHelper，使来源图像在目标上继续显示；拖出OLE源用IDragSourceHelper由当前图标创建图像。辅助接口只负责视觉，不改变Move执行责任、返回effect和文件完成判据；自有IDataObject需支持辅助接口使用的私有数据格式。[Microsoft IDropTargetHelper](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nn-shobjidl_core-idroptargethelper)、[IDragSourceHelper](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nn-shobjidl_core-idragsourcehelper)

内部原捕获与OLE之间需单一图像所有者交接，不并行绘制两个拖影。若来源没有拖动图像，使用已缓存对象图标作兜底；无法取得时显示可辨认的类型图标，不能变成空白。必要的自绘拖影仅为临时、不可激活、不可命中的小范围视觉层，不抬升海报本身、不抢OLE目标、不新增全屏输入窗口。必须验证开始／结束、异常释放及DPI下的实际层级。

当前代码缺少目标端辅助调用，且自绘拖影受内容Canvas裁切，分别是明确的拖入／拖出缺口；尚未原生复现用户描述，不把“辅助调用缺失”直接判为唯一根因。D1需区分图像未显示、被裁切、被遮挡及会话切换后丢失，验收不以只看到允许拖入光标为通过。

## 3. 输入穿透与拖放接收分离

普通点击、双击、桌面框选沿现有稀疏输入岛，不扩大常驻点击区域。文件拖放接收使用海报范围内的独立命中策略；装饰透明度不决定能否拖入。两者仍由同一输入仲裁者管理，不能各自提交内容或抢鼠标捕获。

**先做原生可行性门，再选择具体HWND机制。** Windows OLE按指针下的目标窗口分发DragEnter／DragOver；仅把当前输入岛的DragEnter改成扩大区域，无法解决从透明留白首次进入的问题。[Microsoft DoDragDrop](https://learn.microsoft.com/en-us/windows/win32/api/ole2/nf-ole2-dodragdrop)

验证候选是海报有界的OLE接收宿主，与普通鼠标命中分离；必须实测区域、透明样式、层级及窗口查找对OLE的影响。若需临时扩展接收区域，须先证明可靠的外部拖放会话发现和结束清理。不能仅以“左键按下”认定外部拖入，也不能假定某个系统拖动事件涵盖所有OLE来源。机制未过门不接文件移动。

准入反例包括：直接从四边进入空白、空海报、跨卡片与留白、透明云边缘、另一个前台程序覆盖、两海报相邻、多显示器DPI、Esc、源取消、退出和锁屏。拖动期间不激活海报、不抬到所有应用之上、不引入全屏透明拦截层；结束后不能残留可吞桌面点击的区域。

## 4. 落点与布局只用一套模型

- 拖入和内部拖动共用屏幕坐标到内容坐标的转换：外框位置、DPI、内容内边距、滚动偏移、循环副本和当前投影版本。松手时重查版本，不能把旧预览坐标直接保存。
- 自动排布拟沿现有拖动规则，明确放入内容中的操作预览顺位，提交顺位图钉；手动模式预览网格落点和局部让位。该外部新增映射是本方案待验证规则，不改热度公式。
- 标题区域没有内容网格坐标，显示“加入此海报，由当前规则排布”，不伪造精确落点。空白处允许保留手动留白；批量按稳定输入顺序预览一组位置，不能全部叠到同一格。
- 落在已有卡片上默认仍是加入海报、显示插入／让位，不是替换图标、覆盖文件或移入该卡片对应文件夹。后两类若以后提供，必须有不同明确意图。
- 文件结果与成员／布局在现有版本读集和事务通道内发布。松手后显示处理中反馈；只有成功的项进入正式布局，失败项不能先形成可打开的假卡片。部分成功重新求解其余预览并明确结果。

## 5. 默认存储和设置入口

默认路径为`%LOCALAPPDATA%\DesktopUp\Storage\daily或preview\<配置物理身份SHA256>\`，与安装目录、V3状态库、temp/cache分离。Preview、日常库、不同配置分开；测试必须注入独立存储基目录，绝不落到日常默认目录。D2-04已接按需创建：只查看位置不创建，首次实际使用先存创建意图/身份回执，再登记和选择；不接管已有但无法证明归属的默认路径。

首次有效拖入自动创建并登记受管根及集合；失败不静默改成“仅引用”。已有明确登记的存储位置保留，不因为升级强行搬到默认位置。多个旧根不自动合并：保留其内容，设置中明确活跃根；选址的不确定性不能靠猜测解决。

全局设置提供一行“收纳位置”，包含当前路径、打开文件夹、**更改并迁移**。用户更改的是整个受管存储的位置，不是只改变以后新增内容的路径；没有内容时直接切换，有内容时一次说明数量／大小／目标后开始迁移。安装、升级、清缓存和卸载均不得删除此目录中的收纳文件；卸载策略须与默认根一起验收。

默认目录可能与桌面不同卷。**原生跨卷安全门是默认直收的前置依赖**，不能沿用“只支持同卷”却宣称所有普通桌面文件都可直接拖入。既有跨卷执行器仅支持单文件，复制完成后清源，明确拒绝跨卷目录；可以复用其底层证明机制，不能当作整库保留源迁移执行器。须另补保留源准备与目录支持，验证真实不同卷、快捷方式、权限、取消和提交失败；用户延期的真实满盘项继续如实保留。

## 6. 有内容时更改位置

一次“更改并迁移”隐藏技术阶段，但底层不能把整库跨卷移动称为单个原子操作。

1. 预检查目标合法、可写、非源子目录，身份／归属与容量符合要求。只迁移当前配置拥有的受管集合和配套声明，不移动旧Reference原文件，不递归吞并用户选择目录里的无关文件。目标有冲突不覆盖。
2. 写迁移意图并保护相关集合，暂缓新增拖入／拖出；中心和无关海报仍可操作。正在迁移的内容打开要走一致的可读路径或短暂明确阻止，不给出失效旧地址。
3. 在目标准备并逐项验证文件。D2首版同卷/跨卷均保留源，复制和校验完成前不清源；遇到外部修改、身份变化或失败不删除唯一完好副本。同卷重命名优化后置，不以同卷等同整库原子。
4. 目标完整后，一次事务切换根定位及全部受影响内容引用；ContentItem／PosterItem、图标资产、图钉和布局身份不变。不通过删除海报再创建实现迁移。
5. 核实切换持久化后再安全清理旧受管副本。提交前取消保持旧位置；提交后若清理失败，目标继续可用并短提示旧副本位置，不回切已生效索引、不删除身份不符文件。

重启依持久意图核实已发生结果，只自动收尾，不重复发起整库移动。外部文件管理器移动、改名、拔盘须保留事实并拒绝过期操作，不要求用户操作恢复任务列表；完整watcher仍另属05-11。

## 7. 拖出到Shell的执行责任

当前“自有鼠标捕获＋移动到Desktop目录”不能靠扩大命中范围成为任意Explorer拖出。扩大目标需OLE源、有效载荷、真实目标结果及共享关系更新一起闭环。

原生方案须明确谁执行文件动作、谁清理源及什么证据证明完成。Shell effect会影响源端清理；优化移动与普通移动的责任还可能不同，不能看到MOVE就再次删除源。[Microsoft IDropTarget Drop](https://learn.microsoft.com/en-us/windows/win32/api/oleidl/nf-oleidl-idroptarget-drop)、[Shell传输场景](https://learn.microsoft.com/en-us/windows/win32/shell/datascenarios)

对无法证明实际目标路径和文件结果的目标，不宣称已支持剪切式取出。先以受限原生探针证明桌面／Explorer实际目标与完成收据，包含异步目标、同名、取消、目标关闭和共享引用；证明后才开放该类目标。Shell应用、虚拟流、Copy／Link不会借本方案自动获得能力。

## 9. 本轮实现边界

默认无内容布局由六个虚拟成员改为零成员；空态不再显示DEMO文案。已有真实关系、已明确保存的布局／样片、未知布局原文及旧验收目录均不批量清理。本轮不删除任何实体文件，不改schema18，不清空用户数据库。显式样片仍可用于隔离布局测试，不再由默认读取隐式注入。

默认空内容代码/证据见[直接拖放实施§7](../40_Implementation/V3-05/DIRECT_TRANSFER_DELIVERY.md#7-全区域拖放方案与默认空内容2026-10-12)。D1本机High匹配环境A第1～8项人工通过，B接收未过，Medium/生产携带保持。[D2§10](../40_Implementation/V3-05/D2_STORAGE_LOCATION_AND_MIGRATION.md#10-d2-04默认位置与设置接线)已接默认位置、全局设置、后台迁移和启动收尾；3197合同及同包7设置/4选择器进程通过，人工1～4项通过，D2-04收口。schema19不变，只有自建隔离内容动作；D3-01接收基础新增隔离实现；尚未开放D3生产全区域/实际落点及原生跨卷逐项入库。历史D2-01/02/03数据与替身范围保留，不补写用户验收。
