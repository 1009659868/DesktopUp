## 1 最小统一语义

海报在底层是承载对象的可视化容器实例；模板是一份可复用的设计，不能把模板当成文件所有者。产品仍称海报；ContainerId对应现有PosterId，不要求重命名全库或新建一套实体。

| 概念 | 拥有的状态 | 不拥有的状态 |
| --- | --- | --- |
| 容器实例 | 身份、生命周期、配方版本、实例覆盖、现有内容集合绑定 | 不另记一份文件归属或统计 |
| 画板声明 | 区域、节点树、参数、资源引用、内容槽、操作锚点 | 用户路径、真实Item清单、密钥、任意代码 |
| 场景节点 | 稳定ID、能力类型、父子关系、局部变换、布局、受限属性 | 文件、网络、系统窗口权限 |
| 子场景资源 | 可复用装饰子树、不可变版本／摘要、资源依赖、开放参数 | 运行实例身份、真实内容集合、全局静态状态 |
| 子场景实例 | 资源引用、独立变换、开放参数覆盖、展开后的命名空间 | 静默修改源场景或其他实例 |
| 内容槽 | 宿主内容集合的只读视图及排版空间 | 不收纳、复制、删除文件或伪造打开统计 |
| 操作锚点 | 可供宿主放置菜单或拖动语义的位置 | 不实现动作，不关闭保护 |
| 设计草稿 | 显式目标、基础版本、候选配方及覆盖、请求身份 | 可信授权、执行成功或安全结论 |

统一的是身份、对象绑定、能力与版本、几何坐标和提交生命周期；不统一矩形外框、标题栏、固定装饰层或组件数量。空海报、无标题海报仍有效。物理窗口包围盒不等于画板外形；多个分离区域仍属于同一实例、同一内容集合和一次设计撤销。

最小内核知道几何和布局结果，不识别“台灯模板”“游戏模板”。复杂可信组件提供测量／呈现适配，作者只声明类型和参数；新增适配能力是软件更新，不是加载生成代码。

## 2 画板声明

修订设计使用JSON，`format = desktopup.canvas-recipe.design`、`protocolVersion = 0.2-draft`。下表是待实现字段约定，不是生产导入格式；现有导入器不得直接接受设计格式。原0.1 JSON示例仅保留历史。

| 字段 | 语义与约束 |
| --- | --- |
| id / version / name | 稳定身份、正整数版本、显示名；实例绑定不可变版本和摘要，不随同名文件隐式更新 |
| requires | 能力ID及主版本，如 `layout.canvas@1`；缺少必需能力拒绝应用，不悄悄移除内容槽 |
| regions | 稳定ID及几何；bounds是局部归一化坐标 `[x,y,w,h]`；DIP长度显式带单位；种类由目录协商 |
| nodes | 单根无环树；id、parent、type、transform、layout、props及可选region；同父顺序决定叠放，可重排。ID由编辑器生成，不按样例名称分支 |
| parameters | key、类型、默认值、约束、显示名、分组；节点只能引用已声明参数 |
| resources | 资源ID、类型、内容摘要、包内相对条目和解码元数据；运行时解析为受控句柄。禁止绝对路径、URL、穿越／链接逃逸和可执行载荷 |
| scenes | 子场景ID、版本、摘要、依赖和开放参数；依赖图无环；scene.instance节点引用固定版本，属性覆盖不写源 |
| contentSlots | 槽ID、承载节点ID与宿主绑定语义；J1只用一个host.members绑定，但节点ID任意，不复制真实成员清单 |
| operationAnchors | host-menu、move等宿主动作的节点锚点；可省略，宿主必须补足安全入口 |
| editor | 默认参数组、折叠与条件显示；不授予权限或改变参数上限 |

### 几何与对象布局

- 坐标相对于容器局部空间，不使用屏幕像素或Explorer图标坐标。宿主确定可用尺寸后求区域与节点布局，DPI转换在呈现边界执行。
- 节点 `box` 相对于父节点；根下指定region的节点以该区域为参照。样例采用归一化矩形排版盒，但排版盒不规定最终绘制形状。
- `draw.panel`的fill／opacity只作用于本节点背景，不隐式让全部子Item跟着变透明；节点隐藏不允许隐藏唯一内容槽。命中优先级由宿主决定，Item／菜单优先于其下的整面拖动区。
- 内容槽交给现有布局链，得到实际Item边界后再检查最小尺寸。文本测量、操作命中尺寸与空间限幅不能只凭JSON判定通过。
- 画面、裁剪、Item命中及操作区来自同一代几何；失败不发布半套新画面／旧命中。按原生实际提交结果准入，保留现有失败恢复。
- 标题栏不是必要结构，必要的是可达的拖动、菜单、锁定、收展／恢复等原有操作语义。锚点缺失、过小或遮挡时，由宿主补操作区或拒绝应用；不能只让用户去控制中心找回。
- 雨夜样例表达两个分离区域。圆形／空洞的原生输入待J4确认；J1只在既有矩形输入承载上验证，不自动让透明区域穿透到桌面。
- 多内容槽须先设计不重叠的成员分配、溢出和跨槽移动语义；首批不重复显示同一有效对象，不恢复共享引用。

### 自由组合与场景复用

- 基础类型描述图像、文字、形状、分组、布局、内容承载和宿主入口，不描述“雨夜模板”或“灯盘开关”。同类节点可多次添加、复制、分组、重排与重挂父级；复用只靠数据关系，不靠实例名字。
- `transform`采用局部DIP位置、缩放、角度和枢轴；`layout`区分free、anchored、flow。flow子节点的位置由布局计算，不同时保存相互冲突的手工坐标；退出flow才编辑自由位置。装饰旋转可组合，J1内容承载仍保持轴对齐、无倾斜，不以图像旋转冒充原生命中支持。
- 重挂父级默认保持世界位置，无法逆变换时拒绝；复制产生新节点ID。删除唯一内容承载或必要操作锚点时需补足等价承载／宿主操作后才能应用，不保护某个写死节点名。
- 选中装饰子树可另存为子场景；引用固定版本和摘要，实例覆盖通过公开参数键访问，不使用任意反射路径。实例展开身份是实例路径加源节点ID；父子循环、资源循环和展开后越预算全部拒绝。
- 编辑源场景生成新版本；现有实例只有显式升级才变，升级保留仍合法的覆盖，失效覆盖需修正后再发布。首批子场景不得嵌入真实内容绑定；整份模板可以要求一个由宿主注入的内容绑定。
- 发布模板包含资源和依赖，不携带用户文件、统计、路径、凭据或运行实例身份。模板实例化与文件收纳是两条不同用例。

### 参数与资源

直接值、`{"param":"key"}`及`{"resource":"id"}`为互斥值形态。没有表达式求值、可执行插值、反射路径或模板脚本。条件显示只用有限条件，不执行代码。

用户通过素材导入动作显式选取PNG／JPEG；宿主读取并复制到资源库，按实际文件头、大小、尺寸／像素总量和解码预算验证，成功后发放资源ID。生产首批不开放SVG脚本、视频、字体包、任意URL或原生插件。导入动作本身是授权，不逐文件增加确认框；选取不等于上传给AI。库内副本不依赖源路径，用户源文件永不因取消／卸载模板被删除。

草稿、模板版本、实例及撤销记录各持有明确资源引用；取消只释放本草稿租约，保存草稿转为持久引用，撤销历史仍需要的资源不回收。发布前验证完整依赖和摘要；导出拒绝路径穿越／绝对路径／重解析逃逸，缺资源不静默丢图。存储字节摘要与解码缓存分离；同内容资源共享不可变数据，实例覆盖不修改共享资源。具体解码上限先测量再固化，不能只限制文件字节而不限制解码内存。

优先级为配方默认值 → 预设 → 已保存实例覆盖 → 当前草稿覆盖。恢复默认是移除对应覆盖，不改共享配方。改变可复用配方产生新版本，实例不静默跟随；应用实例覆盖与发布新配方是不同命令。

## 3 能力目录

目录由宿主生成，模板与模型只读，不能上传目录自授权限。`capabilities.design.json` 是拟议目录，`status: proposed`；生产查询只能返回真实注册实现，不能直接将此文件当成可用功能。

每项能力给出稳定ID／主版本、种类、子节点支持、属性类型与约束、参数绑定、资源需求和失效范围。目录更新递增revision；预览与应用均绑定该revision，更新后旧预览失效。控制中心、AI工具描述和宿主验证同源，宿主另外执行语义和几何检查。

初始能力分为布局、基础绘制、内容槽、宿主入口和可信动效。`effect.rain@1`是未来复用已有Rain的适配目标，不说明当前Modules已支持通用协议。必需能力缺失返回 `unsupported-capability` 并保留旧版。可选装饰须先定义替代方案才能降级；未知字段／版本默认拒绝应用，保留原包供更新后再读，不用丢字段后的版本覆盖作品。

### 创作工作台与控制中心

1. 创作工作台：独立工作区，左侧场景树／素材／子场景库，中间可直接操作的画布，右侧类型驱动属性检查器；可从空白开始，不要求先选两份样例。树与画布双向选择，节点增删、变换、层级、素材和实例编辑均走草稿命令。
2. 控制中心：只显示作者主动开放的日常参数及实例覆盖，可折叠和恢复默认；不把所有节点属性堆成设置夹，也不把创作缩成勾选组件。
3. 场景管理：保存草稿、另存为模板／子场景、资源依赖、版本与导入／导出；保存不是应用到海报，发布新版本不是静默更新其他实例。

J1必须包含基础结构编辑、直接操作、图片导入和场景复用，不再后置这些能力。复杂路径编辑、通用粒子编辑器和脚本不是J1要求。文字、背景等可绑定共享色板；作者选择开放字段，不能通过隐藏控件绕过校验。新基础能力仍需软件更新，但在已注册能力内制作新风格不改源码。

## 4 设计草稿与应用

`desktopup.canvas-draft.design / 0.2-draft` 的字段：

| 字段 | 来源与用途 |
| --- | --- |
| requestId / draftId / draftRevision | 宿主分配，草稿修订递增；修订命令带expectedDraftRevision，拒绝旧请求覆盖新草稿；请求ID用于取消、幂等和回执查询 |
| target.containerId / expectedDesignRevision | 准入时固定，切换选择不改变目标；创建实例走明确create命令，不以缺目标当创建 |
| capabilityRevision | 绑定准备时的能力集合 |
| candidate.recipeId / recipeVersion / sha256 | 不可变候选及字节摘要，不仅凭名称信任包 |
| candidate.overrides | 实例覆盖，类型及范围来自配方和目录 |
| requestedBy | human／ai仅描述来源，不是授权凭证 |

宿主另行生成准备结果：规范化diff、基准见证、资源代次、几何可操作性、预算、previewId、规范化候选摘要及应用令牌；模型不得填写或导入这些结论。令牌绑定目标、设计和草稿版本、候选、作用域及会话，修改任一参数后需重新准备。

命令面为读取能力、读取授权目标摘要、创建／修订草稿、校验／准备预览、应用、丢弃、撤销。AI只可调用读取和草稿工具；首版应用与撤销由用户面板动作驱动。内部IPC后续选择，不要求外部MCP客户端。

结构命令补充AddNode、RemoveNode、DuplicateSubtree、Reparent、Reorder、SetProperties、SetTransform、BindResource、CreateSceneResource、InstantiateScene及ExposeParameter；均带目标／草稿预期版本，组操作原子校验，拒绝部分成功。鼠标拖动只在草稿局部预览，松手记一个撤销步骤，不逐帧写库。草稿Undo／Redo与已应用设计Undo分开；节点属性变化失效旧预览令牌。AI以后复用这套有界命令，不获得资源库任意路径读写权。

已授权目标内读取与预览不逐工具弹确认，用户看候选后点击一次应用。导出、素材导入或更广上下文另行授权，不混入设计提交；不改变普通原生拖入／出无额外确认的体验。

### 生命周期与提交顺序

`editing → preparing → preview-ready → applying → applied`。修订回editing并使旧预览失效；校验错误返回结构化问题。取消前置阶段进入discarded，拒绝迟到结果。

应用时重查目标设计revision、目录revision、操作会话和资源／文件新鲜见证。内容布局使用当前成员快照，不回写模型见过的旧成员清单；目标设计冲突重新预览，不用全局旧快照覆盖无关海报。

准备全部成功后经唯一用例登记设计提交并协调原生发布。数据库与窗口并非同一物理事务，须有发布失败恢复与重启重建，不宣称DB／GPU原子事务。提交后取消不自动倒退；撤销是带预期版本的新提交，不恢复旧成员或热度统计。

J1必须验证提交前取消无写入、提交后回执丢失可查询且不重复提交、原生发布拒绝恢复、重启从已提交设计重建。静态核对不替代这些证据。

## 5 AI 与热度模型

AI面板独立于控制中心，只做海报创作。地址／模型／密钥由用户设置；凭据设施保管密钥并绑定选定端点，模型不能改端点或读密钥。默认只发送匿名目标、结构、参数与布局需求，不自动发文件名、路径、截图或其他海报；确需时先说明发送范围。

Skill指导组合、配色、可读性和修订；程序执行能力白名单、授权、版本、配额和生命周期。模板文本、素材元数据、模型输出均不能扩张权限。deepseek-harness仅参考组织并裁剪，默认spine中的Shell、任务、文件系统不纳入；先测安装体积、启动／空闲成本与取消退出再选技术栈，子进程不等于安全沙箱。

AI可提出内容槽空间与设计参数，但不算日常热度、不伪造统计、不生成可执行模型。现有模型继续提出排序／缩放／位置／过渡建议，宿主协调人工优先、限幅和同代提交。装饰动效不得给Item再乘一次尺度或覆盖受保护位置。

## 6 增量与成本边界

| 变化 | 失效范围 | 保留 |
| --- | --- | --- |
| 纯容器平移 | 原生位置及同代空间变换 | Item视图、暖位图、相对布局 |
| 颜色／透明度 | 相关节点绘制 | 身份、内容快照、布局 |
| 文字／间距／区域 | 受影响子树测量及依赖布局 | 无关图标和统计 |
| 装配／类型变化 | 差异节点与依赖资源 | 稳定ID节点、真实归属 |
| 内容／热度 | 内容槽及相邻布局依赖 | 装饰树，无需AI会话 |

经现有按需调度合并，不加每节点timer。静态模板不轮询AI，隐藏／暂停／减少动画时停止不必要动效。先建立身份与失效依赖，再谈缓存，不跨轮复用过期权威快照。

J0可调整预算：单声明256 KiB、128节点、深度16、8区域、64参数、16资源引用；不是修改生产v1的64 KiB上限。资源沿已有类型／大小规则，J1另测总解码内存；数量预算不是性能保证。配对样本为1/3/6容器、20/100对象，不据此承诺支持上限或帧率。AI轮次、上下文与超时由宿主限制，草稿不能提高。

## 7 两个设计样例与自由创作证明

| 场景 | 基础收纳 | 雨夜书桌 |
| --- | --- | --- |
| 区域 | 克制的浅色收纳面，无大标题／副标题／数量介绍 | 冷色雨窗背景、暖色装饰与暗色可读内容区，非同一模板换色 |
| 装配 | 普通背景形状、单内容承载、宿主操作锚点 | 导入图像、独立文字／形状、装饰子场景、单内容承载；不以灯盘ID或组件开关控制 |
| 控制中心 | 作者开放背景／留白等常用参数 | 作者开放色调／文字／装饰强度等常用参数；完整编辑在工作台 |
| 内容 | 一个宿主members绑定 | 同一绑定，不复制或移动文件 |
| AI修订 | 背景／间距 | 调弱灯光、减少雨效、隐藏文字，只生成草稿 |

两例必须由同一通用编辑器创作并保存为普通数据资源，不进入编译分支。另从空白制作第三种结构，证明不只适配两个样例；不得只换名称／颜色。视觉目标见[设计重审](../../40_Implementation/V3-07/CANVAS_J1_CREATION_REDESIGN.md)，当前待确认。

J1按free／anchored／flow明确测量与变换，文字长短、窄尺寸、移除节点均不能靠样例ID判断；布局算法是能力，不将比例盒或文字后接内容槽变成唯一结构。视觉异形与原生空洞仍分批验证。

历史0.1材料：[目录](capabilities.design.json)、[基础收纳](basic-storage.recipe.json)、[雨夜书桌](rainy-desk.recipe.json)、[换装草稿](rainy-desk.draft.json)、[继续修订](rainy-desk-refined.draft.json)。原verify-design.mjs仅核对这些历史设计数据，不证明0.2或产品运行能力；保留原样以便追溯。

## 8 退出标准与余项

J0退出：三份协议职责明确；两配方／草稿引用一致；无标题与非矩形表达不伪造文件身份；中心可据目录列参数组；代表性非法类型、越界、未知能力、重复内容、过期版本和候选摘要错误可识别；旧需求与计划一致；用户集中确认设计。

| 后续裁决 | 进入点 |
| --- | --- |
| 自由创作、素材导入、子场景复用、真实测量与安全闭环 | 视觉确认后的J1实现；新退出门以联合计划为准 |
| 非矩形间隙输入、无标题原生操作区 | J4前确认，当前行为不变 |
| 多槽分配、复杂路径编辑、任意数据源 | 不纳入首个运行切片 |
| AI技术栈、提供方能力、历史留存、总资源成本 | J2探针与隐私设置 |
| 用户代码、组件市场、通用Agent、在线更新器 | 不属于本轮联合闭环 |
