UI C 已获采用（DEC-017），不再进行整套视觉比选。DEC-019确认纯手动/热度自动、直接拖动、手动位置/留白与中心细调；DEC-020进一步确认局部让位、每次进入手动取当前画面、适配后有效编辑保存新构图。DEC-018顺序锚限热度自动。具体算法、双入口及循环接缝继续评审，未接生产；手动部分见[专项推演](CONTENT_LAYOUT_MANUAL_COMPOSITION_REVIEW_V1.md)。

权威：[需求与决定](../10_Requirements/REQUIREMENTS_RISKS_AND_OPEN_QUESTIONS.md) → [整改模块设计](CONTENT_LAYOUT_REMEDIATION_DESIGN_V2.md) → [LR-R1计划](../30_Plans/V3_04_L_REMEDIATION_REVIEW_PLAN.md)。DEC-019替代上一轮“先进入整理才能拖”“所有主体拖动仅改顺序”的前提；热度自动的图钉不改成坐标锁，手动模式的位置/留白另有明确语义。不删除旧配置，不覆盖标题合同；真实Item文件操作仍归V3-05。

## 0. 两种模式、两类入口、一个状态权威

| 维度 | 已确认定义 | 必须区分 |
| --- | --- | --- |
| 纯手动布局 | 用户控制位置/顺位、跨度与留白；可放到指定网格位置 | 不受热度提案自动排序/改大小；不是仅“自动模式关闭排序” |
| 热度自动布局 | 热度决定自动项顺序/默认大小，图钉和尺寸覆盖提供局部人工控制 | 有图钉仍属于自动模式，不另设“锚定＋自动”第三个用户模式 |
| 桌面直接操作 | 两种模式均支持按住图标移动即拖，无定时长按、无整理按钮前置 | 保留抖动阈值区分点击/拖动；不因此取消锁定、只读、收起/失效等安全边界 |
| 控制中心精细编辑 | 提供当前海报/Item的细调，和桌面操作读写相同意图、撤销与命令通道 | 不是第二套布局，不要求先打开中心才可拖动，也不恢复旧全桌面缩略预览 |

“布局模式”是持续保存的策略；“拖动/精细编辑会话”是暂态输入保护。关闭中心或结束一次拖动都不切换布局模式。UI C视觉方向保留，但原“整理内容”强制门控和其演示交互已落后于DEC-019，后续定向修订，不能据采纳C坚持该旧门槛。

DEC-020明确：每次热度自动→手动，都以当前完整逻辑画面作为新构图，不自动调回上次手动图；“两模式分别记住构图”的建议不采用。DEC-023采用退出A：保留原自动图钉/尺寸设置，不带入手动阶段改过的尺寸；说明影响并可取消/撤销，不静默清字段。只缩框未编辑则保原图；适配后有效编辑才承接新图。一个权威状态，不建两个状态仓库。

## 2. 桌面快速操作与中心精细编辑

| 意图 | 入口与结果 | 明确不做 |
| --- | --- | --- |
| 自动模式：把这个放前面/后面 | 桌面直接按住拖→插入预览→松手固定到第N位 | 不改大小/热度，不锁坐标，不先点整理 |
| 手动模式：放到指定位置 | 桌面直接按住拖→网格占位预览→合法处松手保存位置 | 不自动补洞、转为热度排序或给每项加顺序图钉 |
| 暂不让自动排序改它的位置 | 选中→“固定顺序位”；已固定则“解除固定” | 不把它变成碰撞墙；不阻止响应换行 |
| 这个需要更大/更小 | 选中→就近尺寸入口或中心精细面板→预览→提交跨度 | 不顺带改变图钉/布局模式，不伪造热度 |

“跨格”包括Item占多格与跨格移动。热度自动模式的落点是顺序插入，空隙不变成坐标锁；纯手动的落点是指定逻辑网格位置，留白是人工安排的一部分。语义由已选布局模式明确决定，不因拖到卡片还是空地而偷偷切换。坐标采用内容逻辑网格，不是桌面绝对像素；缩框与主轴滚动不能直接覆盖作者坐标。

### UI C中的入口与反馈（细节候选）

DEC-023基础手势与退出A已经用户确认；本轮暂不细化下列控件。DEC-022受限二维浏览的例外及工程边界见[操作与空间收敛](CONTENT_LAYOUT_OPERATION_SPACE_REVIEW_V1.md)。

- 控制中心增加清楚的“纯手动 / 热度自动”二选一；原“整理内容”改为非必需的“精细调整”入口（名称候选），不再承担桌面拖动许可。不是第三种模式。
- 桌面负责快速移动；中心选中Item后按模式出现相关细调：手动位置/跨度/留白，自动顺序位/图钉/尺寸覆盖。建议小步进、直接操作和少量必要数字，不恢复满页坐标表单。具体局部编辑视图/控件待设计，不重新引入旧全桌面预览。
- 两入口共享选择身份、版本、预览/提交/撤销。中心未提交草稿与桌面同Item手势不能并发覆盖：需同一编辑租约仲裁，第二入口等待/提示或明确取消旧草稿，不自行last-writer-wins；具体交接反馈待细化。
- Item左上跨度提示、基线网格继续独立开关；图钉标记放独立角位，不依赖两个辅助开关。选中/悬停/键盘聚焦可读到“固定在第N位”，不用常驻长说明。
- 自动模式显示插入位与“松手固定到第N位”，手动显示吸附网格占位；都显示无效原因，不靠松手后突变。手动模式不把顺序图钉改名为坐标锁；是否隐藏不适用入口、如何保留自动模式图钉偏好待切换规则确认。
- 图钉控件只改图钉，尺寸把手只改跨度，主体拖动按当前模式改顺序/位置；标题/外框仍由现有海报移动/缩框所有者处理。
- 按下即建立待决手势，移动超过抖动阈值才确认拖动；时间不是条件。不发生拖动的释放进入既有点击仲裁，拖动后的释放绝不再打开Item。打开的单/双击选择及外部拖入拖出仍归独立合同。

## 3. 热度自动模式：顺序位不是格子号

输入分三层：排序源（热度或显式人工顺序）→ 图钉分配 → 有效顺序。其后才把有效顺序与每项跨度、网格度量、视口交给保序排布；读序不能从布局坐标或像素面积反推。

例如热度源 A>B>C>D>E>F，C钉第1位：

| 动作 | 有效顺序 | 意图变化 |
| --- | --- | --- |
| 初始 | C,A,B,D,E,F | C=1 |
| 把F拖到第2位 | C,F,A,B,D,E | 仅F新增锚2；C不动 |
| 热度源更新为E>D>B>A>C>F | C,F,E,D,B,A | 锚不变；其余按新热度填空 |
| 把F变为3×2 | C,F,E,D,B,A | 仅尺寸覆盖，不增热度 |
| 缩到最小宽度 | C→F→E→D→B→A单列 | 顺序、跨度、图钉均不写回 |
| 解除F图钉 | C,E,D,B,A,F | F回自动池，3×2尺寸覆盖保留 |

固定项仍可能因前项长高、换行/换列或其他项跨度改变而移动几何位置。图钉承诺排名位置，不承诺“永远位于右上角”。若后来需要固定构图区，必须另命名、另评审，不能扩充此图钉含义。

## 4. 跨格落点与冲突处理

### 4.1 热度自动的候选落点（工程方案待纯模型/原型证明）

1. 按下捕获稳定PosterId/ItemId、已呈现Rect、局部抓取点、布局/滚动/视口代次。主体越过既有输入阈值才进入拖动，无长按定时器、无需第二次按下。
2. 跟手影子保持原尺寸和抓取偏移；拖过空隙不失去输入所有权。只有布局副本发生变化，Item身份唯一，雨云/灯光装饰不参与命中。
3. 用影子中心与本次手势基准快照的阅读带/插入区生成请求序号；主轴滚动只做坐标变换。先确定带，再判断该带Item前/后；大项跨多格仍只有一个成员序号。空隙映射最近可解释的插入区，不保存空隙像素坐标。
4. 请求序号统一解释为包含拖动项的最终1..N序号；求解时先撤掉它自己的旧锚/旧占位再放回，避免向后移动差一位或被自己的图钉挡住。
5. 顺序锚冲突先解析，再同一solver生成完整最终布局预览。不能一边按旧坐标画落点、一边按新顺序保存。候选未发布前禁止使用其命中；不按被自己推走的邻居无限重复生成新落点。
6. 保留小范围滞回与稳定平局规则，跨带/反向/停留时不抖动。具体距离与时间不在文稿拍定；需要单独纯几何和首次原生输入证据，不复制原型shelf算法当最终solver。
7. 抓取影子跟手、插入标记指向最终位置，两者职责不同。不能为了让最终格子总在鼠标下而修改尺寸或产生双轴滚动。

### 4.2 遇到其他图钉

沿既有需求§3.3：目标序号已被另一图钉占用，寻找其后第一个未固定序号；不自动交换两个图钉，不推走已有图钉的序号。新落点在预览中明确显示，例如“第1位已固定，将放到第3位”。几何位置仍可能因重排改变。

- C=1、D=2，F请求1 → F实际固定3，结果 C,D,F,A,B,E。
- E=6，F请求6 → 后方无位，预览无效；不绕回前面、不暗中解除E。
- 拖动本来固定的C：仅在候选中释放C的旧序号，再尝试新序号；失败/取消保留原锚。
- 返回原顺序位且跨度/图钉等均无变化，是no-op；未固定项的零移动/无效拖动不偷偷增加图钉。明确点击图钉仍可固定当前位。
- 无效处松手取消本次编辑，不提交“上一个合法落点”；最后合法画面可作为视觉参照，但不能伪装成最终提交结果。

### 4.3 纯手动位置与留白（DEC-020选择已确认，几何待证明）

DEC-019确认真正的网格位置和留白，不再沿用“自动关时只改人工顺序”的候选。基础链：按住Item→保持抓取点→逻辑网格吸附预览→完整占位合法→松手一次保存。跨度保持，热度不参与重排或大小变化；统计是否继续记录是另一职责，不因手动模式伪造或删除统计。

手动保留空白，不全局补洞。用户已选择可见局部让位：源项和受影响邻居一起预览，一次保存/撤销；不默认拒绝或交换。专项稿§3给出轴归一化、同起点重算、连锁与取消算例。手动“指定位置”仍不等于允许重叠/遮挡、无限画布或跨轴滚动。

AuthorIntent与EffectiveLayout分层：只缩框则保原图、放宽可还原；DEC-020允许在适配画面直接编辑，有效提交时将完整当前投影和本次移动一起保存为新构图，可撤销。具体普通空白投影、读序反例、承接条件见[手动专项§4～5](CONTENT_LAYOUT_MANUAL_COMPOSITION_REVIEW_V1.md)。DEC-022被动不足产品边界已定，受限二维浏览布局只读；显式保留区/旧硬约束兼容及恢复工程未验，不把普通构图演算扩大为全场景完成。

旧Manual/FixedPosition/保留区本就承载坐标意图，不能统一清成PinnedIndex；Anchored只是旧数据兼容枚举，不继续暴露为第三个模式。旧原文、来源、迁移预览和撤销仍保留，纯手动的新数据不自动沿用旧字段错误语义。

## 5. 与尺寸、空间、热度和模板的组合

| 组合 | 规则 / 反馈 | 不变量 |
| --- | --- | --- |
| 图钉＋改变跨度 | 保持顺序位，后续项响应换行；现视口放不下则拒绝并说明需先增大海报/减小尺度 | 不解除邻居图钉，不自动撑大外框/推邻海报 |
| 解除图钉＋手动跨度 | 只回自动排序池，跨度覆盖保留 | “恢复自动尺寸”是另一命令 |
| 自动尺寸增长 | 仅热度自动模式对无尺寸覆盖项评估；手势/精细编辑时延后，越界保留last-good | 手动模式不采纳热度尺寸；不修改原始统计 |
| 外框缩到下限再放大 | 自动保有效序；手动只缩框可恢复原图，适配后有效编辑保存新图并可撤销；几何及特殊约束待证明 | 普通resize不写作者意图；明确编辑才承接 |
| 切纵/横轴 | 自动保顺序位；手动需构图/留白影响预览，不能直接把坐标清成序号；两者交叉尺寸预检 | 不旋转Item、不清锚；切轴一次提交，手动迁移策略待评审 |
| 指针拖动时热度更新 | 自动模式缓存最新提案，手势/编辑租约结束的安全点再评估 | 不在手中重排；中心关闭不切模式 |
| 模板专属视觉微调 | 灯光/雨色等绘制参数不改有效顺序/输入几何 | 装饰不夺capture、图钉不归模板参数 |
| 模板结构/度量热更新 | 输入/整理期间暂缓整体切换；安全点预检后同代次发布 | 不在抓取中改坐标基准，不先卸载last-good |
| 循环接缝直接拖动 | 不能再依靠“先点整理”提前换副本；需在同一次按下保住可见副本、抓取点和身份，再安全暂停/映射浏览 | 不跳回原点、不要求第二次按下；TBD-024需按新入口重新设计 |
| 显示器/DPI/空间被动变化 | 能重排则保意图；被动低于最大项时按DEC-022临时受限双轴，工程与特殊约束仍待验证 | 不借本文批准裁切/缩小/删除作者意图 |

尺寸覆盖的含义是“逻辑跨度不受热度改写”，不是锁死物理像素。用户改宏观尺度/疏密、DPI投影仍可改变实际像素，必须与单项跨度分别解释。

## 6. 连续输入、取消与提交

链：日常桌面直接按下Item → 位移阈值仲裁（无定时等待）→ 按当前模式生成顺序/位置预览 → 松手刷新最后输入 → 最终合法性校验 → 原命令单事务 → 新权威投影 → 释放保护。中心精细编辑接同一命令/意图，不是此链前置。

- 预览不每帧落库。自动拖动修改目标图钉，邻居几何变化不等于给邻居写坐标；手动改目标作者位置，DEC-020已批准局部让位，所有变化需同一预览/事务，不能以临时投影冒充新作者构图。
- 完整读集包括海报/内容/成员版本和本次呈现依赖；候选基于这些见证。复用现有CAS、单DocumentVersion/单revision与资源账本；no-op不增版本。
- 快速连续移动合并为最新位置，不排队播放历史候选；松手必须flush最后输入。不因指针越过透明空地或离开Item就主动取消捕获。
- 主轴边缘浏览有界且使用单一offset；横向不偷偷纵滚，纵向不偷偷横滚。滚动后的内容坐标和抓取点同步，不累计取整漂移。
- 正常松手且落点有效才提交。Esc、真正捕获丢失、失活导致手势终止：取消未提交内容编辑，恢复当前权威顺序；不能把捕获丢失当作松手提交到未知位置。仅pointerleave不是捕获丢失。
- 锁定/隐藏/切目标/删除/退出/库更新/屏幕代次失效：释放旧手势，不用按下时快照覆盖新状态；已提交操作不因中心关闭回滚。
- 提交失败：清草稿，读最新权威投影，解释冲突/保存失败；撤销栈只记录成功事务，重做同样校验。历史栈不是直接写旧DocumentVersion回去。
- 无进行中手势时Esc清选择/关闭可选细调界面；“完成/关闭”仅结束精细编辑会话，不禁用桌面拖动、不切布局模式、不清图钉或恢复大小。跨重启持久撤销不在本轮承诺。
- 本节是Item内容排序/跨度编辑，不改海报标题拖动的“最新可信呈现位置优先”合同，也不重开用户延期的BUG-001。
