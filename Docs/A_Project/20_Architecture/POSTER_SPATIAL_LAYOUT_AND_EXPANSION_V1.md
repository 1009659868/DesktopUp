## 1. 本轮决定与实现边界

用户已确认：正常布局海报之间不能重叠，拖动有碰撞；收起/展开可以推动其他海报；已锁定者是不可被推动的固定障碍；源海报收起时，被推动且未被再次调整者条件归位。展开保持原有尺寸：空间充足向下、贴底向上、部分空间先下后上。

工程设计基线（不是用户逐项指定，也不是已通过的实现）：

- 拖动以接触阻挡和沿边滑动为首版行为，不默认推动整片桌面；缩放遇障碍限制继续增长，不修改邻居尺寸。收展的明确推让与拖缩分开。
- 推让先采用同一工作区内、随扩展方向传播的局部确定性求解，不承诺任意二维布局的最优装箱。无合法方案则保持原状态并反馈阻挡原因。
- 收起通常返回该次展开前的有效 compact 锚点；源海报随后被拖缩或环境变化时旧锚点失效，不能突然跳回历史位置。
- 跨重启的条件归位只有具备有效持久证明才执行；没有证明就保留当前位置，不能推测用户未调整过。

上述设计须在 M04-02 形成带例子的可执行合同；确需改变产品行为的取舍要明确记录，不得用实现默认值偷换。锁定不妨碍海报自己的显式收起/展开及其必要标题栏位移，但其他海报无权推动它。

## 4. 占位、坐标与操作边界

1. 占位取海报可见外框矩形；透明/半透明主题不免除碰撞，装饰阴影不计入占位，圆角空隙不作为另一张插入通道。边界接触可允许，正面积相交不允许；可选间距不是已冻结的像素常量。
2. 持久几何继续采用现有逻辑尺寸/锚点意图；计算快照统一到当前工作区的同一坐标系，DPI 转换后向外取整并复验像素占位。输入、视觉、求解必须引用同一版本，禁止混用屏幕像素与 DIP。
3. 首版工作区按所在显示器扣除任务栏；不把其他屏幕的空位作为推离当前屏幕的理由。主屏门不冒充多屏认证。
4. 普通程序、全屏程序、桌面图标不是需要推动的海报障碍；不修改 Windows 原生图标坐标。应用层级规则保持不变。
5. 显示中的收起海报只占标题条；隐藏者不占当前空间，但重新显示必须求解。拖动、四边/四角缩放、收展、中心数值编辑、新建/复制、显示、导入/恢复均不能绕过同一策略。
6. 恢复/导入的历史重叠或超大配置不静默覆写。先保留原意图及备份，生成可预览的合法投影；无解目标进入可由中心访问的恢复状态，不以重叠显示或自动删除掩盖。环境强制变化不是另一个海报的推动，需独立声明投影原因；不能借它绕过锁定。

## 5. 无障碍时的保尺寸两阶段展开

定义：工作区顶部 T、底部 B；当前收起顶边 y0、高度 c；原展开高度 H。先决条件：收起框有效且 `c ≤ H ≤ B-T`，宽度也能容纳。外框扩展不缩放标题、按钮、Item；内容仍按已接受的响应式列数与连续滚动模型呈现。

```text
extra = H - c
freeDown = max(0, B - (y0 + c))
d = min(extra, freeDown)
u = extra - d
finalTop = y0 - u
finalBottom = y0 + c + d
finalHeight = H
```

- 第一阶段：顶边保持 y0，高度从 c 增至 c+d。
- 还有 u 时第二阶段：底边保持 B，高度继续增至 H，标题随顶边向上移动；不可突然跳转标题命中区域。
- 贴底时第一阶段长度为零，直接向上；空间足够时没有第二阶段。不要求固定动画时长，关闭动画时终态仍须一致。

示例（统一逻辑单位）：工作区 `[0,1000]`，c=60、H=600。

| 收起顶边 | 下扩 d / 上扩 u | 过程 | 最终范围 |
| --- | --- | --- | --- |
| 100 | 540 / 0 | 顶边100保持，直接向下 | 100..700 |
| 940 | 0 / 540 | 底边1000保持，标题向上 | 400..1000 |
| 760 | 180 / 360 | 先760..1000，再顶边移至400 | 400..1000 |

若 H 大于整个可用工作区，不存在满足全部条件的几何解；保持存储的原尺寸意图，反馈空间不足，提供中心调整入口，不能假称“自适应成功”。“完整内容”指恢复原展开视口、不人为压缩；原本就超出视口的 Item 仍可滚动，不保证一次屏幕显示任意数量。

## 6. 碰撞与推让求解

拖缩以连续扫掠或等价保守算法检查路径，不仅检查鼠标事件的终点。碰撞裁决不能结束 capture 或要求重新按下；沿边滑动、斜角和越过多张的快速移动要有确定性测试。锁定的邻居禁止被推移；锁定源仍按原合同禁止人工拖缩。

收展先算无障碍理想轨迹，再根据增长前沿沿下/上方向传播最小必要位移：源触及 B，B 又触及 C 时纳入同一候选变更集。按稳定 ID/几何顺序消除遍历偶然性；检测环和迭代预算，不能无限递归或偷偷把别的海报收起。独立性的含义是只有明确纳入本操作的邻居几何可变，邻居尺寸、锁定、收起、主题、内容顺序不变。

任一阶段碰到锁定者、工作区边界或无可行通路，整次操作拒绝并保留上次有效结果；不先推 B 后才发现 C 无路可退。初版不为了“总能成功”擅自横向绕行或跨屏搬迁；更多路由策略单独通过例子讨论。

收起通常释放空间，但沿原路径返回标题条或执行邻居归位也可能接触新障碍，仍须求解。自动收展采用同一规则；拖动、缩放、菜单/确认框活动期间不插入另一轮空间手势。

## 7. 条件归位与因果账本

每次成功推让生成属于源 PosterId / operationId 的布局记录：受影响 ID、推让前后几何、几何变更代次、相关锁定/显隐/收起状态、工作区/拓扑及会话有效期。几何代次不是 global revision；无关主题变化不应自动剥夺归位资格。最终字段、持久化和迁移在 M04-02 冻结，不能改写已发布 migration。

归位检查同时满足：

1. 对象仍存在，且仍处于该推让预期位置；发生过人工移动/缩放（即使移回相同位置）也视为再次调整。
2. 未被另一轮独立推让接管；锁定、显隐、收起或布局归属变化使旧记录失效或必须重新评估，绝不推动当前已锁定者。
3. 环境可匹配，原位置和归位路径没有新障碍；仅终点为空但路径穿过锁定海报不算安全。
4. 采用最新完整读集复核；源收起和可归位子集作为一个合法布局提交。不满足者保留当前位置，并记录未归位原因，不强制全部回旧位置。

归位记录一次消费/失效，重复收起或重复请求不能二次搬动。源被删除不默认触发一场未确认的布局恢复；相关记录失效。跨重启若没有持久证明，邻居保持当前位置；跨机配置不携带旧 HWND/回调/会话代次或推让回滚指令。

## 8. 模块、CAS 与物理提交边界

| 责任 | 设计落点 | 约束 |
| --- | --- | --- |
| 空间纯计算 | Domain 几何策略 | 输入快照/意图，输出候选、阻挡和轨迹；不访问 SQLite、HWND 或主题 |
| 空间操作协调 | Application PosterSpatialCoordinator（职责名，可并入现有服务） | 收集所有参与/障碍读集、操作幂等、推让因果和失败结果，不新增权威库 |
| 状态提交 | 现有 StateCommandPolicy / IStateCommandRepository | 扩充异构多 Poster 几何命令，同一事务 CAS 和 committed revision；不能用现有仅批量锁定/显隐冒充完成 |
| 呈现协调 | App 会话注册表＋既有 Host/几何提交 | 预备每个窗口视觉尺寸、裁剪、输入；同轮批量提交及读回，保留已验证层级保护 |
| 中心/托盘/海报 | 同 revision 的三端投影 | 展示阻挡/降级；中心选择是 UI 状态，命令目标在发出时冻结 |

读集不仅包含被移动者，还包括被用来证明空间可用的障碍及相关目录版本：未移动障碍的并发移动、新增海报、删除/隐藏/锁定变化都可能使方案过期。全局无关设置更新不应一律阻塞；目录插入导致的“幻影障碍”必须被检测。

手势内只产生暂态候选和有界预览，不每像素写库；结束时一次校验/提交，失败回到已提交布局。离散收展先完整预备并复核再提交。新的同事务投影不能被旧恢复回调分拆覆盖。Explorer generation / 显示拓扑变化、源删除/隐藏或退出时取消整轮旧方案，复用 M03 lifetime/epoch 门。

数据库事务、Win32 多 HWND 移动和渲染合成并不构成跨系统原子事务。需要预备完整变更集、同轮布局版本、批量位置提交、视觉/输入读回和失败账本；不能只加 DeferWindowPos 就宣称无闪烁。物理失败时禁用不匹配输入、保留/恢复最近完整可用呈现并重试权威快照，报告 degraded，不伪报所有窗口同步成功；不以静默数据库回滚覆盖后续命令。
