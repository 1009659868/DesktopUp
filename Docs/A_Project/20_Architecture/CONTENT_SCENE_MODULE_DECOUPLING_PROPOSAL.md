## 1. 当前框架判断

**可动态配置已知渲染能力，但尚不能移除一个具体场景实现而保持宿主独立编译。**

| 已有基础 | 限制及代码证据 |
| --- | --- |
| TemplateRecipeCodec校验、注册事务、动态Color/Range/Boolean表单、逐模板实例及持久化 | `Domain/TemplateRecipes.cs`的TemplateRecipeInstance直接存LampTemplateParameters；不是通用参数容器 |
| 配方renderer/binding有版本与白名单 | minimal/lamp仍通过EffectiveTemplateKey等映射内置模板键，不是可替换模块注册表 |
| Lamp拥有独立partial和共享帧源 | `App/PosterVisualWindow.cs`直接调用Create/Update/ReleaseLampScene，`App.xaml.cs`直接配置LampMotion；删文件会编译失败 |
| 卡片与背景可随模板调色 | 通用`Content.cs`调用的ApplyTemplateCardPaint、`Backdrop.cs`依赖的CurrentLamp实际定义在LampScene中，删除Lamp还会破坏minimal |
| 被动指针不需要拦截鼠标；候选20真实两点跟随/离开轻摆通过 | 已补独立端到端门并修全透明窗口误挡；这不消除宿主对Lamp类型的编译依赖 |

追光和闲置不是两个并行动画控制器：`Application/LampSceneMotion.Resolve`同帧if/else互斥。是否进入跟随由真实指针观察结果决定；不能因为纯模型通过就排除原生链故障。穿透的已确认回归是ContentViewport全幅区域被加入输入岛HRGN，网格绘制开关不是其原因。

最新A单元进展：原生指针已真实复现NVIDIA全透明覆盖窗口被误挡，候选20窄范围修复并通过真实跟随与NativeMouse；详见[输入报告§4.2](../40_Implementation/V3-04/LR_R5_POINTER_AND_MODULE_REVIEW.md#42-真实复现与修复候选20)。图钉正式事务/撤销、稀疏HRGN通过，直接图钉右击与桌面空白手势仍待人工；B/C/D尚未实施。

## 2. 推荐边界

| 层 | 职责 | 不应持有 |
| --- | --- | --- |
| SceneHost（宿主） | 海报生命周期、只读几何/可见性、共享时钟/被动指针、减少动效与暂停、资源配额、模块错误隔离 | lamp/rain分支、模板专属字段、原生输入扩区 |
| SurfacePaint（基础绘制） | 默认背景/卡片/标题、受验证颜色与透明度，独立静态fallback | 灯光运动参数、某模板私有实现 |
| SceneModuleRegistry（能力注册） | renderer ID/version、schema/bindings、受信任模块工厂、能力缺失状态 | 按模板名称写分支，自动下载/执行AI代码 |
| Renderer模块 | 例如Lamp自己的schema/defaults、灯具/锥光/光池、追光与轻摆数学、参数解释 | 直接改Item/布局/数据库、原生capture/hook、注册整面命中 |
| 配方与实例 | 配方声明+通用类型值；实例按PosterId/TemplateId/版本隔离；未知模块原文保留 | 固定LampTemplateParameters字段作为所有模板实例载体 |

建议接口只表达实际需要：`ISceneModule`描述能力与创建实例；`ISceneInstance`接受已校验参数和`SceneFrameContext`（时间、DIP指针或null、可见几何、暂停原因）并绘制/释放。装饰层不可接收输入，Item命中与窗口层级始终由宿主维护。无需为简单颜色模板创建持续帧源。

模块清单在构建期产生注册表，Lamp项目/目录是可选项；模块不存在时不生成其引用，宿主不直接引用Lamp类型。第一版采用仓库内受审查的编译模块，暂不引入任意外部DLL或脚本热执行。

## 3. 实施里程碑

| 步骤 | 工作 | 完成标准 |
| --- | --- | --- |
| A 输入回归收口（本轮） | 稀疏HRGN、真实指针诊断/追光修复、图钉图标与右键正式事务 | 空白不属于本海报原生命中；卡片/编辑命中不回退；真实指针进入两个位置跟随、离开轻摆；解除仅写一次且可撤销 |
| B 通用宿主和基础绘制 | 抽SceneHost/共享帧与观察服务；背景/卡片从Lamp实现移出；参数与资源交界显式 | 关闭/隐藏/编辑/恢复/异常资源门通过；无具体场景也能显示/编辑普通海报；原状态与交互保持 |
| C 可移除Lamp模块 | Lamp实现/声明/默认移到可选模块；实例通用值容器；版本化适配既有配置，注册表只含安装能力 | 带Lamp功能与原配置保真；排除/删除Lamp模块后仍构建启动；缺能力时静态保底、提示只读，不自动改模板ID/参数 |
| D 删除/恢复与AI接入边界 | 删除模块→重开→备份→恢复模块；AI配方草稿使用同一校验/预览/确认事务 | 无模块期间旧数据逐字段保留，恢复后效果/参数回来；未知能力拒绝执行，失败不覆盖last-good；至少两种不同schema验证宿主不再依赖Lamp |

“删除”验收在隔离构建副本中物理排除模块目录，不能只关闭一个开关后宣称可删除。旧JSON字段用兼容层保留；没有安装能力时不得解析失败就重置默认。已存在便携格式不能携带custom字段的问题必须继续显式拒绝，格式扩展另行配套，不能借解耦丢配置。

## 4. AI辅助入口

用户/AI生成配方→大小/结构/能力校验→可解释差异与预览→用户确认→现有CAS事务注册。未知渲染效果先产生模块开发提案，经代码审查/构建测试后作为受信任能力加入；不是把AI输出的任意代码直接装进海报进程。保留将来模块版本/能力协商的接口，不在此阶段引入第二状态仓库或布局求解器。

实施按B→C→D推进，先保持现有行为可回归，再扩展模块能力。D的第二schema可用有界测试模块证明通用性；随后Rain再作为真正产品场景验证，不靠同一种Lamp改名算解耦完成。当前B代码与自动门已完成，C/D待做；类提取和现有配方功能仍不能证明完整可删除模板架构。

## 5. 解耦后的雨夜窗边验收

依据[UI C说明§2～3](CONTENT_TEMPLATE_SCHEMA_UI_C.md)及`Designs/content-layout-controls-c.html`、`content-layout-controls-c-model.js`、`content-layout-controls-c-scenes.js`实际设计。开始制作时需再次查看原型动画和生产对照，不能只按文件名或静态截图推断。

- Rain实现、schema、默认值及运动解释归Rain模块；中心按声明生成控件，宿主只提供已批准几何、时钟、暂停与资源合同，不加入模板ID分支。
- 保留透明云/雨留白、雨量0仍显示云、雨/云/卡片颜色、雨速与闪电；风动只影响云/雾/雨，不移动Item。透明场景不显示无作用的背景不透明度项；具体参数范围/周期从原型核对后写入能力合同，不把原型演示常数直接当冻结产品要求。
- 暂停/减少动效、隐藏/收纳、编辑、恢复与关闭释放走共享宿主；有界粒子与资源预算。装饰不可命中，不扩大输入HRGN，不改布局、浏览锚或作者配置。
- 参数导入/副本/逐海报实例、无效配方拒绝、保存重启和移除/恢复均有正式证据；删除Rain不影响Lamp/minimal，缺能力保持原文与静态保底，恢复后参数回来。
- 取得原型/生产视觉对照和用户可体验候选后，进入R7最终同包验收；不将新增样例扩为完整模板商店或在线AI阶段。

## 6. 可模板化的唯一标题栏（DEC-031；已接生产，原生体验待验）

RR-02实施补充：模块能力以`SceneCapabilityDefinition.TitleChrome/TitleColorBinding`声明，宿主解析`PosterTitleChromePolicy`并共用实体轮廓/动作矩形；Rain展开84、紧凑60、内容起点94DIP，基础46DIP及原度量保留。自定义配方继承已注册能力，缺模块回退基础标题，场景实例失效不删除宿主标题。不是通用动态绘制语言；同包自动/人工边界见C模块§10。

“标题栏”是宿主语义组件，不必永远画成一条矩形。Rain以云朵作为该组件的外观；其他模板可使用相同能力表达木牌、灯架或极简条等受控外观，但本轮只做Rain与基础回退。不是把一朵独立装饰塞到旧标题条下面，再各自接一套拖动事件。

| 职责 | 可变与不可变边界 |
| --- | --- |
| 模板外观 | 描述受限标题背景/形状、材质和装饰层；已校验专属参数仍沿现有schema；不附带原生输入回调 |
| 标题布局 | 宿主依据当前宽度/姿态/DPI/能力预算，一次解析文字、收展、更多、抓取区及内容起点；视觉和命中共用该结果，模板不能任意扩窗口 |
| 命令与输入 | 名称及按钮状态来自原权威状态；按钮优先于抓取区；原输入岛/标题仲裁/唯一capture完成拖动、锁定、自动收展和取消；不存在Rain独立拖动器 |
| 姿态与风动 | 紧凑/展开属于同一标题；标题主体与动作锚点稳定，云雾装饰可轻动。纯装饰没有命中，云外空白继续透传，抓取点不会被装饰动画拖走 |
| 对比度 | 标题与操作具有独立背景/轮廓保障，内容背景透明不等于控制元素透明。模板不得使必需动作不可见或不可操作 |
| 失败回退 | 能力缺失、布局非法或绘制异常时保留基础可操作标题，不随场景释放丢掉菜单/收展/抓取；原模板配置保真，不强改成默认模板 |
| DIY范围 | 本轮是受信任标题样式能力与参数，不做任意控件拖排/用户代码执行/完整设计器；未来编辑器也输出同一受校验声明，不自行拥有输入和状态 |

第一版不改已有收起高度合同、不增加第二顶部区域；展开复用合法顶部预算，去掉重复视觉和无效空槽。具体槽位/最小宽度/裁切/命中轮廓及旧参数兼容由RR-01冻结，不能以“支持DIY”为由一次引入任意高度和一套新布局引擎。已有配方装入/副本/移除恢复门必须覆盖标题样式能力的默认与缺失路径。

本节调整的是原先“所有云仅装饰”的产品呈现角色；不解除renderer不可capture/hook/移动HWND/写状态的安全边界。原§5的雨/雾等装饰不命中仍成立，唯一标题交互由宿主承担。
