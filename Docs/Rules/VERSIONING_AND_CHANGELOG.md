# 版本与更迭记录规则

## 1. 版本类型

| 对象 | 格式 | 示例 | 说明 |
| --- | --- | --- | --- |
| 产品设计 | `V主.次` | `V0.1` | 设计迭代，不等同于应用发布 |
| 应用发布 | SemVer | `0.1.0` | 功能发布版本 |
| 任务 | `层级-模块-序号` | `C-DHF-03` | 可验证工作项 |
| 日志 | `YYYY-MM-DD_topic.md` | `2026-08-02_docs_bootstrap.md` | 不可变实施记录 |

## 2. 设计版本规则

- 文案修正、链接修复且不改变含义：原版本更新，并写入文档底部修订记录。
- 用户流程、数据模型或边界明显改变：次版本递增，例如 V0.1 → V0.2。
- 产品定位或核心交互模型改变：主版本递增。
- 新版本建立后，旧版本标记 `SUPERSEDED` 并链接到新版本，不删除。

## 3. 项目更迭记录

项目级重要变化写入 `A_Project/20_Log/PROJECT_CHANGELOG.md`：

- 产品范围或阶段变化；
- 关键技术决策被接受、拒绝或回滚；
- B 模块激活或完成；
- 发布版本及其重要变化；
- 影响用户数据、兼容性或恢复能力的变化。

具体编码过程、测试命令和局部修复留在 C 日志，不上卷到项目更迭记录。

## 4. 日志模板

```markdown
# YYYY-MM-DD 主题

状态：COMPLETE | BLOCKED | SUPERSEDED

## 目标
## 完成事实
## 决策与理由
## 验证证据
## 遗留问题
## 关联文档与代码
```

## 5. 版本发布前检查

- 所有用户数据变更都有迁移或回退说明。
- `ACTIVE_PATH.md` 与真实活跃任务一致。
- 项目更迭记录已增加发布条目。
- 设计、模块和工作流状态一致。
- 所有相对链接有效。
