# 发布、安装与一键卸载规则

状态：`ACTIVE`

日期：2026-08-02

## 1. 正式产物

首个 Windows 发布必须提供单一安装入口：

```text
DesktopUpSetup.exe
```

正式名称确定前使用上述名称；发布流水线可附带版本化存档名，但用户入口不能要求执行脚本或命令行。

## 2. 安装范围

- 默认按当前用户安装，不要求管理员权限；
- 安装位置默认 `%LOCALAPPDATA%\Programs\DesktopUp`；
- 用户数据默认 `%LOCALAPPDATA%\DesktopUp`；
- 开机自启默认关闭，只有用户明确开启后才注册；
- 安装器不得捆绑广告、下载器或与产品无关的软件。

## 3. 安装目录最低内容

```text
DesktopUp.exe
uninstall.exe
resources/
licenses/
```

`uninstall.exe` 必须是真实可启动的一键卸载程序，不得只是打开系统设置的快捷方式。

## 4. 卸载前置安全规则

卸载器必须区分：

- 应用拥有的程序文件、缓存、日志、数据库和主题副本；
- Desktop-Up 托管的快捷方式副本；
- 用户外部文件、游戏、游戏平台和主题源文件。

只有第一类可以直接删除。第二类必须先按恢复账本恢复。第三类永远不得删除。

## 5. 一键清理顺序

1. 获取卸载锁，阻止新的收纳或数据库写入；
2. 请求主程序保存并退出，超时后提示用户再结束；
3. 校验恢复账本与保险库文件；
4. 恢复所有由 Desktop-Up 移出原位置的快捷方式；
5. 删除当前用户开机自启、协议、文件关联、开始菜单和卸载登记；
6. 删除应用拥有的缓存、主题副本、数据库、日志和备份；
7. 删除安装目录；
8. 通过一次性清理进程删除 `uninstall.exe` 自身；
9. 显示成功、部分成功或失败摘要。

## 6. 恢复失败策略

- 不覆盖同名用户文件；使用带编号名称恢复并记录结果；
- 原始位置不可用时恢复至用户桌面的 `Desktop-Up Restored`；
- 任一托管快捷方式无法安全恢复时，不删除对应保险库和恢复账本；
- 卸载结果必须提供保留目录和重试入口；
- 即使恢复部分失败，也要清除开机自启，避免启动不存在的程序。

## 7. 升级与回滚

- 升级前备份数据库 schema 与恢复账本；
- 安装新版本前验证旧版本可以安全退出；
- 数据迁移必须带版本号、事务和失败回滚；
- 失败升级不能删除旧可运行版本或快捷方式保险库；
- 降级不保证读取更高版本数据库，必须提供导出/恢复说明。

## 8. 验收证据

每个发布版本至少保存：

- 安装器 SHA-256；
- 构建清单与第三方许可证；
- 新装、覆盖升级和卸载日志；
- 开机自启开/关两条验证；
- 有托管快捷方式、同名冲突和恢复失败三条卸载验证；
- 卸载后的进程、启动项、开始菜单、安装目录和数据目录检查。

## 9. 禁止事项

- 不得把删除 `%LOCALAPPDATA%\DesktopUp` 作为恢复托管快捷方式的替代方案；
- 不得静默覆盖桌面同名文件；
- 不得删除用户自行选择但未复制进应用目录的外部主题；
- 不得在卸载后留下自动启动的辅助进程或计划任务；
- 不得在未完成净机验收时宣称安装包可发布。
