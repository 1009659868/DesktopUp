## 3. 产品总画像

### 3.1 一句话定义

DesktopUP 是一款面向 Windows 11 的低资源桌面海报启动器：把散乱的游戏快捷方式安全地组织进可折叠、可换肤、可自动排版的桌面海报，使用户在不打开传统启动器主页的情况下查看和启动游戏，同时保留撤销、恢复、升级和卸载安全。

### 3.2 用户问题

DesktopUP 主要解决以下问题：

- 游戏快捷方式散落在 Windows 桌面，缺乏视觉分组和统一入口；
- 传统启动器通常是普通窗口，不能长期、低干扰地融入桌面；
- 桌面美化工具常要求复杂配置，或者牺牲原生桌面点击、框选和右键行为；
- 自动整理工具如果移动文件，容易造成不可恢复、覆盖或卸载后遗留；
- 游戏库逐渐增大后，用户很难兼顾“常玩项目突出”和“所有项目仍可发现”；
- 主题与 AI 增强容易突破文件、网络和本地执行安全边界。

### 3.3 核心价值

1. **桌面即入口**：海报长期存在于桌面层，不以控制中心为主体。
2. **不破坏 Windows 桌面**：保留框选、右键、图标点击和普通程序层级。
3. **安全收纳**：先只读、再预览、再明确选择“仅添加”或“安全收纳”。
4. **可恢复**：移动、升级、异常退出和卸载均有账本、备份和失败保留。
5. **视觉可塑**：从一键预设到参数、素材和受限覆盖逐级开放。
6. **低资源、低打扰**：静态时不持续渲染，控制中心和 AI 均按需加载。

### 3.4 当前产品形态

- `CURRENT`：主屏、单海报、单实例后台运行；海报是默认持续可见表面。
- `CURRENT`：控制中心按需打开，托盘承担快捷入口与生命周期控制。
- `CURRENT`：海报状态由版本化 SQLite 仓库管理，JSON/localStorage 仅作为旧数据迁移来源。
- `CURRENT`：海报内容仍是演示卡片，正式 Item 主线尚未开始实施。
- `CURRENT`：C-PSI-05 仍未关闭，透明运行时海报的顶部白色条带是当前 P0 阻断。
- `DEFERRED`：多海报创建、第二显示器、混合 DPI、负坐标副屏、主屏切换、跨屏重启与热插拔均未认证。

## 4. 目标用户画像

### 4.1 主要用户：游戏桌面整理者

特征：

- Windows 11 用户；
- 桌面存在多个 Steam、Epic、Xbox、独立游戏或应用快捷方式；
- 希望快速找到和启动项目；
- 不希望工具覆盖其他应用或改变 Windows 桌面习惯；
- 不愿学习复杂主题语言；
- 重视卸载后恢复和“不要动我的文件”。

核心任务：

- 三分钟内完成安装、看到默认海报并开始添加项目；
- 从海报直接启动游戏；
- 自由移动、缩放、锁定、展开或收起海报；
- 重启、Win+D、Explorer 恢复后继续使用；
- 卸载时恢复被收纳的快捷方式。

### 4.2 次要用户：桌面美化用户

特征：

- 看重壁纸融合、透明度、圆角、排版和主题风格；
- 希望通过预设和滑块完成大部分定制；
- 可能导入背景、SVG、字体和主题包。

核心任务：

- 快速切换内置模板；
- 调整颜色、透明、模糊、间距、尺寸和动画；
- 在控制中心预览后保存；
- 导入、导出和恢复主题。

### 4.3 高级用户：主题作者

特征：

- 能编辑 CSS、SVG 或受限 HTML；
- 可能分享主题包；
- 接受安全扫描、权限预览和信任确认。

核心任务：

- 使用 schema 创建自动参数面板；
- 替换素材槽位；
- 在隔离范围内覆盖 CSS/HTML 插槽；
- 导出完整模板并验证版本兼容。

### 4.4 可选用户：BYOK AI 使用者

特征：

- 自己提供 OpenAI、DeepSeek 或兼容接口 API Key；
- 希望自然语言修改主题、尺寸、间距和排序；
- 接受模型只能提出结构化变更，不能获得本机通用权限。

## 5. 产品原则与不可破坏不变量

### RP-INV-01：真实桌面优先（`P0/FROZEN`）

海报不得破坏 Windows 桌面的空白左键、框选、空白右键、原生图标单击/双击、任务栏、普通应用和文件选择器行为。

### RP-INV-02：层级稳定（`P0/FROZEN`）

海报必须位于桌面内容层，不得成为普通应用之上的 TopMost 表面；桌面右键、刷新、文件选择器、控制中心打开、Win+D、拖动和恢复均不得触发瞬时置顶闪烁。

### RP-INV-03：用户文件安全（`P0/FROZEN`）

未经逐批明确确认，不扫描、不移动、不删除用户桌面项目。永不移动或删除 `.exe`、游戏本体、游戏平台目录、文件夹或普通文件。

### RP-INV-04：失败保留（`P0/FROZEN`）

数据库、迁移、主题安装、快捷方式托管、恢复和卸载发生失败时必须保留上一份有效状态、原始数据或恢复副本，不得用空白默认值掩盖损坏。

### RP-INV-05：单一状态权威（`P0/FROZEN`）

业务持久状态只有一个正式权威。控制中心、托盘和海报都是消费者或命令入口，不能各自维护可回弹的第二份状态。

### RP-INV-06：控制中心不是产品主体（`P1/FROZEN`）

普通启动和自启后只显示桌面海报与托盘；控制中心、设置和 AI 必须由用户主动呼出。

### RP-INV-07：锁定是保护边界（`P0/FROZEN`）

锁定后禁止移动、缩放、改变锚点和 Item 排序；仍允许解锁、展开/收起和有效 Item 启动。AI 和自动化不得静默绕过锁定。

### RP-INV-08：渲染器可替换，行为不可退化（`P0/TARGET`）

透明海报可以由 WebView2、Qt Quick 或其他原生渲染器实现，但必须保持同一状态、输入、层级、暂停和恢复契约。具体渲染技术不是最终用户需求；更换渲染器不能重写 SQLite 权威、托盘、生命周期或安全收纳边界。

### RP-INV-09：无 AI 仍完整可用（`P1/FROZEN`）

未配置 API Key 时不得初始化 Provider 或联网，所有核心手动功能保持可用。

### RP-INV-10：个人自用边界（`CURRENT`）

当前项目以个人自用为主，不要求公开分发所需的许可证页面和第三方 NOTICE 载荷；若转为公开分发，必须重新启用许可证与再分发审计。

## 6. 运行表面与信息架构

```text
DesktopUp.exe
├─ Desktop Poster Surface   默认持续可见；桌面级启动与展示表面
├─ Control Center           按需创建；管理、编辑和预览
├─ Settings / AI            控制中心路由或按需表面
├─ Native Tray              常驻轻量入口
├─ Rust App Core            状态、生命周期、Windows 适配和安全操作
└─ SQLite / Recovery Data   持久状态、迁移、账本和恢复材料
```

### 6.1 桌面海报表面（`P0/FROZEN`）

- 正常运行时唯一持续可见的产品界面；
- 无 Windows 原生标题栏、无任务栏按钮、默认不进入 Alt+Tab；
- 不抢前台焦点；
- 透明非交互区域穿透至真实桌面；
- 海报标题栏、按钮和 Item 只在各自命中区接收输入；
- 独立于控制中心生命周期；
- WorkerW/桌面挂载不可用时进入可诊断回退，不伪装成功。

### 6.2 控制中心（`P1/FROZEN`）

- 用户从托盘、开始菜单、快捷方式或普通第二实例主动打开；
- 是普通、可聚焦、可进入任务栏和 Alt+Tab 的窗口；
- 展示海报、项目、主题、性能、启动、自启、备份、恢复和 AI 管理入口；
- 内部画布只是编辑预览，不是真实桌面宿主；
- 预览与真实海报消费同一正式状态；
- 关闭后优先释放 renderer，不能隐藏或销毁真实海报；
- 关闭再打开必须恢复正确投影，不产生第二控制中心。

### 6.3 设置与 AI（`P2/TARGET`）

- 可作为控制中心路由或按需独立窗口；
- 关闭不改变海报；
- 无 Key 时不初始化 AI；
- 所有写入经过统一命令、校验、预览、确认和撤销链。

### 6.4 托盘（`P1/FROZEN`）

- 由原生运行时拥有，不依赖控制中心 WebView 常驻；
- 单击无动作；
- 双击切换控制中心；
- 右键提供主页、设置、海报显隐、编辑、锁定、暂停、快速主题、自启、桌面重连和退出；
- Windows 决定图标位于主通知区域还是折叠栏；应用不得强制修改系统排列。

## 7. 启动、单实例与生命周期需求

### 7.1 启动意图

| ID | 输入 | 预期结果 | 状态 |
| --- | --- | --- | --- |
| RP-LIFE-01 | 首实例、无参数 | 显示已启用海报；控制中心 absent；创建唯一托盘 | `P0/FROZEN` |
| RP-LIFE-02 | 首实例、精确 `--autostart` | 显示静态海报；不创建/聚焦控制中心；不修改自启注册 | `P0/FROZEN` |
| RP-LIFE-03 | 普通第二实例 | 唤回唯一控制中心；不重复海报和托盘；第二实例退出 | `P0/FROZEN` |
| RP-LIFE-04 | 第二实例 `--autostart` | 保持现有 UI 不变并静默退出 | `P0/FROZEN` |
| RP-LIFE-05 | 未知、重复或组合参数 | 不改变现有 UI；结构化拒绝；请求进程以 64 退出 | `P1/FROZEN` |
| RP-LIFE-06 | 内部性能参数 | 只允许首实例进入诊断，不成为产品公开参数 | `P2/CURRENT` |

### 7.2 控制中心生命周期

- 双击托盘：不存在/隐藏 → 创建或显示；已显示 → 释放，释放失败才隐藏；
- “打开主页”：只显示并聚焦，不切换海报；
- 关闭窗口：不解释为退出；
- ready 前命令排队并按序只投递一次；
- 重复或乱序请求最终只能存在零或一个控制中心；
- 控制中心关闭后不得保留动态预览循环。

### 7.3 Explorer 与任务栏恢复

- 收到 `TaskbarCreated` 后重建唯一托盘并核对桌面挂载；
- 重复事件去抖、单飞并限制重试；
- 连续失败进入可诊断 degraded 状态，提供“重新连接桌面”；
- 退出阶段收到的迟到 Shell、显示或托盘事件必须忽略；
- 恢复过程禁止通用 `HWND_TOPMOST/NOTOPMOST` 脉冲。

### 7.4 显式退出

退出顺序必须至少覆盖：

1. 运行阶段粘滞进入 `exiting`；
2. 停止新命令和迟到恢复；
3. 取消 AI/导入等活动任务；
4. 刷新必要状态；
5. 销毁海报与控制中心；
6. 移除托盘；
7. 结束进程。

## 8. 海报外观与几何需求

### 8.1 默认创建

新海报默认快照：

```text
monitor = primary
anchor = top-right
presentation = EXPANDED
interaction = USING
runtime = ACTIVE_STATIC
is_locked = false
auto_collapse_enabled = false
template = transparent-default
```

当前产品入口只创建和认证一张 `poster-primary`。数据关系可以为未来多海报保留，但不得由此声称多海报 UI 已存在。

### 8.2 默认位置和尺寸

| 属性 | 需求 |
| --- | --- |
| 默认显示器 | 主显示器 |
| 默认锚点 | `top-right` |
| 默认位置 | 主显示器工作区右侧，保留安全边距 |
| 默认宽度 | `max(工作区宽 × 0.22, 280px)` |
| 最小宽度 | `240px` |
| 最小展开高度 | `240px`，以当前 C-PSI 契约为准 |
| 最大宽度 | 当前工作区宽度的 `45%` |
| 最大展开高度 | 当前工作区高度减去上下各 `24px` 安全边距 |
| 收起高度 | 约 `60px` 的标题条 |
| 几何恢复 | 归一化锚点优先，绝对坐标仅作回退 |

### 8.3 位置和尺寸不变量

- 收起与展开只能改变高度，标题栏顶部位置、水平位置和宽度保持不变；
- 展开后恢复收起前的宽高；
- 缩放受动态工作区限制，不能只依赖 CSS 或窗口默认约束；
- 右下角缩放不移动左上角；
- 位置或尺寸提交失败时保留最近已接受状态与本地待处理意图，不得闪回错误旧值；
- 显示环境变化后必须迁回合理可见区域，不能把锁定解释为允许永久不可见；
- 当前只认证主屏；跨显示器规则属于延期验证。

### 8.4 视觉完整性硬门

- 无 Windows 原生标题栏；
- 无顶部白条、亮带、灰色透明包络、未裁剪圆角或宿主空白；
- 首帧、冷启动、拖动中、松开后、控制中心开关后、Win+D 后均保持一致；
- 海报透明度不能把宿主未绘制区域显示为白色或灰色；
- 视觉问题不得通过把海报临时置顶、扩大到整屏或覆盖桌面输入来掩盖。

## 9. 海报状态与权限需求

### 9.1 正交状态模型

```text
海报状态 = 呈现模式 × 交互模式 × 运行时模式 + 锁定属性

呈现：EXPANDED / COLLAPSED
交互：USING / EDITING
运行时：ACTIVE_STATIC / ACTIVE_ANIMATED / PAUSED / STOPPED
锁定：is_locked boolean
```

交互模式和运行时模式不进入 Poster 持久表；启动后交互模式始终从 USING 开始。

### 9.2 权限矩阵

下表还要求宿主可见、ready 且未处于系统级输入暂停：

| 状态 | 标题栏拖动 | 内容区拖动 | 缩放 | 收起/展开 | 锁定/解锁 | Item 单击 |
| --- | --- | --- | --- | --- | --- | --- |
| USING + EXPANDED + unlocked | 允许 | 禁止 | 禁止 | 允许 | 允许 | 启动意图 |
| USING + COLLAPSED + unlocked | 允许 | 禁止 | 禁止 | 允许 | 允许 | 不可见 |
| EDITING + EXPANDED + unlocked | 允许 | 允许 | 允许 | 允许 | 允许 | 选中意图 |
| EDITING + COLLAPSED + unlocked | 允许 | 禁止 | 禁止 | 允许 | 允许 | 不可见 |
| 任意呈现 + locked | 禁止 | 禁止 | 禁止 | 允许 | 允许解锁 | 按 USING/呈现规则 |
| 手动暂停动态效果 | 保持原权限 | 保持原权限 | 保持原权限 | 允许 | 允许 | 保持原规则 |
| 锁屏/显示器关闭/退出/宿主未就绪 | 禁止 | 禁止 | 禁止 | 禁止 | 禁止 | 禁止 |

### 9.3 收起、展开与自动收起

- EXPANDED 显示完整标题、Item、装饰和滚动/分页区域；
- COLLAPSED 只显示标题条，不显示 Item；
- 标题文字在收起态可单击展开；
- 展开/收起按钮连续快速点击按最后意图处理，去抖约 300ms；
- `auto_collapse_enabled` 默认关闭；启用后离开热区按延迟收起，进入热区展开；
- 默认延迟 3 秒，可配置范围 1–300 秒；
- 编辑态暂停自动收起，退出编辑后重新计时。

### 9.4 锁定

- 每张海报独立持久保存锁定状态；
- 标题栏保留锁定/解锁按钮；
- 托盘提供锁定/解锁全部海报；
- 锁定不影响展开/收起、解锁和有效 Item 启动；
- 自动布局可以改变海报内部非锚定 Item 排列，但不能改变锁定海报的外部位置、尺寸和锚点。

### 9.5 暂停

- 手动“暂停动态效果”只停止动态绘制，不冻结按钮和日常输入；
- 全屏覆盖、锁屏、显示器关闭、远程断开或系统不可见可以进入系统级暂停并禁止输入；
- PAUSED 保留最后一帧，不补播放错过的动画；
- 恢复后呈现模式保持，交互模式回到 USING；
- STOPPED 进一步释放可选 Canvas、大图片和代码主题资源；
- 当前默认主题静态时，人工验证重点是状态一致和操作无回退，而不是“肉眼看到动画停下”。

## 10. 标题栏、命中与桌面输入需求

### 10.1 自制标题栏

标题栏属于海报内容，不是 Windows 原生非客户区。至少同一行提供：

```text
海报标题 / 模板标识 / Item 数量 | 收起/展开 | 锁定/解锁
```

- 模板可以改变视觉，不能改变按钮语义和命中契约；
- 标题栏空白区和允许的非交互文字可作为拖动入口；
- 按钮、链接、输入、Item 和 `data-no-poster-drag` 节点必须排除；
- 指针移动达到 `5px` 才判定为拖动；
- 点击和拖动不得相互误触。

### 10.2 透明空白

- USING 下，卡片下方、卡片间隙和其他透明非交互内容必须穿透；
- 空白左键拖动应产生 Windows 桌面框选；
- 空白右键应出现 Windows 桌面菜单；
- 不得出现浏览器“复制/打印/检查”菜单；
- 被海报视觉覆盖范围内的原生桌面快捷方式仍可单击选中和双击启动；
- 海报上下文菜单只能从明确的海报非穿透区域进入，不能抢占桌面空白右键。

### 10.3 Item 命中

- Item 卡片自身必须命中；
- USING + EXPANDED：单击产生启动意图；
- EDITING + EXPANDED：单击选择，拖动按布局权限解释；
- 收起态 Item 不存在于可见/命中区域；
- 右键 Item 进入版本化 Item 菜单接口；菜单命令内容由后继工作流提供；
- 菜单打开期间阻止冲突交互，关闭后恢复。

### 10.4 层级与焦点

- 使用态不主动激活前台；
- 海报不得覆盖控制中心、资源管理器、浏览器、文件选择器或普通程序；
- 海报不得因鼠标按下、拖动、右键关闭、桌面刷新、Win+D 或 Shell 恢复短暂置顶；
- 控制中心打开和关闭不改变海报 z-order 角色；
- 回退窗口必须明确、可诊断，且不能常驻 TopMost。

## 11. 控制中心编辑需求

### RP-EDIT-01：预览投影（`P0/FROZEN`）

控制中心预览将真实桌面坐标投影到可变大小画布。调整控制中心窗口大小后，预览始终可见且比例正确；不能直接用桌面绝对坐标定位到预览画布。

### RP-EDIT-02：单向提交（`P0/FROZEN`）

预览是正式状态的投影和命令入口，不拥有第二套几何。所有修改通过 expected-revision/CAS 提交；拒绝、冲突或失败不能乐观伪装成功。

### RP-EDIT-03：连续操作（`P0/FROZEN`）

- 连续拖动至少三次仍可继续；
- 进入编辑态后可连续拖动和多次调整宽高；
- 关闭再打开控制中心后投影保持正常；
- 编辑操作不能使真实海报覆盖控制中心；
- 真实海报随后仍可拖动、锁定、收起和展开。

### RP-EDIT-04：即时预览与保存（`P1/TARGET`）

主题参数变化即时预览，用户保存后才写入正式 ThemeInstance；保存进入撤销栈。当前 legacy `accent/opacity/density` 回弹属于 Template Platform 待修，不属于 Poster State Store 回归。

## 12. Item 与内容模型需求

### 12.1 当前与目标边界

- `CURRENT`：六张 `NIGHT OPS` 卡片是演示数据，不是正式 Item 能力；
- `TARGET`：C-CIM 建立正式 `CollectionItem`/`PosterItem` 契约和 SQLite 仓库；
- `TARGET`：零、一、多、重复、失效 Item 均由仓库快照驱动；
- `TARGET`：硬编码 `GAME_CATALOG` 退出正式运行路径；
- `NON-GOAL FOR C-CIM`：不扫描桌面、不解析真实快捷方式、不启动、不移动用户文件。

### 12.2 CollectionItem

正式 Item 至少表达：

| 类别 | 字段/语义 |
| --- | --- |
| 身份 | 稳定 `id`；绝对路径不得作为唯一身份 |
| 类型 | `game` / `application` / `shortcut`，未来可扩展 |
| 显示 | `display_name`、图标来源、标签 |
| 来源 | `lnk` / `url` / `exe` / `manual`、稳定 source identity |
| 启动 | target、arguments、working directory |
| 托管 | 可选 `managed_shortcut_id`，仅安全收纳后存在 |
| 有效性 | 合法、失效、解析失败、受限协议等可诊断状态 |
| 统计 | 启动次数、最近启动、有限历史、加入时间 |
| 排序增强 | burst/新鲜度/衰减相关字段由后续布局模块使用 |

失效 Item 必须保留可见、可诊断、可删除或等待修复，不能在加载时静默丢弃。

### 12.3 PosterItem

PosterItem 表达 Item 与海报的关系：

- `poster_id`、`item_id`；
- `order_key`；
- pinned/锚定关系；
- 预留 page、local position；
- 同一 CollectionItem 将来可以出现在多张海报，但当前不开放多海报 UI。

### 12.4 零状态与占位

- 零 Item 收起态明确显示数量为 0；
- 零 Item 展开态显示非模态添加引导；
- 提供“拖入快捷方式”“扫描桌面”“打开控制中心”入口；
- 图标缺失时显示项目首字母占位图，不让 Item 消失；
- 首次成功添加后空状态引导消失；
- 从备份恢复已有内容时不重复显示首次引导。

## 13. 只读发现、导入与仅添加需求

### 13.1 主动入口（`P1/TARGET`）

首版只提供用户主动触发的入口：

1. 将 `.lnk`、`.url` 或 `.exe` 拖入海报或控制中心；
2. 用户点击“扫描桌面”，选择当前用户桌面和/或公共桌面。

应用冷启动不得静默扫描。

### 13.2 对象处理

| 对象 | 只读发现/仅添加 | 安全收纳 |
| --- | --- | --- |
| `.lnk` | 用 Shell 语义保留目标、参数、工作目录和图标位置 | 只允许移动 `.lnk` 本身 |
| `.url` | 校验协议白名单 | 只允许移动 `.url` 本身 |
| `.exe` | 只登记启动目标和元数据 | 禁止移动、复制或修改 |

### 13.3 发现与预览

- 扫描后台执行、可取消、有数量和耗时上限；
- C-ROD 只输出候选项，不直接写库；
- 写入前逐项显示名称、类型、来源、启动目标、图标和错误；
- 提示同路径、同目标、同指纹和已有 Item 冲突；
- 用户可以逐项取消；
- 用户明确选择“仅添加”或“收纳并移出桌面”；
- “仅添加”不改变源文件；
- 200 项扫描必须可取消且不阻塞海报交互。

## 14. 真实启动需求

### RP-LCH-01：启动语义（`P1/TARGET`）

启动必须保留快捷方式的 target、arguments、working directory 和 Shell 语义，不得仅对路径执行不完整的直接进程启动。

### RP-LCH-02：交互（`P1/TARGET`）

- USING 态单击 Item 启动；
- EDITING 态单击选择，明确启动入口或双击行为在 C-LCH 冻结；
- 提供“打开文件位置”；
- 单击/双击检测不得重复启动；
- 无效目标显示结构化错误，不让海报或控制中心崩溃。

### RP-LCH-03：统计（`P2/TARGET`）

有效启动更新累计次数、最近启动和有限历史。失败启动是否计入统计必须由 C-LCH 明确，不可由 UI 自行猜测。

## 15. 安全收纳、撤销与恢复需求

### 15.1 两阶段事务（`P0/TARGET`）

```text
Discover → Parse → Preview → Confirm
→ 写 PENDING 账本
→ 复制到保险库临时位置
→ 校验大小与指纹
→ 原子提交保险库副本
→ 移走原快捷方式
→ 写 MANAGED
```

任何一步失败均不得覆盖现有文件。移走原文件之前必须已有经过校验的保险库副本和 PENDING 账本。

### 15.2 恢复账本

账本至少保存：

- 稳定 ID；
- 原始路径和保险库路径；
- 内容指纹；
- target、arguments、working directory 和 icon source；
- 操作批次；
- PENDING/MANAGED/恢复状态；
- 最后错误和时间戳；
- 仅添加或实际托管标记。

### 15.3 撤销与异常恢复

- 启动时检查未完成事务，优先回滚或恢复；
- 批量操作按项提交，单项失败不掩盖其他结果；
- 原位置空闲时恢复原名；
- 同名存在时不覆盖，使用编号名称并报告；
- 原路径不可用时恢复到桌面 `Desktop-Up Restored`；
- 恢复失败时保留保险库、账本和可重试入口；
- 仅添加项目删除时只移除应用记录，不触碰源文件。

### 15.4 故障门

安全收纳阶段至少覆盖复制中断、校验失败、同名冲突、权限失败和进程异常退出；目标是连续 100 次故障注入不丢失、不覆盖用户快捷方式。

## 16. 排序、缩放与布局需求

### 16.1 分阶段范围

- `P1/TARGET`：可用 MVP 至少提供确定性网格和稳定顺序；
- `P2/TARGET`：建立启动统计、排名、对数缩放、弹性流、子列填充、锚定和全手动控制；
- `P2/TARGET`：最终支持网格、书架、错位卡片等布局风格；具体首发完成门以 B-LAR 工作流为准。

### 16.2 排名因子

```text
rank_score = 0.40 × recency_norm
           + 0.35 × frequency_norm
           + 0.25 × newness_norm
```

有效启动次数考虑加入时间保护、使用频率抵抗和不活跃衰减，下限为原累计次数权重的 10%。计算列不持久化，相同输入必须产生相同输出。

### 16.3 动态缩放

```text
ratio = log(1 + game_launches) / log(1 + max_launches_in_poster)
scale = min_scale + (max_scale - min_scale) × ratio
```

- 默认支持 50%–300% 范围；
- 新 Item 无历史时使用默认比例约 150%，不能直接变成最小 50%；
- 排名比视觉尺寸更敏感，缩放使用额外压缩避免频繁跳变；
- 变化使用轻微弹性过渡；暂停时停止；恢复时不补帧。

### 16.4 三层人工控制

1. 全自动：按 rank score；
2. 锚定 + 自动：固定项保持序号，其余项在空隙自动排序；
3. 全手动：暂停自动排序，拖动改变 order key。

所有自动变化可撤销。锚定项显示低干扰图钉；冲突按稳定规则偏移，不能随机交换。

## 17. 模板与主题需求

### 17.1 首发模板（`P1/TARGET`）

| 模板 | 角色 |
| --- | --- |
| `transparent-default` | 正常默认；高透明、低装饰、低焦点 |
| `neon-hud` | 霓虹 HUD、扫描线、数据化排版 |
| `cinema-lightbox` | 暖白灯箱、胶片结构、衬线标题 |
| `minimal-fallback` | 仅错误安全回退，不进入正常模板选择器 |

默认模板加载失败不得把用户保存的模板选择改写为 fallback。

### 17.2 四级定制

| 深度 | 能力 | 风险 |
| --- | --- | --- |
| 0 | 一键预设与开关 | 低 |
| 1 | schema 驱动的颜色、透明、模糊、间距、尺寸等参数 | 低，可逆 |
| 2 | 图片、SVG、字体、Logo 等素材替换 | 文件写入，需校验 |
| 3 | 受限 CSS 和 HTML 插槽覆盖 | 代码/信任边界 |

控制中心参数面板由 `params-schema.json` 自动生成；模板新增参数不要求修改控制中心前端。

### 17.3 隔离

当前 Web 模板设计要求：

- 每张海报独立 Shadow Root；
- 模板 CSS、DOM 和用户覆盖不污染控制中心、宿主页面或其他海报；
- `--tpl-*` 只是模板内部参数约定，不是主隔离机制；
- 宿主拥有命中、暂停、拖动和错误边界；模板不能调用通用原生 IPC。

如果运行时渲染器迁移到 Qt 或其他原生技术，必须建立等价隔离、参数 schema、资源权限和 fallback 契约；不能机械要求保留 Shadow DOM 实现细节。

### 17.4 热切换

- 在离屏结构中构建并验证后原子替换；
- 快速连续切换去抖并取最后意图；
- 不留下半应用主题；
- 目标时间低于 200ms，不含完整 Item 布局重算；
- 切换失败恢复旧模板和旧参数。

### 17.5 导入导出

目标格式：

- `.params.json`：参数快照，≤64KB；
- `.theme.zip`：参数 + 素材，≤20MB；
- `.full.zip`：完整 manifest/schema/template/presets/assets 与可选覆盖，≤20MB。

导入必须覆盖：路径穿越、symlink/junction、压缩炸弹、文件数、单文件大小、类型白名单、图片重编码、SVG 净化、CSS 外链/@import、HTML script/iframe/object/embed/on* 拦截、校验和、版本迁移、预览确认和原子安装。

模板卸载前先迁移所有引用；任一引用或文件失败则拒绝卸载并恢复原状态。

### 17.6 当前主题缺口

- `KNOWN GAP`：控制中心 legacy 视觉参数调整存在回弹；
- owner 是后继 Template Platform/Theme Authoring 参数权威；
- 不得为了修复该问题扩张 Poster State Store schema 或重开已关闭 C-PSS。

## 18. AI 助手需求

### 18.1 产品边界（`P2/TARGET`）

- 完全可选、用户自带 Key；
- 支持 OpenAI、DeepSeek 和 OpenAI-Compatible；
- 无 Key 不初始化、不联网；

### 18.3 工具权限

- 读取、参数修改、排序、预览、应用和撤销共用手动 UI 命令链；

- 不允许 Shell、PowerShell、CMD、EXE、DLL、注册表、进程、文件系统通用权限或任意 Tauri IPC；

- 模板安装/卸载、文件写入、代码信任、快捷方式收纳、解锁并移动始终显式确认；

### 18.4 错误隔离

鉴权、超时、限流、截断、未知工具和预览崩溃不得影响桌面海报、真实启动或手动设置。关闭 Agent、切换 Provider、退出或卸载时取消活动请求。

## 19. 数据与状态需求

### 19.1 权威与存储

- SQLite 是正式业务状态唯一权威；
- schema 独立版本化；contract version 不能代替 schema version；
- 写入执行 Rust 严格校验和事务；
- mutation 使用 revision/expected-revision/CAS；
- 成功原子推进 revision；冲突返回结构化结果；
- 损坏、未知版本、I/O 失败、无数据必须区分；
- 只有“明确无数据且 legacy 处理完成”时才能创建默认值。

### 19.2 Poster 持久字段

正式 v1 至少包含：

```text
id, title, subtitle,
monitorIdentity, anchor, normalizedRect,
width, height, collapsedState,
autoCollapseEnabled, autoCollapseDelaySeconds,
isLocked, layoutKind, layoutSpec,
templateKey
```

Envelope 至少包含：`contractVersion`、`revision`、`selectedPosterId`、`posters`。

### 19.3 禁止持久化

以下不能进入 Poster 业务表：

- USING/EDITING；
- ACTIVE/PAUSED/STOPPED 及原因；
- visibility、host readiness、FPS、性能采样；
- HWND、WorkerW/Progman、物理坐标、设备 DPI、命中区域；
- 权限矩阵派生结果；
- 临时 `minimal-fallback` 和本次失败原因。

### 19.4 Legacy 与迁移

- JSON/localStorage 只读迁移，不再作为正式写入路径；
- 原始 legacy 数据完整保留备份；
- 含 contractVersion 的损坏数据不得退回 legacy 解析；
- 迁移幂等；失败不覆盖原数据；
- 旧演示多海报记录不能被解释为已交付多海报功能。

### 19.5 数据目录迁移

- `CURRENT`：正式 Release 状态仍位于 `%APPDATA%\com.allmight.desktopup`；
- `TARGET`：迁移到 `%LOCALAPPDATA%\DesktopUp`；
- 路径切换只能由 C-UGM 通过版本、备份、原子切换和失败回滚执行；
- 不能由普通启动或安装基线探针隐式创建/迁移。

## 20. 错误、空状态与降级需求

### 20.1 模板失败

- CSS 失败：跳过错误规则并使用安全样式；
- HTML/插槽失败：使用默认或 minimal fallback 结构；
- 参数 schema 失败：海报仍可用，控制中心显示“参数配置不可用”；
- fallback 不写回用户模板选择；
- 控制中心和托盘展示可操作诊断。

### 20.2 Item 失败

- 图标缺失显示首字母占位；
- target 失效保留 Item 与错误状态；
- 数据损坏尽量从合法字段重建；无法重建时显示安全空海报和恢复入口；
- 删除或重置必须说明保留与清除范围。

### 20.3 渲染宿主失败

- 首次崩溃可静默重建；
- 重复崩溃逐级通知；
- 达到上限后停止自动重试并提供手动重连；
- 恢复不能通过置顶普通应用、吞掉桌面输入或打开控制中心掩盖失败。

### 20.4 诊断

- 结构化报告错误类别、阶段、revision、宿主状态和可重试性；
- 默认脱敏用户名、绝对路径、Key 和 Authorization；
- 控制中心提供导出诊断包；
- 诊断失败本身不能阻断退出或恢复。

## 21. Windows 桌面集成需求

### 21.1 平台范围

- 正式目标：Windows 11 x64；
- 当前用户权限安装；
- 不要求管理员权限；
- 不注入 Explorer、不读写 Explorer 内存；
- 不把原生桌面 ListView 坐标作为业务权威。

### 21.2 桌面挂载

- WorkerW/Progman 等非公开行为只存在于 Windows 适配层；
- 必须可关闭、可诊断、可回退；
- Explorer 重启后重新发现并挂载；
- 恢复失败进入 bottom-most ToolWindow 或明确失败状态；
- 普通业务、Item、模板和数据库不能直接依赖 HWND 细节。

### 21.3 显示与 DPI

- 位置使用显示器身份、归一化锚点和工作区约束；
- DPI/分辨率变化后重新计算逻辑与物理坐标；
- 主屏单海报为当前唯一认证范围；
- 100/125/150/200% DPI、多屏、负坐标、主屏切换、跨屏重启和热插拔属于后续矩阵；
- 未执行的矩阵不得标记 PASS。

### 21.4 焦点与任务切换

- 海报默认不激活、不进入任务栏、不成为 Alt+Tab 普通窗口；
- 控制中心是正常应用窗口；
- 托盘消息、桌面恢复和拖动不得抢焦点；
- 文件对话框等系统窗口出现时海报仍处于桌面层。

## 23. 安全与隐私需求

### 23.1 本地优先

- 核心海报、Item、启动、布局和主题不依赖云端；
- 无 AI Key 不联网；
- 不在后台自动抓取在线元数据；
- 游戏平台发现首选本地只读证据。

### 23.2 文件安全

- 所有导入先预览；
- 所有移动先建立恢复材料；
- 不跟随 reparse point/symlink/junction 越出范围；
- 不覆盖同名用户文件；
- 临时目录、包解压和安装使用规范化路径边界；
- 应用拥有的缓存与用户外部源文件严格区分。

### 23.3 主题安全

- 类型、大小、文件数和总包大小有上限；
- 图片重编码去元数据；
- SVG、HTML、CSS 按白名单净化；
- 外部网络默认阻断；
- 代码主题默认禁用并单独信任；
- 失去响应的主题可暂停或终止，不拖死主进程。

### 23.4 日志和诊断

- 默认隐藏 Windows 用户名和不必要绝对路径；
- 不记录 Key、Authorization 和用户请求正文；
- 关键安全操作记录批次、结果和恢复状态，但不泄露敏感内容。

## 24. 安装、自启、升级与卸载需求

### 24.1 安装

| 项目 | 需求 |
| --- | --- |
| 安装器 | `DesktopUpSetup.exe` |
| 安装范围 | 当前用户 |
| 提权 | 默认不需要 |
| 安装目录 | `%LOCALAPPDATA%\Programs\DesktopUp` |
| 最低内容 | `DesktopUp.exe`、`uninstall.exe`、`resources/` |
| 广告/捆绑 | 禁止 |
| 当前分发 | `privateUse`，暂不要求许可证载荷 |

### 24.2 自启

- 默认关闭；
- 只能由用户显式开启；
- 使用 HKCU `...\Run` 中 `DesktopUp`/`REG_SZ`；
- 精确命令：`"%LOCALAPPDATA%\Programs\DesktopUp\DesktopUp.exe" --autostart`；
- 只有正式安装路径可写；开发和便携 Release 必须拒绝并保持零写入；
- 不使用计划任务、服务、Startup 副本或 HKLM 替代；
- UI 以注册表写后读回为准，不能先乐观翻转；
- 禁用只删除应用自有值，不删除父键或其他应用值。

### 24.3 升级

- 升级前备份数据库 schema、状态和恢复账本；
- 迁移有版本、事务和失败回滚；
- 失败升级不能删除旧可运行版本或保险库；
- 降级不保证读取更高版本数据，必须提供导出/恢复说明。

### 24.4 卸载

`uninstall.exe` 必须是独立可运行的一键卸载入口。顺序：

1. 获取卸载锁；
2. 请求主程序保存并退出；
3. 校验账本和保险库；
4. 恢复托管快捷方式；
5. 清除自启和应用集成；
6. 清除应用拥有的数据；
7. 删除程序文件；
8. 自删除；
9. 显示成功、部分成功或失败摘要。

任一快捷方式恢复失败时保留对应保险库和账本，并提供打开目录和重试；不能把删除应用数据当作恢复替代。

## 27. 当前已知缺口与技术风险

当前问题的复现、证据、已否定候选和关闭标准统一维护在 [`DesktopUP 当前问题与回归台账`](../30_Sync/KNOWN_ISSUES.md)。

### 27.1 P0：透明海报顶部白色条带

现象：双击托盘打开控制中心后拖动真实海报，海报顶部出现白色条带；最近版本中条带可常驻。此前可见边界、copy-bits、同尺寸 WebView2 bounds、HRGN、整屏固定宿主和幂等同步等候选均未形成有效根治，部分方案还引入整屏条带、暗灰包络、普通程序覆盖或编辑阻断。

当前证据更符合透明顶层 HWND、WebView2 可视表面和 DWM Alpha 合成链之间的失配，而不是海报位于屏幕边缘、壁纸、原生 caption 或单纯 DOM/CSS 白色背景。

要求：

- C-PSI-05 不得在该问题仍可复现时标记 PASS；
- 不再把未经反证的候选写成根因；
- 下一次实现应先选择可证伪的渲染架构实验；
- Qt Quick/QML、原生 DirectComposition/Direct2D、layered window 或 WebView2 Composition Controller 都可以作为候选；
- 任何候选必须同时验证透明、层级、桌面输入、连续拖动/缩放、Win+D、控制中心和生命周期，不以“白条消失但层级回退”作为通过。

### 27.2 P1：正式内容 Item 尚未进入产品路径

当前六卡片为演示数据。C-PSI 关闭后下一主线是 C-CIM：Item 契约、SQLite 仓库、零/一/多/失效夹具和数据驱动投影。

### 27.3 P1：视觉参数回弹

控制中心 legacy 视觉参数的即时调整会回弹。该问题归 Template Platform 参数权威，不通过扩展 Poster 状态字段临时修复。

### 27.4 P1/P2：架构文档与当前证据需要同步

既有 A 层设计把“单全局透明 WebView2 宿主”冻结为技术方案，但持续白条证据已经要求重新评估渲染宿主。当前尚未正式决定迁移 Qt；若实验接受，必须同步设计基线、技术架构、B-PCR 计划、C-PSI/后继工作流、依赖打包和性能预算。

### 27.5 发布矩阵缺口

正式安装路径、自启漂移修复、净机安装、数据目录迁移、升级回滚、恢复型卸载、离线运行时依赖和签名尚未形成最终 Release 证据。

## 28. 架构约束与可替换边界

### 28.1 当前实现基线

- Rust + Tauri 2；
- 当前前端为原生 JavaScript/CSS，A0 有意保持无 npm 运行依赖；
- WebView2 用于控制中心和当前海报；
- `windows-rs` 承担 Win32/Shell/DWM 适配；
- `rusqlite` bundled SQLite；
- Tauri/NSIS 打包。

`TECHNICAL_ARCHITECTURE_V0.1` 中的 Svelte + TypeScript 是提议目标，不是当前代码事实。

### 28.2 不应随渲染器变化的边界

无论海报继续使用 WebView2，还是改为 Qt Quick/原生渲染，以下必须保持：

- Rust 生命周期、托盘和单实例权威；
- SQLite/CAS 唯一业务状态；
- 版本化 Poster/Item 快照；
- 控制中心只是预览与命令入口；
- Windows 桌面层、输入和恢复由适配层拥有；
- 用户文件安全、主题权限和卸载恢复不变；
- 主屏单海报先认证；多海报不因技术迁移被隐式开启。

### 28.3 渲染器迁移验收最小集

1. 冷启动和多轮拖动无白条、灰框和裁切；
2. 空白框选、桌面右键、原生图标通过；
3. Item、标题栏、锁定、收起/展开、编辑缩放通过；
4. 海报不覆盖普通程序和控制中心；
5. Win+D、Explorer 重启、暂停、显隐、退出通过；
6. 状态恢复与 CAS 不回退；
7. 静态 CPU/内存满足预算或由用户明确接受新预算；
8. 安装器能稳定携带新增运行时依赖。
