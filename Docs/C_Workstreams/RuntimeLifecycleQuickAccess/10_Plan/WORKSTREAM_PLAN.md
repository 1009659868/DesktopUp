# Runtime Lifecycle and Quick Access 工作流计划

日期：2026-08-13

状态：`COMPLETE — C-RLC CLOSED`

## 1. 目的

把当前已经分散存在的冷启动、单实例、控制中心、托盘、海报显隐/暂停、退出和 Shell 恢复行为收敛为一个可诊断、可回归的运行生命周期；在不破坏主屏单海报宿主的前提下，按 C-IBC 冻结契约实现默认关闭、用户显式开启的当前用户自启。

## 2. 范围

本工作流负责：

- 普通启动、精确 `--autostart` 与非法启动参数的单一 launch intent；
- 第一实例和第二实例的意图分流与单表面拓扑；
- 控制中心按需创建、显示、隐藏、关闭和重开；
- 托盘单击、双击、右键菜单、海报显隐、暂停、状态同步和显式退出；
- HKCU Run 的 `DesktopUp` 值启用、修复、禁用和读回诊断；
- Explorer `TaskbarCreated` 后的托盘/宿主有界恢复及退出阶段抑制；
- 自动化、Release/NSIS 和人工生命周期矩阵。

本工作流不负责：用户数据迁移、升级回滚、恢复型卸载、签名/净机发布认证、快捷方式移动、完整主题编辑器、AI Provider 或多显示器认证。

## 3. 冻结决策

1. [`RUNTIME_LIFECYCLE_MATRIX_V1.md`](RUNTIME_LIFECYCLE_MATRIX_V1.md) 是 C-RLC 唯一事件/状态矩阵；设计文档提供产品意图，矩阵提供实施和验收语义。
2. 桌面海报是普通启动和开机自启后唯一默认可见产品表面；控制中心继续按需创建，自启不得打开或预热控制中心。
3. 产品启动只接受无额外参数的普通启动和精确单参数 `--autostart`；既有精确 `--cdrp-performance-gate` 保持为仅首实例可用的内部诊断意图，其他组合不降级成普通第二实例呼回。
4. 第二普通实例只呼回已有控制中心后退出；第二自启实例保持现有 UI 完全不变后退出；任何路径都不得创建第二托盘、第二桌面宿主或第二控制中心。
5. 自启默认关闭。只有当前进程位于 `%LOCALAPPDATA%\Programs\DesktopUp\DesktopUp.exe` 且通过普通文件/非 symlink/精确命令门时，用户显式操作才允许写 HKCU Run。
6. 自启启用和禁用采用读后写、写后读回；失败时不乐观翻转 UI。应用只拥有 `DesktopUp` 值，不删除 Run 父键或其他应用值。
7. 托盘状态由 Rust 原生运行时拥有；控制中心是消费者，不得以 localStorage 或前端猜测覆盖原生状态。
8. `TaskbarCreated` 恢复必须去抖、有界且可诊断；Exiting 阶段忽略恢复，禁止重建托盘、宿主或控制中心。
9. C-RLC 不恢复通用 TOPMOST/NOTOPMOST 轮询；桌面层恢复继续通过真实 Shell 识别和现有宿主恢复协调器执行。
10. 认证范围继续限制为主屏单海报；多显示器、混合 DPI、负坐标副屏、主屏切换、跨屏重启和热插拔不因 C-RLC 激活而视为通过。

## 5. 工作流完成门

- 生命周期矩阵中的所有 MUST 行有可重复证据；
- 单实例在所有有效/无效启动意图下只保留一套运行表面；
- 自启默认关闭、只在正式安装路径显式 opt-in，启停状态读回一致；
- Explorer/TaskbarCreated 恢复不会打开控制中心、置顶海报或形成无限重试；
- 关闭控制中心不退出，显式退出不被迟到事件逆转；
- 主屏单海报既有交互、状态恢复和性能门无回退。

## 6. 已知限制

C-RLC 完成不代表 C-RCG 净机/升级/卸载恢复/签名矩阵完成，也不认证多显示器和混合 DPI。控制中心 legacy 视觉参数回弹继续归后继 Template Platform 参数权威，不在本工作流扩张 schema 修复。
