# C-RLC-04 控制中心与托盘快捷入口收敛

日期：2026-08-14

状态：`COMPLETE`

## 问题与结论

- 旧实现以 `PageLoadEvent::Finished` 作为控制中心 ready，但前端此时可能尚未注册 `runtime-control`，首次设置/Agent 路由存在丢失窗口；
- 托盘编辑、全局锁定和快捷主题通过前端广播执行，控制中心 absent 时命令会丢失，也形成第二套状态执行路径；
- 控制中心关闭仅隐藏 WebView，实测完整进程树稳定在 `297.61 MiB`，超过既有 `256 MiB` 常驻预算。

## 实施

- 新增 `control-center-lifecycle-v1`：记录 absent/hidden/visible、ready、generation/eventCount、待处理命令数和最后触发；
- 控制中心先注册监听、读取原生快照并完成首帧，再显式调用 `mark_control_center_ready`；ready 前设置/Agent 命令按到达顺序保留且只投递一次；
- `MainWindowCoordinator` 继续以互斥执行串行化创建/显示/释放，重复请求只保留零或一控制中心；
- 托盘编辑直接修改 Rust `RuntimeState`；海报显隐和暂停继续使用同一原生生命周期快照；
- 托盘全局锁定和快捷主题通过正式 Poster State Store 的 expected-revision/CAS 修改 `isLocked`/`templateKey`，不唤醒隐藏控制中心，不使用 localStorage；
- 控制中心 X 关闭和双击关闭优先销毁 WebView；销毁失败才回退隐藏。海报、托盘和 SQLite 状态保持运行，下一次请求重新懒创建。

## 待用户 Release 人工矩阵

1. 托盘单击无动作；双击打开/关闭控制中心，连续五轮均只出现一个窗口；
2. 在控制中心未打开时选择“设置…”和 Agent，确认首次打开能到达对应提示/位置且不丢命令；
3. “显示海报宿主”和“暂停动态效果”只改变对应原生状态，控制中心与托盘勾选不回弹；
4. 控制中心关闭时切换编辑、锁定全部和三种快捷主题，确认海报立即更新且不会为了执行命令弹出控制中心；
5. 用 X 关闭控制中心后海报保持正常；再次打开能正常恢复，重复操作不产生第二窗口；
6. 回归顶部无白条/裁切、空白穿透、卡片、标题栏拖动、锁定、收起/展开和普通程序层级。
