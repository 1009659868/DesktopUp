# C-RLC-03 控制中心编辑视口投影回归修复

日期：2026-08-14

状态：`C-RLC-03 IN VALIDATION / EDITOR PROJECTION RELEASE RETEST PASS`

## 用户反馈

用户在最新版 Release 中发现控制中心主画布为空，而真实桌面海报仍显示在工作区右侧。截图同时显示正式默认海报为近全高尺寸，因此需要区分原生宿主尺寸异常、持久状态损坏和控制中心坐标投影错误。

## 只读证据与根因

- 当前 Release 的真实海报 HWND 为无标题栏 `ToolWindow`，原生矩形约为 `729 × 1392`；窗口样式未恢复 caption，说明不是顶部白条或系统缩放截图误差；
- `poster-placement-v1.json` 记录 `DISPLAY2 / anchorX=1 / anchorY=0`，符合真实海报贴工作区右上侧的位置；
- SQLite `poster-state-v1.sqlite3` 中正式单海报为 `563 × 1344`，`normalizedRect.x≈0.993`、`normalizedRect.y=0.5`；该尺寸正是 `2560 × 1392` 工作区按已冻结默认策略生成的近全高合法海报，不是一次拖动把宽高写坏；
- 控制中心此前直接把桌面工作区像素 `x/y/width/height` 写入自身较小的 CSS 编辑画布。靠右或近全高的合法桌面状态因此落到画布外，形成“控制中心看不见海报”；拖动结束时又从 CSS 变量反读画布坐标写回正式状态，存在保存后回弹或漂移风险。

## 实施

- 新增 [`poster-editor-geometry.js`](../../../../../app/src/poster-editor-geometry.js)，把正式桌面矩形投影到控制中心安全编辑视口；小海报保持 1:1，可用空间不足时等比缩小并保留 4% 编辑余量；
- 控制中心只覆盖预览的 `--poster-x/--poster-y/--poster-scale`，真实 `width/height` 和正式桌面坐标仍保持桌面单位；
- 编辑拖动通过冻结的横纵位置比例逆投影回桌面坐标，缩放通过冻结预览比例逆投影回桌面尺寸；提交前约束在主工作区内，不再把 CSS 画布坐标写入 SQLite；
- 收起态按可见 `116px` 高度投影，避免使用展开存储高度把收起预览缩得过小；
- `ResizeObserver` 仅在控制中心尺寸变化时重算预览，不保存状态、不触发原生窗口移动；
- 原生 [`poster-surface.css`](../../../../../app/src/poster-surface.css) 继续以 `.poster-surface .poster { transform: none; }` 隔离控制中心缩放，真实海报宿主不消费 `--poster-scale`。
