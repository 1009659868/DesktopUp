# C-V2P3 数据驱动海报与可用 MVP 工作流计划 V1

状态:`PLANNING — 待闸口 A/B/C 解锁(计划提前准备)`

日期:2026-08-18

设计输入:`A_Project/10_Plan/CONTENT_ITEM_ACTIVITY_LAYOUT_V1.md`(领域模型 §3、身份/失效 §4、发现 §5、启动统计 §6)

## 1. 目的

把海报从占位卡片升级为数据驱动:正式 Item 仓库(单一数据权威在核心)、只读发现、仅添加写入、真实启动。交付闸口 D:数据驱动海报 + 启动可用验收。

## 2. 架构要点

- **数据权威**:Item 仓库归核心(与控制中心/海报同权威模式);SQLite 存储(库位置 `%LOCALAPPDATA%\DesktopUp\data\`,路径策略与日志一致);
- **投影**:海报渲染端只收投影快照(PosterItem 列表 + 参数),不直连数据库;
- **身份**:稳定 id(非路径);source identity 去重;
- **只读发现**:扫描 Start Menu / Desktop .lnk 与已注册应用,**绝不移动/修改任何源文件**(安全边界,V1 教训);仅添加时生成托管副本;
- **真实启动**:核心经 ShellExecute 语义启动(target/args/workdir/protocol),统计时点按合同 §6(启动成功才算有效启动);
- **排序输入**:MVP 用 added_at 稳定序;排名模型(§7-9)整体属 P6 布局阶段,本阶段只搭统计采集字段。

## 3. 任务

| 任务 | 可验证结果 |
| --- | --- |
| C-V2P3-01 Item 仓库 | SQLite schema(CollectionItem/PosterItem/LaunchHistory);迁移与版本;核心侧 CRUD 命令面 |
| C-V2P3-02 只读发现 | 扫描 Start Menu/Desktop 源;结构化解析(lnk 目标/参数/工作目录);无效项标记;零源文件改动(逐项断言) |
| C-V2P3-03 仅添加 | 手动添加(拖入/选择);去重提示;托管副本生成前不动原件 |
| C-V2P3-04 真实启动 | 启动命令执行;成功判定;统计落库;失败错误可读 |
| C-V2P3-05 海报数据驱动 | 渲染端投影快照渲染真实 Item(名称/图标/标签);空状态夹具(零 Item) |
| C-V2P3-06 闸口 D 证据 | 验收矩阵(§4)逐项记录 |

## 4. 闸口 D 证据清单(摘自合同 §18 + 安全边界)

1. 发现全程源文件零改动(文件时间戳/字节逐一核对);
2. 海报显示真实 Item(名称/图标),启动可用(至少 3 类目标:exe/lnk/url);
3. 失效 Item 不崩溃、显示失效态、不启动;
4. 去重提示与人工确认;
5. 统计:成功启动计数与时间落库,失败不计数;
6. 空状态:零 Item 海报显示空状态夹具;
7. 控制中心可浏览/添加/移除(仅移除托管关系,不删源文件)。

## 5. 边界与非目标

- 安全收纳/撤销/保险库 = P4,本阶段**仅只读与仅添加**,无任何移动;
- 排名/动态缩放/弹性流 = P6;
- 平台来源(Steam/Epic)= P8;
- V1 代码不迁移;V1 数据格式仅参考。
