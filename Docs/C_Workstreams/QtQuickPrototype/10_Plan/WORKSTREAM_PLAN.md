# C-QTP Qt Quick 原型工作流计划 V1

状态：`ACTIVE — 待用户批准后实现`

日期：2026-08-18

## 1. 目的

验证 Qt 6 Quick/QML 作为桌面海报宿主能否通过固定证据矩阵(见 [`技术选型候选`](../../../A_Project/10_Plan/TECH_SELECTION_CANDIDATES_V1.md) §6)。这是路线甲的第一个、也是唯一的当前候选实现。

## 2. 拓扑(按用户裁决 SEL-TBD-03)

```text
核心桩进程(Rust,最小化)  ←—IPC—→  渲染侧车进程(C++/Qt Quick)
  ├─ 状态/命令桩                      ├─ 透明圆角海报 + 自制标题栏 + 六占位卡片
  ├─ 生命周期/启动渲染器               ├─ 桌面层挂载、穿透、命中、拖动/缩放/收起/锁定
  └─ 崩溃监视与有限重建               └─ 呈现自检、0 FPS 静态、性能采样
```

- IPC 原型阶段使用 Windows 命名管道 + 长度前缀消息(几何/显隐/暂停/自检命令);最终 IPC 技术是 C-QTP 内的子决策;
- 渲染器崩溃 = 核心桩重建侧车进程(有限次),验证进程隔离模型。

## 3. 范围与非目标

范围:两进程骨架、Qt 透明海报表面、标题栏、六张占位卡片、桌面层与命中、几何交互、自检、静态与性能测量、证据矩阵执行。

非目标:控制中心、SQLite、托盘、正式 Item、主题包、AI、安装器、V1 代码迁移。

## 4. 任务

| 任务 | 可验证结果 |
| --- | --- |
| C-QTP-01 两进程骨架与 IPC | 核心桩启动/重启渲染侧车;命名管道命令往返;崩溃后有限重建 |
| C-QTP-02 透明表面与参考构图 | 无原生标题栏、透明圆角、标题栏 + 六卡片按 NIGHT OPS 参考构图渲染 |
| C-QTP-03 桌面层、穿透与命中 | 空白穿透(框选/右键/原生图标)、标题栏/卡片命中、拖动/缩放/收起/锁定、5px 阈值 |
| C-QTP-04 呈现自检与 0 FPS | 静态时无持续绘制循环;呈现健康可自检;CPU/工作集采样记录 |
| C-QTP-05 证据矩阵与结论 | 8 项矩阵逐项 PASS/FAIL 记录;通过 → 选定输入;失败 → 淘汰记录并激活 C-D2D |

## 5. 证据矩阵(固定,全部通过才算候选通过)

1. 冷启动、拖动 20 轮、控制中心开关 10 轮(本阶段用普通窗口代替)、收起/展开 10 轮:零顶部条带/灰框/裁切;
2. 空白框选/右键/原生图标穿透;标题栏与 Item 命中精确;
3. 海报不覆盖普通程序与文件选择器;Win+D、Explorer 重启恢复;
4. 静态 0 FPS 实测;10s CPU ≤0.10s;工作集实测并记录(超出 50MiB 交用户裁决新预算);
5. 呈现自检可检测"内容未呈现/条带/透明失效"类劣化;
6. windeployqt 载荷清单与净机可运行路径记录;
7. 主题 L0(预设)/L1(参数 schema)骨架演示 + 热切换 <200ms;
8. 渲染侧车崩溃 → 有限重建,核心桩与桌面输入不受影响。

## 6. 已知坑(来自 V1 与调研)

- Qt 透明窗口:Windows 上需 `FramelessWindowHint + WA_TranslucentBackground`,只用一种透明机制,禁止叠加 blur-behind/分层/颜色键;
- 空白穿透用 `WS_EX_TRANSPARENT` + 自维护命中区域,穿透状态切换必须可回退、可自检;
- 静态 0 FPS:禁用 Qt 默认持续动画/定时器,渲染只由命令驱动;
- 壁纸明暗变化下的可读性留到正式主题阶段,原型不冻结视觉。

## 7. 完成门

8 项矩阵全部通过 → 产出选定决策文档草稿;任一失败 → 淘汰记录(失败项、复现、证据)并转 C-D2D。
