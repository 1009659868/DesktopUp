# Desktop Host Feasibility 工作流计划

最后检查：2026-08-06

状态：`COMPLETE — C-DHF-01..08 CLOSED`

## 1. 目标

用最小代码证明 Desktop-Up 可以在 Windows 11 桌面稳定呈现交互式海报，并在桌面不可见时停止渲染。该工作流只回答宿主可行性，不实现完整收纳、主题或游戏平台功能。

正常启动可见性必须遵循 [`运行表面模型 V0.1`](../../../A_Project/10_Plan/RUNTIME_SURFACE_MODEL_V0.1.md)：桌面收纳层是唯一默认可见表面，控制中心、设置和 Agent 均按需独立呼出。

## 2. 冻结范围

原型只包含：

- 单个测试海报和假图标；
- 拖动海报；
- 海报内按钮点击；
- 空白区域鼠标穿透；
- 静态色块和轻量 Canvas 动画；
- 托盘显示/隐藏与编辑模式切换；
- 托盘右键主页/设置/快速主题菜单；
- 全屏、锁屏和显示器关闭暂停；
- 宿主状态和性能诊断。

不移动真实桌面快捷方式，不扫描游戏平台，不加载第三方主题代码。

## 3. 任务

### C-DHF-01：工程基线

结果：Rust/Tauri 2 前端最小程序在目标 Windows 11 主机启动，记录 Rust、Node、WebView2、SDK 和系统版本；建立单实例与托盘菜单骨架。

验证：Debug 和 Release 都能启动；第二实例转发或退出；关闭控制中心后托盘仍工作。

### C-DHF-02：桌面宿主与回退

结果：测试海报显示在桌面环境，不进入任务栏/Alt+Tab，不抢焦点；普通启动不显示控制中心；桌面挂载失败时自动进入可观察的回退模式。

验证：启动后可见窗口只有桌面海报；普通窗口覆盖海报；回到桌面可见；托盘显式打开/关闭控制中心不改变海报；诊断中记录真实挂载模式；退出后无遗留窗口。

### C-DHF-03：命中测试

结果：海报矩形和编辑手柄可接收输入，宿主透明区域允许桌面选择、右键和图标点击。

验证：使用自动化坐标探针和人工桌面操作共同记录；编辑态和锁定态行为不同且明确。

### C-DHF-04：Shell、显示器与 DPI 恢复

结果：Explorer 重启、Win+D、主屏切换、热插拔和 DPI 改变后，宿主在有限时间内恢复且不越出可见区域。

验证：每种场景连续执行至少 10 次，无重试风暴、幽灵窗口或坐标永久丢失。

状态：`COMPLETE`

### C-DHF-05：事件驱动暂停

结果：前台覆盖、锁屏、显示器关闭和恢复事件进入统一状态机，不通过高频轮询维持。

验证：全屏和最大化覆盖触发暂停；桌面重新可见后恢复；窗口化小应用不误停；按应用覆盖规则可生效。

状态：`COMPLETE`

### C-DHF-06：性能基线

结果：记录静态、30 FPS 动态、暂停和停止四种状态的 CPU、GPU、内存、进程数和恢复时间，并在 Desktop-Up 内提供简单性能数值可视化。

任务：

- `C-DHF-06a`：四态性能采集与采样记录；
- `C-DHF-06b`：Desktop-Up 内简单性能数值可视化（内存、FPS、暂停状态、恢复时间等，不要求复杂图表）。

验证：静态状态没有持续动画帧；暂停状态没有主题渲染活动；数据包含测试机器规格和采样方法；Release 运行时可在应用内看到实时性能数值。

状态：`COMPLETE`

### C-DHF-07：托盘快捷入口

结果：Windows 通知区域图标支持双击打开/关闭主页和右键原生菜单；右键菜单可打开主页、设置、切换当前海报主题，并通过“显示海报宿主”控制海报显隐；单击托盘不改变海报可见性。

验证：关闭主页后托盘仍存在；显式退出后进程和图标消失；第二实例不重复创建图标；Explorer 重启 10 次后恢复；未配置 Key 时菜单不启动 AI。

状态：`COMPLETE`

### C-DHF-08：决策封板

结果：验证已冻结的单全局透明宿主、桌面挂载与回退方式、托盘生命周期、暂停触发和下一步生产接口；宿主拓扑不再作为二选一决策。

验证：单全局宿主在主屏、跨屏坐标、命中区域和 DPI 场景形成明确结论；所有硬门有 `PASS`、`FAIL WITH ACCEPTED FALLBACK` 或明确阻塞结论；更新 A/B/C handoff 与日志。

状态：`COMPLETE`

## 4. 硬门

- 不影响 Explorer 稳定性；
- 空白区域不吞桌面输入；
- 海报使用态不抢前台焦点；
- Explorer 重启和显示器变化可以恢复；
- 静态不持续刷新；
- 暂停时停止主题渲染；
- 任一非公开桌面技巧都有可关闭的适配层和回退模式。

## 5. 验证记录格式

每项完成后在 `20_Log/YYYY-MM/` 新建日志，记录目标、主机环境、实现、验证命令/操作、测量结果、结论、遗留问题和代码锚点。失败结果不得省略；它可能决定技术栈调整。

## 6. 退出与后继

通过后：完成宿主可行性硬门，由 `ACTIVE_PATH.md` 激活 [`C-DRP Desktop Runtime Productionization`](../../DesktopRuntimeProductionization/10_Plan/WORKSTREAM_PLAN.md)。

未通过但回退可接受：记录用户体验差异，由 A 层确认是否进入 MVP。

无安全可用回退：停止功能扩张，重新评估原生 DirectComposition/Direct2D、WinUI 3 或桌面模式设计。
