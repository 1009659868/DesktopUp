# 运行表面模型对齐记录

日期：2026-08-02

状态：`COMPLETE — DESIGN DECISION RECORDED`

## 目标

纠正 A0 Demo 容易让人误以为 Desktop-Up 以普通主页窗口为主体的问题，冻结桌面收纳层、控制中心、设置/Agent 和通知区域入口的角色与生命周期。

## 已发生事实

- 用户确认最终正常运行时只应看到融入桌面的海报收纳模块；
- 当前 A0 主页视觉可以保留，但它只属于按需打开的控制中心；
- 主页/设置/Agent 与桌面收纳栏必须分离，关闭主页不得影响海报；
- 同一进程内部仍可使用多个原生窗口/WebView，产品模型不要求为每个角色建立独立 EXE；
- 公开“小智桌面”资料只作为桌面分区与管理面板分离的交互参考，不作为内部技术实现证据。

## 决策

- 新增并激活 [`RUNTIME_SURFACE_MODEL_V0.1.md`](../../../../A_Project/10_Plan/RUNTIME_SURFACE_MODEL_V0.1.md)；
- 普通启动与开机自启的默认可见表面只有桌面收纳层；
- 控制中心是按需普通窗口，主页中的桌面画布只是编辑预览；
- 推荐每显示器一个透明宿主承载多张海报，避免每海报一个 WebView2；最终窗口拓扑仍由 A0 资源与命中测试冻结；
- 当前 A0 的主页默认显示被记录为已知偏差，不在本次文档任务中修改代码。

## 验证

- 产品设计、技术架构、托盘生命周期、A/B/C 交接和 C-DHF-02 计划均链接到同一运行表面模型；
- 文档链接与登记检查必须通过后，本决策才视为记录完成。

## 遗留问题

- 是否立即执行表面角色对齐切片，由用户在阅读本次记录后决定；
- WorkerW、空白命中测试、Win+D、Explorer 恢复和多显示器仍是 C-DHF-02 之后的硬门；
- 当前 A0 运行实例仍会显示控制中心，不能作为最终启动体验证据。
