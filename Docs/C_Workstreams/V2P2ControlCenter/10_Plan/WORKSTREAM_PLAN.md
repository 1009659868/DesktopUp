# C-V2P2 控制中心与状态权威 工作流计划 V1

设计输入:`A_Project/10_Plan/RUNTIME_SURFACES_AND_TRAY_V1.md`(§4-6,生命周期 §10-12)

## 1. 目的

重建控制中心:普通管理窗口,组织复杂功能,不常驻桌面;与托盘、真实海报共读唯一状态权威(核心)。交付闸口 C:控制中心与三表面一致性验收。

## 2. 目标架构

```text
┌────────────── desktopup-core(状态权威,已建) ──────────────┐
│ 单实例 · 状态+修订 · 命令执行器 · 看门狗 · 托盘 · 穿透钩子   │
└───────┬────────────────────────────────┬──────────────────┘
        │ stdio 帧协议                    │ 命名管道 desktopup-core-v1(已建)
┌───────▼──────────┐        ┌────────────▼─────────────────┐
│ poster-renderer  │        │ control-center(新进程,C++/Qt) │
│ (无状态投影)      │        │ 读权威 · 命令(base_rev) · 预览 │
└──────────────────┘        └──────────────────────────────┘
```

- **控制中心 = 独立进程**(与海报/托盘生命周期解耦,关控制中心不影响海报——LIFE 契约);
- **同一时间最多一个控制中心**:由核心登记"控制中心会话",第二实例 → 核心转发 `show_control_center` → 已有窗口置前 → 第二实例退出(LIFE-03);
- **UI 技术**:与渲染器同工具链(Qt 6.8.3);形态为普通窗口,**Widgets 优先**(表单密集、无透明需求),是否 Quick 在 P2 启动时按"视觉连续性"子决策冻结;
- **预览投影**:控制中心内预览是投影而非真实海报——逻辑坐标、按海报尺寸比例缩放,禁止把真实桌面绝对坐标当控制中心像素(设计合同 §5)。

## 3. 共享 IPC 库(先行重构)

管道客户端逻辑与帧协议目前内嵌于 `src/core`。P2 启动时抽 `crates/ipc`(frame 编解码 + pipe 客户端/服务端),核心与控制中心共用同一实现,消除复制。任务 C-V2P2-01 前置。

## 6. 闸口 C 证据清单(摘自设计合同 §12,用户实机)

1. 普通启动/自启不显示控制中心;
2. 双击托盘打开控制中心,关闭后海报不受影响,再打开正常;
3. 第二实例只唤回控制中心,不重复海报/托盘;
4. 连续开闭控制中心 20 轮无资源、层级和状态回退;
5. 控制中心窗口缩放时预览始终可见;
6. 控制中心/托盘/海报按钮读取同一权威(无回弹);
7. 显式退出后海报、控制中心、托盘和进程全部结束;
8. 100/125/150/200% DPI 下托盘菜单、控制中心和命中清晰。
