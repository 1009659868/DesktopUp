## 1. 目的

实现快捷方式安全收纳闭环:保险库、两阶段账本、撤销、异常恢复、卸载恢复接口。交付闸口 E:收纳/撤销/恢复闭环 + 故障注入。

## 2. 安全模型(逐条来自需求合同与 AGENTS 安全边界)

```
Discover → Parse → Preview → Confirm
→ PENDING 账本 → 复制到保险库临时位置 → 校验大小/指纹
→ 原子提交保险库副本 → 移走原快捷方式 → MANAGED
```

- **只允许托管 `.lnk/.url`**;其他类型只读发现或拒绝;
- **失败不覆盖现有文件**;任何一步失败即停留在该步并保留现场;
- **移走前必须有可验证副本和账本**(大小 + 指纹校验);
- **启动时恢复未完成事务**(PENDING 账本重放);
- **恢复同名冲突不覆盖**;恢复失败保留保险库和重试入口;
- **撤销链**:收纳/恢复/移除共用统一命令与撤销栈(与 AI 命令链同一纪律);
- **故障注入**:本阶段自带注入开关(模拟每步失败/断电/杀进程),验收矩阵逐项打点。

## 3. 架构要点

- 保险库目录:`%LOCALAPPDATA%\DesktopUp\vault\`(版本化、只追加日志);
- 账本:SQLite 事务表(两阶段:PENDING → COMMITTED),每笔记录源路径/副本路径/指纹/时间戳;
- 原子提交:副本先写 `vault\tmp\` → 校验 → `rename` 到正式槽位(同卷原子);
- 核心内新增 `collect_*` / `restore_*` 命令面(带 base_rev 之外的独立事务幂等键,防重复执行)。

## 5. 闸口 E 证据清单(用户实机 + 故障注入)

1. 收纳 10 个 .lnk:桌面消失、海报显示托管 Item、保险库副本齐全;
2. 撤销 5 次:文件回到原位、字节一致、海报同步;
3. 同名冲突恢复:不覆盖、提示、保险库保留;
4. 故障注入 6 点:每点中断后重启,账本重放无孤儿、无半提交;
5. 卸载恢复接口:批量恢复全部成功/部分失败均报告与重试;
6. 全程源文件只有收纳的 .lnk/.url 被移动,其他文件零改动(审计断言)。

## 6. 边界

- 不托管 .exe/.bat/.ps1/协议自定义文件(只读或拒绝);
- 不执行任何导入的内容;恢复不自动启动目标;
- V1 代码不迁移。
