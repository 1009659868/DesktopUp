# C-DRP-03 单海报空白穿透失败与视觉/输入分离重做

日期：2026-08-10

状态：`COMPLETE — USER ACCEPTED`

## 范围决定

- 当前阶段只制作和验收一张海报，不要求创建、显示或人工验证多海报。
- “零/一/多/重叠区域探针”改为同一张海报内部的输入命中矩形，不再解释为零到多张海报。
- 第二显示器、混合 DPI、负坐标副屏、主屏切换、跨屏重启和热插拔仍延期至 C-DRP-06。

## 用户实测证据

用户提供的旧版 Release 截图确认：

1. 从海报内部空白起始左键或框选时，WebView 文本被选中，Explorer 没有获得桌面选择；
2. 海报内部空白右键弹出 WebView 默认菜单，而不是桌面菜单；
3. 位于海报下方的原生桌面图标无法从海报内部直接点击。

截图只作为本轮人工证据，不复制进仓库。上述三项均记为 `FAIL`，在新版 Release 复测前不得关闭 C-DRP-03。

## 根因

海报窗口当前 Z 序仍按既定契约位于桌面宿主之上、普通应用之下；失败不等同于“整体 Z 序太高”。直接根因是旧实现把完整海报矩形同时当作窗口可见区域和输入区域：

- 保留完整 `SetWindowRgn` 才能显示半透明海报背景，但 WebView 会占有内部空白输入；
- 把 `SetWindowRgn` 缩到标题栏和卡片又会裁掉需要保留的半透明背景；
- 因此视觉轮廓与输入命中必须拆分，不能继续共用同一张区域图。

## 调整后的实施顺序

1. 先修复单海报真实桌面输入，并禁用 WebView 默认右键菜单；
2. 再完成单视觉轮廓下的零/一/多/重叠命中区、越界拒绝、圆角边界和 DPI 单次换算自动化；
3. 构建新的原生 Release，验证冷启动与收起/展开无回归；
4. 最后执行桌面空白左键/框选、右键、原生图标、海报按钮、标题栏拖动和锁定人工矩阵。

## 收起/展开顶部锚点补充修复

- 用户实测指出：海报位于屏幕中部时，收起后展开按钮下移，展开后收起按钮上移；顶部栏不应随高度状态改变。
- 根因是 canonical sync 先改变窗口高度，再按持久化的归一化 Y 锚点重新恢复位置；可用垂直跨度随窗口高度变化，导致同一锚点换算成不同的 `Top`。
- 修复后首次 surface sync 仍使用持久化锚点完成重启恢复；后续 preserve sync 会在改尺寸前捕获当前物理左上角，并在改尺寸后原样写回。
- 因此收起/展开只改变窗口下边界和视觉/输入区域高度，不再改变顶部栏及按钮的屏幕坐标。
- `pnpm run check` 共 52 项通过，95 个 Markdown 链接通过；Rust 共 38 项通过；Release 无 bundle 构建通过。
- 新 Release SHA-256：`0DEB3D834B3C9E18DF67AD85BFD66C331F6EEEDF1ABE616DEBA48EA67E4E815B`。
- 程序注入鼠标事件未触发 WebView 按钮，WebView2 调试参数也未进入当前子进程，因此未把自动黑盒点击记为 PASS。
- 用户最终确认屏幕中部收起/展开时顶部栏保持原位，该补充缺陷验收通过。

## 实现

- `surfaceRegistry v1` 的每个登记项新增完整 `visualRegion`，并继续携带零到多个 `interactionRegions`；当前生产只提交一个登记项。
- 前端从自制标题栏和每个游戏卡片 DOM 计算逻辑命中区，完整海报矩形只作为视觉轮廓。
- 原生 `SetWindowRgn` 只应用视觉轮廓；输入命中区独立换算并保存在原生命中图中。
- Windows 低级鼠标事件钩子根据指针位置事件驱动切换 `WS_EX_TRANSPARENT | WS_EX_LAYERED`，让空白输入交给 Explorer，同时在标题栏和卡片上恢复 WebView 命中；按键按下期间保持路由，避免框选或拖动中途切换。
- 钩子安装增加线程握手，安装失败会沿初始化路径返回错误，不再仅静默记录。
- WebView `contextmenu` 默认菜单已阻止；折叠兼容路径会把视觉轮廓收敛到新的逻辑高度。

## 自动化证据

- 显示后终检又发现 Tauri 回写 `APPWINDOW`；扩展样式消息不变量现会同时移除 `APPWINDOW`、恢复 `TOOLWINDOW/NOACTIVATE` 并保持当前穿透状态。
