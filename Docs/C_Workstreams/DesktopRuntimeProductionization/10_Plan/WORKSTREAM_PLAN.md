# Desktop Runtime Productionization 工作流计划

最后检查：2026-08-11

状态：`COMPLETE — PRIMARY-SCREEN SINGLE-POSTER CERTIFIED`

上层模块：[`Desktop Runtime Foundation V1`](../../../B_Modules/DesktopRuntimeFoundation/10_Plan/MODULE_PLAN_V1.md)

## 1. 目标

把 C-DHF 已验证的 A0 独立海报窗体收敛为 V1 的单全局透明生产宿主，并向 Poster Core 暴露稳定、可测试的宿主接口。当前阶段只要求主显示器单海报形成完整闭环，但接口和坐标模型不得阻止同一宿主承载后续多海报与跨显示器布局。

该工作流不定义海报业务 schema、模板 DOM、快捷方式导入或正式视觉；这些分别归属 C-PCB/C-PSS、Template Platform、Collection and Launch 与后续视觉阶段。

## 2. 输入基线

- [`C-DHF 关闭结论`](../../DesktopHostFeasibility/30_Sync/CURRENT_HANDOFF.md)：桌面 Z 序、不可激活、透明命中、Win+D/Shell 恢复、暂停和 ToolWindow 回退已经形成验证证据；
- [`DesktopUP V1 设计基线`](../../../A_Project/10_Plan/DESKTOPUP_V1_DESIGN_BASELINE.md)：单全局透明宿主、主显示器默认位置、宿主拥有命中/暂停/原生窗口权限；
- [`运行表面模型`](../../../A_Project/10_Plan/RUNTIME_SURFACE_MODEL_V0.1.md)：冷启动仅桌面海报可见，控制中心/设置/Agent 按需出现；
- 当前 `poster-snapshot-bridge-v1.json` 是过渡状态桥接，C-DRP 只保留兼容边界，不把它升级为正式海报仓库。

## 3. 所有权边界

### C-DRP 拥有

- 全局透明宿主窗口的创建、销毁、桌面挂载、回退和恢复；
- 虚拟桌面/显示器/DPI 到宿主坐标的映射，以及基于有效逻辑工作区的分辨率响应式视觉缩放；
- 海报交互区域集合的原生合并命中与空白穿透；
- 宿主可见性、不可激活、Z 序、暂停原因、性能模式和诊断快照；
- 向上层开放的稳定命令/事件 DTO 与兼容测试。

### C-DRP 不拥有

- 海报内部状态 schema、锚点含义、展开/收起、锁定和标题栏语义；
- 模板渲染、主题包、图标布局和快捷方式数据；
- 控制中心最终视觉和米白清新风改版；
- 安装器、升级器和卸载器实现。

## 4. 任务

### C-DRP-01：宿主接口与所有权契约

结果：冻结 `HostSurface`、显示拓扑、交互区域、运行状态与诊断 DTO；明确原生窗口几何由宿主持有，海报只提交逻辑区域/期望锚点，避免 Rust、WebView 与本地存储多重所有权。

依赖：C-DHF 完成结论。

验证：以行为测试覆盖 DTO 序列化、非法区域拒绝、版本字段、默认值和旧 A0 命令兼容；代码中不存在第二套生产几何写入路径。

状态：`COMPLETE`

### C-DRP-02：单全局宿主拓扑

结果：运行时只创建一个透明桌面宿主 WebView；当前主显示器单海报可用，宿主使用统一坐标空间，并能在显示器工作区、分辨率或 DPI 变化后重新映射与缩放，不为每张海报创建永久 WebView2。

分辨率响应式缩放契约：

- DisplayTopology 同时暴露 physical work area、Windows device scale 与换算后的 effective logical work area；
- 海报业务基准尺寸保持独立，例如当前 `490×392` 仍表示 1.0 倍设计尺寸，不因显示器变化回写持久尺寸或触发图标重排；
- 宿主根据目标显示器 effective logical work area 计算 `responsiveScale`，并与 `deviceScaleFactor` 分离，避免 Windows DPI 与分辨率适配被重复计算；
- 初始验证基线为 `1920×1080 logical = 1.0`，候选缩放范围为 `0.80–1.25`；最终曲线、上下限与舍入策略必须由本任务的真实矩阵冻结，不提前作为产品承诺；
- 预留 `userScale` 乘数入口且当前默认为 `1.0`；用户偏好及其持久化归 C-PCB/C-PSS，C-DRP-02 不新增海报业务字段；
- 展开/收起、宿主尺寸和 interaction region 必须在同一 revision 使用同一有效缩放；跨屏时重新计算缩放并保持归一化锚点，不产生裁切、累计漂移或 resize 循环。

依赖：C-DRP-01。

验证：

- 窗口枚举、任务栏/Alt+Tab/焦点探针和多显示器坐标测试证明单宿主事实；普通应用始终覆盖海报，回到桌面后海报可见；
- 自动化覆盖 `1366×768`、`1920×1080`、`2560×1440`、`3840×2160` 有效工作区，以及 100%、125%、150%、200% DPI；
- 同一有效工作区在不同“物理分辨率 + DPI”组合下得到等价视觉尺寸，响应缩放单调、有限、无双重 DPI 放大；
- Release 人工矩阵覆盖主屏切换和混合 DPI 跨屏，确认视觉比例相近、交互区域吻合、位置不漂移；物理环境不可用时明确保留待测项，不虚假关闭。

2026-08-10 用户确认新版 Release 首次显示无顶部白条，收起/展开无裁切且按钮命中正常；用户同时决定将第二显示器、混合 DPI、负坐标副屏、主屏切换、跨屏重启和热插拔物理矩阵延期。该延期不阻塞 C-DRP-03，但必须在 C-DRP-06 关闭前恢复验证或形成明确发布限制。

### C-DRP-03：单海报表面登记、合并命中与空白穿透

结果：当前仅登记一张生产海报；同一登记项分别提交完整可见轮廓 `visualRegion` 与零到多个 `interactionRegions`。原生窗口保持完整半透明视觉，只有标题栏、按钮和卡片命中区接收输入，其余海报内空白把左键、框选、右键和原生图标点击交给桌面。

依赖：C-DRP-02。

实施顺序（2026-08-10 调整）：

2. 再验证单个视觉轮廓下的零/一/多/重叠命中区、越界拒绝和 100%–200% DPI 单次换算；
3. 构建原生 Release，执行桌面空白左键/框选、右键、原生图标、海报按钮、标题栏拖动和锁定矩阵；
4. 当前不要求创建或人工验证多海报；多海报产品能力由后继海报核心任务另行设计和验收。

验证：自动化矩阵、Release 构建和真实桌面输入复测均已通过。2026-08-10 用户确认空白左键/框选、桌面右键、原生快捷方式、六张卡片、解锁拖动、锁定阻止拖动、顶部无白条及收起/展开无裁切全部通过；屏幕中部收起/展开顶部栏保持原位。

### C-DRP-04：桌面适配器与恢复协调器

结果：WorkerW 适配、`Progman` 上方 ToolWindow 回退、Win+D、Explorer 生命周期、显示器/DPI 变化与位置恢复共用一个幂等协调器；非公开 Windows 行为仍可禁用和诊断。

依赖：C-DRP-02、C-DRP-03。

验证：WorkerW 可用/不可用、强制回退、Explorer 重启、Win+D、主屏切换、热插拔和 DPI 矩阵无幽灵窗口、无 Z 序漂移、无恢复风暴。

## 5. 完成信号

- 一个生产透明宿主承载当前与后续海报，不按海报线性增加 WebView；
- 常见 1366×768 至 4K 工作区使用独立的 DPI/响应缩放后保持相近视觉比例，且不改写海报业务尺寸；
- 宿主/海报所有权边界由接口和行为测试约束；
- 普通应用覆盖海报，桌面图标位于海报之上，海报不抢焦点且空白区域穿透；
- WorkerW 与 ToolWindow 回退均可观察、可恢复、可禁用；
- 静态/暂停性能预算和 Windows 恢复矩阵通过；
- C-PCB 获得稳定接口，A0 兼容路径有明确移除窗口。

## 6. 风险与回退

- 若跨屏单窗口命中在 WebView2/DPI 组合下不稳定，当前阶段仍保持“单宿主 + 主显示器单海报”，记录跨屏限制，不退回“每海报一 WebView”；
- WorkerW 不可用时继续使用已验证的 ToolWindow 桌面 Z 序回退，不强挂隐藏 Shell 窗口；
- 新宿主出现启动/恢复回归时，可临时切回 A0 独立窗体兼容路径，但不得把兼容路径标记为 C-DRP 完成；
- 不采用 Explorer 注入、未验证 COM 指针解引用或高频窗口轮询。
