# B-RND Renderer Selection 模块计划 V1

状态：`ACTIVE — C-QTP`

日期：2026-08-18

## 1. 责任

为桌面海报宿主选定渲染技术:维护候选清单、组织最小原型、执行固定证据矩阵、记录淘汰理由,最终产出选定决策与渲染架构冻结输入。

## 2. 用户裁决(2026-08-18)

| ID | 裁决 |
| --- | --- |
| SEL-TBD-01 原型路线 | **路线甲**:Qt 6 Quick/QML 优先;未通过则原生 D2D/DirectComposition 保底;Web 主题路线(Composition Controller)仅在用户明确要求时并行 |
| SEL-TBD-02 内存预算 | **原型实测后放宽**:坚持先测 0 FPS 与 CPU 预算;工作集实测结果连同证据交用户接受新预算 |
| SEL-TBD-03 集成形态 | **C++ 渲染侧车进程 + IPC**:Rust 核心进程负责状态/托盘/生命周期,渲染器独立进程,崩溃隔离 |

## 3. 边界

- 只做最小表面验证(透明圆角海报 + 标题栏 + 六占位卡片),不实现产品功能;
- 不迁移 V1 代码;原型代码独立目录(`prototype/`),随选定决策决定去留;
- 不使用多层透明机制叠加(V1 教训:单一机制、可自检);
- 每个候选跑同一证据矩阵,未通过即淘汰并记录。

## 4. 工作流

| C 工作流 | 内容 | 依赖 | 状态 |
| --- | --- | --- | --- |
| C-QTP Qt Quick Prototype | 两进程骨架 + Qt 透明海报 + 桌面层/命中 + 自检 + 矩阵 | 无 | `ACTIVE` |
| C-D2D Native Fallback | 原生 Rust D2D/DComp 最小原型 | C-QTP 未通过时激活 | `PLANNED` |
| C-WCC Web Fallback | WebView2 Composition Controller 原型 | 用户明确要求 Web 主题时激活 | `PLANNED` |

## 5. 完成门

1. 至少一个候选通过固定证据矩阵(见 [`技术选型候选`](../../../A_Project/10_Plan/TECH_SELECTION_CANDIDATES_V1.md) §6);
2. 每个被淘汰候选有淘汰记录(失败项、证据、回归清单);
3. 选定决策 + 渲染架构冻结输入形成文档,交用户确认。
