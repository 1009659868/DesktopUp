# Desktop-Up V2 文档结构与阅读规则

沿用 V1 的 A/B/C 三层计划模型。本文件为 V2 副本,规则与 V1 一致,仅将文档引用路径适配到 V2 计划文档。

## 1. 结构目标

| 层级 | 正式名称 | 回答的问题 | 更新粒度 |
| --- | --- | --- | --- |
| A | Project Mainline | 产品当前处于什么阶段,为什么优先做这一阶段 | 产品阶段、范围或发布目标变化 |
| B | Capability Module | 一项能力由谁负责,边界、依赖和模块里程碑是什么 | 能力里程碑、接口或所有权变化 |
| C | Workstream | 当前具体做什么,如何验证,证据和下一步是什么 | 每个实现或验收任务 |

## 2. 每层固定分区

| 分区 | 保存内容 | 不保存内容 |
| --- | --- | --- |
| `00_Catalog/` | 下一级索引、任务索引、决策索引 | 设计正文、过程叙述 |
| `10_Plan/` | 未来工作、依赖、验收标准、设计方案 | 冗长命令输出、已完成过程 |
| `20_Log/` | 已完成事实、决策结果、验证证据 | 持续变化的"下一步" |
| `30_Sync/` | 当前状态、阻塞、下一动作、接手入口 | 长期技术说明和历史大全 |

## 3. 标准阅读路径

新开发者/新 Agent:

1. `README.md` → 2. `00_Catalog/ACTIVE_PATH.md` → 3. `A_Project/30_Sync/COLD_START.md` → 4. 活跃 B/C 的 `COLD_START.md` → 5. C 的 `WORKSTREAM_PLAN.md`、`TASK_INDEX.md`、`CURRENT_HANDOFF.md`

## 4. 同步触发器

- C:任务完成、阻塞改变、验证完成或结论被推翻时更新;
- B:模块里程碑、接口边界、依赖或主要工作流改变时更新;
- A:产品范围、阶段、优先级、发布目标或关键技术方向改变时更新;
- `20_Log` 历史记录原则上不回写。

## 5. 状态枚举

`DRAFT / PROPOSED / ACTIVE / BLOCKED / COMPLETE / SUPERSEDED`(沿用 V1)。

## 6. 归档原则

- 不删除仍可能解释历史决策的文档;
- C 日志按 `20_Log/YYYY-MM/YYYY-MM-DD_topic.md` 保存;
- V1 证据保存在旧仓库,只读追溯,不复制进本仓库。
